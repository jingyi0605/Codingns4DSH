# 需求文档 - 终端工作区聚合与内置列表

状态：实施中。

## 简介

终端进程属于 Host 工作区，右侧栏标签属于 DSH 会话。当前实现把两者一一绑定，导致布局记录和进程记录互相污染。本需求把右侧栏终端改为工作区聚合入口，终端实例在入口内部列出和切换。

## 术语表

- **Host 终端**：由插件 Host 侧创建并维护的持久终端进程。
- **终端库存**：某个工作区当前 Host 返回的全部终端摘要。
- **聚合页**：右侧栏中代表整个工作区终端集合的唯一“终端”页签。
- **终端视图**：聚合页内部绑定某一个 `terminalId` 的 xterm 内容视图。

## 范围说明

### In Scope

- 每个 DSH 会话最多显示一个终端聚合页签。
- 聚合页内部显示终端列表、选中终端内容、新建、切换、重命名和关闭。
- Host 终端库存按工作区刷新并通知所有会话。
- 工作区没有 Host 终端时自动移除所有会话中的聚合页签。
- 兼容并收敛旧版本按终端创建的多个 Sidebar 标签。

### Out of Scope

- 修改 DSH Host 终端协议和 Host 进程归属。
- 修改 dsh-web 或 Desktop Profile。
- 在没有终端时隐藏创建入口；创建入口必须保留，否则用户无法创建第一个终端。

## 需求

### 需求 1：单一聚合页签

**用户故事：** 作为用户，我希望右侧栏只显示一个“终端”入口，以便终端数量不会改变 Sidebar 标签数量。

#### 验收标准

1. WHEN 当前会话打开终端面板 THEN System SHALL 最多显示一个 `terminal` 类型 Sidebar 标签。
2. WHEN 用户连续新建多个终端 THEN System SHALL 在同一个聚合页内显示多个终端记录，不能创建多个同类 Sidebar 标签。
3. WHEN DSH 重启或切换会话 THEN System SHALL 根据工作区库存恢复一个聚合页，不按终端数量恢复标签。

### 需求 2：页内终端列表与内容

**用户故事：** 作为用户，我希望在终端页内选择具体终端并查看内容，以便终端进程和 Sidebar 布局解耦。

#### 验收标准

1. WHEN 工作区存在多个终端 THEN System SHALL 展示每个终端的标题、Shell 和运行状态。
2. WHEN 用户选择列表项 THEN System SHALL 切换所选终端的可见视图；其他终端视图保持挂载并保留 Host attach，使再次点击无需重新连接。
3. WHEN 用户在页内新建或关闭终端 THEN System SHALL 只对对应 `terminalId` 调用 Host create/close。
4. WHEN 用户重命名终端 THEN System SHALL 更新 Host 记录和列表标题。
5. WHEN 聚合页重新挂载或另一个 DSH 会话订阅同一终端 THEN Host SHALL 复用该 `terminalId` 的内存 resident connection，并立即发送当前状态与有限输出缓存。

### 需求 3：跨会话库存同步

**用户故事：** 作为同一工作区的多会话用户，我希望一个会话的终端变更能反映到其他会话，以便不会看到失效记录。

#### 验收标准

1. WHEN 任一会话创建或关闭终端 THEN System SHALL 刷新共享库存并通知其他聚合页。
2. WHEN Host 返回的库存不包含某个终端 THEN System SHALL 从所有会话的列表中移除该终端。
3. WHEN Host 暂时不可用 THEN System SHALL 保留当前已连接视图并显示可重试状态，不误删正在运行的终端。
4. WHEN resident connection 因连接层故障断开且运行时仍存活 THEN Host SHALL 结束失效 follower、后台重建 resident，并保持终端 `running` 状态。

### 需求 4：无终端时隐藏页签

**用户故事：** 作为用户，我希望没有终端时右侧栏不显示空的“终端”页签，以便界面保持干净。

#### 验收标准

1. WHEN 工作区库存为空且恢复请求已完成 THEN System SHALL 关闭所有会话中的聚合页签。
2. WHEN 工作区没有终端 THEN System SHALL 保留创建入口，但不自动打开空的终端页签。
3. WHEN 用户从创建入口新建终端 THEN System SHALL 打开一个聚合页并显示新建终端。

### 需求 5：旧布局迁移与生命周期

**用户故事：** 作为已有用户，我希望升级后旧终端标签能平滑收敛，不误关闭仍在运行的 Host 终端。

#### 验收标准

1. WHEN 发现同一会话存在多个旧 `terminal` 标签 THEN System SHALL 只保留一个聚合页签并移除多余标签。
2. WHEN 迁移旧标签 THEN System SHALL 不因移除 Sidebar 标签而调用 Host close。
3. WHEN 用户关闭聚合页签 THEN System SHALL 只隐藏页签，不关闭工作区内全部 Host 终端；终端关闭必须通过页内操作完成。

## 非功能需求

### 非功能需求 1：可靠性

1. 终端列表刷新必须按工作区库存去重，不能依赖 Sidebar 导航参数判断身份。
2. 创建竞态期间不得把刚创建的终端从列表或聚合页误删。

### 非功能需求 2：可维护性

1. 终端库存、终端视图和 Sidebar 聚合页职责分离。
2. 恢复逻辑只处理“是否存在聚合页”，不再处理每个终端的标签身份。

## 成功定义

- 一个工作区无论有多少终端、多少会话，任一会话最多一个终端页签。
- 关闭最后一个终端后，所有会话的终端页签自动消失。
- 新建第二个终端不会复用第一个终端，也不会随第一个终端一起关闭。
- `pnpm run typecheck`、`pnpm run build`、`pnpm test` 全部通过。
