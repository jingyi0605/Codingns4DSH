# spec007.1：外部 Agent 适配器扩展

状态：首批适配器已实施，待真实 CLI 登录态验收。

## 这份 Spec 解决什么问题

插件已经接入 8 个外部 Agent 适配器（Command Code、Claude Code、Kimi、Gemini、Pi、Codex、OpenCode、Grok），共用 `CodingNsCliDriver` + `CodingNsCliAdapterRegistry` 这一套 Host 侧边界。

上一轮调查确认了两件新事：

1. **WorkBuddy 与 ZCode 都能接入**，而且不需要改造现有适配器契约（见 `docs/调查报告/20260929-Zcode与WorkBuddy外部Agent适配器可行性调查.md`）。
2. **同类宿主 codex-host 已经接入 15 个适配器**，其中 11 个是本项目没有的。

于是出现了一个选型问题：这 11 个加上 WorkBuddy、ZCode，哪些值得接、按什么顺序接、走哪条协议路径。如果没有结论就开工，很容易出现三种浪费：接了用户根本不用的产品、同一产品重复实现两遍、以及把"看起来支持"的能力写进界面结果一用就卡住。

本 Spec 只做**选型、接入架构和验收标准**，不写实现代码。

## 核心判断

- **优先接"同源复用"的适配器**：CodeBuddy 与 WorkBuddy、Kimi 与 Kimi Code 属于同一 CLI 代码库的不同产品身份。先把产品身份参数抽出来，接第二个几乎不用写新驱动。
- **传输路径按需求选，不按熟悉度选**：需要可应答的权限与提问就走 ACP；只要流式文本和工具事件就走 stream-json。同一条产品可能有两条路，选错会白写一遍。
- **没实测过的能力不声明**：某些路径下权限请求只能被拒绝、或者原生交互会让运行无限等待。这类限制必须前置写清，否则用户会以为功能坏了。
- **只随桌面应用分发的 CLI 要单独处理**：它们不在 PATH 上，且内置路径不是对外承诺的稳定接口，发现规则和失败降级都要显式设计。
- **新增适配器只加不改**：新适配器只写驱动加登记，不修改已有 8 个适配器的行为语义。

## 阅读顺序

1. `requirements.md`：选型范围、规则性需求和验收标准。
2. `design.md`：接入架构、传输基座选择规则、产品身份与发现规格、测试策略。
3. `docs/20260929-适配器选型矩阵.md`：逐适配器结论、证据、缺口与批次建议。
4. `docs/20260929-适配器接入规范.md`：产品身份隔离、安装发现、能力声明、会话探测、回归要求。
5. `tasks.md`：分阶段任务与验证方式。

## 当前范围

本 Spec 覆盖：

- `codex-host` 15 个适配器加 WorkBuddy、ZCode 的逐项评估与分级结论。
- 新增适配器的接入架构与传输基座选择规则。
- 产品身份与配置根隔离规则。
- 安装发现与平台边界规则。
- 能力声明门槛与会话探测约束。
- 与现有 8 个适配器的回归要求。
- 实施任务分解与验收标准。

明确不在本 Spec 内：

- 不写实现代码，不新增或修改适配器源码。
- 不替换现有 8 个适配器的传输实现。
- 不引入厂商 SDK 依赖，除非选型结论明确判定某适配器只能走 SDK 并给出理由。
- 不实现跨 Harness 委派或 Team 编排；那属于 spec007 主线。
- 不接管桌面应用的窗口、登录态或私有 owner runtime。
- 不做版本发布、提交、推送或 npm 发布。

## 与现有 Spec 的关系

- 是 `spec007-AgentTeam外部Agent适配器原生集成` 的补充：spec007 解决"外部成员如何被统一编排"，本 Spec 解决"有哪些外部成员值得接进来"。
- 依赖 `spec005-DSH能力注册与版本路由机制` 的验证命令与能力门禁。
- 复用 `CodingNsCliAdapterRegistry`、CLI driver、session store 与消息 projector，不改变它们的契约。
- 不改变当前非 Team 模式下外部 Agent 会话的行为。

## 分层结论

```text
选型层（本 Spec）
  ├── 候选差集与同源产品识别
  ├── 逐适配器证据与分级结论
  └── 实施批次建议

接入规范层（本 Spec）
  ├── 传输基座选择规则
  ├── 产品身份与配置根隔离
  ├── 安装发现与平台边界
  └── 能力声明门槛

实现层（后续按适配器逐个实施）
  └── CodingNsCliDriver 实现 + 登记 + 测试
```

选型结论必须以证据为准；社区逆向结论可以作线索，但不能当作官方契约。
