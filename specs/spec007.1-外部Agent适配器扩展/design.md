# 设计文档 - 外部 Agent 适配器扩展

状态：Draft

## 1. 设计目标和约束

### 1.1 目标

- 用一份带证据的选型矩阵替代"凭直觉排期"，明确先接什么、暂缓什么。
- 让新增适配器只写驱动、只做登记，不改动已有适配器。
- 把"同源产品"（同一 CLI 代码库、不同产品身份）收敛到一套驱动加产品参数，而不是复制两份实现。
- 把能力声明的门槛写成可检查的规则：没实测过的不声明。
- 保证新增适配器失败时只影响自己。

### 1.2 覆盖需求

- `requirements.md` 需求 1：适配器选型矩阵
- `requirements.md` 需求 2：接入方式选择规则
- `requirements.md` 需求 3：产品身份与配置根隔离
- `requirements.md` 需求 4：安装发现与平台边界
- `requirements.md` 需求 5：能力声明与降级
- `requirements.md` 需求 6：会话标识与续接
- `requirements.md` 需求 7：与现有适配器的兼容

### 1.3 技术约束

- 后端：Node/TypeScript，Host 侧运行；适配器全部在 `src/host/cli-adapters/`。
- 传输：只允许使用现有三种基座（`StandardStreamDriver`、`JsonRpcProcess`、HTTP/SSE），不新增第四套传输框架。
- 依赖：当前 `dependencies` 只有 11 个包，且**没有任何厂商 Agent SDK**。引入 SDK 必须作为独立决策点显式评估。
- 契约：`CodingNsCliDriver`、`CodingNsCliAdapterDescriptor`、`CodingNsAgentEvent` 保持不变；新增适配器不得要求扩展这些契约。
- 凭据：适配器的认证一律由外部 CLI 自己负责，Host 不保存、不复制、不推断。

## 2. 总体架构

### 2.1 现有分层

```text
Client（输入栏适配器选择器、设置页、图标）
        │ RPC: cli/catalog、cli/models、cli/session/*
        ▼
CodingNsCliAdapterRegistry（探测缓存、模型缓存、会话绑定、分段轮次）
        │
        ▼
CodingNsCliDriver（每个适配器一个实现）
        ├── StandardStreamDriver  ← stream-json（claude / kimi / command-code 等）
        ├── JsonRpcProcess        ← ACP / JSON-RPC（grok / gemini）
        └── HTTP-SSE 客户端        ← 网络型适配器
        │
        ▼
外部 CLI 子进程或协议会话
```

本 Spec 不改变这个分层，只在最底层的驱动集合里增加条目。

### 2.2 模块职责

| 模块 | 职责 | 输入 | 输出 |
| --- | --- | --- | --- |
| `CodingNsCliDriver` 实现 | 单个适配器的探测、模型目录、执行与事件归一化 | DSH 会话与轮次输入 | `CodingNsAgentEvent` 流 |
| 传输基座 | 进程生命周期、逐行解码、取消、清理 | 启动参数与事件映射 | 统一事件 |
| `CodingNsCliAdapterRegistry` | 探测缓存、模型缓存、会话绑定、启停 | 驱动集合与设置 | 适配器目录与会话状态 |
| 产品身份参数 | 配置根、数据目录、历史目录规则 | 产品常量 | 子进程环境与路径 |
| 客户端登记 | 显示名与图标 | 适配器 ID | 选择器与设置页条目 |

### 2.3 关键流程

#### 2.3.1 新增一个适配器

1. 在选型矩阵中确认结论为"值得"及以上，并记录接入协议与不覆盖能力。
2. 选择传输基座：优先复用与目标事件格式同构的基座。
3. 实现驱动：`detect()`、`listModels()`、`executeTurn()`，按需实现 `probeSession()`、`respondPermission()` 等可选方法。
4. 在 `src/host/cli-adapters/feature.ts` 的驱动数组中登记。
5. 在 `model-catalog.ts` 增加静态回退目录，在客户端 `provider-icons.ts` 增加显示名与图标。
6. 为探测、事件映射、能力缺失和资源释放补测试。
7. 运行 `pnpm run typecheck`、`pnpm run version:check`、`pnpm run capability:check`、`pnpm test`。

#### 2.3.2 无模型探测

1. 只执行版本命令或协议 `initialize`，不提交 Prompt。
2. 解析版本号，成功则标记已安装并缓存命令路径。
3. 失败或超时则标记未安装，并缓存较短时间避免反复重试。
4. 不创建用户会话，不写会话存储。

## 3. 组件和接口

### 3.1 核心组件

覆盖需求：1、2、3、4、5、6、7

- **选型矩阵**：一份文档，逐适配器给出结论与证据。它是排期依据，不是实现。
- **传输基座复用规则**：判断"走 stream-json 还是 ACP"的规则表。
- **产品身份描述**：一个产品身份由配置根环境变量、默认根目录名、历史目录编码规则、命令目录组成。
- **发现规格**：候选命令名、安装根目录、显式覆盖环境变量、平台适用性。
- **能力声明清单**：每个适配器实际声明哪些 capability，以及为什么其余不声明。

### 3.2 数据结构

覆盖需求：3、4、6

#### 3.2.1 产品身份描述

| 字段 | 类型 | 必填 | 说明 | 约束 |
| --- | --- | --- | --- | --- |
| `adapterId` | `string` | 是 | 适配器唯一标识 | 与已有 ID 冲突时必须报错 |
| `displayName` | `string` | 是 | 选择器与设置页显示名 | 不得冒充其他品牌 |
| `configRootEnvVars` | `readonly string[]` | 是 | 需要强制指向同一根的环境变量 | 多个变量必须同值 |
| `defaultConfigRoot` | `string` | 是 | 用户未指定时的默认根 | 相对 `$HOME` |
| `historyDirRule` | `'lowercase-slug' \| 'preserve-case' \| 'none'` | 是 | 历史目录编码规则 | 同源产品可能不同 |
| `platforms` | `readonly string[]` | 是 | 官方支持平台 | 未列平台不猜路径 |
| `commandEnvOverride` | `string` | 否 | 显式指定安装路径的变量 | 显式无效时不回退 |

#### 3.2.2 发现规格

| 字段 | 类型 | 必填 | 说明 | 约束 |
| --- | --- | --- | --- | --- |
| `binaries` | `readonly string[]` | 是 | 候选命令名 | 按顺序尝试 |
| `installRoots` | `Record<platform, string[]>` | 否 | 非 PATH 安装位置 | 仅填已知布局 |
| `bundledInApp` | `boolean` | 是 | 是否只随桌面应用分发 | 为真时不回退 PATH 同名程序 |
| `versionArgs` | `readonly string[]` | 是 | 版本命令参数 | 默认 `['--version']` |

### 3.3 接口契约

覆盖需求：2、5、7

#### 3.3.1 传输基座选择规则

- 类型：设计规则
- 输入：目标 CLI 的事件格式、交互需求、配置需求
- 输出：选定的基座与理由
- 校验：选定后必须列出该路径不覆盖的能力
- 错误：无法判断时标注为待实测，不得默认按最省事的路径实现

判断顺序：

1. 输出是逐行 JSON 且事件结构与 Claude Code 同族 → `StandardStreamDriver`。
2. 需要可应答的权限、提问、会话级配置或精确回滚 → `JsonRpcProcess`（ACP）。
3. 只有网络端点 → HTTP/SSE 客户端。
4. 只有厂商 SDK 且无 CLI 协议 → 列为独立决策点，评估依赖成本后再定。

#### 3.3.2 能力声明门槛

- 类型：设计规则
- 输入：实测证据
- 输出：`capabilities` 数组
- 校验：每个声明项必须能指向一次真实交互；未验证项不得出现
- 错误：能力缺失时必须给出结构化诊断，不得静默降级为"看起来能用"

## 4. 数据与状态模型

### 4.1 数据关系

- 一个适配器 ID 对应一个驱动实例，ID 唯一。
- 一个 DSH 会话绑定一个适配器 ID 与可选模型/思考档位。
- 同源产品的两个适配器共享驱动实现，但配置根、历史目录和显示名互相独立。
- Provider 会话标识只存在于 Host 会话表，不下发到客户端。

### 4.2 状态流转

| 状态 | 含义 | 进入条件 | 退出条件 |
| --- | --- | --- | --- |
| 未安装 | 探测失败 | 版本命令失败或超时 | 用户安装后刷新探测 |
| 已安装未启用 | 探测成功但设置中关闭 | 用户关闭开关 | 用户开启开关 |
| 已启用 | 可被选择执行 | 探测成功且开关打开 | 用户关闭或探测失效 |
| 执行中 | 有活动轮次 | 收到轮次输入 | 收到 finish 或中断 |
| 错误 | 执行失败 | 进程异常或协议错误 | 用户显式重试或归档 |

## 5. 错误处理

### 5.1 错误类型

- **未安装**：候选命令与已知安装位置都不存在。
- **显式路径无效**：用户指定了安装目录但其中找不到目标 CLI。
- **协议错误**：事件无法解析或缺少必需字段。
- **认证失败**：外部 CLI 报告需要登录。
- **进程异常退出**：执行过程中子进程退出且未给出终态。
- **能力不可用**：请求了该适配器未声明的能力。

### 5.2 错误响应格式

沿用现有 RPC 错误结构，不新增格式：

```json
{
  "detail": "用户友好的中文消息",
  "error_code": "稳定错误码",
  "field": "可选字段名"
}
```

### 5.3 处理策略

1. 未安装：标记为未安装并给安装提示，不影响其他适配器。
2. 显式路径无效：明确失败，不静默回退到其他安装。
3. 协议错误：记录脱敏诊断，终止当前轮次。
4. 认证失败：提示用户在该产品自己的配置根下完成登录，不代存凭据。
5. 进程异常：只标记当前会话，其他成员与适配器继续。
6. 能力不可用：返回结构化不可用诊断，不伪造成功。

## 6. 正确性属性

### 6.1 属性 1：适配器隔离

*对于任何* 适配器 A 的探测失败、执行失败或配置错误，系统都应该满足：其他适配器的探测、执行和默认 DSH 会话不受影响。

**验证需求：** 需求 4、需求 7

### 6.2 属性 2：能力声明真实

*对于任何* 出现在 `capabilities` 中的能力，系统都应该满足：存在一次真实交互证据；反向地，任何未验证能力都不出现。

**验证需求：** 需求 5

### 6.3 属性 3：产品身份不互相污染

*对于任何* 同源产品的两个适配器，系统都应该满足：两者子进程的配置根环境变量指向各自产品根，且任一方的历史与认证不会被另一方读取或写入。

**验证需求：** 需求 3

### 6.4 属性 4：探测无副作用

*对于任何* 会话探测调用，系统都应该满足：不创建新会话、不修改 Provider 状态、不产生计费请求。

**验证需求：** 需求 6

## 7. 测试策略

### 7.1 单元测试

- 发现规则：候选命令顺序、显式覆盖、无效路径不回退、平台不匹配不猜路径。
- 事件映射：文本、思考、工具、权限、用量、完成六类事件从原始事件正确转换。
- 能力缺失：请求未声明能力时返回结构化诊断。
- 产品身份：配置根环境变量被强制指向同一根。

### 7.2 集成测试

- 用 fake 驱动验证注册表新增适配器后，已有适配器行为不变。
- 用 fake 子进程验证 stream-json 与 ACP 两条路径的完整轮次。
- 验证未安装适配器不阻塞启动，且其他适配器目录正常返回。

### 7.3 端到端测试

- 真实安装的适配器完成：探测 → 模型目录 → 一轮执行 → 事件流 → 释放。
- 无模型探测不产生会话记录。
- 会话续接：第二轮带上第一轮取得的会话标识。

## 8. 风险与待确认项

### 8.1 风险

- **同源产品重复实现**：CodeBuddy 与 WorkBuddy、Kimi 与 Kimi Code 都属于同源不同身份，若不抽产品参数会产出两份近乎相同的驱动。
- **协议漂移**：外部 CLI 版本迭代快，事件字段和参数可能变化，需要版本探测与降级。
- **非 PATH 分发的稳定性**：只随桌面应用分发的 CLI，其内置路径不是对外承诺的稳定接口。
- **未验证能力虚报**：某些路径下权限请求只能被拒绝或会让运行无限等待，若照搬能力矩阵会误导用户。
- **平台缺口**：部分产品没有 Linux 官方分发，需要明确不支持而不是猜路径。

### 8.2 待确认项

- 每个候选适配器的安装探测在本机实际可用的命令名与版本。
- 各候选产品的配置根默认值（同源产品之间可能不同）。
- 事件流的真实字段形状（尤其自有点号协议与工具生命周期）。
- 权限与提问在各路径下是否可应答，不可应答时的规避方式。
- 会话存储格式非 JSONL 时的探测方式。
- 厂商 SDK 路径的必要性评估结论。
