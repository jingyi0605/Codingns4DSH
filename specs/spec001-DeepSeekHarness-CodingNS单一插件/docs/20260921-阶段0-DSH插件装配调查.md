## 已确认的 manifest

DSH 的 `package.json` 公共字段由 `DshPackageManifest` 描述：`name`、`version`、可选 `description`、`type`、`main`、`exports`、`files`、`engines` 和 `dsh`。`engines.dsh` 是兼容声明；当前源码将它视为声明，是否由具体安装器强制执行仍需由上游版本确认。

`dsh` 当前确认的字段只有：

```json
{
  "manifestVersion": 1,
  "bundle": { "patch": "./dsh.bundle.patch" },
  "client": { "platform": "web", "inject": [], "immediately": true, "external": [] },
  "profile": { "bundles": ["dsh-codingns"] }
}
```

每种角色不是同一个文件：

- 发行插件是 Bundle，使用 `dsh.bundle.patch`。
- 用户可启动的 Profile 是独立目录的 `package.json`，使用 `dsh.profile.bundles`。
- 当前源码没有 `dsh.host` 字段。Host entry 就是 Bundle patch 行 `name` 指向的包根模块（`exports["."]` / `main`）。
- Client entry 不是 patch 行的另一个 `name`，而是包 manifest 的 `dsh.client` 加 `exports["./client"]`。

因此本包的 Host 来源是 `dist/index.js`（重新导出 `host.apply`），Client 来源是 `dist/client/index.js`。

## Bundle 与 Profile 加载顺序

DSH 启动器在空 entry 列表上依次应用：Profile 的 `dsh.profile.bundles` 中各 Bundle patch、Profile 自己的 `cordis.patch.yml`、Harness home 的 `cordis.patch.yml`，再到命令行 `--patch` overlay。后层替换同 id 行的完整 `config`，不是深度合并。

Bundle patch 的最小有效形状是：

```yaml
- insert:
    - id: dsh-codingns
      name: dsh-codingns
```

## Host / Client 装载顺序

Host 侧由 Cordis Loader 先装载 patch 中的包根行；行的 `apply(ctx)` 是普通 Cordis plugin 生命周期，fiber dispose 负责卸载。

Web Client 侧由 `client-modules` 扫描当前 Loader 行，读取包的 `dsh.client`。它要求包提供 `exports["./client"]`，把 `dsh.client.inject` 作为模块图依赖，`immediately: true` 只代表启动第一阶段预取，并不等于可覆盖默认 Connection 的专用优先级。浏览器加载 `./client` 后，再由 Client Loader 创建 entry fiber。

## Transport 接入时机与限制

`@deepseek-ai/dsh-client-connection` 的 `src/client/index.ts` 明确提供：

- `ClientTransportHooks`：`rpc`、`fetch`、`openStream`、`loadBundle`、`ownsHost`、`streamBaseUrl`。
- `installConnection(ctx, options)`：建立 Context-owned `connection` service。
- `ConnectionGenerationSource`：`(signal, ready) => Promise<void>`，由 API Gateway 的单一 generation loop 持有。
- `connection.registerGenerationSource()`、`start()`、`reconnect()` 和 `ConnectionLoop.stop()`。

默认 `dsh-client-connection` entry 在其 `apply` 中读取 `globalThis.__DSH_TRANSPORT__` 后调用 `installConnection`。它的包 manifest 标记 `dsh.client.immediately: true`，而 `web-app/cordis.patch.yml` 直接把它作为 `connection` 行装入。

当前没有发现一个官方的 `dsh.transportProvider`、`dsh.host` 或“替换默认 Connection 的动态插件”字段。普通 Bundle 的 Client entry 在应用层加载，不能仅靠 `immediately` 保证先于默认 `connection` 行运行；重复调用 `installConnection` 还会尝试再次提供同名 `connection` 服务。

本机发行版还包含 `@deepseek-ai/dsh-experimental-webworker-runtime`。它的 `client` 入口明确标注为 **pre-Cordis glue，不是 Client plugin**：页面先调用 `connectWorkerHost()`，设置 `globalThis.__DSH_TRANSPORT__`，执行 boot injection，再让普通 Client tree 启动。这证明 DSH 自己有“启动前设置 Transport”的内部使用方式，但它是 WebWorker 专用实验运行时，不是面向第三方 CodingNS Transport 的通用 `dsh.transportProvider` manifest 字段。

结论：阶段 0 采用“独立 CodingNS Profile + 版本锁定的 pre-Cordis 启动胶水 + `dsh-codingns` Bundle”。启动胶水在 DSH Client/Cordis 创建前登记 `globalThis.__DSH_TRANSPORT__`，随后再启动 DSH；它不是普通动态插件，不重复调用 `installConnection()`，也不覆盖默认 `connection` 行。当前仓库只提供登记和生命周期契约，真实 CodingNS Transport 工厂留到阶段 1。禁止修改 DSH 核心，也禁止用普通动态插件偷偷覆盖默认 Connection。

## 2026-09-22：DSH Web 设置页未显示插件的原因

在本机 `dsh 0.1.6-alpha.2` 的 Web 启动清单中，最初没有出现 `dsh-codingns` Client entry。检查
`@deepseek-ai/dsh-client-modules` 的真实源码后确认，Client Loader 解析
`exports["./client"]` 时只接受两种形状：直接字符串，或者包含字符串 `default` 的对象；它不会把
`import` 条件当成 Client bundle 路径。

因此插件的浏览器出口必须写成：

```json
"./client": {
  "types": "./dist/client/index.d.ts",
  "default": "./dist/client/index.js"
}
```

修正后，manifest 测试已经锁定 `default` 字段，Client 构建和定向测试通过。DSH 已经生成的 Web
boot graph 不会因为磁盘上的包文件变化而自动重算，所以修正包后必须重启对应 Profile 的 DSH 进程，
再重新打开 Web 设置页；预期入口名称为“CodingNS”。这次问题不是 `settings.section` 注册代码没有执行，
而是 Client entry 在 Loader 阶段就被漏掉了。

## 当前发行方式

每个 DSH 版本单独发布一组兼容物：

| 组件 | 当前版本约束 | 责任 |
| --- | --- | --- |
| `dsh-codingns` Bundle | npm `0.1.0`，`engines.dsh = 0.1.6-alpha.2` | Host/Client 入口、共享契约和业务模块 |
| `profile/` | `dsh-codingns-profile@0.1.0`，`engines.dsh = 0.1.6-alpha.2` | 选择 Bundle，不改变默认 Connection |
| `dsh-codingns/bootstrap` | 随 Bundle 发布 | pre-Cordis 版本校验、Transport 登记和失败清理 |

DSH 升级不会自动让旧插件“猜测兼容”。若版本不是 `0.1.6-alpha.2`，启动胶水会抛出 `DSH_VERSION_UNSUPPORTED`；需要先发布新的兼容 Profile、Bundle 和启动胶水，再切换安装版本。
