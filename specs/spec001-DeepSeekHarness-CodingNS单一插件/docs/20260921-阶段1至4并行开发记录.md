# 阶段 1 至 4 并行开发记录

日期：2026-09-21  
DSH：`0.1.6-alpha.2`  
CodingNS 主仓库契约基线：当前工作区源码（重点为 `apps/codingns-proxy/packages/shared-contracts` 和 Control API/Relay Signaling 路由）。

## 阶段 1：模块注册和生命周期

已完成 `FeatureRegistry` 和资源生命周期契约：

- 模块描述符运行时校验、重复注册、缺失依赖和循环依赖拒绝。
- 依赖顺序启动，逆依赖停用。
- `disabled/enabling/enabled/draining/failed` 状态转换。
- 启动失败清理、disposer 逆序释放、错误聚合和并发启动去重。
- Host/Client 入口仍保持无副作用；阶段 1 不启动服务器、Control API 或 WebRTC。

验证：`tests/feature-registry.spec.ts`，8 个子测试通过。

## 阶段 2：登录、设备、Host 绑定

已完成 Host 专属认证边界：

- refresh token 只存在 Host credential store；共享快照和 Client 出口不暴露 token。
- 登录、刷新、恢复、退出、设备查询、Host 绑定/解绑和标签可用性契约。
- 原生 `fetch` Control API 客户端，Bearer token 只进入请求头，不进入日志或快照。
- 已按 CodingNS 当前源码使用真实路径：
  - `/api/public/auth/login`
  - `/api/public/auth/refresh`
  - `/api/auth/devices`
  - `/api/v1/hosts`
  - `/api/v1/hosts/bind`
  - `/api/v1/hosts/:bindingId`
  - `/api/v1/hosts/availability`
  - `/api/v1/relay/signaling/ticket`

验证：`tests/auth.spec.ts`，6 个子测试通过。

## 阶段 3：资源作用域模型

已完成 `ResourceScopeManager`：

- `hostId/workspaceId/targetHostId/scopeGeneration` 形成不可伪造的作用域快照。
- 切换串行化，旧作用域在清理前立即失效。
- 旧异步结果不能回写新作用域；`assertCurrent` 和 `commitIfCurrent` 提供统一检查。
- disposer 只执行一次，清理异常聚合。

验证：`tests/resource-scope.spec.ts`，7 个子测试通过。

## 阶段 4：WebRTC 到 DSH Transport

已完成可注入的连接和 Transport 骨架：

- Relay Signaling ticket、`/signal?ticket=...`、offer/answer、ICE candidate。
- 使用 Control API 实际下发的 `iceServers` 和 `iceTransportPolicy`，不再写死空 ICE 配置。
- Host DTLS fingerprint 规范化校验；校验失败不会进入 ready。
- DataChannel Carrier、Tunnel Frame、RPC/Fetch/Stream/Control 多路复用、取消和 generation 生命周期。
- Tunnel Frame 默认 1 MiB 上限、序列耗尽保护、pending/stream 关闭收敛、generation 轮换和可注入背压/窗口回调。
- `DshCodingNsTransport.asTransportHooks()` 可交给 pre-Cordis 启动胶水；没有普通动态插件抢占默认 Connection。
- DSH API Gateway 已经独占 `ConnectionGenerationSource` 和 `connection.start()`；普通 Client entry
  只注册设置页面，不重复创建 generation owner。`bindDshConnection*` 仅保留给显式 adapter
  测试/独立运行时。

验证：`tests/transport.spec.ts`、`tests/webrtc-client.spec.ts`、`tests/webrtc-host.spec.ts`，10 个子测试通过。

## 尚未完成和明确边界

当前实现仍是接口注入和 Fake 联调骨架，不宣称远程业务已经端到端可用。尚未完成：

- Host 侧 WebRTC acceptor 和 Node WebRTC runtime 的具体实现。
- 真实 Control API、Relay Signaling、Host、Browser Client 四端联调。
- DSH 真实 Client/Cordis 启动回放中，尚未完成 Relay/Host 真实 Transport 接入实际 generation loop；
  当前已确认由 DSH API Gateway 持有 generation owner，插件不应自行启动 loop。
- Tunnel Frame 的生产级分片、窗口调度、鉴权上下文和协议版本协商；当前只有可注入背压/窗口契约。
- 断线重连、ticket 过期和 generation 替换的完整恢复策略。

因此阶段 4 的状态是 `IN_REVIEW`，不是“真实远程连接已完成”。
