# 需求文档 - 智能助理生命周期集成

状态：Completed（源码集成与自动验证完成）

## 简介

现有三部分能力入口和对话状态分散。以一位全局助理的创建、交流、配置、重置组织产品，复用已有能力及权限边界，保留工作区未提交开发成果。

## 术语表

| 术语 | 含义 |
| --- | --- |
| 助理档案 | 名称、性格背景、创建状态和固定/跟随默认的模型选择 |
| 连续对话 | 文字和语音共用的一份消息与压缩摘要，没有线程列表 |
| 项目认知 | 所选工作区内符合既有规则的会话结构化索引 |
| 对话代次 | 清理、范围变化或重置后撤销异步结果的编号 |

## 需求

### 需求 1：初始化与兼容迁移

**用户故事：** 作为用户，我希望用默认值创建助理，已有配置无需重新配置。

1. WHEN 首次打开助理 THEN System SHALL 只展示名称、模型、性格背景、形象四项配置与预览，性格字段缺省时预填可编辑的标准性格，不覆盖已有设定或用户明确留空；不展示项目或声音选择、高级设置，不申请麦克风。
2. WHEN 用户通过四项表单创建助理 THEN System SHALL 校验并持久保存档案和配置，默认使用浏览器 TTS（文字转语音），进入正式对话，不依赖 MOSS 或识别模型安装。
3. WHEN 已有范围、语音或自定义形象/音色配置且缺少档案 THEN System SHALL 预填身份配置，保留项目范围、模型路径及形象/音色资料，不自动视为已创建，不清理历史；创建输出默认改用浏览器 TTS。
4. WHEN 档案明确 initialized=true THEN System SHALL 视为已创建；档案缺省或 initialized=false 时，正式文字和语音对话 SHALL 等待统一创建完成。
5. WHEN 用户编辑性格背景 THEN System SHALL 校验并使用最多 4000 字符的角色设定；草稿不修改正式档案或历史。初始化与配置的形象展示不提供试聊或问候试听。
6. WHEN 首次创建或配置形象 THEN System SHALL 将第三方角色标为外部依赖；首次创建只提供男女基本形象与已登记形象，不自动补入或预览未登记旧预设，不预置、下载或安装第三方插件代码与 Live2D 引擎。已创建助理的旧选择继续兼容，缺少外部引擎不阻塞创建。
7. WHEN 用户选择基本形象 THEN System SHALL 使用生图工具生成的蓝白鲸鱼风格男女透明 PNG，男生名称为「鱼仔」、女生为「鱼妞」，通过固定同源 URL 展示，默认女生；不手绘角色，不依赖外部引擎。旧默认 ID 和内置名称写入继续兼容，升级补充男生选项时保留原有 19 个自定义形象名额。

### 需求 2：统一连续对话

**用户故事：** 作为用户，我希望文字和语音可以连续追问，刷新后仍能看到交流内容。

1. WHEN 文字或语音完成问答 THEN System SHALL 将有效问答加入同一 Host 持久化记录，并在另一输入方式中使用同一上下文。
2. WHEN 项目索引自动更新或语音租约停止 THEN System SHALL 保留对话记录；下一轮使用最新可用索引。
3. WHEN 索引不可用 THEN System SHALL 允许普通交流，但不得凭旧对话或摘要编造当前项目事实。
4. WHEN 模型失败、被停止或结果迟到 THEN System SHALL 显示真实状态，不把失败或撤销结果加入后续上下文。
5. WHEN 范围变更 THEN System SHALL 撤销旧请求，保留显示记录但隔离旧范围上下文。

### 需求 3：简洁统一界面与能力管理

**用户故事：** 作为用户，我希望日常只有消息、形象和输入区，能力管理都从设置进入。

1. WHEN 打开已创建助理 THEN System SHALL 展示单栏消息、所选形象、文字输入与语音控制，不显示助理会话列表。
2. WHEN 创建后点击设置 THEN System SHALL 使用「基本信息、形象管理、声音管理、更多设置」四个标签页，默认基本信息，不把所有设置堆在同一页；基本信息仅名称、模型、性格背景，形象页负责形象选择与素材/显示管理，声音页负责声音选择、识别模型、音色/模型/设备管理，更多设置负责项目关联、提示词、索引诊断和重置助理。初始化仍只提供四项身份表单。
3. WHEN 切换形象、声音或停止语音 THEN System SHALL 保留连续对话，不重建项目索引。
4. WHEN 形象或语音不可用 THEN System SHALL 保留文字操作，状态与故障按影响范围呈现。
5. WHEN 显示初始化或配置页面 THEN System SHALL 仅展示形象、名称和性格摘要，移除预览标题/说明、试聊表单/回复和问候试听；声音管理中的音色试听继续隔离正式对话，不隐式派发项目任务。
6. WHEN 助理档案缺省或未初始化 THEN System SHALL 隐藏悬浮形象，保留初始化表单里的形象预览及既有展示设置；仅已创建且悬浮开关打开、工作台关闭时显示悬浮形象。
7. WHEN MOSS 未安装或不可用 THEN System SHALL 保留浏览器声音选项与试听，不提供不可用音色；资源与旧音色资料保留，浏览器不支持 TTS 时仅提示试听不可用，不阻止文字交流与创建。
8. WHEN 正式文字或语音对话开始 THEN System SHALL 使用已保存性格背景，仅影响角色与交流方式，不把该设定当作项目事实。
9. WHEN 切换配置标签 THEN System SHALL 保留未保存草稿和已访问页面的资源表单，不挂载未访问页的编辑器；只显示当前页，更多设置使用全宽布局。标签支持键盘焦点导航；离开声音页停止试听，资源安装不因切页中断。
10. WHEN 设置悬浮形象大小 THEN System SHALL 提供迷你 72、标准 144、自定义三个档位，仅自定义显示尺寸输入；允许 72–320 像素，沿用既有数值字段并保留旧自定义尺寸。
11. WHEN 勾选启用第三方形象 THEN System SHALL 弹出使用协议，明确同意并保存后才启用目录；取消或未同意不写设置、不加载目录或素材。开关单独位于当前形象选择框下方，与对话显示开关布局相同，不展示带边框的说明区块或内联协议。管理页不展示 GitHub 兼容目录按钮，撤销启用仍保留已安装形象。
12. WHEN 添加形象 THEN System SHALL 使用统一入口选择形象包安装或自定义素材，只显示当前方式的表单，保留方式切换前的输入及既有安装/取消逻辑。
13. WHEN 展示助理设置选项 THEN System SHALL 统一使用 13px、常规字重与 1.5 行高，开关、许可复选框、项目选择、字段标签与模型选项共用排版规则。
14. WHEN 展示已创建助理 THEN System SHALL 在名称右侧使用小字标签展示思考中、认知更新、空闲或工作中；回复和操作状态优先于认知更新，不在形象下方重复显示项目状态。
15. WHEN 浏览日常消息 THEN System SHALL 让消息区独立滚动、输入栏固定于窗口底部；输入栏采用圆角布局，包含添加附件、实时通话电话及发送／停止图标。输入框按内容自动增高，超过上限后内部滚动，不显示拖拽手柄或蓝色焦点边框。移除底部压缩／清理工具栏、独立实时对话按钮行、运行时不可用说明段落和维护折叠区；实时通话不可用时禁用电话按钮并提示前往声音管理，文字交流保留。
16. WHEN 展示标题与输入栏操作 THEN System SHALL 优先复用 DSH 的添加、设置、关闭、发送、停止和普通对话图标；宿主缺少电话或普通对话图标时使用相同尺寸、线宽与主题颜色的听筒或三点气泡，保留按钮的可访问名称、悬停提示与键盘焦点。返回对话使用气泡，点击进入已有对话。
17. WHEN 用户选择或粘贴附件 THEN System SHALL 支持移除待发送附件及仅附件发送，发送时才上传；最多 6 个、单个 10 MiB、合计 20 MiB。Host 校验字节并委托 DSH 原生附件服务生成引用，图片随消息进入模型，文本附件通过限定已收到引用的只读工具读取；历史不保存编码或用户提供的 Host 路径。上传失败保留草稿，取消、清理或重置后的迟到上传不得启动模型或加入记录。

21. WHEN 查看初始化或配置面板 THEN System SHALL 使用上下 11px、左右 22px 的正文内边距，顶部标题区与底部操作区内边距均为 22px；身份字段及主要设置分组采用紧凑间距，保存／取消位于滚动区之外。保存成功后不显示「配置已保存」提示，失败仍反馈真实错误。

### 需求 4：清理、压缩和完整重置

**用户故事：** 作为用户，我希望分别清理交流、减少上下文或重新创建助理。

1. WHEN 清理对话 THEN System SHALL 停止当前生成和语音，删除消息及压缩摘要，保留配置和项目索引。
2. WHEN 正常连续对话接近上下文上限 THEN System SHALL 由 DSH Agent 的自动压缩机制接管，不按固定轮数重建 Agent，也不提供手动压缩按钮。原压缩接口保留兼容，摘要只能作为历史交流而非项目事实。
3. WHEN 兼容压缩接口失败或期间发生清理/重置 THEN System SHALL 保留原对话，禁止迟到摘要回写；可见历史不再以 200 条消息为硬上限，仍遵守存储大小限制。
4. WHEN 完整重置 THEN System SHALL 停止运行与初始化任务，清空助理档案、配置、对话和派生索引，返回创建界面；保留原始项目会话和下载素材。
5. WHEN 点击更多设置中的重置助理 THEN System SHALL 依次展示两次模态确认；第一次确认只进入第二个模态框，第二次明确确认后才调用重置接口。任一步取消均不执行，默认焦点位于取消按钮，执行中禁用重复操作，失败在当前模态框中显示并可重试。
6. WHEN 用户点击日常标题栏中配置左侧的清理图标，或发送完整 `/clear`、`/清理`、`/reset` 或 `/重置` 指令 THEN System SHALL 展示一次模态确认，确认后仅清理交流并保留配置与项目索引，取消不执行，不将指令交给模型。标题清理图标采用 DSH 原生重置箭头，与斜杠指令共用确认和执行逻辑；尚未创建、配置视图不显示，未完成读取或操作中禁用。输入 `/` 时提供清理指令提示；路径、带参数文本和普通消息不得误触发。指令与附件同时发送时提示先移除附件；完整重置仍只从更多设置的两次确认进入。

### 需求 5：验证及操作边界

**用户故事：** 作为维护者，我希望集成保持兼容并具备可重复验证。

1. WHEN 新 RPC 被调用 THEN System SHALL 沿用原生鉴权、白名单、参数和设置写入校验。
2. WHEN 本轮执行验证 THEN System SHALL 使用源码定向测试和不产出文件的类型检查，不构建、启动服务器或操作 Desktop。
3. WHEN 每个任务完成 THEN System SHALL 及时更新 tasks.md 的状态及验证证据。
