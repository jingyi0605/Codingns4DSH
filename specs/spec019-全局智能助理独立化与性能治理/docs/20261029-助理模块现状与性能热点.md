# Assistant Module Current State and Performance Hotspots

Date: 2026-10-29

Status: Source investigation plus initial lifecycle optimizations. No machine profiling, build, server, Desktop, or user-profile operation was performed. The observations below identify candidate work; they do not prove the cause of user-reported whole-computer lag.

## Scope and ownership footprint

The global assistant is not a single isolated module. The current implementation spans:

- Client registration and UI: `src/client/features/global-voice-assistant.ts`, multiple `src/client/features/assistant-*.ts` modules, assistant locale modules, and `src/client/avatar/`.
- Host features: `src/host/features/global-voice-rpc.ts`, the `assistant-*` Host feature modules, voice coordinator/runtime, notification services, and session index/cache/storage.
- Native companion: `src/host/desktop-assistant/`, `src/host/avatar/`, and `assets/desktop-assistant/`.
- Shared contracts/data: `src/shared/assistant-*`, assistant avatar/voice/notification contracts, desktop-assistant contracts, and assistant configuration fields.
- Integration points: Client and Host feature registries, `src/dsh-capabilities/`, RPC validation/allowlists, package exports, tests, assets, and plugin configuration.

These locations are discovery results, not an exhaustive move/delete list. Import graphs and non-assistant consumers must be checked before ownership changes.

A TypeScript import-graph walk from four current Host/Client assistant entries resolved 289 local source files. This includes unrelated feature contracts and capability adapters pulled in through shared configuration and service types. The graph is a conservative compile-time dependency map, not the runtime bundle size. It confirms that a standalone plugin cannot be made independent by copying only files whose names contain `assistant`; the package needs a narrower service/config contract or an explicit set of neutral shared modules.

## Prioritized hypotheses

1. Profile the whole-document Client observer under realistic DOM churn; the successful-mount scan guard is an initial mitigation, not a change to observer scope.
2. Validate in an isolated runtime that disabling the assistant prevents Host assistant/avatar/companion feature startup; the descriptor and dependency wiring now enforce that intent.
3. Measure active native companion polling and visible avatar rendering separately from idle; those loops are expected only while their surfaces are active.
4. Verify resource leaks and CPU after voice/index/preview workflows stop. Existing paths include cancellation and visibility gates, but source inspection alone does not prove cleanup.

## Measurement needed

Use the same isolated DSH build/configuration and machine for a baseline and candidate comparison. Record:

- Host and Client CPU over a quiet 5-minute window; memory/RSS and post-GC retained heap where available.
- Timer wakeups, MutationObserver callback count and nodes/buttons scanned, animation-frame activity, recurring RPC/network count, worker/process count, and long tasks.
- Separate runs: base plugin only; assistant installed but disabled; assistant enabled and idle; voice; indexing; visible avatar; companion; then repeated stop/teardown.
- The exact DSH version, OS, hardware, plugin combination, settings, warm/cold state, and profiler/tooling versions.

The 5-minute window is a proposed minimum protocol, not a measured baseline or approved numeric budget. Compare repeated runs and report variance. Do not use Desktop user data or processes without item-by-item authorization.

## Review conclusion

The source confirms avoidable continuous work candidates, but does not establish that this plugin alone explains user reports. Two unneeded idle loops were removed; CPU improvement has not been measured. Extraction is justified by product isolation and optionality; the performance claim must be independently validated against matched profiles. The safest sequence is a baseline, a narrow independent package/service contract, parity and migration, remaining measured hot-path fixes, then removal from the base package.
