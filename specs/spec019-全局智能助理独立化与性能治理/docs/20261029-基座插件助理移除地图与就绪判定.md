## 1. 判定结论

截至 2026-10-29，基座插件的**主动全局助理注册、设置/RPC/资源所有权和相关构建产物已移除**。这次切换没有触碰 Desktop、用户 profile 或真实数据。
八组跨文件耦合的移除点（见 §2）已在 task-12 中完成；任务仍处于 IN_REVIEW，因为独立包的 live workflow parity、真实 profile 迁移和匹配的运行时性能证据尚未闭合。

## 2. 移除地图（最终要移除什么）

以下每一组都是"功能在基座里的落点"。移除后基座不再启动、注册、校验、打包对应能力，由独立助理插件承载。

1. `src/host/features/index.ts`：`createGlobalVoiceRpcFeature` / `createAssistantAvatarRuntimeFeature` / `createDesktopAssistantFeature` 的 import、`createHostFeatures()` 数组中的三项注册、对应 re-export。作用：Host 侧三项助理/语音/形象功能的启动注册。
2. `src/client/features/index.ts`：`globalVoiceAssistantFeature` 的 import、`CLIENT_FEATURES` 数组注册项、re-export。作用：Client 侧功能注册（驱动设置页与 UI）。
3. `src/host/index.ts`：`registerAssistantVoiceStreamRoutes`（assistant-voice-stream）与 `registerAssistantAvatarRoutes`（assistant-avatar-runtime）的 import 与调用；`AssistantAvatarPackages` / `assistantAvatarPackageDirectory`（avatar/packages）导出。作用：Host 入口级语音流与形象路由、形象资产导出。
4. `src/client/index.ts`：assistant notification remote 挂载逻辑；`AssistantAvatarAdapter` / `AssistantAvatarAdapterContext` 类型再导出（shared/assistant-avatar-adapters）。作用：Client 通知链路降级挂载与形象适配器契约。
5. `src/host/settings.ts`：assistant 设置 schema、normalizer、`assistantProfile` / `model` / `appearance` / `prompts` 校验器。作用：assistant 设置块的形状定义与写入清洗。
6. `src/host/rpc.ts`：`CODINGNS_RPC_ENDPOINTS` 中的 `assistant/*` 端点清单（lifecycle、chat、notifications、conversation、voice/*、tts/*、index/*）；`parseSettingsOp` 的 assistant 守卫（`validateAssistantProfile` / `validateAssistantModel` / `validateAssistantAppearance` / `validateAssistantPrompt(s)`）；`isAllowedSettingsPath` 的 assistant 分支与 `modules/globalVoiceAssistant` 放行项。作用：RPC 服务面与设置写入守卫。
7. `src/shared/contracts/config.ts`：`AssistantSettings` 类型、`DEFAULT_ASSISTANT_SETTINGS`、`DEFAULT_CODINGNS_SETTINGS.assistant`。作用：共享类型契约与默认值。
8. `package.json`：`sherpa-onnx-node` 依赖；`assets/assistant-basics`、`assets/desktop-assistant/**`、`assets/voice/**` 打包条目；`bundle:client` 的 `tsdown.desktop-assistant.config.ts` 脚本。作用：语音运行时依赖与打包面。

## 3. 为什么移除必须作为一组执行（耦合与并发冲突）

- import ↔ 注册 ↔ export 互为闭环：删注册不删 import/export 会留下死代码或断链，反之亦然。
- settings.ts 的校验器被 rpc.ts 的守卫直接调用；config.ts 的类型被两者共同消费。先删类型则编译失败，先删注册则功能当场失效。
- 因此八组移除点必须同一次原子变更内完成，且变更后 typecheck 与聚焦回归同时通过。
- 这些变更已由 task-12 以同一工作阶段完成；后续只允许继续做独立包验证和迁移验证，不能恢复基座注册。

## 5. 目的地包就绪判定

`dsh-global-assistant`（`@jingyi0605/dsh-global-assistant` 0.1.0-rc.1）已有 Host/Client 源码、neutral contracts、tests、manifest 与构建配置。2026-10-29 的实际检查结果为：`pnpm run typecheck` 通过，`pnpm test` 55/55 通过，`pnpm run build` 通过，`pnpm run check:package-graph` 通过（235 个源文件），`npm pack --dry-run --json` 可解析 1,007 个归档条目。Typert `.mjs`/`.d.mts` exports 已按实际产物修正并逐项验证。

这些结果是独立源码/构建/包图检查，不代表 live DSH 集成通过。Connection 合同审计发现：
- `src/host/rpc.ts` 注册了唯一的 `connection.rpc.intercept('/api', ...)`。Connection 明确只允许一个 `/api` interceptor，而 Typert Gateway 也依赖该通道；二者会冲突，且当前 Host entry 测试 fake interceptor，未覆盖此真实组合。
- `src/host/features/assistant-voice-stream.ts` 与 `src/host/avatar/runtime-routes.ts` 将 Fetch route path 去除 `/api/`。Connection 校验要求 route 使用完整 `/api/...` path，并按请求完整 pathname 精确查找，因此功能启用时这些注册会失败或无法匹配。
- `fetch.register` 是 exact-path Map，没有 wildcard/prefix API。维持 Client 当前 `/api/globalAssistant/...` URL 的话，Host 必须登记有限的 POST endpoint 集合并在 handler 内分派，或改用与 Gateway 共存的稳定公开路由；不能通过 fetch wildcard 绕开单 interceptor 限制。
- 本地 `node_modules` 是混合/不完整树，与目的地 lockfile 的部分 DSH 依赖版本不一致，`dsh-api-remotes` 缺失。当前构建成功不等于 lockfile clean install 已验证。
- 包清单存在未闭合的发布依赖边界：`src/host/config.ts` 导入的 `@deepseek-ai/schemastery` 未在 manifest 任一依赖区声明；构建产物仍对 `@deepseek-ai/dsh-client-ui-primitives` 发出 `require()`，但该包当前只在 `devDependencies`。此外，task-6 声明的 `tests/assembly.spec.ts`、`tests/typert-assembly.spec.ts`、`tests/settings-store.spec.ts` 不存在，相关行为只有间接覆盖。

此外，历史设置仍位于基座 `codingns` namespace；对话、语音模型、avatar engine/packages、desktop companion 的旧数据使用 `codingns4dsh` 路径。独立包已改为 `global-assistant` 数据根，但未实现 legacy read/migration、备份、失败恢复或 downgrade 兼容。行为对等和运行时 CPU/内存/网络 profile 也未完成。

结论：独立包 shell、源码构建和基础测试已具备证据，但运行接入、数据所有权切换和性能验收**未就绪**；task-2 描述中的"不得删除"门槛仍然关闭。

- 未操作 Desktop、用户 profile 或真实迁移数据；assistant-only donor implementation sources, assets, replay harnesses, and obsolete tests were removed after import-graph review. Generic DSH session/message and external-Agent adapters remain.
- 未触碰 Desktop、用户 profile、任何运行进程；未安装、发布或替换任何包。
- 未创建 `tests/assistant-package-boundary.spec.ts`：该测试属于目的地包边界工作（task-1.1），此刻创建要么得到失败断言、要么与并发工作重复。

- 基座全量测试实际结果已在开发记录中记录为 4,140 total / 4,101 pass / 17 fail / 22 skipped；本地临时输出由并发会话清理，未作为仓库 artifact 保留。
