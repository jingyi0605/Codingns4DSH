# Ordinary subagent Activation contract regression (2026-11-17)

## Evidence and cause

The supplied ordinary Codex session failed at `agent_subagent action=start` with `Cannot read properties of undefined (reading 'id')`, before returning a child ID. A subsequent `read` without that ID returned `DELEGATE_CHILD_NOT_FOUND`.

Read-only inspection of the installed DSH Desktop `0.2.2-rc.3` package established that `startActivation(spec)` reads `spec.parent.id`. CodingNS still passed the older `spec.request.parent` layout. The installed method and installed plugin reproduced the same error in isolation without starting an Agent. Team mode is a separate setting and does not enable ordinary child creation.

## Repair

Keep the existing ordinary subagent API and re-export its startup contracts from `native-team-subagent.ts`. Perform host-specific conversion inside the DSH capability boundary. The named-tree `namesOf`/`rootOf` structure selects top-level Activation parameters; older Activation and `startContinuable` retain their existing nested layout. Do not invoke the probe methods, mutate the parent, retry creation, change permissions, or enable Teams.

Regression coverage includes external Codex and native `spawn` providers, exact parent identity, prompt, directory/model options, cancellation signal, parent delivery, optional message ID, native failure propagation without retry, and ordinary background creation followed by `wait`/`read` completion. Existing tests continue to cover legacy contracts and rejected Activation result cleanup.
