## Findings and evidence

### 1. Ordinary follow-up status can retain the first turn's result

Zcode, Command Code, and OpenCode children produced the requested `DELEGATE_ACK 55` on their second turns, while parent `agent_subagent` read/wait calls could still return the initial `DELEGATE_DONE 55`. The native completion notification and the child's persisted journal contained the actual follow-up answer. Parent models sometimes repeated reads before accepting the notification.

The lifecycle cache is populated by the first-turn waiter. `waitNativeSubagentLifecycle()` immediately returns an already terminal cached entry; follow-up delivery does not consistently refresh that observation. Relevant source: `src/host/cli-adapters/native-subagent-dispatch.ts` and `src/host/cli-adapters/subagent-tool.ts`. A correction should track the specific sent turn or message boundary without dropping the previous completed result during an uncertain send.

Both Lead and collaborator runs failed to discover CodingNS `agent_team`. The collaborator could find its provider's private `task_get`/`task_list`, but `task_get("task-1")` reported no such task. The native Team task remained pending and unowned at revision 1, even though the worker wrote the requested artifact. That is a shared-task workflow failure.

The Lead test was stopped at an unapproved environment-probing shell command; no environment values were approved or collected. The ordinary invocation control passed both rounds, separating the missing Team transport from general adapter startup.

### 5. An ordinary explicit child model changed an adapter preference

The ordinary Gemini `provider-default` control added `agentAdapterPreferences.gemini.modelId` to the saved Stage0 configuration. The preflight snapshot had no Gemini preference. Another concurrently finishing test consequently recorded `preferencesUnchanged: false`; that difference does not imply it caused the write.

`registerNativeTeamSubagentProviders()` calls `registry.setSession()` for ordinary children without disabling preference persistence. Team children already avoid remembering selections through their `teamId`; ordinary children do not. The correction should make resolved child selections session-owned for both forms of delegation.

The observed Gemini test preference was restored through native `settings/mutate`, using the current namespace revision and an exact value comparison. Only `agentAdapterPreferences.gemini` was removed. A subsequent deep equality check confirmed all adapter preferences matched the preflight snapshot. Restoration evidence is `/tmp/codingns-stage0-preference-restoration.json`; original reports retain the side effect.

### 7. Native Lead effort selection can break after Team creation

Two early native Lead pilots created real external teammates, then failed on the next model step with `UNSUPPORTED_REASONING_EFFORT`: `glor02/deepseek-v4.1-flash` does not support remembered effort `high`. The same native parent worked before becoming a Team Lead. Its saved DSH adapter preference includes `high`, while the native catalog's default route has no effort selection.

The native Team selection override in `src/host/cli-adapters/feature.ts` keys on `adapterId=dsh` and `teamId`, allowing a Lead to be treated as a child with a pinned model/effort. A correction should pin explicitly resolved native children and preserve the native model selection owned by a Lead.

The Grok pilot parent was `session-b8acafde-f51a-41ae-8624-052f83ac50b4`. This is a parent model-selection failure and must not be counted as evidence that Grok could not start.

## Fixture corrections and ownership

The first fixture reassigned a pending task from the Lead, which already transitioned it to in-progress, then required the worker to claim it again. That double claim was a fixture mistake. Final fixtures leave tasks unowned and pending and accept an already-owned in-progress task without claiming again.

An early runner waited for the next `turn/end` count. An automatic child-settlement turn could end before the queued human follow-up, creating a false follow-up failure. The corrected runner assigns each submitted prompt a unique cue and waits for the turn containing that accepted input. The first OpenCode Lead follow-up result is excluded from product failure claims and was rerun with this correction.

The corrected OpenCode Lead run `session-d26014bd-7a7a-4c36-b384-d758dcd1a67e` passed both rounds with Codex child `aa42e255-b1c8-4a96-aac6-37b3bce6511a`. The shared task stayed completed at revision 3, the artifact hash was unchanged, the same child/provider conversation handled the follow-up, and the actual peer ACK reached the Lead. Codex Lead/collaborator acceptance used root `session-440478e4-a68b-4740-aff1-4fbc9eff2612` and child `82be1664-acce-4432-bdb7-7e594ce852a1`; OpenCode collaborator acceptance used root `session-96daa36e-381e-4e84-91ad-3ffff892457d` and child `3bb7c7df-22c8-42bb-8cb6-89016d704963`.

Managed children must be interrupted with native `subagents/interruptByParent(childSessionId, parentSessionId, "continuable")`. `session/cancel` is the root-session Stop path and does not reliably stop a managed child. The runner now verifies durable parent identity and uses the correct endpoint for its own children. Cancellation results and final journal state are separate evidence.

At the beginning of this work, the exposed session-bound `codingns.agent_subagent` bridge was mistakenly assumed to target Stage0. Three read-only smoke-test children were created under Desktop before ownership checks identified the mismatch. This was outside the requested scope and was disclosed to the user.
