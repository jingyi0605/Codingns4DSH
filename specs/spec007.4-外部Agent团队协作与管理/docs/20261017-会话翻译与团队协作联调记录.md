## Conflicts and fixes

| Boundary | Failure mechanism | Resulting behavior |
| --- | --- | --- |
| Internal prompt translation and Team continuation | A translation settings/model-generation change previously raised `SessionTranslationCancelled` while the Agent was assembling its next step. Native inbox claim happens before assembly, so an optional translation failure could terminate the Lead before accepted Team input was delivered. | Internal invalidation retains the complete original prompt and cancels only translation work. Agent Stop and feature disposal remain effective. This protection was introduced in the preceding session-export follow-up. |
| Human and Team input accepted together | The old early return skipped translation for an entire batch whenever any peer/settlement message was present. Simply translating the human message was insufficient because the external prompt builder subsequently ignored its translation record. | Translate genuine human messages individually, preserve Team protocol text and provenance, and consume each human translation exactly once when forwarding the mixed batch. Both Codex/OpenCode regressions cover two human messages around one peer report. |
| Cancelled human translation within a mixed batch | Rejecting the whole native pre-step discarded an independently accepted Team report along with the cancelled human submission. | Omit only the cancelled human message while merging producer-owned messages by original position/identity. A normal standalone cancelled submission still rejects; explicit Agent interruption still stops the turn. |
| Native completion notifications | `subagent-settled` was not treated as new external input, allowing a completed child's result to be replaced with the original human task. | Settlement notifications share ordered delivery/uncertainty tracking with peer messages. This protection was introduced in the preceding session-export follow-up. |

Team message bodies, member names, task IDs, revisions, and sender framing are coordination data. They are intentionally preserved rather than sent through human-input translation. Enabling native translation does not remove the existing exclusions for native delegated-child prompt/output translation.

Two additional Team defects were found by the live tests. They are independent of the translation model:

1. **Late native model catalog:** a freshly started Team adapter captured `sessionController` before it was published. Codex could create a shared task but native teammate creation returned `TEAM_NATIVE_ROUTE_UNAVAILABLE`. The adapter now resolves the current controller when selecting the native route, including after service replacement. A late-publication/replacement regression reproduces the original failure.
2. **Effort restored after a native tool step:** the first native child route correctly omitted effort, but later `llm/stream` synchronization borrowed the remembered native preference `high` again. In the live reproduction the native reviewer read `task-1`, then subsequent steps failed with `UNSUPPORTED_REASONING_EFFORT`. Native Team bindings now retain their owned model selection across all updates and persistence; ordinary native preferences remain unchanged. The regression covers initialization, later synchronization, and the persisted record.
