The Claude teammate completed three failed turns without producing text, calling a tool, or claiming its task. Each request selected `codingns-cli-claude-code` with model `sonnet`; each recorded terminal failure was `PROVIDER_ERROR: server_error`. A fourth turn was still in progress when exported. Its runtime context identifies DSH `0.2.1-rc.2` and inherited `workspace-write` / `never` permissions.

The corresponding Claude Code 2.1.301 transcript is `/Users/jackson/.claude/projects/-Users-jackson-Code-TEST/e6eed4cb-15f5-460f-9844-7bc7596a439e.jsonl`. Matching prompts and timestamps connect it to the exported teammate. All four requests received HTTP 502 with `Upstream service temporarily unavailable` and error type `upstream_error`. ## Failure mechanism and correction

Claude emits `type=system`, `subtype=api_retry` while it schedules another API attempt. The [official Agent SDK changelog](https://github.com/anthropics/claude-agent-sdk-typescript/blob/main/CHANGELOG.md#0277) documents this notification and its retry fields.

The Claude parser previously passed that notification to the generic stream parser. Its `error: server_error` field became an immediate `finish(error)`. The shared stream driver then released the process, preventing Claude from performing its scheduled retry. This explains why repeating the Lead's instructions produced another failure at the first retry boundary.

The correction consumes only Claude's `system/api_retry` notification before generic error handling. Claude retains ownership of its retry schedule and existing conversation. The adapter continues reading until a genuine result, error, cancellation, or stream closure. Existing terminal-result cleanup remains intact. No prompt replay, process relaunch, model fallback, additional Team authority, or saved preference change was added.

This parser is shared by ordinary Claude sessions, Team Leads, and teammates. All three execution contexts reproduced the failure with protocol replays, so the defect is not restricted to subagents. Team permissions did not cause the exported failure: no tool invocation or approval request occurred.

## Verification and limits

- Before the correction, all seven new protocol regressions failed with premature `server_error`; `/tmp/codingns-claude-api-retry-before.log` retains the output.
- After the correction, all seven passed: ordinary/Lead/teammate recovery, exhausted retries preserving the final HTTP error, cancellation during retry backoff, unexpected EOF, and genuine error events. The teammate case resumes the same provider conversation. The success cases retain one launch, one submitted prompt, and the selected model; `/tmp/codingns-claude-api-retry-after.log` retains the output.
- The affected Claude/stream/Team suite passed 104 tests with two explicit skips and zero failures. The skips are the unavailable default-path alpha.2 TeamService fixture and a Windows-only native command replay. Log: `/tmp/codingns-claude-api-retry-focused.log`.
- Typecheck, version synchronization, and capability retirement checks passed. Logs: `/tmp/codingns-claude-api-retry-{typecheck,version,capability}.log`.

The tests replay the protocol with memory streams. No fresh paid model call, distribution build, server restart, profile mutation, Desktop operation, commit, or publication was performed for this correction. Existing README and mobile close-icon edits were preserved.

The upstream 502 remains an independent failure condition. Preserving Claude's retry loop lets a transient outage recover and allows a persistent outage to reach its genuine final failure. This source correction does not certify that the configured upstream route is currently healthy or automatically rerun the failed debate task.
