# 需求文档 - DSH 本地会话永久删除

状态：In Progress

## 简介

DSH 原生只提供归档（隐藏会话），不提供永久删除会话的入口或接口。用户清理无用、测试或误建的本地会话时，需要一种不会留下幽灵条目、不会损坏并发写入、也不会误删工作区或派生分支的安全永久删除能力。

## 术语表

- **System**：Codingns4DSH 插件（包含 Host 服务、DSH 能力适配层与 Client 界面）
- **本地 DSH 会话**：由当前 Host 的 JSONL 持久化后端落盘存储的单个会话，不包含 PeerHost 远端虚拟会话
- **立即删除**：目标会话在当前无任何活动写入者、无运行任务、无子代理持有且可证明跨进程排他时，立即移出持久化目录并清理全部关联记录
- **下次重启时删除（延迟排队）**：目标会话当前仍由运行时持有，用户单独确认后记录删除意图，等下次 Host 正常启动且无活动写入者时再安全执行

## 范围说明

### In Scope

- 「工作区会话增强」中的默认关闭开关（「永久删除会话…」）与原生会话行右键/`…` 菜单项（`codingns.session.delete`）
- 经 Host 校验的本地所有者权限控制，一次针对一个本地 DSH 会话
- 会话日志及所有历史代际、专属临时产物、投影缓存、工作区成员与归档/置顶记录、可证明归属的 spill 文件清理，以及全文搜索索引协调与核验
- 运行时持有时的「下次重启时删除」单独确认、排队状态查询、排队阶段取消与崩溃/重启回放
- 仅在主视图仍显示被删会话时清空主视图，并通过原生会话服务刷新列表

### Out of Scope

- 工作区项目目录与用户文件、共享附件、独立 fork 分支、备份、导出文件、外部 Provider 原生历史或其他插件数据库
- 批量删除、级联删除子代理、删除远端 PeerHost 会话
- 回收站、已删除数据的恢复或撤销
- 自动终止运行中任务、自动排队、自动关闭或重启 DSH

## 需求

### 需求 1：默认关闭的入口、精确定位与确认交互

**用户故事：** 作为本地 DSH 所有者，我希望能在开启开关后从任意会话行的右键或 `…` 菜单发起永久删除，并在二次确认后执行，以免误删。

#### 验收标准

1. WHEN 「永久删除会话…」开关处于默认关闭状态 THEN System SHALL 不在原生会话行菜单中暴露删除入口。
2. WHEN 用户从原生会话行菜单点击删除 THEN System SHALL 严格使用原生菜单传入的 `sessionId`（拒绝标题匹配、DOM 猜测或回退到当前主视图会话 ID），并排除 PeerHost 虚拟会话。
3. WHEN 打开确认框 THEN System SHALL 展示会话名、完整可读的会话 ID、删除范围与不可撤销说明，且必须勾选确认后才启用危险提交按钮。
4. WHEN 当前会话已有待执行或清理中的操作 THEN System SHALL 禁止再次提交同一会话，仅提供状态查询及（仅排队阶段可用的）取消入口。

### 需求 2：Host 端授权、路径校验与安全排他删除

**用户故事：** 作为系统维护者，我希望每次删除动作都由 Host 验证本地所有者、合法路径与写入排他，以防越权或并发损坏。

#### 验收标准

1. WHEN 收到任何 `sessionDeletion/*` RPC THEN System SHALL 验证已认证所有者身份与可信本地请求上下文，并绑定短期 `operationId` 到调用者、准确 `sessionId` 与会话生命周期身份。
2. WHEN 目标为非本地、虚拟会话、未物化会话、非 JSONL 后端、拥有子代理会话的父会话、仍受父会话引用的子代理、存在符号链接/junction/重复位置或越界路径 THEN System SHALL 拒绝删除，不留模糊状态。
3. WHEN 执行立即删除 THEN System SHALL 先建立进程内按 `sessionId` 管理的准入预留（覆盖 `open`、`create` 与子会话派生），再获取与后端一致的跨进程写入租约，并重新验证无活动写入者、无运行中 Agent/子代理/后台作业/定时提醒。
4. WHEN 执行文件系统移除 THEN System SHALL 在排他保障下先把验证后的会话目录原子重命名至 DSH 搜索根之外的私有同文件系统 staging 目录，再递归删除 staging 并确认原路径与 staging 均已消失。

### 需求 3：延迟排队、崩溃恢复与派生数据协调

**用户故事：** 作为正在使用会话的用户，我希望无法立即删除的活跃会话能安全排队到下次重启，并在日志移除后干净清理全部派生数据而不产生幽灵行。

#### 验收标准

1. WHEN 会话仍由运行时持有且支持启动回放 THEN System SHALL 允许用户单独确认「下次重启时删除」，在 `queued` 且未进入不可逆阶段前允许同一授权调用者取消。
2. WHEN Host 在记录意图后、移动后或清空 staging 后发生崩溃并重启 THEN System SHALL 能识别各阶段并安全恢复，同时核验生命周期身份防止删除后来复用同一 ID 的新会话。
3. WHEN 持久化日志确认不可恢复后 THEN System SHALL 依次清理工作区成员与归档/置顶、投影缓存、可确认归属的 spill 文件，并在启用全文搜索时协调并核验索引中已无目标会话；若后续必需清理失败，返回「历史已删除，清理未完成」并支持幂等重试未完成项。
4. WHEN 删除完成 THEN System SHALL 通知原生会话服务刷新列表，且仅当主视图仍显示被删 ID 时清空主视图，不自动打开其他会话，不覆盖后续导航。
