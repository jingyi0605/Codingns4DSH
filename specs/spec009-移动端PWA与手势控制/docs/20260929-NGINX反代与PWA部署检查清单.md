# NGINX 反代与移动端 PWA 部署检查清单

本清单对应 [spec009 移动端 PWA 与手势控制](../../README.md) 的阶段 2/5：HTTPS 是 Service Worker、通知与 Android 安装提示的唯一前提，而 HTTPS 由 NGINX 提供，因此这里的每一项都直接影响手机上能看到的功能。

## 拓扑

```text
手机浏览器 / PWA（https://dsh.example.com）
        │  TLS
        ▼
NGINX（443，证书与鉴权）
        │  HTTP/1.1
        ▼
插件局域网代理（0.0.0.0:13080，登录保护在这里）
        │  HTTP，Host/Origin 重写为 127.0.0.1:<dshPort>
        ▼
DSH Web（只监听 127.0.0.1:<dshPort>）
```

## 必须做

1. **证书必须被设备信任。** Service Worker、`beforeinstallprompt`、通知与推送都要求安全上下文；自签证书需要先在手机安装并信任 CA（Android 用户证书 / iOS 描述文件），否则等同 HTTP。
2. **同机 NGINX 会绕过登录保护。** 代理把来自回环地址的连接判定为本机流量并直接放行。NGINX 与本进程同机时，必须在 NGINX 侧补一层鉴权（`auth_basic`、mTLS 或 IP 白名单），或改用异机反代。
3. **WebSocket 与 SSE 必须能透传。**
   - WebSocket：`proxy_http_version 1.1;`、`proxy_set_header Upgrade $http_upgrade;`、`proxy_set_header Connection "upgrade";`
   - SSE：对 `/api/*` 流式端点关闭缓冲 `proxy_buffering off;`，并放长 `proxy_read_timeout`
4. **不要给上游配置 keepalive。** 代理对每个上游请求强制 `Connection: close`，且请求侧拦截（登录校验与 PWA 资产合成）只作用于每条连接的首个请求。配置 `upstream` 的 `keepalive` 没有收益，只会让语义变复杂。
5. **挂域名根路径。** manifest 的 `start_url`/`scope` 都是 `"./"`，Service Worker 必须从 `/sw.js` 提供才能拿到 `/` 作用域。挂子路径（如 `https://host/dsh/`）需要同时改 manifest、注册脚本与 NGINX 重写，不推荐。
6. **不要缓存 `/sw.js`。** 代理已返回 `Cache-Control: no-cache`；若在 NGINX 侧再加长缓存，插件升级后旧 Service Worker 会长时间停留。
7. **Host/Origin 交给代理改写。** 不要把浏览器看到的域名还原进上游请求头，也不需要 `proxy_set_header Host`；代理统一重写为 `127.0.0.1:<dshPort>`。
8. **不要记录 Cookie。** 访问日志保持默认格式即可，避免把登录会话写入磁盘。

## 建议

- 开启 HTTP/2（浏览器→NGINX）以减少握手开销；DSH 的长连接仍走 WebSocket/SSE。
- 与 DSH Web 保持一致的请求体上限与超时，避免大消息分片被截断。
- 只对本域名的 443 暴露代理；13080 继续限制在局域网内。

## 验证清单

```bash
# manifest：200 + application/manifest+json，正文含插件标记
curl -sI https://dsh.example.com/manifest.webmanifest
curl -s  https://dsh.example.com/manifest.webmanifest | grep -o '"codingns4dsh":[^}]*}'

# Service Worker：200 + text/javascript + no-cache
curl -sI https://dsh.example.com/sw.js

# 图标：200 + image/png（未启用时是 404，属预期）
curl -sI https://dsh.example.com/__codingns/pwa/icon-192.png
curl -sI https://dsh.example.com/__codingns/pwa/apple-touch-icon.png
```

真机验收（iOS 与 Android 各走一遍）：

1. 打开 `https://dsh.example.com`，登录后确认设置卡片里 PWA 与 Service Worker 均已开启。
2. Chrome Android：地址栏出现安装入口，或应用内安装引导条可点击；安装后从桌面启动应为无浏览器栏的独立窗口。
3. iOS Safari：分享 → 添加到主屏幕；图标来自 `apple-touch-icon`，启动后为独立窗口（`viewport-fit=cover` 生效，无 Safari 栏）。
4. 进入会话后横滑：右滑开合左侧会话列表、左滑开合右边栏；贴边起手应留给系统返回手势。
5. Android 返回手势：在右栏全屏打开时先关闭右栏，而不是退出会话。
6. 通知：先用面板里的“请求通知权限 → 发送测试通知”验证本地通知；再切到推送档位订阅并发送测试推送（iOS 必须已添加到主屏幕）。
7. 关闭「启用 Service Worker」后点“注销 Service Worker”，确认 `navigator.serviceWorker.getRegistrations()` 为空，且页面仍可用。

## 回滚

- 面板关闭「提供 PWA 资产」→ manifest、图标与注入脚本消失，`/sw.js` 回到原有语义。
- 手机上已有注册时，用“注销 Service Worker”清理；也可在浏览器站点设置中清除该域名数据。
- 极端情况下把代理端口从 NGINX 摘除，手机侧只留一个打不开的 PWA 图标。
