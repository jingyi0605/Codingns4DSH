# spec005：DSH 能力注册与版本路由机制

状态：技术规划完成，待实施。

## 这份 Spec 解决什么问题

`dsh-codingns` 目前有功能模块注册表和少量 DSH 版本判断，但 DSH API 兼容逻辑仍分散在设置、Connection、UI、Locale、Theme 和终端代码中。新增 DSH 版本或功能时，开发者需要在多个文件里增加条件分支，旧版本接口也没有统一的淘汰依据。

本 Spec 建立一套集中式能力注册、版本路由、功能声明和旧接口退休机制，让现有与未来功能模块都通过稳定的 CodingNS 内部能力接口工作。

## 阅读顺序

1. `requirements.md`：要解决的用户和维护问题，以及验收标准。
2. `design.md`：注册表、适配器、版本矩阵和生命周期设计。
3. `docs/20260925-技术规划与能力矩阵.md`：当前 DSH 0.1.5/0.1.6/0.1.7 的能力基线。
4. `tasks.md`：按阶段执行和回写状态的任务清单。

## 当前范围

本 Spec 规划并实现：

- DSH 能力 ID、版本范围和适配器注册表。
- Host/Client 统一的能力服务接口。
- FeatureRegistry 对能力依赖、降级和不可用原因的处理。
- DSH 0.1.5、0.1.6、0.1.7 的能力矩阵。
- 旧能力的弃用、退休和移除证据链。
- 能力选择、模块装配和兼容性诊断测试。

本 Spec 不重新实现终端、Transport、认证或业务模块本身；它只改造这些模块使用 DSH 能力的方式。
