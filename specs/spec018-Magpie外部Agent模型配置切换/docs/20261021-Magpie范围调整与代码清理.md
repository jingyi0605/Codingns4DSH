# Magpie scope adjustment and switching cleanup

Date: 2026-10-21

## Decision

Magpie already exposes its configured provider/model choices as models inside each Agent. CodingNS therefore does not need to reproduce a CC-Switch-like model configuration workflow. The active Spec keeps only:

- read-only Agent catalog recognition;
- aggregate and current-session usage display; and
- route reading and display for a safely matched Agent session.

## Removed behavior

- the separate Magpie model group and confirmation page in the model selector;
- `cli/magpie/models` and `cli/magpie/set-model` RPCs;
- Magpie setter/current-model read-back commands and switch serialization;
- Client-supplied and persisted `modelProvenance` state;
- partial-success/retry flows and switching locale strings;
- Magpie-specific PeerHost routing and scope guards.

The ordinary Agent catalog and `cli/session/set` remain the only model-selection path. The Host no longer probes Magpie during model selection or session updates.

## Retained behavior

For a subscription request, the Host reads the current session's adapter/model and checks exact membership in the mapped Magpie catalog. A matching model enters the read-only usage path; a non-match returns `null` and uses the existing provider subscription path. Route reads require a distinct Provider session ID, an exact Agent/session match in Magpie usage data, and an echoed session ID in the route response.

## Verification boundary

Focused tests use captured CLI fixtures and fake Gateway responses. No Magpie setter, Gateway, model inference, DSH Desktop, Desktop profile, or real Agent configuration is operated by this cleanup.
