## Implemented

- Added bounded `MagpieContextSession`, category, item, and request-point contracts.
- Added Host parsing for `/api/context?days=7`, with exact Agent/session matching, numeric and collection bounds, control-character removal, and prompt-text exclusion.
- Added the `magpie/context` RPC with native and external Magpie-model gating. Non-Magpie and unmatched sessions return `null`.
- Added a per-RPC/per-session Client store with request coalescing, native fallback, stale-session isolation, and a minimum three-second open-panel refresh interval.
- Added the screenshot-shaped circular trigger and anchored panel with six categories, cache summary, proportional composition blocks, category filters, bounded item rows, session breadcrumb, and request points.
- Integrated the data through the composer presentation. A valid Magpie snapshot is projected into the native `ContextMeter`; a zero-layout enhancer redirects the native button to the screenshot-shaped panel, so no duplicate visible trigger is rendered.
- Stabilized polling and refresh lifecycles: ready snapshots remain mounted while refreshes are pending or temporarily fail, unchanged snapshots do not notify React, and the subscription slot no longer clears working usage on every DSH snapshot update.
- Fixed native DSH usage matching to prefer the DSH session identity while retaining the legacy provider-session fallback and accepting the current Magpie usage payload wrapper.
- Kept the Host capability bundle React-free by passing the Client meter and readiness hook through an optional presentation boundary.
- Added English and Chinese locale keys for all new visible UI text.

## Native popup binding correction

The user's follow-up screenshot still showed DSH's default context popup. Inspection of the installed DSH renderer confirmed that `SlotOutlet` adds a `display: contents` element around dock entries. The enhancer had searched its immediate parent, but the native ContextMeter sits outside that slot wrapper as a sibling.

- Resolve the enclosing `[data-composer-dock]` before finding or observing the native trigger.
- Keep trigger selection scoped to that same dock, including when several composers exist.
- Restore the native `aria-expanded` value and remove capture listeners when a button is replaced, Magpie data clears, or the enhancer unmounts.
- Add `tests/magpie-context-dom.spec.ts` with the actual slot-wrapper hierarchy. Its first two tests failed before the correction. All three tests pass after it and cover opening the six-category portal, content refresh while open, button replacement, session isolation, Escape, and native fallback.

Validation for this correction: 89 focused tests passed using `node --import ./tests/register-source-loader.mjs --test` across the context DOM, context store/parser, session performance, composer model picker, PeerHost attachments, Host entry, and Magpie usage suites. `pnpm run typecheck`, `pnpm run version:check`, `pnpm run capability:check`, and `git diff --check` also passed. The full-suite results above predate this correction; no build, server, Desktop operation, or live visual replay was performed for this follow-up.
