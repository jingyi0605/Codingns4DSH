## Live procedure and results

Two temporary shortcuts, **Stage0 Storage A** and **Stage0 Storage B**, were created through the actual launcher. Both referenced the same unchanged HTML source in the same workspace, with distinct shortcut identities. All writes contained dedicated probe strings. No existing app's storage or business data was used.

| Check | Visible result |
| --- | --- |
| Initial app A | Local and session values were null; the async API was available in the first inline script. |
| Native and async writes | Synchronous `localStorage.setItem()` immediately returned A; `flush()` acknowledged it. Async writes returned `async-A`; session writes returned `draft-A`. |
| Property compatibility | `localStorage.stage0Property` returned `property-A`; `Object.keys()` listed exactly the three probe keys. No storage error event occurred. |
| Viewer reload | The native reload control created a fresh launch; the first original inline script already saw A and `draft-A`, with `CSS1Compat` preserved. |
| Same-source app isolation | B initially saw empty local and session storage. Writing B and `draft-B` did not change A or `draft-A` after reopening A. |
| Full Stage0 page reload | Reopening A after reloading the entire Stage0 page restored A and the current tab's `draft-A` before the first script. |
| Independent browser tab | A new top-level Stage0 tab restored persistent A but had null session data. The original tab retained `draft-A` after the second tab closed. |
| Sandbox | Parent DOM access, cookie access and `indexedDB.open()` each threw `SecurityError`. The document fit the current browser width. |
| Quota | Oversized native and async writes each returned `QuotaExceededError`; the oversized key remained absent and existing A data was preserved. |
| Scoped clear | Clearing A emptied only A. Reopening B still restored B and `draft-B`. Both probe areas were then cleared. |
| Standard resources | The relative module and its dynamic import displayed PASS throughout the exercise. |
| Cleanup | Both temporary shortcuts were removed through the UI; the rail returned to the original two shortcuts, AGENTS and 会员管理. Both agent-created browser tabs were closed. |

These are observations from the running application. The 16-check verification summary validates the captured UI text; it is separate from the earlier automated repository test totals. The quota check covers the application's size limit. Browser-wide disk quota, denied native storage and acknowledgement failure injection remain covered by the earlier fixtures rather than this live exercise.
