# Quick Apps entry and dedicated HTTPS configuration

Superseded default (2026-10-16): the user selected Host-proxied sandboxed previews. The certificate/domain setup below applies only to the retained dedicated-origin provider. Supported Hosts now use their existing DSH address without app-specific hosting setup. See `specs/spec016-快捷应用与受控静态HTTP托管/docs/20261016-主机代理预览与局域网回归修复.md`.

The frontend entry is implemented in `src/client/features/quick-apps.ts` and `src/client/quick-apps/launcher.ts`. Enable **Quick Apps** in CodingNS module settings to register the native `sidebar.footer.action` entry at the lower left. The module is opt-in. It does not require a selected conversation or create one.

The launcher supports adding, editing and removing shortcuts; selecting a managed workspace, application folder and entry file; ordering; optional resource mounts; optional read/write/delete permissions; and revocation. HTML opens in a sandboxed iframe at a separate HTTPS origin. Text and Markdown open as literal text. Removing a shortcut leaves source files intact. The actual React launcher and DSH primitives have been exercised at desktop and 390px widths in a disposable browser fixture; this is not an installed Desktop or physical-phone acceptance result.

Shortcuts load automatically, including without an active conversation. The picker reuses the native Host workspace file-listing service and DSH UI primitives without a conversation. Direct path entry remains available when browsing is unsupported. ## Module switch rejected by the Host

If enabling the module reports `CODINGNS_SETTINGS_FIELD_FORBIDDEN` with `modules.quickApps`, the request reached the Host settings RPC but its field allowlist rejected the switch. This is separate from HTTPS transport availability. The current repository source and build already allow exactly `['modules', 'quickApps']`; shortcut metadata and grants still require their dedicated management RPCs.

On 2026-10-16, `tests/quick-apps-settings.spec.ts` verified the actual settings card through the client settings bridge, Host RPC and schema persistence, including both switch states and reload. The same test passed against the repository build. A running instance producing this error is consistent with older or different Host code; the screenshot alone does not identify the loaded build or owning Host. Client refresh alone cannot update already loaded Host code. Checking or updating an installed Host requires separate authorization for its exact target and operation. No installed profile was inspected or restarted during this investigation.

## Operator-owned HTTPS transport

Update (2026-10-16): an alternative `transport: "lan-ports"` configuration now reuses the current LAN hostname or literal IP with separate HTTPS ports. It requires no new domain or wildcard DNS. See `specs/spec016-快捷应用与受控静态HTTP托管/docs/20261016-局域网地址与独立端口托管.md` for the configuration, origin/cookie guard, port history and current verification. The domain configuration below remains supported unchanged; its DNS requirements apply only to that provider.

The Host entry now loads `CODINGNS_QUICK_APPS_HTTPS_CONFIG` when present. Its value is an absolute path to a JSON configuration file owned by the operator. It is not a browser setting or a request-supplied file path. No listener starts until an authenticated user opens an HTML app. Missing/invalid configuration leaves text shortcuts available and HTML unavailable.

Example configuration, to be provisioned only in a separately authorized environment:

```json
{
  "appDomain": "apps.example-apps.net",
  "uiOrigins": ["https://dsh.example.com"],
  "listenHost": "127.0.0.1",
  "listenPort": 8443,
  "publicPort": 443,
  "certFile": "/operator/quick-apps/fullchain.pem",
  "keyFile": "/operator/quick-apps/private-key.pem"
}
```

The operator must supply wildcard DNS for `*.apps.example-apps.net`, a browser-trusted certificate covering that wildcard, and reachability from every intended browser to the configured public port. The example assumes TCP/TLS passthrough from public port 443 to loopback port 8443. Direct exposure can use a configured interface address and equal public/listen ports. The plugin terminates TLS and validates both SNI and the exact Host header. HTTP reverse proxies that terminate TLS, forwarded-Host headers, path prefixes and arbitrary upstream URLs are not supported by this provider.

Use a distinct cookie site for applications. The parser conservatively rejects app/UI hostnames with the same final two DNS labels, even where a public suffix would permit a finer distinction. This prevents UI Domain cookies from reaching application pages. It may require separate registered domains, for example `example.com` and `example-apps.net`. The listener serves no DSH UI or management routes.

Each launch gets a fresh random hostname, including across restarts. The app root is `/`, so root-relative imports and fetches work without rewriting. Certificates must be currently valid and match the app hostname; clients still perform their own certificate-chain trust checks. The plugin does not install certificates, alter DNS, obtain certificates or reconfigure any running profile.

## Embedded credentials

The authenticated management response contains an app-only, one-use bootstrap URL. Its random ticket is in the fragment, excluded from HTTP requests and referrers. A separate landing page immediately removes the fragment from browser history, exchanges the ticket by same-origin POST within 60 seconds, and checks that the browser returns the cookie before navigating to the entry file. No script or bridge is inserted into application files.

The cookie uses `__Host-quickapp`, `Secure`, `HttpOnly`, `Path=/`, `SameSite=None` and `Partitioned`, without a Domain attribute. A failed cookie check displays a localized explanation and does not report the app as connected. The protocol uses [partitioned cookies](https://developer.mozilla.org/en-US/docs/Web/Privacy/Guides/Third-party_cookies/Partitioned_cookies) to support an iframe on a different site. Chromium was tested with third-party-cookie phaseout enabled; Safari/WebView/physical-phone behavior remains unverified.

The 2026-10-16 workspace-access policy persists with the shortcut and authorizes read/write/create/delete within its owning workspace. The file-owning Host derives and validates each launch's scope. Workspace mode does not scan app code or require per-path approval. Legacy scoped grants retain their earlier bounded code checks and runtime-only approval lifecycle for compatibility. Explicit revocation clears the saved workspace policy and active launches; changing metadata/workspace roots invalidates active access. No watcher or general DSH credential is added.

## Direct Web, Desktop access and PeerHost

Every allowed containing UI origin must appear explicitly in the target Host's configuration. This value chooses an allowed embedding context; it does not authenticate a user or grant file access. Opaque/file UI origins are unsupported. No remote client is given a loopback app URL or a mixed-content HTTP fallback.

For PeerHost, both controlling and owning Hosts need the Quick Apps module. The controlling Host persists the shortcut and verifies its virtual workspace belongs to the selected PeerHost and is explicitly visible. It sends only the fixed `POST /api/codingns/quickApps/remote` management operation through the existing authenticated PeerHost carrier. The target resolves the exact local workspace, owns grants and launch credentials, and serves resources directly at its configured HTTPS origin. General PeerHost/DSH tokens stay in the Host management carrier.

The browser must be able to reach the owning Host's app ingress. A working PeerHost management connection alone does not make the app ingress reachable. Relay-only routes currently return `QUICK_APP_RELAY_UNAVAILABLE` and a localized unavailable state. No general proxy or relay fallback was added.

Close, disconnect and module disable revoke local launches and attempt remote revocation. An unreachable target cannot acknowledge remote revocation; callers receive an error, and the target's 30-minute expiry remains the bound. The last disposed lease closes the dedicated TLS listener. Expired leases are reclaimed before the next allocation, without polling.

## Verification boundary

Repository tests create disposable certificates, explicit per-browser certificate trust, loopback listeners, temporary workspaces and temporary browser profiles. They do not install system trust or change system proxy settings. The fixture browser context explicitly connects directly to its locally mapped test names.

Production DNS/certificate provisioning, an authorized reachable DSH test deployment, real Desktop/Web embedding and physical-phone/PeerHost acceptance remain prerequisites. No installed Desktop, dsh-web or Stage0 profile was operated in this work. The external membership page and real membership data were not modified.
