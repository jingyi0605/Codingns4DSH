# Native document and HTML experience for Quick Apps

Date: 2026-10-16. Repository implementation and local verification only; installed Desktop/Web profiles were not operated.

## Result and reuse boundary

Text shortcuts now reuse the public DSH `MarkdownText` and `MarkdownDelegateProvider` components used by the native document preview, plus this repository's existing CodeMirror file editor. The native Modal, Menu, PathLabel, Tooltip, file/control icons, theme and font tokens remain shared. This supersedes the earlier presentation-only viewer, which displayed all documents as literal text.

The pinned upstream [MarkdownBody](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-alpha.3/packages/client/ui-sidebar-documentpreview/src/client/markdown/MarkdownBody.tsx) composes those public renderers. The entire private sidebar document panel also owns session resources and sidebar tabs; importing it would introduce session dependencies. Quick Apps therefore supplies its own scoped document loader and lifecycle around the shared renderer/editor. Native YAML frontmatter field presentation, sidebar tabs, arbitrary file types and external-editor integration are not part of this change.

HTML retains the real isolated HTTP(S) runtime and unchanged resource files. Its compact native-style toolbar has a credential-free entry address, Reload, loading feedback and maximize/restore. Reload allocates a fresh launch and revokes the previous one. The address describes the configured entry; it does not inspect cross-origin iframe navigation. Maximize fills the application viewport, not the operating system's fullscreen mode. No DSH credential, bridge or SDK is passed to the app.

## Document interaction

- Markdown opens rendered by default, with headings, tables, block quotes, code highlighting and native link controls. Source view and wrapping remain available. Missing native renderer exports produce a localized source-view fallback.
- Relative document links and raster images resolve under the shortcut's document root on its owning Host. Unicode/space URLs decode once; traversal, encoded separators, double encoding and schemes cannot select another root. Images use bounded authenticated document reads, never an app write grant. Raw HTML remains non-executable text.
- Edit opens a native confirmation explaining the exact file and temporary permission. Approval applies only to that file in the current viewer launch. It grants neither creation nor deletion, and is lost on close/revocation/expiry. A linked document requires its own approval.
- CodeMirror supplies syntax highlighting, undo, selection and editing. Save and Ctrl/Cmd+S submit the version read from the Host. Stale writes preserve the draft and show a conflict; no silent retry or overwrite occurs. Typing during a pending save is preserved.
- Switching between Markdown, Source and Edit retains the draft. Close, Escape, Reload and document navigation ask before discarding changes; Cancel keeps them. A browser unload warning protects dirty documents where supported. After access expiry, the error asks the user to copy the draft before reopening.
- Desktop views can maximize/restore without remounting HTML; narrow layouts fill the available viewport. Native content-font settings and dark theme apply.

## Ownership, permissions and compatibility

`quickApps/document` is an authenticated management operation, registered in both the Web channel and exact native Fetch route list. It accepts a launch reference and one of `read`, `image`, `allow-edit`, or `save`. The reference selects the Host-owned app/workspace/principal; payload Host/workspace fields cannot override it. HTML launch identities are rejected by this interface.

Text launch results now include `path`, `version`, `canWrite`, `launchId` and `expiresAt`. The client retains a read-only fallback for older text responses without launch metadata. Updated Host code is required for editing. Text launch cleanup now shares the existing close/disconnect/module-disposal lifecycle, including late responses.

Reads and writes reuse the existing controlled file service. Saves require the current version, valid bounded Unicode text and exact file permission; the shared physical-file queue and atomic replacement revalidate the grant, workspace and path when executing. Document operations are limited to eight concurrent requests; local raster images are limited to 2 MiB each and 32 per rendered document, fetched four at a time. SVG is excluded from the trusted Markdown image adapter. These image data URLs do not change ordinary HTML resource delivery.

PeerHost document operations follow the recorded owning launch. They run outside the definition-management queue so a waiting save cannot hold revocation behind it. Definition changes, removed workspaces, revocation and close still invalidate access. No synthetic conversation or watcher is created. Existing file management and the legacy HTML connector remain compatible.
