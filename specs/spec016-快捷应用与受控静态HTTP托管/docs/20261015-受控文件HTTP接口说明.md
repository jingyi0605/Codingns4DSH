# Optional workspace file HTTP API

Status: implemented and verified through local HTTP, configured HTTPS, actual launcher/browser bootstrap and a disposable PeerHost carrier. Live deployment/mobile acceptance remains subject to `specs/spec016-快捷应用与受控静态HTTP托管/docs/20261015-隔离传输接口调查与阻塞项.md`.

Ordinary HTML resources need no SDK or changes. File mutation uses this separate optional API. Following the user's 2026-10-16 decision, saving an HTML shortcut in the current UI authorizes reads, creation, updates and deletion throughout its owning workspace. The three path-permission fields are removed. This policy persists as `fileAccess: 'workspace'`; launches derive their scopes on the Host without application-code scans or reapproval. Hidden/credential files and paths outside the owning workspace remain inaccessible. Static URLs keep their document-root/mount mapping.

Existing shortcuts without this field retain their previous static-only or scoped-grant behavior until explicitly saved with workspace access. The old grant RPC remains compatible. Revoke removes workspace trust from the saved shortcut and invalidates launches; reopening does not restore it. Legacy runtime approvals still expire on restart/code changes. No launch credential is persisted. Text-document editing retains its separate exact-file approval flow.

Paths below are workspace-relative, not relative to the entry HTML. Only a single `path` query parameter is accepted. No request-supplied Host, workspace, identity, grant or scope is accepted as authorization. Existing parent directories are required for writes. Symlinks, traversal, hidden/secret paths and directories as mutation targets are rejected. Static mounts do not imply file API permissions.

| Request | Behavior |
| --- | --- |
| `GET /__quickapp/files?path=data/members.json` | Returns `{ content, version }`, requiring read permission |
| `GET /__quickapp/list?path=data` | Returns `{ items: [{ name, kind }] }`, requiring read permission |
| `PUT /__quickapp/files?path=data/new.json` with `If-None-Match: *` | Create only; fails if a file already exists |
| `PUT /__quickapp/files?path=data/members.json` with `If-Match: <version>` | Atomically replace only if the version still matches |
| `DELETE /__quickapp/files?path=data/members.json` with `If-Match: <version>` | Delete only an approved regular file with a matching version |

PUT uses `Content-Type: text/plain; charset=utf-8` and a UTF-8 text body, including when the text contains JSON. The limit is 4 MiB. Successful PUT returns `{ ok: true, version }`. Versions are opaque quoted tokens; use them exactly as returned. Missing mutation preconditions return 428, stale versions/create collisions 412, denied operations 403, absent files 404, and oversized bodies 413. Invalid UTF-8 returns 400. Errors are `{ error: { code, message } }`; error bodies never contain source contents or app credentials.

In the current Host-proxy default, prepend the launch base path (`/__codingns/quick-apps/<launch-address>/`) to the API paths above. The browser sends its sandbox Origin automatically; the Host permits scoped CORS/preflights and supplies the credential internally. The launch address is app-scoped, should not be shared/logged, and is omitted from referrers and the viewer address field. No DSH cookie/token is provided to app code. For a root-level entry use `./__quickapp/files?...`; nested-entry examples are in `specs/spec016-快捷应用与受控静态HTTP托管/docs/20261016-主机代理预览与局域网回归修复.md`.

The retained dedicated-origin transport instead uses the app's host-only HttpOnly bootstrap cookie and exact application Origin, without cross-origin API access. Its bootstrap fragment is removed before the entry loads.

```js
const launchBase = location.pathname.match(/^\/__codingns\/quick-apps\/[^/]+\//)?.[0] ?? '/';
const endpoint = launchBase + '__quickapp/files?path=' + encodeURIComponent('data/members.json');
const loaded = await fetch(endpoint);
if (!loaded.ok) throw new Error('Cannot read the approved workspace file');
const { content, version } = await loaded.json();

// Keep the editor's text until the Host confirms the save. A failure is not a download.
const editedText = content;
const saved = await fetch(endpoint, {
  method: 'PUT',
  headers: { 'Content-Type': 'text/plain; charset=utf-8', 'If-Match': version },
  body: editedText,
});
if (!saved.ok) {
  const failure = await saved.json();
  // Leave editedText in the editor for conflict resolution, retry or explicit export.
  throw new Error(failure.error.message);
}
const nextVersion = (await saved.json()).version;
```

The Host serializes its own operations per physical path. It checks grants and canonical paths again after entering the queue, uses exclusive temporary files, and performs atomic replacement or a create-only hard link. Revoked queued operations cannot execute. The temporary file is cleaned on failure. This is not an OS sandbox or a transaction with external editors: another process can still race the final filesystem operation. Applications must handle conflicts and preserve unsaved content. Service workers, recursive directory mutation, arbitrary backend execution, and general proxying are outside this API.

The retained legacy `codingns.html-files.request.v1` preview bridge remains a separate compatibility protocol with its existing behavior. It now shares physical-file mutation ordering with local and remote Quick Apps and revalidates paths after queueing. It is not exposed through these HTTP routes, and its payload scopes are never used as Quick Apps grants. Full grant-service consolidation/retirement remains pending a verified production replacement. The external membership page was subsequently adapted under separate user authorization; its HTML and real data are excluded from these repository commits. See the current acceptance report for that scope distinction.
