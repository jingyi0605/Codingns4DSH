# 设计文档 - 全局助理统一形象插槽

状态：In Review（源码完成，待浏览器与真实模型验收）

## 1. 概述

复用上游的展示方式和精灵图帧布局，编写适合本项目 React 18、设置 RPC 和资源生命周期的实现。不会整体引入上游插件的旧版 DSH 注入、语音栈、会话读取或 Desktop 窗口。

## 2. 架构

### 2.1 数据流

`assistant.appearance` 保存角色清单、当前角色、两个展示开关和尺寸。`GlobalVoiceOverlay` 将现有全局语音状态传给统一 `AssistantAvatarSlot`。悬浮容器和对话容器调用同一插槽；对话打开时卸载悬浮实例。

### 2.2 渲染接口

渲染器具有稳定英文 ID 和 React 组件，输入为角色配置、归一化状态、展示位置、尺寸、错误回调。由公开 `registerAssistantAvatarRenderer` 注册，返回幂等注销函数。注册表通过订阅通知组件，并按服务实例隔离；扩展停用后恢复内置渲染。

### 2.3 设置兼容

`AssistantSettings.appearance` 为可选字段，读取时统一补默认值。默认内置原创矢量角色、对话显示开启、悬浮显示关闭。形象设置作为现有助理卡片中的纵向分组，写入只触及 `assistant.appearance`，不覆盖用户的语音和受管范围。RPC 写入白名单和 Host schema 同步扩展。

对话工具栏也提供「助理形象」按钮，在原窗口内展开同一份表单。表单通过稳定订阅读取当前设置快照，成功和失败反馈显示在当前区域；关闭角色展示不会隐藏配置入口。打开配置不停止或启动语音，不新建嵌套模态框。

## 3. 渲染实现

### 3.1 内置和图片

内置形象直接用 SVG（可缩放矢量图）绘制，无图片下载、无模型版权依赖。图片使用 `object-fit: contain`，加载失败显示内置形象与明确反馈。地址只支持 HTTP(S) 和同源根路径；拒绝脚本、文件协议和协议相对地址。

### 3.2 精灵图

参考 `Signalight/codex-to-dsh-pet`：单帧 192×208，8 列，v1 为 9 行，v2 为 11 行。以 DOM 背景图定位，不依赖 Pixi/WebGL。状态映射使用 idle、running、waiting、review、failed 等共有九行动作；v2 额外两行完整角色视线帧暂不用于鼠标追踪。帧步进限制为实际动作帧数，百分比背景定位允许窄屏等比缩小。取消动画帧、页面可见性监听和媒体查询属于渲染器自己的清理范围。

### 3.3 Live2D

参考 `dsh-live2d-avatar` 的 `load / setState / resize / destroy` 分工，使用同类 `l2d` 引擎。Host 通过固定 GET 入口提供已安装依赖的独立 ESM（浏览器模块）文件，Client 仅在选择 Live2D 时动态加载，避免进入主浏览器包。模型地址由用户指定；支持 `.model.json` 和 `.model3.json`。模型动作音量为 0，不创建麦克风、TTS 或会话。动作映射根据模型提供的动作组选择，缺少映射时保持待机。

异步加载采用实例销毁标记：旧加载完成不得写入新实例或恢复已隐藏的角色。双展示在同一时刻只挂一个实例，避开 Live2D 全局 WebGL 状态争用。依赖或模型失败只影响形象，文字和语音入口保持可用。

## 4. 数据与状态

### 4.1 角色与设置

角色字段：`id`、`name`、`renderer`、`source`、`spriteVersion`。清单最多 20 个，ID 唯一，内置角色固定保留；名称最大 80 字符，资源地址最大 2048 字符。尺寸限制为 80–320px（悬浮）及 120–480px（对话）。无效当前 ID 回落内置角色。

### 4.2 状态映射

| 全局助理状态 | 形象状态 |
| --- | --- |
| disabled / standby / interrupted | idle |
| loading / pending | thinking |
| listening / recording | listening |
| speaking | speaking |
| error | error |

形象不扫描普通会话。后续文字助理可通过同一状态接口使用 `thinking / waiting`，不修改渲染器。

## 5. 错误与不变量

- 素材失败不关闭或中断助理；保留内置形象。
- 加载或扩展不可用时统一给出本地化回退提示；添加非法地址时在设置表单明确提示。
- 打开/关闭形象不会增加语音租约，不触发设备权限。
- 设置写入拒绝时显示错误，不谎报保存成功。
- 页面内浮层位置按真实视口夹紧，存储失败只丢失位置记忆。
- 用户不配置远程模型时无额外远程请求；运行时脚本地址不是用户配置项。

## 6. 测试策略

使用源码内存加载器进行定向 Node 测试：旧设置、配置白名单、非法地址、精灵图状态/帧边界、注册/注销、渲染失败回退、异步销毁竞态和双展示结构。执行带超时保护的 `tsc --noEmit` 与 i18n 检查。不得运行带 prebuild 的测试命令。

真实浏览器交互、用户自备全身模型和麦克风联动属于可视验收；当前没有授权启动 Stage0，结果必须留为 IN_REVIEW，不以源码测试代替实机通过。

## 7. 风险与恢复

引擎和示例模型的许可分开。默认角色为仓库原创 SVG，不复制上游非商业素材。关闭两个展示开关即可恢复原有入口；删除新增 appearance 设置不会丢失受管范围或语音模型。

## 8. 形象包与适配器管理

数据流改为「JSON 形象包 → 格式适配器 → 统一形象配置 → 管理器 → 渲染注册表 → 插槽」。格式适配器只负责解释素材清单；渲染器只负责展示。两个注册表都按 Client 服务隔离、公开注册、幂等注销，内置渲染器也走注册表，插槽不再维护独立类型分支。

保留既有 id/name/renderer/source/spriteVersion 字段，新增可选 package（适配器、来源、作者、许可）及 surfaces（两个位置的素材覆盖）。图片可声明 stateSources，Live2D 可声明 motionGroups 与 live2d 缩放/位置。CodingNS 清单使用 avatarManifestVersion: 1 与 asset/surfaces；另提供 Codex、DSH Live2D、Cubism 2/3 清单适配器。相对素材路径相对于最终清单 URL 解析，拒绝非 HTTP(S) 素材；不读取或执行清单内的脚本。

统一管理器从现有 settings store 读取清单，使用既有 sameSettingsValue 提供 getSnapshot/subscribe 稳定快照，语音变化不通知形象订阅者。串行处理变更，执行当前 revision 与 writable 检查；不新建存储，不覆盖语音字段。提供 list/getSelected/add/update/remove/select/configure/importPackage 接口。重复 ID 明确拒绝，删除选中形象才回落内置，导入失败或取消不写配置。列表由同一份设置驱动，导入选项来自适配器注册表。

阶段 5 完成抽象与导入入口；阶段 6 补充独立预设目录，不把网络素材文件写入插件包，不自动操作运行环境。真实模型和列表点击仍属于阶段 4.2 的可视验收。

## 9. 大肥鱼预设目录

本节记录阶段 6 的历史设计，当前目录与安装行为以 §14 为准。

问题是列表只列出持久清单，而两套大肥鱼此前仅有文档中的导入地址。新增共享预设目录，保存经 Codex/DSH 适配器转换并核验的统一模型数据；使用独立 `codingns-preset-*` ID 和固定提交的素材地址，不占用已有 20 项清单容量，不覆盖此前按上游 ID 导入的角色。

管理器 `list()` 合并持久清单与预设，内容未变时返回稳定引用；`getSnapshot()` 仍表示实际持久配置。表单读取统一 `list()`，选择仍走 `select()` 和原 RPC 写入。Shared 的读取归一化、写入校验和角色选择器共同识别目录 ID，因此 Host schema 回读和两个插槽都不会把合法预设选择重置为机器人。

预设常驻目录，不允许覆盖、更新或删除，也不能被写进自定义清单。默认选择仍为机器人；读取目录与切换设置不获取远程清单，实际素材由选中的渲染器按需加载。Q 版使用 Codex v2 全身图集；Live2D 是桌前造型，保留明确的动作组、缩放和位置。包详情展示作者、真实许可边界及固定版本来源，区分代码许可与美术许可。

## 10. Live2D 预设首屏与缓存

本节只保留旧配置兼容路径，新安装使用 §14 的独立素材仓库。

核对固定版本清单与 l2d@2.1.1：Cubism 3 加载器先获取模型，再等待所有表情、物理和动作，最后加载贴图；同一模型清单还会读取两次。大肥鱼包含 44 个表情和 8 个动作，当前统一助理只使用 Idle 与 SprayWater，换装与表情接口未被消费。

新增共享固定资源包描述：上游提交地址、同源版本路径、动作映射、文件白名单、类型和体积上限。预设仍是原统一模型，只把 source 指向同源清单，动作映射与缓存包共用数据；自定义与普通导入路径不变。Host 在现有形象运行时模块中登记引擎和 8 个固定素材 GET 路由，仍使用原生 buffered 请求，不提供任意 URL 代理。

首次请求清单才下载并校验原始模型 JSON，输出保留模型、贴图、物理、布局和参数分组的精简清单；Expressions 为空，Motions 仅保留配置中消费的两个组。六个首屏依赖并行预取，后续引擎请求共享正在下载的 Promise 或成功缓存；DisplayInfo 可读取但不预取。失败移除缓存，响应为不可缓存的 503；成功响应带 private/immutable 缓存头。流式读取执行每文件体积限额，Host 缓存由固定白名单限制，不写入磁盘。

固定同源路径同时含上游提交与精简策略版本，修改资源或策略时必须更新路径。原模型和贴图不修改，清单精简在许可说明中标注。引擎 ESM、WebGL 生命周期、隐藏时销毁与助理权限接口保持原实现，不以保留隐藏 WebGL 实例换取速度。

资源层通过真实下载记录冷/热缓存耗时；该结果不包含页面传输、图片解码、WebGL 上传和首帧渲染，真实显示速度仍由任务 4.2 验收。

## 11. 统一加载状态与缓存证据

渲染器增加可选加载状态回调；插槽统一展示呼吸光晕、轨道光点和进度条。内置图片、精灵图和 Live2D 声明支持加载反馈，旧扩展未声明时保持原行为，避免永久占位。减少动态效果时停止动画；占位不接管宠物点击或拖动。

Live2D 区分引擎准备、真实文件加载、渲染准备和就绪。只使用 l2d 的 loadstart/loadprogress/loaded 事件推进文件数量，未知进度显示循环指示，不伪造百分比。正式环境就绪后仅显示角色，移除所有载入调试元素；Stage0 完成后保留轻量耗时和缓存摘要，资源就绪耗时包含引擎处理与图片上传，并非纯下载或独立 GPU 基准。失败、超时及销毁后事件均不能更新旧插槽。

固定资源包另有只读 cache-status.json 入口，返回缓存代际 generation、首屏资源成功缓存数、正在获取数、总数和 Host 累计外网下载次数，读取本身不下载素材并明确 no-store。生产 Handler 共用模块级有界内存缓存，路由重新登记不丢失成功文件；不落盘、不承诺跨进程或模块热替换保存。素材响应附带 miss/hit/shared 标记，分别表示新下载、已完成缓存和共享进行中的下载。

仅 Stage0 的 Client 在加载前后获取状态，加载前成功缓存数和同一代际内两个快照的 Host 下载次数差值构成可观察证据；提示明确属于 Host，不混称浏览器缓存。短超时诊断失败只显示缓存状态未知，不影响形象加载。Host 重建导致代际变化时不显示下载差值，防止计数恰好相同被误判为零。自定义素材保持原 URL，不被这项固定预设诊断代理。

## 12. Stage0 诊断边界与刷新持久化评估

复用 Stage0 HMR（热重载）桥的环境判定：Host 必须同时收到专用启动器的 stage0 Profile、仓库根目录和启动器路径，才下发布尔环境标识。Client 装配服务时只接受布尔 true，未注入或非法值都按正式环境处理。不能通过 NODE_ENV、页面端口、查询参数或持久化用户开关推测环境，当前 Stage0 和正式包的浏览器构建都使用 production 模式。

两个展示插槽通过同一服务标识控制诊断 UI，并将可选 diagnostics 字段传给渲染器。正式环境始终保留加载动画与真实进度，但不显示缓存提示、计时、完成摘要和调试 tooltip；即使旧扩展上报这些元数据也不显示。内置 Live2D 在正式环境不计时、不请求 cache-status.json，无诊断等待成本。Stage0 保留阶段 8 的完整证据链，资源缓存和错误回退独立于诊断开关。

本地持久化评估：资源字节可以通过 HTTP 缓存、浏览器数据库或 Host 磁盘缓存跨刷新复用，当前仅有 HTTP 缓存与 Host 内存缓存。浏览器数据库可保存 Blob（文件数据对象）和序列化配置，无法恢复已销毁的 JS/WebGL 实例、GPU 纹理与着色器；l2d@2.1.1 没有模型实例序列化/恢复接口。刷新仍需重新初始化渲染器，不能保存 loaded=true 后跳过初始化。

推荐后续方案是在统一插槽保存上次成功渲染的透明静态预览，刷新时先读本地预览，同时后台重建 Live2D，真实首帧就绪后替换。预览键需包含形象、资源版本、渲染器和展示位置/构图；更换或删除形象时失效。首次使用、读取失败或没有有效预览时继续现有动画与进度。需要确认首帧有效、同源截图能力和存储容量，并兼容 DSH 既有 Service Worker（后台请求处理器）。本阶段仅完成评估，尚未实施预览或磁盘持久化，证据见开发记录。

## 13. 统一插槽本地透明预览

阶段 10 落地阶段 9 的静态预览方案；§12 的“尚未实施”保留为评估阶段状态。本轮不实现模型文件落盘或活的 WebGL 实例恢复。

渲染器注册项新增可选 previewVersion，声明稳定捕获版本；组件接收可选 onPreview，提交透明 PNG Blob 与宽高。CodingNS 插槽负责存储和恢复，渲染器不接触 IndexedDB。内置 Live2D 首先接入，其他扩展可复用接口，旧扩展不声明时保持原行为；统一插槽不按渲染器 ID 分支。

预览键包含格式版本、形象 ID、展示位置、渲染器/捕获版本、解析后的资源地址、图集版本、缩放/位置与排序后的状态映射。资源路径自带固定包版本，自定义地址和构图变化使用新键；尺寸和角色名称变化可复用预览。IndexedDB 专库只存透明 PNG，每张最长边 512px、最大 512KiB，最多 8 张，30 天过期。写入时清理同一形象/展示位置的旧版本及过期项，超限移除最早保存项；删除形象清理其全部位置预览。数据库开库和事务各有 1 秒超时，失败静默回落原加载流程。

插槽通过 AbortController 隔离每个缓存键的读取与写入，临时 Blob URL 在卸载时释放，旧读取不能覆盖新捕获，损坏图片会移除缓存且不阻断后台模型。已经显示的缓存图片保持同一 src 直到淡出，避免新 PNG 解码造成交接闪白。缓存预览不把 aria-busy 或真实进度改成 ready；有预览时改为底部小型动画和进度条，无预览时保留完整呼吸光晕占位。正式环境依然不显示调试摘要。

Live2D 加载确认后观察当前 WebGL 上下文的 drawElements/drawArrays，同帧同步绘制结束的微任务中拷贝完整画面到有界 2D 画布，再异步编码 PNG。不会开启 preserveDrawingBuffer，也不替换引擎或增加 Service Worker。全透明像素不能保存；获取有效帧、取消或超时后还原临时观察函数，旧实例不得提交迟到预览。引擎未绘制、截图失败或 PNG 编码失败最多等待 1 秒后仍按原模型流程显示。

## 14. 素材外置与仓库安装

阶段 11 取代第三方内置目录；后续基本形象改为生图生成的男女透明 PNG。两张图片随包提供，固定同源 URL 按需读取，不加载外部 SDK；旧默认 ID 保留，新增男生选项，两个基础名额加原有 19 个自定义名额。来源、格式、素材、渲染四类适配器共用稳定注册机制；前三类在 Host 的包仓库中隔离，渲染与旧清单导入仍在 Client。来源发现支持公开 GitHub 仓库/目录/文件并固定到提交，其他 HTTP(S) 清单/模型/图片直接解析；候选由用户选择后安装。

完整依赖保存在 CodingNS 自有数据目录，不写源码或 DSH Profile。Cubism 2/3 的全部文件引用在素材适配器中转换，其他模型字段原样保留。l2d 通过字符串拼接目录读取依赖，所以模型 JSON 中使用同目录相对固定入口，不能简单写成绝对 URL。资源入口只接受安装记录内的版本和文件键；新配置登记引擎、素材、状态、目录预览及两张基本图片共六个 GET 路由，无动态路径通配或任意 URL 代理。

下载无凭据、逐跳校验网络地址，支持代理 Fake-IP 域名路由，限制并发、文件数和字节数。安装过程只收集数据，全部成功后写临时目录、完成记录并原子改名。取消/失败不登记半包；Client 设置保存成功后才选择新形象，保存拒绝回滚本次未使用的新素材，Host 卸载检查权威配置避免删除其他角色正在使用的版本。

安装 ID 根据模型与素材内容生成，文件地址带内容版本；Host 重建按完成记录恢复并从磁盘读取。静态预览使用版本化地址自然失效，加载反馈与 Stage0 诊断边界不变；状态入口核对实际文件存在与大小，不用旧 loaded 标记冒充 WebGL 恢复。

旧版两个预设及固定资源表仅放在 legacy 兼容模块，新配置不列出、不请求也不登记这些专用路由。旧配置当前选中的预设仍可显示并提供本地安装入口；已有外链与旧扩展 API 保留。兼容的是素材格式，第三方插件的脚本、换装 UI、语音和桌面窗口不自动执行或迁入。

## 15. 外部兼容形象目录

阶段 12 保存独立 `avatar-packages/catalog.json` 和原生安装清单，正式目录使用 `assets/assistant-avatar-catalog.md` 固定文件名，以六列呈现用户指定信息。上游素材引用固定提交，原生清单补齐真实素材作者和许可，不复制模型、图集或第三方脚本。阶段 12 仅提供链接；阶段 14 根据后续要求将目录及清单元数据加入 npm 文件白名单。每个条目实际验证完整依赖下载和有效绘制，技术兼容与素材许可分开记录。

Client 只持有本仓库 GitHub 目录链接，不导入外部形象枚举；共用形象表单提供浏览入口和复制安装 URL 的说明。只读连接也可打开目录，但不会触发注册或下载。用户仍通过阶段 11 的安装器登记后切换形象。

GitHub 目录必须推送后才可在线访问；涉及提交与推送时单独确认。工作区含其他开发时，目录可独立提交，不把未提交的形象源码或其他会话改动一起发布。

## 16. 第三方协议、右侧临时预览与确认采用

默认角色和已安装清单仍使用 `appearance.models`，外部目录不自动写入该持久清单。界面通过 `assistantAvatarChoices` 将已登记模型与有效协议下的目录元数据合并成一个「当前形象」下拉列表，名称与 `thirdParty` 来源标记分开保存；第三方统一显示蓝底白字的独立标签，内置形象只显示名称。选择器复用 DSH 原生 `Menu` 的富文本行、方向键、焦点归还和外部点击关闭，当前选中项与菜单行共用标签组件，创建页复用同一选择器。菜单通过 Portal（传送门）避开窗口滚动裁剪，层级高于助理窗口，宽度限制在视口内。目录 ID 映射到安装后的 `catalog-${id}`，相同 ID 只保留已登记选项及用户命名；已登记项直接选择，未登记项携带目录元数据供预览，不占持久模型容量。协议是可选的 `thirdPartyConsent: { version, acceptedAt }`，共享归一化保留有效历史版本，是否允许浏览由当前说明版本判断；旧配置默认无同意记录。独立同意操作保存设置，普通显示开关不会隐式同意。关闭仅删除协议记录，保留已安装形象和当前选择。

Client 未同意时仍提供当前形象和启用开关，不调用目录 RPC（远程过程调用）或挂载素材预览。同意后读取随包目录及十二份安装清单的元数据，直接追加到同一个下拉列表，避免依赖尚未推送的 GitHub 文件。目录快照及暂存预览绑定协议版本与时间，协议变化或卸载取消在途请求并丢弃迟到答复。工作台把右侧形象区域作为唯一预览目标，列表组件通过 Portal 挂载所选条目的预览与许可操作；独立设置入口使用同级侧栏，窄屏自动换行。选中条目后由组件生命周期自动开始临时下载，不请求仓库宣传图，不提供手动下载按钮。下载状态只控制右侧原位动画及采用按钮，不锁定左侧选择器；每次选择创建新预览实例，重新选择同一条目也能重试。旧静态小图 API（应用程序接口）保留兼容，当前界面不再调用它。

`previewCatalog` 无需单个形象许可确认，复用目录清单和原子安装器，将完整依赖下载到系统临时目录中的独立 `codingns-avatar-preview-*` 子目录。随机 UUID（通用唯一标识）租约隔离不同预览；固定临时素材入口 `/api/codingns/assistant-avatar-temporary-assets` 仅读取租约所属安装版本，Live2D 清单相对引用也携带租约，响应 `no-store`（不缓存）。临时模型使用独立 ID，在统一插槽以 `transient` 模式加载；禁用预览和头像持久化，失败显示提示而非误显示内置角色。Host 已安装的 Live2D 引擎继续负责渲染，不下载或安装外部引擎代码。

下载阶段在实际形象位置复用统一加载组件的 `animationOnly` 模式；临时插槽在引擎及模型准备阶段也使用此模式，只保留光晕与轨道动画和无障碍状态，不渲染文字、百分比、进度条或诊断摘要。就绪后动画消失，错误仍显示具体原因。删除停止预览按钮及下方整个下载状态组件，许可与采用操作保留；普通已应用形象继续沿用原加载反馈。

Client 在下载和展示期间每 60 秒续期，租约三分钟未续期即失效，Host 每 30 秒清理过期项。切换、隐藏形象页或组件卸载立即取消并释放租约；取消标记隔离先到的释放与后到的创建，迟到答复再次释放。清理等待在途安装退出后递归删除整个独立临时目录；撤销协议或连接转为只读不妨碍释放，Host 模块停用取消全部请求并清理所有租约。

Node HTTP 通道必须区分请求体读完与客户端断开：`IncomingMessage.close` 在请求体正常完成时也会触发，仅 `request.complete` 为假时取消；响应端 `close` 仅在 `response.writableFinished` 为假时取消。正常请求和响应结束不会中断完整素材下载或有效租约，用户在发送完请求体后中断响应仍传播取消并清理。回归通过真实隔离 HTTP 通道验证两种情况，不能只用直接调用 Host 处理器代替传输生命周期验证。下载错误使用通用预览提示，只有 Live2D 渲染失败才提示检查对应引擎。

源码开发以精确版本 `l2d@2.1.1` 开发依赖准备引擎，默认固定入口从仓库依赖解析；正式发布继续使用可选对等依赖，不捆绑引擎。正式 Host 在用户选择 Live2D 形象并确认当前版引擎许可后，从固定 registry 地址下载该精确版本、校验 SHA-512 摘要并原子安装到 `DSH_HOME/codingns4dsh/avatar-engine`；Host 解析顺序为自有目录优先、依赖解析回退，素材安装器仍只安装素材。Client 成功加载后共享模块，失败后重试 URL 增加独立计数，避免浏览器缓存失败的动态导入。仅在导入失败时探测入口状态；503 显示引擎不可用，其他 HTTP 状态保留，接口异常、WebGL 不可用及原始模型错误分别显示。错误只影响形象插槽，租约仍由既有生命周期负责清理。

角色许可勾选不预置，切换条目清空勾选，勾选或取消勾选不改变临时预览。临时下载只传 `id/revision/lease`，Host 校验当前协议、权威写权限和目录版本；正式采用仍传 `licenseAccepted`，Client 和 Host 均要求明确确认。正式采用携带租约时，由 `AssistantAvatarPackages.copyFrom` 复制已验证的完整素材并原子提交，不再次请求上游，也不移动仍在绘制的临时文件；没有租约的旧安装调用沿用原流程。安装结束和 Client 登记前再次检查状态；取消、关闭或设置拒绝时不登记，回收未使用的新建正式副本，清理临时目录不会删除已登记素材。旧 URL 安装 API 保持兼容。正式环境继续仅保留既有加载动画和进度条。

## 17. 统一自动头像

头像是由已选择形象派生的静态资源，不增加另一份形象选择或 Host 设置。`AssistantAvatarRenderer` 可声明 `portraitVersion` 和 `createPortrait(model, signal)`；统一服务按 Client 隔离任务与订阅。对话使用的素材是标准头像来源，展示尺寸、姓名及语音状态不触发重新生成。素材 URL、差分、构图及适配器版本变化失效缓存，双展示实际资源不同则不能互相复用。

图片使用待机差分，内置形象使用随包 PNG（便携式网络图像），动作图集严格按 v1/v2 格式只截左上待机帧。透明轮廓分析最长边 512px，去透明边距后裁角色上部，输出 128×128 透明 PNG；这是通用轮廓裁切，不依赖人物或角色识别服务。Live2D 先读取已有透明预览，缺少时创建一次临时实例，成功捕获后销毁。正在显示的插槽提交现成帧可取消临时头像任务，旧任务迟到不能覆盖新头像；多条消息与按钮共用一个 URL（资源地址）。

头像存放独立 IndexedDB（浏览器本地数据库）`codingns-assistant-avatar-portraits`，沿用预览存储的八项、30 天、单项 512KiB 上限，避免挤占全身预览。已生成头像刷新直接读取图片，无需为头像恢复模型；实际全身动画仍按原插槽初始化。页面卸载或切换取消无消费者的生成，内存回收无订阅者的旧 URL，角色移除同时清理持久头像。跨域截图、图片编码、存储或外部引擎失败均保留默认头像与对话入口。

`AssistantAvatarPortrait` 给正式和流式消息提供相同静态头像，旧对话组件接口继续可用。全局按钮更新自身图片填充，不重建原生会话行；保留 38px 尺寸、焦点、无障碍说明及只打开工作台的点击行为。形象预览发布回调按资源键保持稳定，普通状态更新不会因此重新加载 Live2D。

## 18. 名称同一行的头像微调

基本信息首行使用两列网格，名称位于左侧、`AssistantAvatarPortraitEditor` 的头像和微调入口位于右侧；窄屏保持左右顺序，名称列可收缩。编辑器以 `display: contents` 让说明及裁剪面板参与父网格并跨两列，保持完整编辑宽度；名称字段独立挂载，切换头像不重建输入框。编辑器展开圆形裁剪区域、缩放滑杆及实时预览，采用成熟组件 `react-easy-crop@5.5.6`；组件负责拖动、触控和方向键，CodingNS 负责统一 Canvas 输出及持久化。禁用滚轮缩放，避免在设置页滚动时意外改变构图。PNG 保留透明像素，显示时圆形遮罩由头像组件处理。

完整来源通过可选 `createPortraitSource` 适配器按需提供，或复用资源和构图相同的全身预览；旧扩展可回退既有头像。完整源最长边 512px，输出 128px。裁剪会话绑定资源键，打开时恢复持久化的百分比位置，否则初始化到角色上部。取消、只读、切换及卸载释放临时 URL 并终止在途读取，保存阶段锁定交互。

用户确认后的头像属于设置，另存 `codingns-assistant-avatar-portrait-overrides`，最大项数与形象容量 21 对齐，不设置时间有效期；采用现有有界预览存储事务，自动头像仍维持八项、30 天。工作台确认裁剪时仅暂存 PNG 和百分比元数据，底部统一保存后持久写入并发布正式共享 URL；独立编辑接口保持兼容。手动设置读取完成前不能让早到的动画帧抢占；之后始终优先手动头像。资源或版本变化隔离旧设置，删除角色清理相关记录。该配置仅存在当前浏览器，清除网站数据会删除它。

## 20. 工作台统一草稿保存

形象选择、注册记录、第三方协议、显示与尺寸都由 spec013.1 的 AssistantConfigurationSession 暂存。悬浮开关置于悬浮尺寸上方，对话显示开关置于对话尺寸上方，底部统一保存后才更新正式插槽、消息头像与全局按钮；取消不改变实际配置。首次第三方同意需保存后再读取目录，下载可先准备素材，但注册启用须统一保存。渲染器和素材适配器沿用正式扩展表，草稿头像服务和正式头像服务分离；设备及删除资源延后提交。
