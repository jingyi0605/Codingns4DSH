## 五、已实测确认的技术事实（不要重新假设）

### 会话数据

- `ctx.sessionQuery.listSessions()` 返回 **`{ header, live, persisted }` 包装对象**，不是扁平记录
- `SessionHeader` **不含 `title` 和 `workspaceId`**，字段集为：`version`/`id`/`createdAt`/`cwd`/`parentSession`/`isSeeded`/`origin`/`delegationDepth`/`agentPreset`
- 标题来自日志中的 `session/title` 事件，**必须取最后一条**（实测 6 个会话首条是暂态 HTML 片段，末条已修正）
- 工作区归属来自 `ctx.workspaceRegistry`；归档集合是 `workspaceRegistry.archivedSessionIds`
- **`sessionQuery.filterSessions()` 没有 archived 谓词**（只有 `id`/`cwd`/`created-at`/`parent`/`availability`），归档过滤必须自行实现
- 会话存储是 `session.jsonl.zstd`，**三种格式版本并存**（v0/v3/v4），且 **47 个会话存在多个格式文件**（按文件枚举会重复计数）
- 流式 chunk 类事件占绝大多数，**摘要绝不能遍历原始日志**，必须用 `readSurface()`
- 会话数据**在实时变化**，文档中的绝对数字会漂移，不要硬编码

### 性能实测（2026-10-04 15:51 快照）

| 场景 | 耗时 |
| --- | --- |
| 全量扫描 594 个格式文件 / 543 会话 | **6.56 秒** |
| 仅活跃会话 108 个文件 / 89 会话 | **1.03 秒** |
| 解压单个最大会话（5.38 MB → 13.0 MB） | 0.118 秒 |

### 派发

```js
await ctx.sessionController.prompt({
  requestId, sessionId, mode: 'queue' | 'steer',
  content: [{ type: 'text', text }]
}, signal)
```

`requestId` 幂等：已进入 queue 或日志时重试返回原结果，不重复插入。

### 语音

- `ctx.speechToText.register(provider)` 是公开可扩展服务；本地 SenseVoice 模型**已下载**在 `~/.dsh/speech-to-text/`
- ⚠️ `@deepseek-ai/dsh-experimental-voice-input-bundle` 已在 profile 的 bundles 列表中，但 `cordis.patch.yml` **无对应条目** —— `speechToText` 服务**可能尚未挂载**，任务 4.1 必须先确认或在 GUI 插件页启用
- **DSH 核心没有 TTS**（已核实 290 个 `@deepseek-ai` 包），播报需自选实现

### 等待处理状态

`SessionSummary` 只有 `running` / `completed`，**没有「等待审批」**。必须用 `approval/request`、`user-questions/request` 事件或 `ctx.uiSession.pendingInteractions`，否则需求 7 失效。

## 六、本次新增的两条硬约束（用户明确要求）

### 约束一：受管工作区范围由用户手动选定（需求 8）

- 默认**不纳入任何工作区**，必须显式勾选
- 范围外的工作区**不读取、不提及、不派发**
- 范围变更后立即重建索引
- 范围为空时明确提示，**不得报告「没有进展」**

### 约束二：仅索引未归档会话（需求 9）

- 通过 `workspaceRegistry.archivedSessionIds` 排除
- 归档即退出索引并停止更新订阅；取消归档即重新纳入
- **保留归档会话的历史记录不动**（不删除、不修改、不压缩）
- 向已归档会话派发**被拒绝**，不自动取消归档

**索引范围恒为：`用户勾选的受管工作区 ∩ 未归档会话`。任何绕过该范围的读取都是缺陷。**

## 十一、参考：voiceAgent 复刻的关键契约

来自 `dsh-realtime-voice@0.3.3`，已逐条核实（`docs/20261004-voiceAgent服务契约调查.md`）：

```ts
interface VoiceAgentService {
  capabilities(): VoiceAgentCapabilities
  startConversation(options): Promise<VoiceConversation>   // 注意：没有 onEnd/onError 回调
  registerActions(ownerPrefix: string, actions): { dispose(): void }
}

interface VoiceAction {
  execute(args, control): unknown | Promise<unknown>
  timeoutMs?: number
}
```

必须保真的行为（`design.md` §6.3 共 11 条），关键几条：

- owner 匹配用 `startsWith`；**同名前缀后注册者优先**
- `ownerId` 为假值时**静默不匹配**，不报错
- 未注册动作名 → `{ ok: false, error: 'Unknown action: <name>' }`
- 参数错误 → `{ ok: false, error: 'Invalid action arguments.' }`
- 默认超时 **300000ms**，计时器在调用 `execute` **之前**武装
- `control.resolve` **幂等且返回 boolean**
- 结果 `output` 做**递归 4000 字符截断**
- 动作分发由事件发出路径**自动**完成，无独立 invoke API

**本复刻与参考实现的关键差异**：注册在 **Host 侧**而非 Client 侧（使会话汇聚与派发同进程可达）。
