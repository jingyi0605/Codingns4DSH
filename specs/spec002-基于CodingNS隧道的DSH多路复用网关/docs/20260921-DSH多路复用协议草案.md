# DSH 多路复用协议草案

状态：Draft，供 spec001/spec002 实现和评审使用。

## 1. 协议层次

```text
CodingNS WebRTC / HTTP / WebSocket Tunnel
  -> 单 WebSocket 载体
    -> DSH Envelope
      -> DSH、CLI、PTY、Task、File、Port、PeerHost、Web、Plugin 流
```

控制站和 Relay 不解析下面任何 Envelope。CodingNS TunnelFrame 版本、DSH Envelope 版本、DSH 应用协议族和 DSH 运行时版本必须独立维护。

## 2. Envelope

```ts
interface HostScope {
  hostId: string;
  hostLabel?: string;
  workspaceId?: string;
  sessionId?: string;
  kind: "local" | "remote";
}

interface DshEnvelope {
  version: 1;
  messageId: string;
  streamId: string;
  channel: "session" | "rpc" | "adapter" | "pty" | "task" | "file" | "port" | "peerhost" | "plugin" | "web";
  type: string;
  sequence: number;
  generation: string;
  hostScope: HostScope;
  flags?: {
    endOfStream?: boolean;
    cancelled?: boolean;
    binary?: boolean;
  };
  meta: Record<string, unknown>;
  body?: Uint8Array;
}
```

约束：

- `meta` 只能放路由、状态和小字段，不能放 token、文件内容、命令输出或模型消息。
- `body` 是原始二进制，禁止在 Carrier 层统一 Base64。
- 同一个 `streamId` 内 `sequence` 严格递增；关闭后不得复用。
- `generation` 和 `hostScope.hostId` 必须在消息投递前校验。
- 单消息、单流、会话和模块都有明确大小与窗口上限。

## 3. 会话消息

### 3.1 `session.hello`

```json
{
  "version": 1,
  "messageId": "m-1",
  "streamId": "session",
  "channel": "session",
  "type": "session.hello",
  "sequence": 0,
  "generation": "g-123",
  "hostScope": { "hostId": "host-a", "kind": "remote" },
  "meta": {
    "protocol": "dsh-transport-v1",
    "dshVersion": "0.1.6-alpha.2",
    "capabilities": ["rpc", "adapter", "pty", "task", "file", "port", "peerhost", "web", "plugin"]
  }
}
```

### 3.2 `session.ready` / `session.close`

`session.ready` 返回双方最终接受的能力、窗口、HostScope 和 generation。未收到 ready 前不得创建业务流。`session.close` 关闭会话；单流必须另外发送 `stream.close` 或频道结束消息。

## 4. 通用流消息

```text
stream.open
stream.accepted
stream.rejected
stream.window
stream.cancel
stream.close
stream.error
```

`stream.open` 至少声明频道、操作名、HostScope、工作区/会话摘要和客户端能力。Gateway 先检查权限与模块状态，再返回 accepted/rejected。

## 5. 频道消息

```text
rpc.open / rpc.request / rpc.response / rpc.event / rpc.cancel / rpc.close

adapter.open / adapter.stdin / adapter.stdout / adapter.stderr /
adapter.signal / adapter.exit / adapter.error

pty.open / pty.input / pty.output / pty.resize / pty.signal / pty.close
task.create / task.started / task.output / task.status / task.cancel / task.exit

file.open / file.chunk / file.progress / file.close / file.cancel

port.list / port.open / port.status / port.close / port.data

peerhost.discover / peerhost.open / peerhost.data / peerhost.close / peerhost.error

web.session.open / web.boot.get / web.asset.get /
web.ws.open / web.ws.data / web.ws.close

web.plugin.manifest / web.plugin.bundle / plugin.open / plugin.close / plugin.error
```

`web.plugin.bundle` 只能返回对应 HostScope 的远程 Client Bundle。Client 不得把它注册到本地全局 Loader。

## 6. 流控

`stream.window` 的 `meta` 至少包含：

```json
{ "byteCredit": 65536, "messageCredit": 32 }
```

发送方同时受单消息、单流、会话和模块队列限制。窗口耗尽时暂停读取上游；取消或关闭时释放队列、文件句柄、PTY、进程和 WebSocket。

## 7. 错误

```json
{
  "type": "stream.error",
  "streamId": "stream-123",
  "generation": "g-123",
  "errorCode": "RESOURCE_SCOPE_STALE",
  "detail": "资源属于已经失效的 HostScope",
  "retryable": false
}
```

错误不得包含 access token、refresh token、完整命令行、文件内容、模型消息或 PeerHost 凭据。至少支持：`PROTOCOL_VERSION_UNSUPPORTED`、`MESSAGE_INVALID`、`SESSION_NOT_READY`、`FEATURE_DISABLED`、`FORBIDDEN`、`FLOW_CONTROL_INVALID`、`STREAM_LOST`、`RESOURCE_SCOPE_STALE`、`PLUGIN_SCOPE_MISMATCH`、`PEERHOST_NOT_ALLOWED`、`PEERHOST_PROXY_UNREACHABLE`。

## 8. 版本协商

```text
CodingNS TunnelFrame 版本：CodingNS relay-tunnel-wire 管理
DSH Envelope 版本：本协议管理
DSH 应用协议族：dsh-transport-v1
DSH 运行时版本：例如 0.1.6-alpha.2
```

任一项不兼容都必须在业务流开始前明确拒绝，不能把 DSH 消息当成普通 CodingNS HTTP/WS 消息继续转发。
