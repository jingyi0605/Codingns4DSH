# 20260922-框架兼容矩阵

## 使用规则

这张表只决定“是否允许自动生成端口和联动计划”，不负责猜启动命令。实际执行命令必须来自用户已经保存的 `LaunchProfile`。

- `supported`：官方覆盖入口明确，可以自动生成计划
- `conditional`：可以适配，但必须补齐表中列出的额外条件
- `unsupported`：当前不自动适配
- `unknown`：证据不足，不自动适配

适配顺序固定为：

```text
CLI 参数 -> 环境变量 -> 临时覆盖产物 -> AI 兜底
```

AI 不是默认入口。只有前三层不适用、候选文件可以收敛、用户确认预览时才允许使用。

## 自动计划的硬条件

即使表中是 `supported`，也必须同时满足：

1. 已有用户确认的启动项
2. 工作目录位于 Workspace 内
3. 适配器能给出确定参数、环境变量或覆盖产物
4. 需要的 HMR、服务发现和 callback 处理已经完成或明确要求用户处理
5. 端口池仍有可租用端口

任何条件不满足，都不能把计划标为“可以自动运行”。

## AI 允许条件

必须同时满足：

1. 兼容等级为 `supported` 或 `conditional`；`unknown` 只允许用户额外确认后的受限尝试
2. CLI、环境变量和覆盖产物均有明确失败记录
3. 候选文件不超过实现设定的数量和总字节限制
4. 文件属于开发配置、启动入口或端口配置
5. 不涉及依赖清单、数据库迁移、业务逻辑和生产配置
6. 用户可以先看到统一 diff
7. Host 能生成安全逆向补丁

以下场景禁止 AI：

- 候选文件无法收敛
- 需要大范围搜索并修改业务源码
- 复杂 monorepo 的服务关系未登记
- Electron、Tauri 或原生壳配置
- 回滚路径不清楚
- 文件在预览后已经发生变化

## 代理兼容说明

路径前缀代理不是透明虚拟域名，框架仍可能生成根路径资源或固定 WebSocket 地址。因此每个适配器都必须分别验证：

- 页面资源是否带正确 base path
- API 请求是否指向代理下的后端入口
- HMR WebSocket 是否使用正确 host、port 和 path
- 重定向与 Cookie Path 是否仍留在代理前缀下
- callback 是否需要用户到第三方后台更新

不能因为首页能打开，就宣布该框架的代理兼容已经完成。
