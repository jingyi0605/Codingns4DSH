# 20260922-父仓库移植范围与差异

## 必须重做的地方

### 1. 页面承载方式

父仓库页面属于自有 Workbench。插件必须使用 DSH 的正式右侧栏扩展接口：

- `ctx.sidebarRightTabs.register(...)`
- `sidebar.right.pane.tab`
- `ctx.sidebarRight.openTab('debug')`

不能复制父仓库 Workbench，也不能用 DOM 补丁在 DSH 页面硬塞一个面板。

### 2. 持久化

父仓库使用自己的 SQLite。插件使用 DSH `ctx.storageDomain` 和 Host 插件数据目录：

- 小型结构化记录进入 `dsh-codingns-debug` 领域
- 大型日志和补丁进入 Host 受控文件目录
- 所有记录带 `workspaceId`
- 浏览器 `localStorage` 只允许由 DSH 保存侧栏布局，不能保存调试业务数据

### 3. 进程主数据

父仓库当前轻量实现仍把 Terminal 和端口探测放在较重位置。插件采用独立 `ProcessInstance`：

- Terminal 是可选的查看或附着入口
- 浏览器断开不会让项目进程失去记录
- 停止动作根据 Host 保存的进程身份执行

### 4. 不能按端口杀进程

父仓库 `stopTemplateRuntimeProcess()` 会先按端口寻找监听 PID，然后直接结束对应进程或进程组。这种“查到就杀”在插件中不允许照搬。

端口只能说明“有人在监听”。插件先判断监听者属于哪一类：

- 调试面板创建并登记的进程：直接按运行实例停止
- 能追溯到当前 Workspace 的 AI Agent 私有终端命令：结束该次命令子树，不结束 Agent 和终端 Shell
- 只能通过端口发现的进程：展示 PID、启动时间、命令、目录和父进程链，用户明确确认后再结束

外部进程确认后，Host 必须重新核对端口、PID、启动身份和保护名单。确认前后信息变化时拒绝执行，不能把旧 PID 直接交给 `kill` 或 `taskkill`。

### 5. 反向代理不能只绑定启动项配置端口

父仓库代理从启动项读取固定端口。插件代理必须绑定本次运行的 `RuntimeBinding`：

```text
代理 slug -> 运行绑定 -> 进程身份 + 实际监听端口
```

这样即使端口后来被另一个进程复用，旧代理也不会误转发过去。

### 6. 文本改写必须收窄

父仓库为了兼容路径前缀，会对 HTML、JavaScript 和 CSS 文本做替换。任意文本替换容易破坏源码、source map 和动态字符串。

插件的优先顺序是：

1. 框架适配器设置 base path、HMR path 和 WebSocket 地址
2. 代理重写 `Location`、Cookie Path、Origin 和 Host
3. 只对满足类型、编码和大小限制的 HTML 做有界改写
4. 不对任意 JavaScript/CSS 做全局正则替换

### 7. AI 必须完成真正的安全链路

父仓库当前实现记录了 AI 兜底和状态，但没有完成模型自动改源码的完整主链路。本 Spec 的“完整实现”必须包含：

- DSH 正式 AI 接口
- 候选文件收敛
- 统一 diff 生成
- Host 校验
- 用户预览和确认
- 原子应用
- 冲突检测
- 安全回滚

没有这些，只能说“AI 兜底记录已实现”，不能说 AI 兜底已完成。

## 插件现有命名冲突

当前 Client feature `reverseProxy` 实际承载 CodingNS 登录、设备、Host binding 和中转访问设置。它不是项目服务反向代理。

本 Spec 采用以下处理：

- 保留现有 `modules.reverseProxy` 设置键，避免破坏用户配置
- 新的项目代理命名为 `debugServiceProxy`
- 新代理入口放在调试面板，不把现有设置卡片偷换成另一个功能

## 移植完成的判断

只有同时满足以下条件，才算完成移植：

1. DSH 右侧栏真实页面可用
2. Workspace 数据可重启恢复并互相隔离
3. Host 独立管理进程、日志和端口租约
4. 框架分析不越权猜启动命令
5. worktree 能继承并重新编排
6. 四层适配链有清楚失败记录
7. AI 补丁能预览、应用、冲突拒绝和回滚
8. HTTP、SSE、WebSocket 和 HMR 代理通过真实测试
9. Agent 私有终端服务可以准确归属并停止；未知端口进程只有在用户确认和执行前复核后才能结束
10. macOS、Linux、Windows 均有验收证据
