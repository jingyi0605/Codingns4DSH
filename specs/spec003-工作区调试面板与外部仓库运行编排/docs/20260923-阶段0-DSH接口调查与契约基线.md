# 阶段 0：DSH 接口调查与契约基线

## 调查目的

这份记录确认 Spec003 能依赖哪些 DSH 正式接口，以及哪些接口当前不能从安装包公开类型中确认。没有确认的 Host 接口不进入业务实现，避免用父仓库私有实现或动态字段猜测替代正式契约。

调查对象锁定为 DSH `0.1.6-alpha.2`，依据是本仓库 `package.json`、已安装包的 `package.json` 和公开 `.d.ts` 文件。调查没有启动 DSH 开发服务器，也没有调用 CodingNS 父仓库源码。

## 已确认的公开接口

### Client 右侧栏

安装包 `@deepseek-ai/dsh-client-ui-sidebar-right@0.1.6-alpha.2` 暴露了 Spec003 需要的两段式页面注册契约：

- `SidebarRightTabRegistry.register(definition)`：注册页面类型，返回可重复调用的注销函数。
- `ctx.sidebarRightTabs`：取得页面类型注册表。
- `ctx.slots.register('sidebar.right.pane.tab', ...)`：注册页面正文。
- `ctx.slots.register('sidebar.right.pane.tab.title', ...)`：注册标签标题。
- `ctx.slots.register('sidebar.right.tab.guide.entry', ...)`：注册开始页入口。
- `ctx.sidebarRight.openTab(kind, options?)` 与 `openTabIn(sessionId, kind, options?)`：打开页面。
- `ctx.sidebarRight.registerCloseHandler(kind, handler)`：页面关闭时释放附着资源。

因此，Spec003 的 Debug 页面可以使用正式 Sidebar 接口，不需要复制 DSH 布局或修改 DOM。页面状态仍必须按 Session 作用域管理。

证据文件：

- `node_modules/@deepseek-ai/dsh-client-ui-sidebar-right/lib/types/client/tab-registry.d.ts`
- `node_modules/@deepseek-ai/dsh-client-ui-sidebar-right/lib/types/client/service.d.ts`
- `node_modules/@deepseek-ai/dsh-client-ui-sidebar-right/lib/types/client/contract/slots.d.ts`

### Host Connection RPC 和 Fetch

安装包 `@deepseek-ai/dsh-client-connection@0.1.6-alpha.2` 的 `HostConnectionHandle` 暴露：

- `rpc`：Host 侧逻辑 RPC 注册面。
- `fetch.register(...)`：精确 HTTP Fetch 路由注册面。
- `createSharedFetchHandler('/api')`：组合共享 Fetch 处理器。
- `requestRejection(...)` 和 `authorizeIndex(...)`：Host/Origin 与浏览器认证边界。

这足以承载后续 Debug RPC。当前公开 Host 类型没有发现独立的 WebSocket Upgrade 注册方法；`fetch.register` 不能被文档描述成已经支持调试代理的 Upgrade 转发。

证据文件：

- `node_modules/@deepseek-ai/dsh-client-connection/lib/types/rpc-host.d.ts`
- `node_modules/@deepseek-ai/dsh-client-connection/lib/types/rpc.d.ts`
- `src/host/rpc.ts` 中现有精确 `/api/codingns/*` 路由登记

## 当前未确认、阻止进入业务实现的接口

### Workspace Registry

现有插件代码可以通过 `ctx.get('workspaceRegistry')` 读取一个运行时对象，但仓库和安装依赖中没有对应的公开 DSH 类型声明或稳定方法契约。当前只能把它当作待确认依赖，不能据此冻结 `WorkspaceView`、根目录解析或 Session 归属算法。

### Storage Domain

当前安装的 DSH 公共包没有发现 `StorageDomain`、领域表、插件数据目录或可重开恢复的 Host 持久化 API。Spec003 设计中的 `dsh-codingns-debug` 领域和日志/补丁受控目录因此尚未具备实现依据。

### Host Web Server Upgrade

当前公开类型没有调试代理所需的 Host Web Server Upgrade 扩展点。HTTP Fetch 路由已确认，但 SSE 和 WebSocket Upgrade 的生命周期、请求认证和双向流转发方式仍未确认。

### 真实 DSH 联调

本阶段按项目规则没有启动开发服务器，也没有进行真实 DSH Host/Browser 冷启动。右侧栏 Debug 页面、Storage Domain 重启恢复和 Upgrade 行为必须在取得正式 Host 接口后再做人工回放。

## 阶段 0 结论

| 项目 | 结论 | 后续动作 |
| --- | --- | --- |
| Client Sidebar | 已确认 | 阶段 4 可按公开接口注册 Debug 页面 |
| Host RPC/HTTP Fetch | 已确认 | 阶段 1/后续 RPC 可复用现有 Connection 边界 |
| Workspace Registry | 未确认 | 需要 DSH Host 公共类型或安装版运行时证据 |
| Storage Domain/数据目录 | 未确认 | 在确认前禁止实现持久化领域 |
| WebSocket Upgrade | 未确认 | 在确认前禁止实现反向代理 Upgrade |
| 终端 PTY | 已有前置能力 | Spec003 只调用 `terminalProcess/*`，不重复实现 backend |

因此，阶段 0 已经产出 Client/Connection 的可用接口证据和共享契约骨架，但 `0.1` 仍不能标记 `DONE`。阻塞点是缺少 DSH Host 的公开 Workspace、Storage Domain 和 Upgrade 契约，不是终端 PTY。

## 共享契约落点

- `src/shared/contracts/debug.ts`：状态联合类型、Debug RPC 清单、稳定错误码、作用域和 PTY 请求解析。
- `src/shared/index.ts`：包内共享导出。
- `tests/debug-contracts.spec.ts`：运行时输入边界和 RPC 清单测试。
- `tests/spec003-stage0-dsh-contract.spec.ts`：锁定 DSH 公共包版本与 Sidebar/Connection 声明证据。
