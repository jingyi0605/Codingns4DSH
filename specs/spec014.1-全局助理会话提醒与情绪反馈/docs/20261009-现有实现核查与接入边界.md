2026-10-09 已按源码契约和脱敏输入回放确认以下身份及终态。这里记录协议判断，不表示后续页面与原生联调已经完成。

| 实际来源 | 最小脱敏载荷/身份 | 通知判断 |
| --- | --- | --- |
| 原生轮次 | `turn/start {turn:1}` → `turn/end {turn:1,reason:{kind:'completed'}}`，流事件含 `seq` | 正常完成；轮次键使用明确 `turnId`、轮次数字或已观察起始边界 |
| 外部 Agent 投影 | `dsh-message-projector.ts` 将已确认的外部正常原因映射为 `reason.kind='stop'` | 仅对注册的外部适配器接受正常 stop，未知来源同名 stop 不认作成功 |
| 失败、停止与截断 | `turn/end.reason.kind='error'/'aborted'/'max-tokens'` 等 | error 为失败；停止、取消、截断、未知原因和 `step/end` 不报成功 |
| 原生审批 | `approval/asked.data.id='a1'` → `approval/decided.data.id='a1'` | 按真实审批 ID 精确配对；waterfall 的工具 `callId` 不替代审批身份 |
| 阻塞式问题 | 原生 `user-questions/request` 的请求对象、`agent.session` 和 waterfall `next` | 原样调用 next，以当前请求对象的稳定 ID 观察开始与 finally；取消只结束该请求 |
| 定时问题 | `wait.callId`、`wait.timed` 与当前 `sessionProjections.userQuestions.active` | 等待超时 `ASK_TIMED_OUT` 不代表问题取消；当前 active 或续答结算确认请求生命周期 |
| 续答结束 | `user/message.message.source={kind:'user-question-reply',callId:'q1'}` | 只结束 q1，不清空同会话其他问题 |
| 父子归属 | 已注册父链与明确可定位的父子交互投影 | 有证据才归并父会话；显示目标与实际请求会话分别保存。默认无此能力证据时不生成不可处理的子请求提醒 |

当前恢复边界：DSH Host 侧可直接读取的状态源是 `ctx.workspaceRegistry`（工作区成员与 `archivedSessionIds`）和 `sessionProjections.userQuestions`（当前提问投影）。`uiSession.pendingInteractions` 属于浏览器客户端服务（`dsh-client-ui-session`；0.2.1-alpha.1 中已重构为 `sessionStatus`），Host 上下文读不到，不能作为恢复源；已按 0.1.7-rc.2、0.2.0-rc.2、0.2.1-alpha.1 三个版本的 Host 包核对，均不存在名为 `uiSession` 的服务注册。通知读取优先按“当前非隐藏工作区 → 非归档会话”过滤，然后实时扫描会话自身的事件流：未闭合回合内 `approval/asked` 没有配对 `approval/decided`、问询工具调用（`ask_user_question`/`question`）没有结果，就是当前待处理请求；没有活跃 Agent（`ctx.agents`）的未闭合回合按进程残留忽略，只决定是否展示，不阻止已处理记录被清理。可跨重启续答的定时提问以 `userQuestions` 投影为准。扫描结果不落表，事件只触发重扫，不会用历史正文猜测待办；工具结果、审批决定或投影结算写入后，旧提醒在读取时自动移除（点过“查看”或 Agent 已释放同样生效），不需要手动收起。
