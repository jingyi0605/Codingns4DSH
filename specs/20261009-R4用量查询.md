# R4 Coder 用量查询

## 需求

- 在现有订阅用量入口中支持 R4 Coder，无需新增设置或独立页面。
- 复用 Host 对 DSH 与各 Agent 的来源发现；按 HTTPS 官方地址 `api.r4.codes` 识别，不依赖用户给 Provider 起的名字。
- 查询使用现有推理 Key，仅在 Host 发送 Bearer 请求，不把 Key、Key 前缀或原始响应传给 Client。
- 账户余额、Key 限额和账户近 7 天消费分别展示。Key 未设限不等于账户余额无限；负剩余额度不能截断为零。

## 接口与设计

依据 https://r4.codes/docs/usage-api（2026-10-09，通过公开页面文本读取）：

- `GET /v1/cli/meta`：套餐与钱包余额快照；套餐余额和钱包余额独立展示，合计作为账户余额。不把套餐总额作为整个账户总额，也不把套餐到期当作 Key 到期。
- `GET /v1/cli/key`：当前 Key 的 `limit_usd`、`spent_usd`、`held_usd`、`remaining_usd`；这些是终身计数器。`limit_usd=null` 表示未设限，缺字段表示未知。
- `GET /v1/cli/usage`：账户今日、近 7 天逐日与逐模型统计；默认 UTC，界面明确标注 UTC，不称为累计消费。
- 三个请求并发、共享项目用量超时，无自动重试。沿用现有刷新和并发查询去重。拒绝跳转，避免凭据被发到另一来源。
- 官方地址确定后不探测 New-API/Sub2API，也不在请求失败时回退其他账号。单接口失败保留其他成功摘要；全部无有效数据返回 null。401/403/429、超时和畸形响应均不伪造零余额。
- 在 `ProviderBalanceUsage` 增加可选 R4 摘要，复用余额入口与弹层。按最终验收要求，详情仅显示账户余额、Key 限额/剩余、今日费用（UTC）和请求数；Key 未设限时不显示剩余额度。后端保留套餐、钱包与近 7 天摘要，界面不显示这些明细、Token 明细或重复的余额标题。新增可见文案同时提供中英文。
- 用量入口优先使用 R4 官方品牌图标，资源本地保存并记录来源；R4 不注册为可执行 Agent。

## 验证

- 覆盖金额字符串、零值、负值、未设限、缺字段、套餐/钱包、近 7 天口径、认证与 URL、部分失败、超时和错误状态。
- 覆盖统一路由和多个 Agent 来源，证明不会调用旧协议或回退官方订阅。
- 渲染中英文弹层，确认账户余额与 Key 限额独立、无凭据、无伪造累计统计。
- 在独立 Stage0 环境验证，执行类型、版本、能力、国际化、适配器和项目全量检查。结果写入开发记录。
- 2026-10-09：独立 Stage0 的真实账户查询已验证，用户确认最终页面验收通过。全量检查的失败与未完成项见本地开发记录，不计为通过。
