# 终端启动进程调用说明

## 这次实现了什么

终端现在支持一条 Host 主导的 PTY 启动链路：

```text
TerminalLaunchProfile
  -> TerminalProcessService.launch()
  -> CodingNsTerminalService.create()
  -> tmux / local-pty / ConPTY 直接启动 command
  -> 返回 TerminalProcessInstance + terminal
  -> DSH 原生 terminal UI 使用 terminalId attach
```

普通终端仍然只启动 shell。只有 `runtimeMode: 'pty'` 的启动项才会把 `command` 作为 PTY 的实际进程入口，不会把命令字符串写入已经打开的交互 Shell。

## Host 内部调用方式

Host 或后续 Spec003 的调试服务可以直接使用 `ProcessRuntimeService`（当前实现类名为 `TerminalProcessService`，两者是同一个服务）：

```ts
const profile = await terminalProcesses.createProfile({
  id: 'frontend-dev',
  workspaceId: 'workspace-a',
  name: '前端开发服务',
  cwdRelative: '.',
  command: 'pnpm',
  args: ['dev'],
  env: { NODE_ENV: 'development' },
  shell: {
    profileId: 'zsh',
    path: '/bin/zsh',
    args: ['-i'],
    name: 'zsh',
  },
  runtimeType: 'tmux',
  runtimeMode: 'pty',
})

const result = await terminalProcesses.launch({
  workspaceId: profile.workspaceId,
  profileId: profile.id,
  dshSessionId: 'dsh-session-id',
  cols: 120,
  rows: 32,
})

// result.instance.id 用于停止、恢复和后续调试面板状态展示。
// result.terminal.id 用于打开或恢复 DSH 原生 Terminal tab。
sidebarRight.openTabIn('dsh-session-id', 'terminal', {
  params: { terminalId: result.terminal.id },
})
await terminalProcesses.stop(result.instance.id)
```

`resolveWorkspaceRoot` 必须由 Host 提供。它把稳定 `workspaceId` 解析成受信任的 Workspace 根目录；浏览器不能提交绝对路径替代这个解析。`cwdRelative` 经过目录越界检查，只能落在 Workspace 内。

## 浏览器 RPC 调用方式

Host 已登记 `terminalProcess` 命名空间。浏览器应通过 DSH Connection RPC 调用，不要直连 Host，也不要携带 Host token：

```ts
const response = await rpc.call('/codingns', 'terminalProcess/launch', {
  workspaceId: 'workspace-a',
  profileId: 'frontend-dev',
  dshSessionId: 'dsh-session-id',
  cols: 120,
  rows: 32,
})

if (!response.ok) throw new Error(response.error.message)
const { instance, terminal } = response.value
```

可用动作：

| RPC | 作用 |
| --- | --- |
| `terminalProcess/profile/list` | 列出工作区启动项 |
| `terminalProcess/profile/create` | 创建或递增更新启动项 |
| `terminalProcess/profile/delete` | 删除没有活动进程的启动项 |
| `terminalProcess/launch` | Host 创建 PTY 进程并返回终端信息 |
| `terminalProcess/runtime/list` | 列出运行实例 |
| `terminalProcess/runtime/get` | 读取一个运行实例 |
| `terminalProcess/runtime/stop` | 按运行实例 ID 显式停止 |

## 当前边界

- 目前只支持 `runtimeMode: 'pty'`，非交互 `process` 模式留给 Spec003 的 `ProcessRuntimeService`。
- 当前终端启动器已经分离了启动项和运行实例，但还没有实现 Spec003 的端口租约、日志游标、框架分析、反向代理和 Agent 命令归属。
- 插件卸载或 generation 切换只释放终端 attach；`runtime/stop` 和终端显式关闭才会结束底层 tmux、local-pty 或 ConPTY 进程。
- 启动项环境变量禁止持久化包含 `TOKEN`、`SECRET`、`PASSWORD`、`PRIVATE_KEY` 或 `API_KEY` 的字段。
