## 刷新后能否无需重新加载直接显示

可以减少重复下载，并用本地静态预览提前显示形象；无法跨刷新直接恢复已经初始化的 Live2D/WebGL 动画实例。保存一个 `loaded=true` 只能记住上次完成过，不能重建渲染资源，跳过初始化会出现空白。

| 数据层 | 当前状态 | 能否跨刷新保存 | 能省略的工作 |
| --- | --- | --- | --- |
| 形象选择与构图配置 | 已持久化到统一设置 | 可以 | 重复选择与配置 |
| 模型、动作、贴图文件 | Host 内存缓存、浏览器 HTTP 缓存 | 浏览器遵循缓存策略；Host 内存不跨进程重启 | 缓存命中时减少下载 |
| 上次成功渲染的透明图片 | 尚未实现 | 可保存 Blob（文件数据对象）到 IndexedDB（浏览器数据库） | 首屏先展示静态形象 |
| JS/Live2D 实例、WebGL 上下文、GPU 纹理和着色器 | 属于当前页面 | 无法直接持久化恢复 | 刷新仍需解析、解码与渲染初始化 |

依赖源码证据：`l2d@2.1.1` 的 `Options` 只提供资源路径、构图、日志和音量，没有实例序列化或恢复接口。`load()` 获取模型清单并初始化模型，`destroy()` 释放模型和 WebGL 资源。Cubism 3 路径创建新的 WebGL2 上下文，从文件字节重新创建 GPU 资源，不能由历史加载状态代替。

官方依据：[WebGL 1.0.3 规范](https://registry.khronos.org/webgl/specs/1.0.3/)将纹理、缓冲、着色器与程序作为渲染上下文管理的资源；[IndexedDB 3.0 规范](https://www.w3.org/TR/IndexedDB/#values)支持序列化数据和 Blob 按值存取。结合依赖接口，能保存文件和预览，不能保存活的上下文供新页面直接复用。这是对规范与源码的实现判断，不是引擎已经具备的恢复能力。

阶段 8 的隔离实测中，同一页面销毁后再初始化，第二次约 0.53 秒，Host 新增外网下载为 0；说明缓存生效后仍有初始化成本。这不是跨刷新持久缓存的实测，本轮没有操作用户运行环境，不能保证用户刷新后的耗时。

## 推荐后续方案

1. 由统一插槽管理本地预览，适配器继续提供模型与双展示素材。预览按角色、渲染器、资源版本、展示位置和构图生成键；切换、删除或版本变化时失效，避免桌前和全身预览混用。
2. 成功绘制后捕获透明静态预览，保存文件数据到 IndexedDB，限制尺寸和存储容量；捕获失败不影响正在显示的形象。不能用 loaded 事件代替实际像素验证。
3. 刷新时先读取有效预览显示，后台按原流程初始化 Live2D。继续保留加载反馈，真实首帧就绪后淡入替换；首次使用、无缓存、存储不可用时使用现有动画与进度条。
4. 资源持久缓存单独处理：现有版本化 HTTP 缓存先复用；若要解决 Host 重启后的重复外网获取，可增加固定白名单资源的有界磁盘缓存。浏览器 CacheStorage（请求响应缓存）写入并不会自动影响 l2d 的 fetch 和 Image 请求，须有读取接入，不能简单写入后宣称加载已命中。

截图需关注同源/CORS（跨域读取许可）和绘制缓冲清理。WebGL 规范指出默认呈现后可能清空缓冲，截图应与有效绘制同步；不能为截一张预览而长期全局启用 preserveDrawingBuffer，它在部分设备上有性能成本。DSH 已有 PWA（可安装网页应用）Service Worker（后台请求处理器），后续不能另注册冲突的根作用域缓存处理器。

本阶段只完成评估，尚未实现预览数据库、模型文件落盘或跨刷新即时显示。
