# Git 面板双列时操作按钮位置修复记录

日期：2026-10-24

## 背景与结论

用户反馈：Git 面板进入双列布局后，「Git 操作」按钮（`⋯` 菜单）位置错误。
期望它靠右显示，并与「6 个已暂存 · 27 个未暂存 · 1417 条提交（全部分支）」摘要同一行。

原因是旧结构把摘要文本放在标题行（`header`）之后的独立一行，而操作菜单挂在标题行末尾的
`headerActionsStyle` 容器里。单列时视图切换与菜单同处标题行，看起来正常；双列时
`@container codingns4dsh-git (min-width:612px)` 只把切换控件隐藏，标题行只剩一个菜单，
但它仍占据标题行，于是在视觉上被摘要行整行宽度推开，落到摘要行上方/外部，和用户看到的
「按钮错位」一致。

结论：把操作菜单从标题行移到摘要行，成为摘要行的第二个子节点，用
`display:flex; justify-content:space-between` + `margin-left:auto` 固定贴右；标题行只保留
单列视图切换，并整行复用 `.codingns4dsh-git-column-switch`，双列时连同行盒一起隐藏，不留空白高度。

## 决策

1. **菜单跟随摘要行，而不是固定在标题行。** 摘要行本身就是通栏，无论单列还是双列都跨越整个面板宽度，
   菜单与摘要天然同一行且靠右；也顺带消除了双列时标题行只剩一个按钮的孤行。
2. **标题行整体使用 `columnSwitch` 类名。** 之前类名挂在内层 `div` 上，外层 `header` 在双列时仍占
   `min-height:28px`。现在类名直接挂在 `header` 上，`display:none` 会连同行盒一起移除。
3. **`menuStyle` 增加 `margin-left:auto`。** 该样式同时用于历史记录行内的提交菜单，那里由
   `fileNameStyle` 的 `flex:1` 占满剩余宽度，`auto` 外边距不改变既有对齐；本次不改动历史行行为。
4. **给菜单根节点加 `data-git-operations-menu`。** 便于在不递归渲染子组件的测试夹具里定位它，
   同时作为布局归属的稳定标记（类似已有的 `data-git-management-panel`、`data-git-column`）。

## 变更清单

| 文件 | 变更 |
| --- | --- |
| `src/client/git-management.ts` | `header` 只保留单列视图切换并整体挂 `gitPanelClass.columnSwitch`；新增 `summaryRowStyle` 摘要行，文本 + `GitOperationsMenu` 同行靠右；删除未再使用的 `headerStyle`、`headerActionsStyle`；`menuStyle` 增加 `marginLeft:'auto'`；菜单根节点增加 `data-git-operations-menu` |

## 需要特别注意的地方

- 切换控件与操作菜单现在分属两个不同容器，若后续再把切换控件放回标题行以外的地方，需要同步更新
  `tests/git-panel-layout.spec.ts` 中按 `element.props.id === 'codingns4dsh-git-view'` 定位的断言。
- 摘要行新增了内层 `div`；历史行 `menuStyle` 的 `marginLeft:auto` 与摘要行共用同一常量，修改它时
  需同时确认历史提交行（`HistoryGraphRow`）的对齐不受影响。
