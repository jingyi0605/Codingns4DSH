# 远程新建会话目录作用域修复记录

## 问题

远程工作区新建会话时，适配器目录和外部适配器模型目录在 Session ID 尚未生成的阶段回落到本地 Host，导致对话框显示本地配置。

## 根因

`cli/catalog` 与 `cli/models` 在新建阶段通常只有空对象或 `adapterId`，没有虚拟 Session ID。原有 PeerHost 路由只能从请求正文找作用域；同时本机旧会话的后台 `session/follow` 可能清掉当前远程作用域。

## 修复

- `cli/catalog` 和 `cli/models` 在缺少 Session ID 时继承当前远程工作区作用域。
- Desktop Connection 路由复用同一套 CLI 作用域判定。
- 仅显式携带本机 workspaceId 的导航才清理远程作用域，后台基线流不再误清理。
- 本地工作区路径仍会阻止无参数目录请求错误路由到远端。

## 验证

- PeerHost 原生连接器、Desktop 路由和原生协议测试通过。
- 新增回归测试覆盖无 Session ID 时的远程适配器与模型目录路由。

完整类型检查仍受工作区已有的 `peer-host-native-store-projection.ts` 未提交改动阻塞，与本次作用域路由改动无关。
