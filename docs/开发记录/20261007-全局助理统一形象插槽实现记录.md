# 20261007-全局助理统一形象插槽实现记录

## 已实现的行为

全局助理现在使用同一个形象配置和同一个 `AssistantAvatarSlot`（形象插槽），分别用于可拖动的页面悬浮入口与原有语音对话窗口。对话打开时卸载悬浮实例；关闭后按已保存的坐标恢复。点击宠物只打开窗口，开始语音仍由原来的按钮控制。

形象按全局助理的待机、监听、准备、播放和错误状态展示，不读取当前普通 DSH 会话。受管工作区、语音模型、索引调试和原有转写控制保持原有职责。

## 配置方式

1. 在 CodingNS 设置中启用「全局智能助理（测试中）」，展开「助理形象」；也可在助理对话窗口点击「管理模型」右侧的「助理形象」，直接展开同一份配置。
2. 默认使用原创 CodingNS 全身机器人，对话显示开启、悬浮显示关闭；按需开启悬浮入口。
3. 在「添加自定义形象」填写名称、格式和可访问的资源地址，点击「添加并使用」。
4. 同一个「当前形象」同时作用于悬浮和对话；两个显示开关和尺寸可独立调整。
5. 移除自定义角色后回到内置角色，仅删除清单引用，不删除资源文件。

| 格式 | 资源与要求 |
| --- | --- |
| 图片 | PNG、WebP 等图片地址；透明背景更适合悬浮显示 |
| 宠物动作图集 | 单帧 192×208、8 列；v1 为 1536×1872，v2 为 1536×2288；按文件选布局 |
| Live2D | `.model.json` 或 `.model3.json` 地址；模型、贴图和动作文件须保持正确相对路径且可被浏览器访问 |

支持 HTTP(S) 地址或本站以 `/` 开头的资源路径；不支持本地文件路径、文件上传和任意脚本入口。跨域 Live2D 资源需要资源服务器允许浏览器跨域读取；HTTPS 页面上的 HTTP 资源可能被浏览器阻止。全身展示需要模型本身包含全身；不同模型的实际构图仍需实机确认。

图集沿用上游九行动作布局。v2 额外两行是完整角色的视线方向帧，首期使用共有的九行状态动作，不包含鼠标视线追踪。原版精灵图和模型都由用户自行提供，插件不附带上游人物素材。

## 实现与复用边界

- `src/shared/assistant-avatar.ts`：可选配置、读取兼容、严格写入校验、状态与动作行映射。
- `src/client/avatar/`：统一插槽、按服务隔离的扩展注册表、原创 SVG、图片、纯 DOM 精灵图、Live2D 适配器、悬浮交互和设置。
- `assistant-panel.ts`、`global-voice-assistant.ts`、`voice-conversation-dialog.ts`：增量接入原有功能。
- `assistant.appearance` 独立写入，并传入最新 revision（设置版本）；不会通过整段保存覆盖语音或受管范围。Host RPC 也校验兼容的一级 `assistant` 写入，避免绕过校验。
- Live2D 使用可选依赖 `l2d@2.1.1`；通过固定同源 `/api/codingns/assistant-avatar-runtime?v=2.1.1` 加载独立 ESM。真实包的 `index.min.js` 是 IIFE（全局脚本），不能用于动态 import，因此固定读取 `dist/index.js`。
- 精灵图在隐藏或减少动态效果时暂停；Live2D 在隐藏、切换或卸载时释放。加载期间销毁后，迟到成功与失败都清理旧实例。

参考 [dsh-live2d-avatar](https://github.com/clown139880/dsh-live2d-avatar) 的双展示与生命周期，参考 [codex-to-dsh-pet](https://github.com/Signalight/codex-to-dsh-pet) 的轻量帧布局，没有安装这两个完整 DSH 插件。其旧注入、会话读取、独立语音和 Desktop companion 代码不属于本实现。

## 扩展渲染器

Client 公开导出 `AssistantAvatarSlot` 和 `registerAssistantAvatarRenderer`，共享入口公开角色和状态类型。CodingNS 功能模块可以在自己的 `start(context)` 中注册新渲染器，并把返回的注销函数放入 `context.resources`：

```ts
import { registerAssistantAvatarRenderer } from '@jingyi0605/codingns4dsh/client'
import type { AssistantAvatarRendererProps } from '@jingyi0605/codingns4dsh/client'

// CustomAvatar 是模块自己的 React 组件；只消费形象配置和助理状态。
function CustomAvatar(props: AssistantAvatarRendererProps) {
  return renderCustomCharacter(props)
}

function start(context: CodingNsFeatureContext) {
  context.resources.add(registerAssistantAvatarRenderer(context.services, {
    id: 'custom-character',
    component: CustomAvatar,
  }))
}
```

此处 `renderCustomCharacter` 和 `CodingNsFeatureContext` 由扩展模块定义。新增角色清单项的 `renderer` 使用注册 ID，其他字段遵循共享契约。内置 ID 为 `builtin`、`image`、`spritesheet`、`live2d`，不能覆盖；重复注册拒绝，注销幂等。扩展停用或出错时显示内置回退；修复后重新注册可恢复。
