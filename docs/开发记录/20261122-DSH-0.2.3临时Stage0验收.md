# DSH 0.2.3 临时 Stage0 验收

插件开发版本升到 `0.2.3-beta.1`。保留 DSH `0.2.2` 和 `0.2.3` 两条版本线：npm 上最早可安装的 `0.2.2` 是 `0.2.2-alpha.2`，因此实际下界是 `>=0.2.2-alpha.2`，拒绝 `0.2.1`。更高版本继续沿用仓库规则：提示未经验证，不阻止安装。接口变更见 [调查报告](docs/调查报告/20261122-DSH-0.2.3-alpha.1接口差异.md)。

可在仓库用 `node scripts/check-version.mjs 0.2.3-beta.1` 重跑命名门禁。历史 tag 只比较同一版本线、同一预发布类型，例如 `0.2.3-beta.*`；首次发 beta 不会被 `0.2.2` 的历史 tag 拦住。

## 旧接口

能力矩阵有 91 条路由，其中 27 条低于新下界，均已标记 `deprecated`，附替代能力，计划在验证目标达到 `0.2.4-0` 后清理。本次只标记，不删除实现。

| 来源 | 条数 | 说明 |
| --- | --- | --- |
| 0.1.x | 23 | 既有失效项，包含设置、RPC/Peer、图标、语言、主题、终端与 PeerHost 等 |
| 仅 0.2.1-alpha.2 | 4 | `session-activation-020`、`message-presentation-020`、`connection-peer-admission-020`、`connection-rpc-uplink-020` |

仍需保留 `0.2.2` 的浏览器认证旧入口和模型名称搜索旧导出；它们不能跟失效路由一起移除。完整替代关系见 [能力路由报告](docs/生成报告/20260925-能力路由报告.md)。

## 验收结果

- 在 macOS 上用实际 tarball 安装到两个全新的 `stage0` Profile，分别运行 `0.2.2-rc.5` 和 `0.2.3-alpha.1`。都验证了原生登录、首页和插件 Client 资源、版本注入、设置读写及还原、Agent 目录、原生会话创建和终端工作目录 RPC。两处官方终端入口均禁用，未出现 patch 找不到 entry 的提示。
- `0.2.3-alpha.1` 裸 npm CLI 在插件加载前就会报错。临时目录内用上游 `dsh-v0.2.3-alpha.1` 的原始源码构建 Cordis、Loader 等配套组件后才完成验收；没有修改正式 Stage0 的依赖或配置。稳定的 `0.2.2` Boot 校验器作为开发测试依赖保留，`0.2.3` 的实际门禁由安装回放覆盖。
- 安装回放 6 项通过：Agent 目录、模型目录、会话创建与跟随、PeerHost 原生 RPC、内存 Relay DataChannel。锁文件冻结安装、类型检查、版本检查、能力退休检查及构建通过。
- 未验证浏览器交互、Desktop、Linux/Windows 实机、iOS、真实计费/自定义网关或公网 Relay。正式 Stage0 和 Desktop 未改动；未发布。
