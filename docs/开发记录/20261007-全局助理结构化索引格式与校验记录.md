# 全局助理结构化索引格式与校验记录

日期：2026-10-07

## 问题与判断

用户提供 `assistant-debug-2026-10-07T05-11-57-605Z.json`。手动索引已调用 DeepSeek 模型，但结果是把两个 TEST 会话合在一起的播报段落。目标、工作结果、阻碍和建议没有独立字段，无法稳定回答“哪个会话卡在哪里”“哪些是已有待办”“为什么下一步这样做”。

内部索引需要严格的机器结构，最终对话才需要简短口语。两者分开：索引字段中的文字仍然简短、自然，对话不向用户朗读 JSON（JavaScript 对象表示法）。

## 固定模型输出协议

模型只允许返回一个合法 JSON 对象，不允许前后说明或 Markdown 围栏。根对象固定为 `schemaVersion/sessions`，版本固定为1。每个当前范围内会话必须出现一次，以 `hostId/sessionId` 联合定位。

| 字段 | 类型与用途 | 无证据时 |
| --- | --- | --- |
| `objective` | 目标事实对象，可引用同一会话标题或正文 | `null`，并记录信息缺口 |
| `progress` | 已做动作、历史工作结果、验证结果 | `[]` |
| `blockers` | 原文已出现的实际阻碍 | `[]` |
| `pendingTasks` | 已提出、尚无完成证据的任务 | `[]` |
| `nextActions` | 具体下一步，含类型、优先级、理由和证据 | `[]` |
| `openQuestions` | 判断状态或安排下一步还缺少的具体信息 | `[]`；目标或正文缺失时不得为空 |

事实对象为 `{"text":"一句具体事实","evidence":[{"source":"summary","quote":"连续原文"}]}`。证据 `source` 只允许 `title/summary`；除目标外，事实和行动必须引用正文。每项1至3段引用，引用2至160字符，文字字段最多300字符。各事实/行动数组最多5项，信息缺口最多8项。

行动对象固定为 `action/kind/priority/reason/evidence`：

- `kind=recorded`：来源记录中已明确提出的任务。
- `kind=suggested`：模型的新建议，未安排、未执行。
- `priority=high/normal/low`：高、普通、低；Host 按优先级排序，没有证据支持紧迫程度时使用普通。

以下是依据用户快照中计算题测试摘录编写的协议示例，**不是本次实际模型生成结果**。真实调用必须覆盖快照里的两个会话。

## Host 校验与存储

`assistant-structured-index.ts` 在模型轮次完成前校验：固定键、类型和版本、会话数量、联合身份、重复与范围外条目、字段长度和数组数量、证据是否为同一会话脱敏来源里的连续原文。不存在自动补齐、猜测修复或把普通段落伪装成有效结构。

校验通过后，Host 添加 `generation`，逐会话添加 `workspaceId/workspaceName/title/sourceStatus/updatedAt/material`。模型不得生成或覆盖这些来源属性。`material=excerpt` 明确只是有限摘录；无正文为 `unavailable`。运行状态为 `unknown` 时，仍可记录有证据的历史工作进展。

结果放在 `index.analysis.result`，`analysis.text` 保留序列化后的兼容文字字段；来源摘录保留在 `entries[].summary`。模型生成上限为8192 token（模型输出计量单位），普通文字问答仍为2048。长度不足、断流、取消和校验失败均不标记成功。

无效结果只有调试原文和错误，没有 `result`，调试状态为 `incomplete`。Host 拒绝继续问答，Client 只读展示原始材料，要求重新索引。索引运行记录只保留模型、状态、耗时和错误，排除结构化正文。

引用校验保证可追溯性，不能自动证明模型的语义判断正确。原文冲突、会话助理推测、有限摘录和验证缺失必须保留；模型不能因此声称独立检查了完整项目。

## 问答与调试展示

文字问答系统提示词优先使用通过校验的结构，按 Host/会话定位，再按工作区聚合。按用户问题提取目标、进展、阻碍或待办；安排下一步时区分已有任务与建议，优先考虑阻塞与任务依赖，并针对信息缺口澄清。来源材料与提取结果冲突时以来源为准。

调试结果逐会话显示六类信息，证据放在可展开区域，已有任务与“建议（未安排）”分开标注。流式半截 JSON 仅在诊断折叠区显示。播报从校验后的字段生成简短文字，绝不直接朗读 JSON。

两套前置提示词仍然可独立保存。索引的固定格式优先于旧提示词中“三到五句播报、不使用列表”的要求；字段内部使用简短口语。对话继续使用一到四句口语要求，不强制输出内部结构。
