## 协议修复

Grok 使用 ACP（Agent Client Protocol，代理客户端协议）传输会话更新，但内建提问使用私有扩展请求 `_x.ai/ask_user_question`，不能按 ACP 标准表单询问 `elicitation/create` 处理。无下划线的历史方法别名保留兼容。

驱动只把 `grok_build` 命名空间、名称为 `ask_user_question` 的工具调用映射为公共 `question-request`，读取 `rawInput.questions`，保留原始 `toolCallId`。私有请求中的 `toolCallId` 关联同一问题卡，JSON-RPC 请求编号用于原样回包，两者不混用。

回答使用 Grok 的单层 `outcome`：

```json
{
  "outcome": "accepted",
  "answers": {"问题原文": ["选项标签"]},
  "annotations": {"问题原文": {"notes": "补充文字"}}
}
```

多选保留多个选项；只有自由文本时回答为 `["Other"]`，正文放在 `annotations.notes`。问题卡关闭时回传 `{"outcome":"cancelled"}`。这些响应不调用 `acpElicitationResponse()`；标准 ACP 表单询问仍走原有路径。

工具通知可能先于私有请求抵达，所以问题卡先收到的答案会暂存到私有请求到达。重复工具更新不会生成第二张问题卡或普通工具记录。回合结束时释放监听器和未回答请求，下一轮可以继续提问。

每轮 Grok 请求增加宿主能力说明，明确 `ask_user_question` 是独立于 MCP 连接状态的内建工具；用户明确要求问题卡时，应调用工具并等待答案。

上游契约来源：[Grok 问题请求与响应类型](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-tools/src/implementations/grok_build/ask_user_question/types.rs)、[Grok 内建提问实现](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-tools/src/implementations/grok_build/ask_user_question/mod.rs)。
