# PeerHost 子智能体状态与适配器显示修复记录

## 问题与根因

通过 PeerHost 打开远程工作区时，主会话出现 Codex 与 DSH 两个模型选择器；子智能体列表误报“当前未运行”；子会话输入框将 Codex 显示成默认 DSH。

- 模型选择器以 `html` 和 `body` 上的适配器属性决定显隐。主会话和右栏子会话各自写入同一个属性，后挂载的默认 DSH 会覆盖主会话的 Codex。
- 聚合摘要直接丢弃 `origin: subagent` 的会话，原生会话目录缺少这些会话的运行状态基线。远端 `$events`（事件流）又只合并交互请求，丢弃了 `api-session/status`（会话运行状态通知）。
- 原生 `subagentCatalog`（子智能体目录）的 `id` 未编码为虚拟会话 ID。子会话也没有进入两端路由表，导致 CLI（外部 Agent 适配器）配置查询落到本机。

## 实现

1. 把适配器属性放在各输入框自己的 Agent 控件上，CSS 通过当前 `data-composer-card` 内的属性控制原生模型选择器，不再写整页属性。
2. 聚合工作区新增可选 `subagentSessions`，通过原生 `parentSessionId`（父会话标识）收集工作区内的后代。只携带摘要、父子关系和适配器标识，不包含消息或工具正文。集合遍历去重，异常循环不会阻塞。
3. 子会话进入原生 `session/list` 基线和 Host、Client 路由表，保留 `origin`（来源）、虚拟父会话 ID、标题原生序号与运行状态；工作区的侧栏成员和归档集合仍不包含子会话。
4. 子智能体目录 `id` 与状态通知位置参数中的会话 ID 使用同一套虚拟编码。事件合并器仅接收当前已登记作用域的运行状态通知，继续过滤远端全局设置通知。
5. 父会话快照公布子智能体目录后，立即用已有的临时作用域机制登记子会话，补齐聚合刷新前的配置查询窗口。聚合确认、超时和模块释放沿用现有清理机制。
6. 原生转发白名单补齐 `subagents/prompt`（子会话输入）与 `subagents/interruptByParent`（父会话停止子会话），资源身份由原生请求改写边界还原。

新增字段均为可选字段，旧版摘要保持兼容。本机普通会话的模型选择、状态事件和原生列表通道继续保留原有行为。

## macOS 与 Windows 跨平台复核

本次复核未发现上述修复引入依赖本机操作系统的行为，不需要新增平台分支。

- 会话 ID、父子关系和运行状态通过 URL 分段编码与 JSON（结构化文本）传输，不使用路径库或本机操作系统判断。中文、冒号、空格和百分号标识在代理层往返后仍能解析到同一 Host。
- 远端 `cwd`（工作目录）保持目标 Host 原始路径，标题回退同时支持斜杠与反斜杠。虚拟根目录在 Host 边界还原，不能使用本机路径库重新解释远端路径。
- Windows 文件位置按目标工作区识别，覆盖盘符反斜杠、盘符正斜杠和 UNC（网络共享）路径；macOS 的冒号文件名保持原样，不使用 Windows 行号拆分规则。
- CLI 适配器配置与子会话输入按资源归属转发。父会话和子会话 ID 在目标 Host 解码，正文中的路径、模型 ID、思考强度和服务档位原样保留；本机同名会话不会抢占远端请求。
- 模型显隐规则使用原生输入框和 Slot（界面插槽）标记，不绑定 macOS/Windows 的构建类名。`:has()` 是仓库现有布局已使用的 CSS 能力；此次未对两端实际浏览器引擎或系统版本作兼容实测。
- 唯一使用 `node:path` 的相关资源表代码用于本机顺序文件的持久化，没有把远端工作区传给本机路径库。
