# 通知联动会话已读实现记录

## 变更目的

用户从侧栏、会话列表或通知按钮打开会话后，对应的全局助理通知应自动标记为已读。通知匹配必须使用 Host、工作区和会话三元组，不能使用会话标题或同名会话 ID 猜测。

## 实现内容

- 在 `uiWorkspace.selection` 上订阅 DSH 的前台会话选择 Store。首次挂载也会读取当前选择，避免助理浮层晚于会话打开时漏记已读。
- 新增 `assistant/notifications/read-session` RPC。Host 通知中心按 `hostId + workspaceId + sessionId` 批量匹配记录，复用现有 `readNotice()` 语义，重复调用不会重复推进状态。
- 客户端将本地会话、远端虚拟会话和 `local` 虚拟别名归一化为安全三元组；Host 只把 `local` 别名解析为当前真实 Host ID。PeerHost 工作区同时兼容虚拟 Workspace ID、`hostId:workspaceId` 旧格式和真实工作区 ID，避免编码形式差异漏匹配。
- `uiWorkspace` 采用可选服务注入；PeerHost 延迟注册导航服务后仍会建立选择监听。
- 会话选择确认进入通知 Store 的串行 RPC 队列。提交前校验最近一次选择，快速切换时丢弃旧选择，避免迟到操作误读新会话。
- 通知按钮原有的单条 `read` 路径保留。按钮导航和会话选择监听同时触发时由 Host 幂等处理。

## 展示语义

完成和错误通知标记已读后会折叠并离开气泡列表。仍处于 active 状态的提问和审批只标记已读，继续保留待处理入口；不会代替用户回答或批准请求。
