# OpenCode V2 适配兼容记录

## 问题与方案

升级 OpenCode V2 后，旧适配器仍访问 V1 的目录接口，并按嵌套模型对象解析响应，最终吞掉接口错误、返回空列表。V2 的认证、会话输入和服务端事件同样不兼容。

核心数据边界是 OpenCode 的版本化线协议。保留已有 V1 投影，在 `OpenCodeDriver` 探测真实服务端点后选择独立的 `OpenCodeV2Protocol`，共同输出插件标准事件。这样避免把 V2 判断散落进 V1 的每个事件分支。

## 实现

- `/api/info` 探测 V2，V1 保留原健康接口；200 HTML 页面不能被判为有效服务。
- 读取 V2 原生后台服务登记，核对 PID 后复用地址与认证；不修改或重启用户后台服务。
- 托管进程显式设置随机密码，HTTP 与 SSE（服务端事件流）共用认证头；进程结束清除对应凭据。
- 解析扁平模型目录、提供商名称、默认模型和 variants。使用目录 id 保留模型别名，不误用上游 modelID。
- 按 100 ms 间隔重读目录，确认连续两次结果一致；最多重试 15 次。未收敛时标记短缓存，保留后续刷新的机会。慢插件仍可能需要再次刷新。
- 会话创建、读取、续聊和目录校验使用 V2 的 data/location 结构；续聊先通过会话 model 接口选择模型和档位。
- 等待 server.connected 握手后再发送 prompt，按 sessionID 隔离事件，分别处理文本增量、结束快照、工具、推理、用量、压缩和执行终态。
- prompt 出错会主动结束事件等待；异常断流不会被报成成功。取消仅中断对应会话，不杀共享服务。
- 权限回复使用 decision；原生 question 工具映射到 DSH 问题面板，保留真实问题、标题和工具调用 ID。回复时把展示标签还原为 option.value，支持字符串、多选、布尔和数值字段。没有扩展 DSH 对外部交互字段、动态条件表单的表达能力。
- Skill 使用原生 Skill.id 引用；附件转换成 files/uri。V2 不再调用已移除的 V1 debug skill 子命令。
- 配置摘要增加 OPENCODE_CONFIG_DIR 和原生服务登记文件，摘要不包含配置原文或密码。

涉及源码：

- `src/host/cli-adapters/opencode-driver.ts`
- `src/host/cli-adapters/opencode-v2-protocol.ts`

- TypeScript 类型检查通过。
- 199 项相关回归测试通过，包括 V1 行为和 13 项新增 V2 用例。
- 真实 `opencode v2.0.24` 冒烟测试通过：模型读取、两轮对话、会话复用、附件、真实 question 工具、表单回复和完成事件。模型请求由本地 HTTP 替身响应，不产生付费推理调用。
- 使用现有用户配置单独验证原生目录，可见 OpenAI、DeepSeek，默认模型为 `openai/gpt-5.6`。临时进程、数据目录和测试上游在结束后回收。
- 本机 CLI 从 `opencode-ai@1.18.34` 更换为 `@opencode/cli@2.0.24`。用户原配置未改写。

## 边界与兼容性

V2 原生目录会忽略旧配置里的 whitelist/blacklist，因此模型列表可能变长，见 `docs/调查报告/20261008-OpenCodeV2协议变化调查.md`。本次验证没有调用真实付费模型，也没有操作 Desktop、dsh-web 或 Stage0，没有推送或发布插件；运行中 DSH 的实际加载效果尚未通过重启或 GUI 验证。
