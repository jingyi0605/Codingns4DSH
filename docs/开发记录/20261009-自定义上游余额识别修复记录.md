# 自定义上游余额识别修复记录

## 问题

DSH 当前会话使用自定义 Provider 时，订阅入口没有读取活动 Profile 的 Provider 配置。读取器只检查 `settings.yaml` 与 `settings.yaml.imported`，找不到自定义来源后会按旧的官方默认 Provider 查询 DeepSeek 余额，导致界面显示官方 Key 的余额。

## 修复

- 新增统一的 DSH 配置发现模块，优先读取活动 Profile 的 `profiles/<name>/cordis.patch.yml` 与 `cordis.yml`，兼容旧版导入设置。
- 支持从 Profile 的 `apiKeyEnv` 配置和 DSH 凭据文件解析自定义 Provider 的地址与密钥引用。
- New-API、Sub2API 统一使用该来源发现逻辑，避免两套读取器得到不同 Provider 结果。
- DSH 自定义 Provider 探测失败时返回空用量，不再回退到官方 DeepSeek 余额。

## 验证

- 通过 TypeScript 目标模块检查。
- 增加活动 Profile 配置读取和“自定义 Provider 不借用官方余额”的回归用例。
