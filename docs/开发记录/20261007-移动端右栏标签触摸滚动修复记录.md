# 移动端右栏标签触摸滚动修复记录

## 问题与机制

移动端右栏顶部标签数量超过可见宽度后，触摸横滑会调整标签位置，无法滚动查看被遮住的标签。

本仓库保留的 DSH 源码包中，`ui-dockkit`（停靠布局组件）的 `TabPanel.tsx` 与 `dockkit.module.css` 明确采用桌面拖拽优先策略：

- 标签条 `[data-dockkit-strip]`、滚动容器 `[data-dockkit-strip-tabs]` 和标签 `[data-dockkit-tab]` 都设置 `touch-action: none`，阻止浏览器触摸平移。
- 标签的 `onPointerDown` 不区分鼠标与触摸，调用 `onTabPressed`；`followPointer` 随后捕获指针，并在窗口级监听移动与释放。超过阈值后提交标签排序或停靠操作。
- 标签选择独立走 `onClick`，关闭按钮也有独立的点击处理。因此可以只阻止触摸启动拖拽，保留原生点击。

已安装的右栏组件通过 `[data-sidebar-right-panel]` 承载 DockLayout（停靠布局），本次样式与事件均限制在这个面板内，不依赖生成的 CSS 类名。

## 实现

1. 新增 `src/client/mobile-rightbar-tabs-dom.ts`，由移动端访问增强模块装配，沿用该模块的移动视口上限。
2. 窄屏触摸视口下，在插件自有作用域内把上述三层 `touch-action`（触摸默认动作）改为 `pan-x`，保留浏览器原生横向滚动和惯性。
3. 文档捕获阶段只拦截标签滚动容器内、`pointerType === 'touch'` 的 `pointerdown` 传播。不会调用 `preventDefault()`，后续标签切换及关闭按钮的点击不受影响；鼠标和手写笔继续原生拖拽。
4. 全局侧栏手势始终让位右栏标签条，不依赖当前是否发生横向溢出；事件路径和后续移动中才暴露的标签条也会让位。
5. 使用全局 CSS（层叠样式表）作用域和事件委派覆盖会话切换后新建的标签，无需 MutationObserver（DOM 变更观察器）或逐标签监听。
6. 设置上限变化、横竖屏切换或模块停用时完整撤销属性、样式和监听。
