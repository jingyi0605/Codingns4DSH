# 会话完成后自动增量索引实现记录

日期：2026-10-07

## 需求与结果

用户要求按会话记录版本自动增量索引，只处理受管范围内发生有效变化的会话；一轮执行结束后合并更新，复用其他会话结果。模型、索引提示词或固定格式变化时才全量重建。运行中不得触发索引。

本次把后台自动更新接入既有逐会话结构化索引服务，不依赖打开调试窗口。原4.11的“只有手动索引才调用模型”规则由本次策略替代。手动“执行索引”保留，主要用于立即处理已结束的待更新项和重试失败项，也不能绕过会话完成门禁。

## 完成判定

项目是否完成与 Agent（执行代理）是否结束当前轮次是两件事。索引门禁使用执行状态，不使用 LLM 判断的项目进展。

- 本地原生 `agent/status` 的 `running → idle`，外部适配器 `api-session/status` 的结束通知，或明确 `session/complete` 通知可确认执行结束。
- 原生 `running` 包含驱动收尾阶段；工具的 `step/end` 不代表整轮结束。`turn/end` 只安排检查，还要复核执行状态；日志刷新也不能放行。
- 正在运行、等待审批/提问或执行状态未知时，任务标为 `deferred`（等待会话完成）。不提取新索引正文、不调用索引模型；旧材料可保留展示，但不能冒充当前完整索引。
- 一次读取或模型能力解析后，会话可能已经进入新轮次。模型请求前和结果写入前再次检查来源版本、活动状态和范围。收到新轮次通知时只中止该会话任务，其他任务继续；晚到结果不更新缓存。

初次启用会为当前范围内已确认空闲的历史会话建立基线；启动时正在运行的会话仍等待结束，未知状态不猜测完成。

## 版本与复用

`AssistantIndexUpdates` 以 `[hostId, sessionId]` 为键保存来源版本、已索引版本、已尝试版本、有效事件序号、执行状态和是否处于开放轮次。

范围由既有成员过滤器决定，始终是受管工作区内的普通未归档会话。范围外、归档、子代理和空白占位的事件不会新增索引任务。真实用户消息、助理消息、工具调用和结果、标题、待办、压缩摘要、来源更新时间及运行边沿推进对应版本。事件序号去重；流式片段、运行时上下文消息和工具步骤结束不进入有效变化表。

| 情况 | 行为 |
| --- | --- |
| 一条会话执行中发生变化 | 只推进该会话来源版本，等待本轮结束 |
| 多条会话接近同时结束 | 延迟5秒合并为一个批次，每条仍使用独立任务；有效变化重新计时，普通刷新和无变化通知不延长已有等待 |
| 仅一条会话材料变化 | 重新提取该会话摘录并调用模型，其他成员复用材料和结果 |
| 来源版本变化，但标题与实际摘录相同 | 复用已校验模型结果，只推进已索引版本和 Host 来源字段 |
| 增加工作区或取消归档 | 仅为新增成员建立索引，共同成员复用 |
| 移除工作区或归档 | 移除对应成员及缓存，不重新生成其他成员 |
| 模型、索引前置提示词或固定格式变化 | 所有成员模型结果失效；空闲成员更新，运行成员延后 |
| 只修改对话提示词 | 重开文字对话上下文，不重建索引 |
| 同一来源版本索引失败 | 保留失败证据，轮询及其他会话更新不顺带重试；手动操作可重试 |

正文缓存绑定来源版本。模型缓存使用模型提供商、模型、索引前置提示词、固定格式、标题与实际摘录的 SHA-256（内容摘要）。成功项可跨相同材料的来源新版本复用；失败项只在相同来源版本复用失败状态，不作为有效索引进入问答。

仍保持最多两个独立模型请求、每项8192 token输出预算、90秒超时和原生关闭思考参数。记录保留逐项状态与版本，不保存正文。自动更新不能并发启动多个索引批次；停止当前批次后不会立刻被同一版本自动重试。

## 本地与远端

本地通过 `nativeSessions.subscribe` 接入持久化语义事件，通过原生事件总线读取 Agent 与外部适配器状态。没有原生桥时才使用事件总线的语义事件入口。

每5秒做一次元数据同步，补充远端变化及遗漏通知，不在轮询中读取索引正文。远端新增独立 `activity` 字段，明确区分 `running`、`idle` 和 `unknown`；侧栏为兼容显示而默认填入的 `idle` 不能作为执行结束证明。每个真实远端模型请求前再查询执行状态和更新时间，确认仍空闲且版本相同后才调用。

远端发现延迟取决于元数据同步周期和网络，不能把本地事件订阅描述成远端推送。没有可靠完成状态时继续等待，不靠标题、历史成功结果或导航默认值猜测完成。

## 调试与边界

调试页显示每条会话的当前来源版本与已索引版本，任务显示复用、等待完成、运行或失败。模型切换通过 `assistant/index/configure` 配置后台任务，该端点同时登记主 RPC（远程调用）与旧 HTTP 入口。面板轮询只更新显示，关闭窗口后后台索引继续运行。

增量单位是会话，不是逐条消息追加的历史数据库。变化会话重新读取当前有界摘录，仍使用既有最近80条语义事件与正文长度限制，不能宣称覆盖完整历史。版本表、正文缓存、模型结果缓存和最近30次运行记录属于当前 Host 内存；Host 重启后从会话日志重新建立基线，不具备跨重启增量复用。

本次没有改语音识别模型、正式助理界面或 LLM 对话设计。

## 后续调整：合并等待改为5秒

按用户反馈，将原500毫秒合并窗口改为5秒，给收尾记录和短时间内的连续轮次留出合并时间。新的有效材料或执行结束通知重新计时；重复空闲通知、日志刷新、面板刷新和无变化元数据轮询只保证任务已被安排，不重置现有计时。避免轮询间隔同为5秒或面板频繁刷新时持续推迟索引。

触发时仍复核执行状态与来源版本，延迟不能替代完成门禁。手动执行仍可立即处理已确认结束的会话；运行中的会话继续等待。

此调整使用源码加载器运行增量索引、调试和独立任务回归，38/38通过；新增5秒边界、普通刷新不推迟、收尾有效材料重新计时的验证。当前 `pnpm exec tsc --noEmit` 与 `git diff --check` 均通过。未构建或启停 Stage0/服务器，未操作 dsh-web/Desktop。
