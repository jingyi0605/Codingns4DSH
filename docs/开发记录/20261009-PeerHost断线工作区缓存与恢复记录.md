# PeerHost 断线工作区缓存与恢复记录

## 核心判断

值得做。网络故障不是删除工作区的理由；已添加配置、连接状态和缓存展示应分别表达，不能让一次失败的摘要读取变成“远端没有工作区”。

## 数据与行为

- 继续以 `PeerHostRecord.visibleWorkspaceIds` 为工作区添加状态的唯一来源。
- 在当前 Host 状态目录增加 `peer-host-workspace-cache.json`，保存最后一次成功的远端工作区与会话导航摘要。包含普通、归档和子会话的目录信息，不包含消息正文、工具内容或认证凭据。
- 缓存按所属用户、PeerHost ID、路由与目标身份隔离；取消添加、删除 Host、禁用 Host 或身份变化时不再投影旧缓存。损坏的缓存不会阻断在线重建。
- 网络失败时保留缓存工作区与会话成员，使用灰色标签与淡化效果，仍可点击展开。过期的运行状态不再显示成持续执行。
- 灰色工作区行末的 `×` 调用独立的 `dismissDisconnectedWorkspace` 接口。隐藏状态持久化，仅影响断线期间的缓存展示，不修改添加配置，也不操作远端目录或会话。
- 成功重连后使用完整的新摘要替换缓存并清空临时隐藏集合，按当前添加配置恢复工作区。远端成功返回空列表时清空旧缓存。

## 实现边界

1. `buildSources` 在握手或认证失败时仍提供断线 Host 节点；聚合 RPC 在替换虚拟资源目录前恢复缓存。助理索引仍读取真实可用性，不把缓存导航摘要当成在线数据。
2. 握手检查中和网络失败时保留上次确认的目标身份与元数据，避免断线导致缓存身份失效，同时保持重连身份变化检测。
3. `workspace/follow` 流在完整 baseline（基线快照）到达前结束时报告失败；真正的空工作区必须由包含 `items: []` 的有效基线证明。
   `session/list` 明确的网络或认证故障同样交给缓存，避免用成员 ID 占位覆盖已缓存的标题；旧版不支持摘要协议时保留原有占位降级。
4. 原生 Workspace Store 首轮聚合前保留提前到达的远端条目；首轮后远端成员、标题和归档集合以当前投影为准，避免底层旧快照复活已移除的记录。本机资源继续由宿主管理。
5. 工作区行只改变视觉样式，不设置禁用状态。重连、DOM（文档对象模型）行复用或停用模块时恢复原样式并清理按钮；移除按钮阻止事件冒泡，失败时可重试。
6. 轮询共用原有串行计时器：正常周期 30 秒，有断线 Host 时周期 5 秒；隐藏页面暂停，恢复可见或浏览器发出 `online` 事件时刷新。复检周期从上一轮完成后开始计时，网络请求仍受原有超时约束。
7. 缓存与隐藏操作串行，文件原子替换；内容未变化时不重复写磁盘。持久化失败时仍保留内存列表。

## 验证

使用 `tests/register-source-loader.mjs` 在内存加载源码，不执行构建。覆盖缓存重启恢复、普通与归档成员、子会话路由、断线临时移除、配置保留、重连新标题、无效缓存、身份隔离、旧 Store 残留清理、按钮事件隔离和轮询周期。

真实 Feature（功能模块）与 RPC（远程过程调用）夹具模拟连接成功、网络失败、握手失败、缓存移除、本机重启与重新连接，确认这些阶段不会丢失工作区添加状态。网络与监听入口使用测试替身，没有连接用户的远端机器。

另执行 `pnpm run typecheck`、`pnpm run i18n:check` 和 `git diff --check`。

开发与验证仅修改仓库源码、测试和文档，保留已有工作区改动。未构建、启动或重启 Stage0，未操作 Desktop，尚未进行实际断网的界面回放。后续按缓存功能、侧栏恢复、回归测试与开发记录分批提交，不推送或发布；共享文件仅暂存本会话的差异块。
