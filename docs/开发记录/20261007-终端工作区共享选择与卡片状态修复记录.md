# 终端工作区共享选择与卡片状态修复记录

日期：2026-10-07。

## 问题与判断

用户明确要求同工作区的终端卡片共享打开状态和子终端选择。上一轮选择记录按会话保存，导致同一会话切换标签正常，切到其他会话却回到首个子终端。

恢复逻辑还按会话保存关闭标记，并在调用 `openTabIn` 后直接记为已打开。DSH（宿主平台）的原生侧栏布局按会话装配，未装配时 `openTabIn` 不产生实际打开动作；下一轮看到卡片缺失便误判为用户关闭，阻止后续恢复。真实关闭、布局暂未装配、自动清理此前被混在了同一分支中。

## 实现

`CodingNsWebTerminals` 按工作区统一保存 `{ selectedId?, cardOpen? }`。新记录使用 `dsh.codingns.terminal.workspace-state.v1.` 加 JSON 编码的工作区作用域键，浏览器读写失败时继续使用内存。没有工作区 ID 的旧环境保持会话级回退。

旧会话选择在首次解析工作区时迁移；已有工作区记录优先，避免旧会话偏好覆盖共享选择。库存刷新只校验一次工作区共享选择，关闭选中终端后统一回退，空库存清除选择。

卡片打开由 Guide（创建入口）和显式新建写入共享开关；用户关闭由原生 `registerCloseHandler` 写入，并同步清理同工作区其他会话的卡片。自动清理空库存和迁移多余旧标签时使用投影标记，避免原生关闭钩子把清理动作记成用户关闭工作区。

移除会话级关闭推断，不再把原生布局尚未装配视为用户关闭。恢复组件监听共享开关、库存、当前会话和全局布局索引，在会话进入及布局更新后继续投影。打开请求未生效时允许后续恢复再次打开；每个会话仍最多一个聚合页签。

工作区解析前发生的显式开关先暂存，解析后覆盖工作区旧开关。新建只在开始时写入打开意图，完成时不再改写，保证用户在创建过程中关闭卡片后不会被重新打开。

卡片开关仅控制布局，关闭卡片不会关闭 Host（宿主）的终端进程，也不会清除子终端选择。其他工作区的状态保持隔离。
