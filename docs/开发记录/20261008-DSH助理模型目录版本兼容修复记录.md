# DSH 助理模型目录版本兼容修复记录

日期：2026-10-08。

## 问题与根因

用户在 Windows DSH Desktop 0.2.0-rc.2 通过插件管理页安装本地 beta.4 包。完整重启后，生命周期读取、内置形象和页面操作恢复，但助理模型目录显示“当前 Host 没有可用的 DSH 原生 LLM 服务”。官方账号与第三方 API 已配置可用。

插件整体支持 `>=0.2.0-rc.2 <=0.2.1-alpha.1`，而 `src/dsh-capabilities/routes.ts` 和 `src/dsh-capabilities/matrix.ts` 中，`llm.text`、`assistant.agent` 只允许 alpha.1。`createAssistantLlmAdapter` 因版本不匹配返回 undefined，`AssistantTextChat.catalog()` 随即生成空目录。此时尚未查询原生模型提供商，因此不是凭据校验失败。

最初只用 alpha.1 标签回放用户指定 tgz，生命周期、模型夹具和两张 PNG 均通过；改用用户确认的 rc.2 后，同一 tgz 稳定复现原始模型错误。这说明打包回归必须覆盖最低支持版本。

## 修复

- 两条能力路由及矩阵复用 `DSH_COMPATIBILITY`，保留原路由 ID、结构探测和旧版本拒绝行为。
- 同时开放经过验证的 rc.2 根 Agent 能力，避免仅恢复模型列表后，正式对话仍因第二条版本限制失败。
- 更新两版模型目录、默认选择、流式回复和工具隔离测试。原生运行时测试读取实际包版本，避免硬编码 alpha.1 绕过版本门禁。
- 增加 `scripts/check-assistant-package.mjs`，默认按目标包声明的最低 DSH 版本回放生命周期、模型目录及内置图片；输出文件指纹，使用内存配置、对话存储和模型夹具。

两版原生 Agent、AgentLoop、SystemPrompt、默认模型服务实现的文件哈希一致。LLM 差异集中在适配器变更通知的异常处理，Tools 差异为代码工具说明和参数呈现顺序；本次消费接口保持一致，并通过真实内存运行时执行验证。

完整重启已解决最初的页面锁定和图片问题，因此本轮临时的界面重试调整已撤回，最终代码修复集中于版本兼容。

## 验证

- 修复前新增的 rc.2 模型和 Agent 路由回归均失败；修复后通过。
- 六个定向源码测试文件共 86 项通过，0 失败、0 跳过，包含 alpha.1 原生运行时。
- 额外指定 rc.2 原生核心库，5 项通过，覆盖模型目录、官方与第三方提供商注册形状、受限管理与搜索工具执行、普通 Agent 隔离。
- `pnpm run typecheck`、版本同步、能力退休、脚本语法与差异格式检查通过，能力报告已重新生成。
- 原 beta.4 tgz 在 rc.2 标签下被新增打包校验正确拒绝；该验包时的旧产物尚未包含源码修复。

测试只将已安装核心库加载到独立内存 Context（运行上下文），使用模拟模型流和搜索响应；没有访问真实模型账号、密钥或网络。本会话未启动服务器、构建、打包、安装或操作 Desktop。

用户后续确认最新包已能加载模型，但正式对话出现 `Stream ended without finish reason`。该错误仍待定位，不能仅凭截图判断为超时；本次提交没有包含对话流错误修复。
