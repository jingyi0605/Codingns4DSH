# 全局助理工作区会话可见性修复记录

日期：2026-10-07

## 问题与证据

用户选择 Stage0 的 TEST 工作区，原生侧栏只有两个普通会话，助理调试页却显示 49 个未归档会话。

只读核对 `/Users/jackson/.dsh-stage0-020` 的工作区成员、全局归档集合与会话元数据，得到以下结果：

| 类型 | 数量 | 应否纳入当前索引 |
| --- | --- | --- |
| 普通未归档会话 | 2 | 是 |
| 空白会话占位 | 3 | 否 |
| 已归档的根会话 | 103 | 否 |
| 子代理会话 | 44 | 否 |

TEST 持久化成员共有 108 个，即 103 个归档根会话、3 个空白占位和2个普通会话。该目录下的日志共 152 个，其中额外的44个均为 `origin=subagent`，父会话全部已经归档，且这些子会话不属于 TEST 的工作区成员。直接按归档 ID 排除根会话后恰好剩下49个。

原代码使用 `sessionQuery.listSessions()` 的历史全集，并通过 `cwd` 相同或路径前缀匹配补充工作区归属。这样，归档父会话的子代理日志被重新算成了 TEST 的独立会话；原生 `sessionController.list()` 只用于补充状态，其 `origin`、`blank` 没有参与过滤。

DSH 0.2.1-alpha.1 原生侧栏先按工作区 `sessionIds` 取得成员，再排除子代理、空白占位和全局归档集合。归档不会删除成员槽位，也不会删除子代理日志。因此，日志存在以及 `cwd` 相同都不能证明一个会话是当前工作区成员。

## 修改

- 本地会话目录优先读取 `sessionController.list({})` 的原生投影；原生列表为空或失败时不再改用全量历史，失败给出明确诊断。只有缺少列表能力时才保留旧版本回退。
- 本地归属只使用 `workspaceRegistry` 的成员关系，移除 `cwd` 和子目录推断，也不信任游离记录自带的工作区标识。
- 在标题和正文读取前排除 `origin=subagent` 和 `blank=true`。独立 fork（分叉会话）仍按自身成员关系纳入，不因父会话归档而被误删。
- 归档仍以全局 `archivedSessionIds` 为准；原生列表省略归档记录时，按成员与归档集合的交集补充无正文的排除元数据。
- 调试刷新比较当前可索引成员和上次索引成员。归档或成员变化后显示当前元数据并标记结果过期，不继续返回旧范围正文；索引运行记录保留。

这些规则同时作用于调试面板、正文索引、语音摘要与意图目标来源。未修改原生工作区和归档数据。
