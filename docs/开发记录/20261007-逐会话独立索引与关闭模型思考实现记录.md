# 逐会话独立索引与关闭模型思考实现记录

日期：2026-10-07。对应 spec013 任务4.13。

## 问题与调整

三个会话共用一次结构化索引请求，输出预算8192 token仍达到上限，整批没有有效结果。简单扩大预算没有消除会话数量与输出长度的耦合；本次改为每个会话独立调用模型、独立校验，再由 Host 汇聚结果。

用户同时要求检查关闭模型思考以加快索引。索引使用结构提取任务，按已配置模型的原生能力关闭思考；文字问答参数不随之改变。

## 任务与数据边界

- `AssistantIndexAnalysis` 专门管理索引任务，不复用 `AssistantTextChat` 的30轮聊天记录容量。35个会话的回归覆盖了该限制。
- 每个任务有独立请求标识、取消信号、状态、原始增量、8192 token输出预算及90秒超时。最多两个任务并发，排队时间不计入单项超时。
- 每次请求只携带当前唯一会话的事实和原始摘录，不携带其他会话正文、其他会话生成结果或排除目标。所选模型和索引提示词由整批任务固定。
- 原始正文先读取并保存，再立即返回后台任务状态；Client 继续轮询现有 `assistant/debug`，不让长请求占用索引 RPC。
- 单项输出超限、格式无效、能力解析失败、模型错误或超时只终止对应任务，其他任务继续。即使适配器忽略取消，服务也按超时结算，迟到结果不再写入。
- Host 对每项验证唯一会话、字段、长度和原文证据；汇聚结果只含已通过校验的项。完成项清理重复保存的原始 JSON 文本。
- 运行中、停止或失败时保留成功项；整批只有全部会话成功才是完整索引。有失败项时调试页显示不完整，现有 LLM 问答仍要求完整索引。
- 停止批次同时取消排队和运行项；改范围、来源变更、改索引提示词或释放服务会停止任务。模型目录和能力读取后再次复核来源，晚到结果不会污染新一代索引。

这里的独立任务是独立模型请求与生命周期，并不为每个请求创建操作系统子进程、Agent或新的项目会话。

## 关闭思考参数

索引前调用 DSH 原生 `llm.resolveModelInfo(provider, model, signal)`。模型公布 `off` 或 `none` 档位时才发送对应的 `reasoningEffort`；没有能力信息或不支持关闭时省略参数，并显示使用默认参数。读取能力失败会明确失败，不伪装成关闭成功。

当前安装的 DSH 0.2.1-alpha.1 的 DeepSeek 适配器公开 `off` 档位，将其转成供应商请求：

```json
{
  "thinking": { "type": "disabled" },
  "max_tokens": 8192
}
```

关闭时不发送 `output_config.effort`。CodingNS 不绕开 DSH 直接向上游塞入未知参数，也不修改供应商配置或安装目录。官方 API 同样提供关闭思考的参数，见 [DeepSeek 思考模式文档](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)。

在独立 Node 内存测试中调用真实安装的 DeepSeek 适配器，临时用模拟 `fetch` 截取请求体并中断发送，确认适配器输出 `thinking.type=disabled`、`max_tokens=8192`，没有 `output_config`。没有发送网络请求，也没有修改 DSH Profile。该验证只证明参数映射；真实索引耗时与关闭思考后的输出质量需要模型联调确认。

## 调试与记录

索引结果页显示完成数量、排队、运行、失败或停止数量，以及每个会话状态、错误和思考参数状态。未校验的模型文本放在对应会话诊断中，已完成结构结果继续展示目标、进展、阻碍、待办、行动和信息缺口。

索引记录保留逐项身份、状态、起止时间、错误和思考参数状态，排除原始模型增量与结构结果正文。失败记录不暴露错误中的凭据。
