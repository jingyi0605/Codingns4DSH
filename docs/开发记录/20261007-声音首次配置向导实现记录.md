# 声音首次配置向导实现记录

## 用户流程

入口为最新智能助理工作台的「配置 → 声音管理」。初次向导展示识别、音色的推荐值和一个「启用语音」按钮，没有必填字段。向导下方提供独立的「语音输入」「语音输出」折叠卡片，用户无需手动选择模型也可一键初始化。

1. 打开页面只读取资源状态，不下载、不安装、不请求麦克风。
2. 用户主动启用后，Host 依次准备并验证识别模型、独立运行环境和 MOSS 模型。
3. 未配置时使用中文轻量 14M、Junhao 和默认播报参数；已有目录模型、音色与参数保持原样。
4. 完成后显示「语音已就绪」与「试听声音」，输入与输出保持用户的展开状态。展开对应卡片可管理设备、识别模型或音色、语速、音量。音频设备默认使用系统设备。
5. 开始对话时仍由用户点击「开始语音」申请麦克风；初始化及试听不录音。

按需策略落在用户主动启用时：文字对话和打开声音页面不安装语音组件。本次提供向导主动准备识别与播报的完整链路；不在聊天回复期间静默启动安装。

## 数据与保存

- `AssistantVoiceInitializationSnapshot` 汇聚识别验证结果、MOSS 状态、当前进度和错误。下载完成和推理验证通过是独立事实；只有识别通过验证、MOSS 就绪且选用 MOSS 后端，向导才报告完整就绪。
- `assistant/voice/initialization` 为只读状态查询；`assistant/voice/initialize` 为一次准备入口，Host 负责按序调用现有模型与 TTS（文字转语音）服务。
- 未知长度保持不定进度，字节进度只代表当前下载，不伪造整体百分比。
- 重复请求以及准备期间的模型切换、播报设置变更和实时启动被拒绝；完整重置撤销旧任务并等待结算，再清空设置，已下载资源保留。
- 普通下载失败保留已完成文件；ONNX（开放神经网络交换格式）图验证失败会在重试时重新下载模型资源。只有验证成功才写入就绪标记并切换后端。
- 旧的手工识别路径没有目录 ID 时，不会被默认轻量模型覆盖；明确显示错误，引导通过高级模型管理确认模型。
- 最新声音页面去掉外层草稿音色选择，实际音色管理使用原 Host RPC（远程过程调用）独立保存。完成初始化后重读权威设置，避免后续「保存配置」写回旧后端。

## 自动运行环境

默认按 Host 操作系统与架构选择 python-build-standalone 的 CPython 3.12.12／20251014 安装包，固定官方 URL 与 SHA-256 摘要。目前提供 macOS ARM64／x64、Linux glibc ARM64／x64、Windows x64 的路径；其他架构明确报错，不猜测兼容包。

官方分发说明：[安装用发布包](https://gregoryszorc.com/docs/python-build-standalone/main/distributions.html#install-only-archive)、[固定版本发布页](https://github.com/astral-sh/python-build-standalone/releases/tag/20251014)。摘要取自该版本 GitHub Release 资源的 `digest` 字段。解压使用系统 `tar`，发布包不随 npm 分发。

解释器、虚拟环境、pip 缓存和模型均位于当前 Host 的专用语音资源目录。下载先校验摘要，再在暂存目录解压、执行版本检查，最后原子提升；损坏的解释器缓存可自动重新准备。创建专用虚拟环境后只安装固定版本的 CPU 推理二进制依赖，不进行本机源码编译。

已有可运行的专用虚拟环境继续复用；明确设置的 `CODINGNS4DSH_TTS_PYTHON` 仍可作为基础解释器。工作进程清除宿主 `PYTHONHOME`／`PYTHONPATH`，避免串用系统库。运行环境命令取消后等待子进程关闭，防止重置与残留安装进程竞争写入。

## 识别模型组件显示修复

原声音页只有顶部的「语音识别模型」按钮，实际模型选择、下载及验证组件位于二级弹窗，向下滚动后容易错过入口。该轮将同一组件直接装配在声音页内。后续按用户要求改为输入、输出两组独立折叠卡片：展开输入即可管理模型，无需初始化 MOSS 或展开输出。识别用于将麦克风语音转成文字，播报音色独立管理。

- 内嵌组件与旧弹窗共用控制器、模型卡片、下载进度与验证操作，保留旧入口兼容性。
- 新配置默认选中中文轻量 14M；已有配置保留，Host 当前模型改变后同步选中项，普通状态刷新保留尚未应用的选择。
- 应用模型后重读设置；隐藏页面停止闲置轮询；首次向导准备过程中禁止从识别面板重复发起操作。
- 内嵌模式不显示弹窗关闭按钮，也不增加嵌套滚动区。打开页面只读取状态，初始化和模型下载仍需用户主动点击。
- 工作台、首次向导、模型展示、模型文件管理与初始化 RPC（远程过程调用）定向回归 43/43 通过。没有构建、启停服务或操作 Desktop；当前运行页面的更新和真实浏览器布局仍需在用户已有开发链路中确认。
- 类型、版本、能力退休及差异检查通过。当前全仓国际化检查有 5 处其他模块阻断：`assistant-composer-input.ts` 的四处中文命令识别文本和 `peer-host.ts` 的一处导航日志；本次新增的识别说明走中英文词典，没有新增违规。
