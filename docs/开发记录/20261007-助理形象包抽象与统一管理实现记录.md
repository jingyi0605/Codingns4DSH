# 20261007-助理形象包抽象与统一管理实现记录

## 问题与结果

用户截图已显示形象设置，但原有模型仅有名称、类型和地址，列表管理写入散落在表单内，内置渲染器也在插槽单独查表。此次补齐形象包契约、格式适配器、统一管理器及两个展示位置的资源选择，使导入包和手工素材使用相同接口。

数据流为「包清单 → 格式适配器 → 统一管理器 → 持久形象列表 → 渲染注册表 → 插槽」。旧配置保留原字段；新增包来源、作者、许可、双展示素材、图片状态差分、Live2D 动作与构图参数。内置、图片、图集、Live2D 和扩展渲染器共用注册表。

## 实现

- `src/shared/assistant-avatar.ts`：资源与身份契约分离、兼容归一化、共享严格校验、选中角色与展示素材解析。
- `src/shared/assistant-avatar-adapters.ts`：CodingNS、Codex v1/v2、DSH Live2D、Cubism 2/3 适配器、相对地址解析及原生清单导出。
- `src/client/avatar/manager.ts`：稳定快照、多个订阅者、串行写入、最新 revision、只读检查、导入取消、增删改选和展示设置。
- `src/client/avatar/registration.ts`、`registry.ts`：服务实例隔离、内置保护、稳定注册快照、幂等注销。
- `settings-panel.ts`：所有操作通过管理器；新增「导入形象包」，动态格式列表、角色来源与许可；选择仍使用同一「当前形象」列表。
- `slot.ts`、`image.ts`、`live2d.ts`：按 floating/dialog 选择包内素材，图片状态差分、Live2D 明确动作映射和缩放/位置；等值设置对象不重新加载模型。
- `src/host/settings.ts`：保留新包字段；RPC 沿用共享严格校验，非法嵌套资源不能绕过写入策略。
- Client/Shared 入口：公开适配器注册、管理器、包类型和清单导出。

每个变更只写 `assistant.appearance`。更新包保持当前选择，删除其他包不切换，删除当前包才回落内置。网络、解析、取消或保存拒绝均不报告成功。适配器注销不删除已导入数据；渲染器不可用由既有错误边界回落。
