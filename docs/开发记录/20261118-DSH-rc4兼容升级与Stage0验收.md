## Implemented candidate

The translation classifier now treats an explicit `CONTENT_REFUSED` failure
as nonretryable before matching arbitrary provider explanation text. It
recognizes both the native error's `failure.code` and a direct `code`.
Caller cancellation still takes precedence. Existing malformed failures are
not renamed.

Added refusal, route/version, Webhook deduplication and terminal-state tests;
an opt-in Stage0 native Messages fixture and verifier; and an actual CLI
lifecycle verifier using deterministic loopback model responses. No paid
model inference is required for these protocol checks.

The existing Stage0 verifier now compares canonical patch paths, accepting
macOS `/tmp` and `/private/tmp` aliases without weakening profile ownership.

Normal Codex turns now subscribe to the existing RPC process-exit listener
before `turn/start` and dispose it with the notification and abort listeners.
An unfinished turn receives `finish: error` with the existing `PROVIDER_ERROR`
code, including when partial output preceded process death. Earlier cancellation
or provider completion retains its terminal reason. The existing empty-response
presentation and structured provider error codes are preserved.

The Grok and Claude real-runtime fixtures now install `TokenMeter` through the
Cordis plugin lifecycle and await its readiness. Claude also awaits projection
installation and asynchronous cleanup. There is no upstream field rename and
no alternative capability route to add.

The rc.4 launcher change is only in the isolated candidate. No Desktop
profile, process, GUI or installation was operated.

## Root causes and differential evidence

### Codex normal-turn abnormal exit

Reproduction is preserved in `scripts/verify-cli-rc4-lifecycle.mjs`. After
six successful real-Codex cases, the model fixture holds a request open and
kills the owned CLI. No error terminal arrives. The 45-second acceptance
deadline aborts the input signal; the driver then yields `finish: cancel`.
That is not a passing abnormal-exit result.

Source inspection found that the ordinary turn path in
`src/host/cli-adapters/codex-driver.ts` waits on its notification queue and
the caller's abort signal but did not attach the existing
`JsonRpcProcess.addExitListener`; the compaction wait already used it.
The unmodified pre-upgrade source at `9dd603ab868f528cda4a2587e3d625d1ebc5da14`
was extracted to `/private/tmp/codingns-rc3-baseline-20261118`. Running the same
real-subprocess regression against that source reproduced waits until the
3-second cancellation deadline for both empty and partial responses. The startup
exit rejected instead of producing the requested driver terminal. The corrected
source passes all five cases without deadline cancellation.

This is a **verified pre-existing plugin defect**, not an rc.4 regression.
The driver regression does not invoke DSH or a model service. Independently,
the fixed rc.3-to-rc.4 upstream production diff does not touch this plugin-owned
driver or its process transport. No new process-exit error taxonomy was invented:
`PROVIDER_ERROR` is the existing projector fallback for abnormal provider failure.

### Existing real-runtime projection fixtures

The original component run had two failures. Both were reproduced with the
unmodified fixture source and the **rc.3** native runtime:

1. `tests/session-performance.spec.ts:357` reads
   `view.tokenUsage.outputTokens`, but the test-created registry has no
   `tokenUsage` view.
2. The Claude fixture calls asynchronous
   `createSessionPerformanceAdapter(ctx).install(...)` without awaiting it,
   then invokes the Promise as `remove()` at line 417. This cleanup failure
   can mask an earlier assertion or initialization failure.

Both runtimes define the projection key as `tokenUsage` and register it in
`TokenMeter[Service.init]`. Direct construction bypassed this async lifecycle.
`ctx.plugin(TokenMeter)` followed by `await meter.await()` installs the actual
native projections. The corrected suite passes 14/14 on rc.3 and rc.4 with
unchanged usage and replay assertions. Claude's original missing `await` also
masked this initialization error; both are fixed.

The actual Claude CLI throws immediately when its process dies. Production
`feature.ts` converts that rejection through `CodingNsDshMessageProjector.fail`.
The CLI verifier now exercises that same boundary and requires one native
error finish with `PROVIDER_ERROR` in under five seconds. Codex additionally
must emit its own driver error finish; cancellation is never accepted as an
abnormal-exit pass. Each CLI runs even if an earlier scenario fails.

### Harness issues resolved before the final Stage0 run

Earlier logs are retained: canonical patch-path ownership initially rejected
the `/tmp` alias; the model fixture initially omitted discovery metadata;
its context window/output budget initially prevented a model switch.
These were fixture/setup problems, corrected without changing the intended
terminal/billing/history assertions. The final Stage0 run passed.
The first CLI harness also used the wrong binding-event name; it was fixed
to the existing `session-binding` contract before the measured CLI run.

The first full repository run found four additional fixture failures:

- Two model-selection tests still invoked the removed `selectionFor` API.
  Both rc.3 and rc.4 already use `AgentModel` and `installModelSelection`.
  The fixture now initializes the real AgentLoop projection and prompt-variable
  registration, tests native image admission through the plugin's session RPC,
  and retains checks for model-switch notices, the native fallback, disabled
  adapters and unchanged global defaults. Existing legacy accessor tests remain.
- The launcher test hardcoded rc.3. It now checks the version contract while
  retaining the persistent Home/state-path assertions.
- The Webhook deletion fixture used November 10 finished records with the
  wall clock at November 18, so the independent seven-day retention policy
  correctly removed them. This fixture now injects its existing November 10
  clock. The separate retention-period test still verifies expiry.

The original full-run failures are preserved. These fixes change fixture
setup and expectations for existing API contracts; production Webhook retention
and model-selection behavior are unchanged.
