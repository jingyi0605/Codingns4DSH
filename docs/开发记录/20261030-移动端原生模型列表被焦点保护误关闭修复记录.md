# 移动端原生模型列表被焦点保护误关闭修复记录

Date: 2026-10-30

## 现象

移动端（含 iPhone 窄屏 WebView）在 DSH 原生会话中点按 Composer 的模型按钮，根菜单能正常弹出；再点「模型」行时弹窗直接关闭，模型列表没有出现。

## 根因

问题不在 DSH 的菜单交互，也不在模型目录加载，而在本仓库自己的触摸键盘保护：

1. DSH 的 `ModelSelect` 在从根菜单进入模型面板时会主动把焦点交给搜索框（`searchRef.current?.focus()`），并给整个选择器挂 `onBlur`，一旦焦点离开就 `close()`。
2. `src/client/touch-input-focus.ts` 的保护逻辑会拦截所有“非用户直接点按”的输入聚焦，并在 `focusin` 时把已经聚焦的输入框 `blur()` 掉，目的是拦住会话恢复、弹窗自动聚焦这类自动唤起键盘的行为。
3. 于是 DSH 的程序化聚焦被立刻撤销，`onBlur` 触发，菜单被 DSH 自己关闭。

实测证据（Chrome for Testing，iPhone 13 视口，直连 stage0 产物）：

- 事件顺序为 `click`（模型行）→ `focusout`（触发器，relatedTarget=搜索框）→ `focusin`（搜索框）→ 本插件 `focusout` 搜索框 → 菜单节点被移除。
- 把 `HTMLInputElement.prototype.blur` 置空后，菜单保持打开并渲染 35 个模型选项；把 `focus` 置空同样保持打开。两者都指向“本插件收走搜索框焦点”这一条路径。

## 变更内容

`src/client/touch-input-focus.ts`

- 新增 `POPUP_SURFACE_SELECTOR` / `POPUP_ITEM_SELECTOR` 与 `inPopupSurface()`。
- `inPopupSurface()` 只承认真正承载可选项、且自身不在可点按控件内部的弹层（`menu` / `listbox` / `dialog` / `group` / `aria-modal`），要求容器内存在 `menuitem` / `menuitemradio` / `menuitemcheckbox` / `option`。
- 三个收口点全部跳过豁免区：原型 `focus` 包装、`focusin` 同步失焦、迟到微任务里的二次失焦，以及 `blurActiveInput()`。

这样弹层内部由宿主应用自己发起的焦点导航（模型列表搜索框、对话框首个输入项）得以保留，而弹层之外的自动聚焦仍然照旧被拦下。

## 已排除的方案

先前一版改动在 `src/client/native-model-translation-menu.ts` 里加了移动端 `mousedown` 阻止与 `pointerup` 合成 `click`，并配了两条用例。该方案针对的是“WebKit 不派发 click”的假设，与本次实测的事件链不符；而且 `pointerup` 合成点击会让滚动手势误选模型。已回退，相关用例一并删除。
