# 兼容形象包目录与页面入口实现记录

## 需求与选择

用户要求联网收集兼容形象包，在本仓库保存并通过 GitHub 浏览，助理形象页面提供链接；列表包含序号、名称、仓库地址、作者、简介、备注。用户在原生问题面板选择「目录与安装链接」，因此保存目录、元数据和可安装 JSON 清单，素材由安装器从上游下载。

## 实现

- `avatar-packages/catalog.json` 保存 12 个条目的完整索引、固定上游提交、许可地址和下载核验结果。
- `avatar-packages/manifests/` 保存 12 份 CodingNS 原生清单，补充素材作者、许可说明和详情链接。仅引用固定提交中的模型或图集，不复制素材或第三方插件脚本。
- [兼容形象包目录](../../assets/assistant-avatar-catalog.md) 提供用户指定的六列列表，每行包含统一安装清单、上游原始清单及素材许可。按用户后续要求使用固定正式文件名，存放在 `assets/`，不再使用带日期的调查报告路径。
- `assets/assistant-avatar-catalog.md` 不受调查报告忽略规则影响；已移除旧路径的 `.gitignore` 例外，恢复调查记录原有忽略策略。
- 助理形象共用表单新增「浏览兼容形象包（GitHub）」入口，设置页与对话窗口同时可见。只读状态也可浏览，不触发设置写入、注册或下载。
- 新配置仍仅内置机器人；目录与清单不在 npm 的文件白名单中。安装成功后才进入可切换的形象列表。

首批包括大肥鱼 Live2D、大肥鱼精灵图、娜斯佳、小满、Scout 水彩柯基、布布编程熊，以及 Live2D 官方 Haru、Hiyori Momose、Mao Niziiro、Mark-kun、Rice Glassfield、Wankoromochi。

## 上游与许可核验

读取四个上游仓库的实际清单、素材许可与权利说明，并核对 Live2D 官方角色条件。没有将插件代码的 MIT 许可标为角色素材许可，也没有把仓库维护者统一写成素材作者；Scout 和布布分别记录真实贡献者。

官方样例采用 Live2D 素材协议及个别角色条件；Hiyori 不可修改设计，Mark 须保留卡通性质，Wankoromochi 须尊重年糕主题。素材再分发和运行库许可另有边界，目录只链接上游。三只原创动物与大肥鱼 Live2D 是 CC BY-NC-SA 4.0，娜斯佳是 CC BY-NC 4.0；大肥鱼精灵图仅对作者有权授权的新增贡献提供自定义许可，底层参考作品的权利说明原样保留。未逐项明确许可的 Codpet 集合未列入首批安装清单。
