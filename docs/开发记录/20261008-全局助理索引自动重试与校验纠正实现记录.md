# 全局助理索引自动重试与校验纠正实现记录

## 核心判断

值得增加有限自动重试。附件中的失败是模型引用丢失 Markdown（文本标记格式）导致的证据校验失败，并非读取材料失败或索引超时。重新调用同样的请求没有反馈，会反复产生同样的错误；放宽证据校验则会把改写内容当成原文。正确处理是保留严格校验，把错误位置和有限原文反馈给模型，同时限制费用和等待时间。

## 错误证据

- 用户提供的 `assistant-debug-2026-10-08T00-19-28-081Z.json` 包含三个会话，材料均成功读取，两个索引成功，一个失败。
- 失败会话的模型调用约 3.32 秒结束，错误是引用不在来源原文中。失败字段为 `$.sessions[0].progress[2].evidence[0].quote`。
- 来源含 `**问题从未真正渲染给你看**`，模型引用跨过这段文字时省略了内部的结束标记 `**`，严格连续子串校验因此拒绝。补回这两个星号后，附件中的全部结构与证据均可通过校验。
- 快照距离该批次结束约 28 分钟，只有一次索引记录；原来的同版本失败缓存禁止后台再次调用，手动执行索引才能重试。

## 数据与复杂度

- 会话执行状态、索引任务状态和单次模型尝试分别记录。等待重试时任务仍在运行，成功后才推进当前来源的索引版本。
- 沿用逐会话任务及模型、提示词、格式、实际材料的指纹缓存。失败缓存同时比较来源版本，后台新批次与面板刷新不会重置已用完的预算；来源版本、模型或索引提示词变化允许新任务，手动执行索引开启新的有限尝试。
- 单独的重试策略根据结构化错误码与 HTTP（网络请求协议）状态判断，不匹配可编辑错误正文；取消与缓存规则仍由原有任务生命周期管理。
- 缓存仅存在当前 Host 服务内存中，服务释放后不保留调用预算；本次不增加磁盘状态或新配置项。

## 重试策略

每个会话任务最多 **3 次尝试，即首次调用加 2 次自动重试**。成功会话继续复用，不随其他失败会话重复调用。

| 失败类型 | 处理 |
| --- | --- |
| JSON（结构化文本）格式、字段或证据校验失败 | 立即在新尝试中附校验位置、原因；证据错误额外附至多 240 字符的脱敏原文片段，重新生成完整 JSON |
| 原生限流、服务器故障、超时、传输故障、空回复；HTTP 408、429、5xx | 两次等待基准为 5 秒、20 秒，各带 ±20% 抖动；如提供 `providerRetryAfterMs`，至少等待服务端要求的时长 |
| 认证、余额或配额、参数、上下文长度、主动取消；其他明确 4xx | 直接失败或停止，不自动重试 |
| 不带可识别错误码的未知异常 | 保留失败，不猜测可重试性 |
| 服务端要求等待超过 60 秒 | 保留失败供手动处理，不提前请求或长期占据队列 |

原生 `finish`（结束事件）的错误码、状态码和服务端等待时间现在通过适配器保留。原生流式调用直接抛出的结构化异常也能分类；普通文字和语音聊天没有因此新增自动重试。

## 生命周期与展示

1. 并发上限仍为两个任务。每次尝试独立设置九十秒期限与取消信号；超时只终止该次尝试，达到上限后明确标为索引失败。
2. 用户停止、会话进入新轮次或受管范围变化会终止旧任务。等待可以取消，每次重新调用前再次核对范围和会话空闲证明。
3. 每次尝试结束关闭自己的取消信号，迟到的正文和结果不能污染后续尝试。
4. 调试页当前索引与索引记录显示已用尝试次数、总上限、下次重试预计时间及最近错误。复用缓存时明确标为前次调用次数，不把旧用量冒充新调用。最终失败保留最后一次未经校验的模型输出，供调试查看，不进入有效索引或问答上下文。
5. `attempt`、`maxAttempts`、`nextRetryAt` 均为可选契约字段，旧快照与旧记录仍可展示。重试等待不冒充成功，也不改变原始会话材料。

## 验证

- 九个相关测试文件，**110/110** 源码回归通过，覆盖证据纠正、三次上限、同版本失败缓存、手动及新版本尝试、网络故障、服务端退避、超时、停止、来源变化、迟到片段、调试页与记录展示。
- 直接读取用户附件，在内存中回放原失败输出，再返回只补齐星号的正确引用：失败会话第二次通过，另外两个会话各调用一次，最终三个结果全部完成。此回放使用假适配器，不代表真实模型一定能在第二次纠正成功。
- `pnpm run typecheck`、本次前端国际化检查及本次变更的空白检查通过，中英文词典各 1508 个键。
- 只在内存加载源码运行测试。没有执行构建、启停服务或真实模型调用，没有操作 dsh-web、Desktop 或实际 Profile；运行端加载新版代码后的实际模型与页面验收仍需完成。
