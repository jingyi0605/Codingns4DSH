# 全局助理简短回复与重点提示词调整记录

日期：2026-10-07

## 问题与调整

用户询问需要处理的会话时，助理把记录中的待办、多个附加建议、排查背景和通用状态说明塞进同一段，难以听出重点。原提示词仅要求“一到四个短句”，未限定总长度，也没有明确筛选用户需要介入的事项。

默认对话提示词改为一到两个短句、100字以内，每句一个重点；先给结论，再说必要的处理动作。用户明确要求全部事项、细节或证据时才展开。

Host（宿主）在事实材料后追加回复规则，避免旧前置提示词和历史长回复继续影响本轮表达。询问用户需要处理的事项时，优先考虑审批、回答、确认及需要用户介入的阻碍；不把助理可自行处理的普通待办或模型建议全部报成用户必须处理的任务。只保留定位所需的简短项目/会话名、当前问题和一个动作，不主动讲背景、其他会话或支线建议。未知状态和证据不足仍限制结论，只有影响当前回答时才简短说明。

依据用户截图，期望的简短表达示例：

> 优先查看 TEST 的计算题测试会话，记录里有权限错误。建议检查权限配置后重测。

## 兼容与范围

`readAssistantPrompts` 读取已保存设置时，仅升级完整匹配的旧默认对话文本，不修改原配置对象；真正自定义的对话提示词保留。调试编辑器和 Host 都使用该读取器，因此旧默认配置也能应用新要求。

索引提示词、结构化格式和结果缓存不因回复表达变化而失效。文字聊天仍保留2048 token输出预算，用户追问时可完整展开。100字是 LLM（大语言模型）的生成要求，不通过本地裁剪截断句子或隐藏输出；本次未对真实模型生成长度作硬性保证。
