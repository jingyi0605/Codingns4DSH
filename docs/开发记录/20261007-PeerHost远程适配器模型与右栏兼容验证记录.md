## 验证时发现的外部模型缓存问题

品味评分：🔴 旧缓存遗漏了 Host 身份。`model-catalog-cache.ts` 只按页面 RPC（远程过程调用）实例和适配器名缓存，而 PeerHost 页面中各个 Host 使用同一个 RPC 实例。

实际内存复现：

```text
先加载本机 Codex → 返回 local 目录
再加载 Stage0 Codex → 仍返回 local 目录
实际 RPC 调用只有一次，目标为 local
```

这属于既有缓存缺陷，与原生 DSH 全局目录是两套状态。即使 PeerHost 路由已经正确，外部模型目录也可能不发请求，直接命中另一个 Host 的缓存。

### 改进方向与实现

在 [model-catalog-cache.ts](../../src/client/model-catalog-cache.ts) 中引入由虚拟会话 ID 解析得到的稳定 Host 缓存身份：

- 缓存维度为 `RPC 实例 + Host + adapterId`。
- 成功目录、在途请求合并、缓存时间与供应商复检节流使用相同的 Host 身份。
- 同 Host 的不同会话继续共享模型目录，保留已有有效期与回退目录重试行为。
- 指定会话的失效操作只影响对应 Host；旧调用省略会话参数时保留全 RPC 失效语义。
- 本机普通会话保持原 RPC 缓存键，兼容既有调用。

在 [cli-slots.ts](../../src/client/cli-slots.ts) 中统一携带当前 `sessionId` 读取、复检和失效缓存。模型控件内部的目录状态也绑定当前会话，组件复用时不会短暂显示上一会话的目录。委派目录原本已传入 `sessionId`，通过统一加载函数自动获得 Host 隔离。

没有改动适配器选择与模型配置的持久化协议，也没有修改右栏开关、导航选择、终端保活、文件或 Git 处理器。
