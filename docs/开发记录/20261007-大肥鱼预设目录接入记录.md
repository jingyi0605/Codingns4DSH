# 20261007-大肥鱼预设目录接入记录

## 问题与判断

用户截图中「当前形象」只有机器人。上一轮已完成包导入和管理接口，但没有登记大肥鱼预设；仅在文档列出清单地址不能让形象出现在下拉框。

值得修复。可选目录属于源码数据，用户保存的清单属于设置数据，应合并展示并保留各自的所有权。直接往默认持久清单塞两套模型会挤占旧容量，也无法让已经保存的旧配置自动发现新预设。

## 实现

新增 `src/shared/assistant-avatar-presets.ts`，保存经适配器转换并核验的统一模型数据；只保存素材引用和元数据，不复制美术文件。

| 下拉名称 | 稳定 ID | 适配器 | 素材 |
| --- | --- | --- | --- |
| 大肥鱼 · Q版全身 | `codingns-preset-whale-sprite` | `codex-pet` | Codex v2 图集 |
| 大肥鱼 · Live2D 桌前 | `codingns-preset-whale-live2d` | `dsh-live2d-pet` | Cubism 3 桌前模型 |

预设 ID 与上游导入 ID 不同，既有 `deepseek-whale-v2`、`ds-whale-girl` 自定义项继续保留。管理器 `list()` 合并目录，保持稳定引用；`getSnapshot().models` 仍为实际持久清单。原 20 项容量不变。

Shared 读取、严格校验与选择器统一识别预设 ID。选择由原 `select()`、权限和 revision 检查持久保存，Host schema 回读不会丢失选择；悬浮与对话都通过原插槽解析同一角色，无需在展示组件中添加大肥鱼分支。

预设不能覆盖、更新、删除或写进自定义清单，界面也不显示其删除按钮。默认仍为机器人；显示列表、读取或保存选择不获取远程清单，选中且展示时才由渲染器加载素材。来源固定提交，作者、许可摘要与原始声明链接一并展示。
