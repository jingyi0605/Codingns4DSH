# 移动端右栏仅手动呼出修复记录

## 问题与机制

移动端新建或切换会话后，右侧面板仍会自动弹出。右栏存在两条独立的恢复链路：

1. DSH 的右栏布局按会话持久化。`mounted`（当前显示会话的通知）在 React 渲染和会话 Store（状态存储）接管前发布，通知到达时不一定能读到目标会话的展开状态。
2. `src/client/git-management.ts` 的 `GitWorkspaceRecovery` 异步读取工作区和会话归属，再调用 `openTabIn(sessionId, GIT_KIND)` 恢复标签。DSH 的内容打开动作会同时展开右栏，因此新会话也会被工作区已有的 Git 标签恢复任务拉开。

旧实现只在通知到达后立即收起，并在 0、60、240 毫秒重试；一次收起成功就取消余下重试。工作区读取晚于 240 毫秒，或第一次收起后再次恢复标签，都会绕过这段逻辑。单纯延长超时不能解决问题。

## 实现

- 新增 `src/client/mobile-rightbar-visibility.ts`，统一管理当前移动会话的手动显示许可。默认关闭，新建、切换会话及重新进入移动触摸视口都撤销旧许可。
- 原生展开按钮的真实点击、有效的右栏呼出手势，以及宿主 `aria-keyshortcuts`（无障碍快捷键属性）声明的右栏快捷键可以授予许可。手势在调用宿主开关前发送通知；合成按钮点击不授予许可。
- 手动入口未实际提交展开动作时，微任务内撤销许可；关闭右栏后也撤销许可，避免后台恢复再次打开。
- 使用 MutationObserver（DOM 变更观察器）持续跟踪右栏提交，不再依赖定时重试窗口。未获得许可的展开通过原生 `toggleExpanded()` 收起；通知不可用时，以可见 SessionView（会话视图）的标识变化作为补充。
- 未获许可时通过插件自有 CSS（层叠样式表）隐藏右栏面板，阻止异步收起前闪现。宿主继续管理标签、列宽与实际展开状态。
- 修复普通鼠标会话点击提前返回导致未收起的问题；已被屏蔽的 iOS 延迟 click 不会撤销随后手动呼出的许可。
- 退出移动视口或销毁控制器时，移除观察器、订阅、事件监听、样式及自有属性。桌面视口保持宿主原有行为。
