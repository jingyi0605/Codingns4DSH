# Global Assistant Extraction: Local Acceptance Update (2026-10-30)

## Scope

This record updates Spec019 after the donor ownership cut, source purge, startup-safe cleanup, and standalone package verification. It does not authorize or claim Desktop operation, real-profile migration, publication, commit, or release.

## Donor cleanup and compatibility boundary

- Assistant Host/Client registration, feature implementations, assistant-owned RPC/settings/asset wiring, and assistant-only assets/tests have been removed from `dsh-codingns`.
- `cleanupLegacyAssistantSettings()` removes only the obsolete `assistant` settings object and `modules.globalVoiceAssistant` when the settings document is writable. It is idempotent, retries after skipped attempts when the provider emits a document update, contains ordinary provider errors, and does not delete conversations, voice models, avatar packages, or other user data. A throwing optional event-subscription API is now contained, and listener disposal errors do not escape Host startup/unload.
- The orphaned `src/shared/contracts/assistant.ts` contract was removed. The small native LLM catalog/model/message types still used by session translation and Git commit generation now live in `src/shared/contracts/llm-chat.ts`; the reused Host adapter is named `llm-text-adapter.ts` and no longer contains assistant-index-only options.
- The donor isolation verifier now rejects the deleted contract and adapter paths/names in active source surfaces, and `tsconfig.json` no longer excludes deleted assistant/avatar/voice/desktop paths. Remaining assistant-related identifiers are limited to stale-setting cleanup/tests/verifier assertions, generic DSH message/attachment semantics, and legacy `codingns-assistant-` session compatibility filters. The reusable control-icon adapter was also renamed to neutral UI terminology. These are not registered assistant runtime modules; the legacy filters remain to avoid reclassifying historical sessions.

## Source-level workflow test expansion

The parity audit found that the donor purge removed 101 assistant tests, while the first standalone suite covered only a subset. Three new standalone test groups add 39 checks without touching Desktop or real user data:

- `tests/voice-agent-service.spec.ts`: 21 contract tests for action registration, validation, dispatch settlement, result correlation, timeout cleanup, and idempotent resolution.
- `tests/assistant-dispatch.spec.ts` and `tests/assistant-scope.spec.ts`: 10 checks for queue/steer behavior, idempotency, validation, managed workspaces, archive handling, and scope rejection.
- `tests/assistant-notification-source.spec.ts` and `tests/assistant-notification-events.spec.ts`: 8 checks for epoch/revision baselines, gaps, leases, deduplication, event-derived pending state, and Host isolation.

These tests increase the standalone suite from 132 to 171 passing tests. They improve source-contract confidence but do not substitute for live accepted-workflow parity.
