# 远程工作区模型目录缓存刷新修复记录

## 问题

远程工作区新建会话时，DSH 模型选择器继续显示本地 Host 首次加载的模型目录。远端 Host 上的 DeepSeek API、自定义提供商模型虽然能由 `session/modelCatalog` 返回，但不会进入已缓存的选择器。

## 根因

DSH `modelDirectories.catalog` 是 Host generation 级全局缓存。PeerHost 只切换了原生请求的路由作用域，没有触发 DSH 自己的 `connection/reset`、适配器更新或设置更新事件，因此目录一直复用本地结果。

## 修复

- 在 PeerHost Transport 中记录当前远程 Host、工作区和 generation 作用域。
- 远程工作区首次进入、远程工作区切换以及切回本地工作区时，运行时探测 `modelDirectories.catalog` 并调用 `resetGeneration()`；旧版本只有 `refresh()` 时使用后者。
- 目录刷新在作用域真正变化时才执行，避免同一工作区的每个原生请求重复刷新。
- 保留 `session/modelCatalog` 的无参数请求路由，刷新发起的目录请求会使用当前作用域发送到目标 Host。

## 验证

- `pnpm run typecheck`
- `node --test tests/peer-host-native-connector.spec.ts tests/peer-host-desktop-transport.spec.ts tests/peer-host-native-protocol.spec.ts`

新增回归测试覆盖：进入远程工作区清除本地目录、同一作用域不重复刷新、切回本地重新加载本地目录。
