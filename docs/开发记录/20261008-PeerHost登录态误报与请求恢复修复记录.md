# PeerHost 登录态误报与请求恢复修复记录

## 问题与证据

用户反馈远程工作区调试页持续提示“目标 Host 登录态已失效”，但目标正常登录。

源码中有两条可复现的误报路径：

1. 旧版目标 LAN（局域网）入口没有把 `debug/*` 加入 Bearer（持有者票据）白名单。有效票据被忽略，转入浏览器 Cookie 校验并返回 HTTP 401；其它已支持接口仍可正常访问。
2. HTTP 代理遇到任意 401 都调用 `invalidate()`，随后无条件返回登录失效。该函数即便静默重登成功，原请求也没有重试，页面仍然收到错误。

会话层还把续期和重登中的网络失败吞掉，最后统一返回需要登录，进一步扩大了误报。

以上由源码与测试夹具确认，未读取或操作用户的实际目标 Host，未把生产现场原因当作已验证事实。

## 修改

- HTTP 业务接口出现 401 时，使用同一票据请求固定只读 `host/status` RPC（远程过程调用）。仅在该接口也返回 401 时认定票据被拒；正常信封说明票据仍有效，返回 `PEER_HOST_PROXY_ACCESS_DENIED`，提示检查目标插件版本和接口权限。
- 状态检查有 5 秒超时、不跟随重定向，普通登录网页即使返回 HTTP 200 也不算认证成功。检查失败保留凭据。
- 票据被拒后先续期；刷新票据被拒且保存过账号密码时静默重登。成功后原方法、正文与作用域保持不变，使用新票据重试一次。网络失败不重放业务请求。
- 同一目标的并发续期只执行一次；迟到的旧票据请求复用已经恢复的新票据。
- 网络、限流和响应错误不再被统一包装成登录失效，已保存凭据保持可重试；确实拒绝账号时仍清理凭据。
- 仅缓存状态为 `session_required`、凭据仍有效的目标可以自动恢复，无需先手动重新握手。

改动落在 HTTP 代理、会话协调器、稳定错误契约和诊断文案；现有路由白名单、目标身份检查和凭据隔离继续生效。

## 生效边界

本次仅修改仓库源码、测试及文档，使用源码加载器免构建测试，未构建、安装、发布或重启任何服务，也未操作 Desktop 或 dsh-web。

当前 Host 加载修复后可以消除这两条误报路径。如果目标旧插件本身没有放行调试接口，当前修复会准确显示接口拒绝；要使用该功能，目标仍需加载支持此接口的插件。客户端版本较高仅允许握手，不会让旧目标凭空拥有新增接口。
