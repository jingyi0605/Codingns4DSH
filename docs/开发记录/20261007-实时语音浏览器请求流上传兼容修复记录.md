# 实时语音浏览器请求流上传兼容修复记录

## 问题与判断

真机点击开始实时对话时抛出 `ReadableStream uploading is not supported`。原客户端把永不结束的 `ReadableStream` 作为 `fetch` POST 正文，并等待同一请求的响应后才启动麦克风。

这不仅依赖浏览器实现请求流上传，还假设请求能同时提供响应。浏览器的 `duplex: half` 要求请求正文发送完才向客户端交付响应，因此即使支持上传流，也可能在开始录音前一直等待。官方依据：[Chrome 请求流上传说明](https://developer.chrome.com/docs/capabilities/web-apis/fetch-streaming-requests)、[MDN Request.duplex 兼容性说明](https://developer.mozilla.org/en-US/docs/Web/API/Request/duplex)。

随后真机出现「语音流连接失败（HTTP 400）」。上一轮测试直接调用语音处理器，漏掉了 DSH 原生 HTTP 桥的请求转换：GET 与 POST 共用 `requestBody: streaming` 时，桥会无条件将 `Readable.toWeb(req)` 作为请求正文传给 `new Request()`。Node 拒绝 GET/HEAD 正文，语音处理器尚未执行；DSH WebServer 捕获该异常并返回空正文 HTTP 400。该行为已对照当前安装的 DSH 0.2.1-alpha.1 发布包，并用实际桥代码复现。

## 实现

- `src/client/voice-stream-uploader.ts`：每 60 ms 合并采集小帧，以普通 `Uint8Array` POST 上传；请求顺序执行，待发送音频最多 128 KiB，单次请求超时 5 秒。失败会关闭队列并报告，不做自动重试或语音转写回退；HTTP 错误保留 Host 结构化错误详情。
- `src/client/sherpa-voice-adapter.ts`：租约启动后打开独立 `/events` GET 事件连接，再开始收音。epoch 取 Host 返回值，打断只发送一次 RPC，采集回调使用当前代次。事件读取不等待动作或播报，断线后停止采集并释放租约；关闭窗口时等待尚未返回的租约请求结算后释放。
- `src/host/features/assistant-voice-stream.ts`：`registerAssistantVoiceStreamRoutes` 独立登记 buffered GET `/events` 和 streaming POST `/stream`，避免原生桥给 GET 附加正文；buffered 不影响响应持续下发。`?mode=frames` 接收有限 PCM POST，Host 沿用同一识别流，校验批次完整性、大小、owner 和 epoch。事件连接立即发送状态，重复状态不回声，静音期间发送保活空行，取消和停止时释放订阅。
- `src/host/index.ts`：调用统一的语音路由登记函数，沿用现有鉴权和请求路由。
- `src/shared/voice-stream.ts`：统一上传和事件路由常量，新增有限批次结束时的完整性检查。
- `src/client/features/global-voice-assistant.ts`：错误状态中的 active 按真实租约来源设置，断线清理完成后不再显示正在采集。

旧版单 POST 流路由继续保留，供未刷新的旧客户端使用。新的浏览器上传不使用请求流，不等待整句录音结束；没有接入 DSH `speechToText`。

## 验证与边界

新增测试模拟拒绝 `ReadableStream` 请求正文的浏览器，并覆盖顺序 PCM 上传、独立 partial/final 回显、打断后的 Host epoch、动作未完成时继续回显、断线清理、设备准备失败、启动尚未返回就关闭、错误 owner、过期 epoch、截断正文、超大批次、上传积压以及订阅释放。

`tests/assistant-voice-http-bridge.spec.ts` 从已安装 DSH 包读取实际 HTTP 桥，在内存为未公开导出的 bridge 补测试导出，配合原生 `HostConnectionService` 与真实语音处理器验证完整请求转换。测试先复现旧路由配置在进入处理器前抛出 GET 正文错误，再验证独立事件 GET 返回 200、PCM POST 返回 204、实时 partial 下发、错误 owner 返回 403，以及停止后事件连接结束。测试不修改依赖、不绑定端口。

测试使用 `tests/register-source-loader.mjs` 在内存加载源码；没有执行构建，没有启动或重启 Stage0，没有操作 Desktop，也没有提交或推送。本轮真机麦克风、HTTPS 反向代理和扬声器验收尚未执行，spec013 任务 5.2 保持 IN_REVIEW。
