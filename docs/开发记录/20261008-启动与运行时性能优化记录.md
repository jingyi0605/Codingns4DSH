# 启动与运行时性能优化记录

## 问题与结论

macOS Desktop 启动和运行期间出现多个本地 RPC（远程过程调用）请求长时间等待，侧栏曾显示约 16 秒延迟。代码中存在同步启动 CLI 子进程、侧栏定时触发会话历史迁移、语音原生推理占用 Host 主线程等会放大延迟的路径。

`ERR_UNEXPECTED` 和 `ERR_FAILED` 本身不足以区分进程阻塞与传输故障。本次消除已确认的代码热点，并单独处理语音路由 405 和形象运行时 503 的重复请求；没有把所有错误归因于单一故障。账户菜单的 CPU、内存指标改称“主机 CPU / 主机内存”，避免与插件自身占用混淆；延迟只计 `host/status` 请求，不再包含等待其他账户请求的时间。

## 已完成的改动

### 会话映射与持久化

- 移除侧栏每两秒查询适配器映射的定时器，改为工作区成员变化、会话导航、页面重新获得焦点时刷新；同一 RPC 实例合并并发请求。
- `cli/session/adapter-map` 直接读取内存绑定表，不枚举原生会话，不补齐祖先，不读取历史事件。
- 启动不再全量迁移旧会话。打开旧 DSH 会话时才补齐相关祖先，并按照祖先到子会话的顺序恢复多层 fork 绑定；已绑定会话跳过历史读取。
- 未绑定会话的检查结果按加载对象缓存；普通 DSH 消息不会让缓存失效，新增外部 Agent 来源证据时才重新检查。
- 相同会话更新不重复落盘，写入进行期间合并为一个最新快照；防止设置监听回送的旧快照覆盖新 Provider 会话 ID。
- 不自动导入 DSH 之外创建的 CLI 历史；原有显式历史操作入口保留兼容。

### CLI 检测与模型目录

- Host 入口让出事件循环，版本探测按优先级惰性读取；已拿到版本时不再额外执行 `dsh --version`。
- Agent 首轮安装检测延迟一秒异步执行，启动不预热全部模型目录；普通 `catalog` 请求立即读取缓存。
- 移除安装检测和模型目录的周期刷新。未安装及失败结果同样缓存，避免失败路径不断拉起 CLI。
- 插件设置的 **Agent 集成** 增加“全部重新检测”和单个 Agent“重新检测”；检测结束后同步更新已挂载的选择器、模型目录，并重建订阅读取器。
- 界面补充：全部与单个重新检测按钮统一使用宿主刷新图标；顶部按“代理列表—数量—刷新图标”排列，刷新按钮靠最右侧。保留悬停提示、无障碍名称、检测中旋转及禁用状态，并适配移动端和减少动画偏好。
- 模型目录首次使用时异步读取，后续复用；手动检测或 Provider 配置改变才失效。并发读取合并，迟到结果不能覆盖刷新后的目录。
- 首轮检测未完成时，实际委派只等待所选 Agent 的检测，避免误报“未安装”。
- Host 生产路径的同步子进程调用改为异步调用，短 CLI 命令最多并发两个，带超时、输出上限和插件停用取消；tmux 控制请求单独执行并设置三秒超时。
- 登录 Shell 的 PATH 只解析一次，手动检测时可重新解析；不再为每个候选 CLI 反复启动登录 Shell。

### 运行期间的请求与日志

- 账户状态、Git 状态、订阅查询采用上次完成后再计时的轮询方式；失败退避，隐藏页面暂停，销毁取消请求，手动刷新共享在途任务。
- 通话租约保留后台续签，但只保留一个在途心跳，并限制请求时长。
- 助理元数据请求合并，标题按版本缓存，标题读取最多并发四个，缓存最多保留 2000 项；工作区归属用映射表读取。
- Qoder 会话用量改成逐行流式解析，定期让出事件循环，不保留完整历史文本副本。
- Qoder 日志后备读取最多检查最近 64 个 run，每个日志只读末尾 256 KiB；缺少额度日志时最多执行一次 CLI 后备刷新，周期查询不重复探测。重新检测或订阅设置变化后允许重试。

### 语音与形象

- Sherpa-ONNX 原生模型加载、识别、合成转移到 Worker（工作线程）；Host 只处理控制与结果消息。
- 待识别音频最多积压两秒，控制队列最多 64 项；超时或异常释放线程；停止通话后最多保留模型 60 秒以便短期复用，随后释放线程及模型。
- 保留语音诊断事件转发与 epoch 过期事件过滤；停止失败也释放通话租约，销毁过程不产生未处理的异步异常。
- 语音控制 RPC 遇到 404/405 时回退 `/api` 并记住成功路由；普通超时不重复提交控制操作。
- Live2D 运行时失败缓存 30 秒，Host 返回 `Retry-After`；引擎安装成功立即失效缓存。新加载不受旧失败请求影响。

## Inspector 回环调试连接报错分析

用户重启后反馈 `ws://127.0.0.1:9230/ingest` 持续连接失败，并确认通过浏览器 IP 或域名访问。只读检查 Stage0 使用的 DSH `0.2.1-alpha.1` 安装包后，定位到 `@deepseek-ai/dsh-experimental-inspector`：其 `lib/client.js` 第 3229 行创建 WebSocket、第 3313 行安排重连、第 2485 行执行重试，与用户堆栈一致。

该插件把 Worker 的回环监听地址直接下发给浏览器。跨设备访问时，`127.0.0.1` 指向浏览器所在设备而非 Host；同机通过 IP 或域名访问时，未列入 `clientOrigins` 的来源会被握手校验以 403 拒绝。连接关闭后按随机指数退避继续重试，默认退避上限为 5 秒，没有失败次数上限，因此持续刷屏。现有日志无法区分现场实际发生的是连接拒绝还是握手 403。

这条连接用于 Inspector 浏览器调试，与 Agent 刷新 RPC 独立。不需要调试时可由用户停用 Inspector；仅收起面板不会停止连接。本次只分析原因，未修改插件配置、连接逻辑或运行进程。相关设计参见 [DSH Inspector 官方说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/experimental/inspector/README.zh.md)。

### Stage0 首次编译的同文件动态导入误报修复

用户启动 `dsh-stage0` 后，Client 在 `codingns4dsh:native-client-chunks` 的转换阶段报错：`动态分块没有可转换的导入表达式：bundle.js`。

根因是转换脚本将 `chunk.dynamicImports` 中的每一项都视为需要下载的独立文件。Rolldown 的动态导入元数据可能包含当前分块自身，而同文件导入已被生成为 `Promise.resolve().then(() => namespace)` 或带初始化函数的表达式，不存在相对 `require()`。既有产物中的 CLI 动态加载也能看到这种内联表达式。原检查因此要求转换一个并不存在的跨文件导入。

依据：[Rolldown 1.2.9 动态依赖收集实现](https://github.com/rolldown/rolldown/blob/v1.2.9/crates/rolldown/src/stages/generate_stage/compute_cross_chunk_links.rs) 在收集目标分块时未排除当前分块；[渲染元数据实现](https://github.com/rolldown/rolldown/blob/v1.2.9/crates/rolldown/src/utils/chunk/mod.rs) 将这些目标直接映射到 `dynamicImports` 文件名列表。

修复在统一去除 `./` 前缀后，仅将文件名不等于当前 `chunk.fileName` 的目标纳入跨文件转换校验。入口和动态叶子遵循同一规则；同文件表达式保持原样，保留异步初始化和命名空间对象身份。真实跨文件导入仍必须转换，缺失目标、非法相对导入、同步依赖循环等门禁继续生效。

同时按 [tsdown 依赖配置](https://tsdown.dev/options/dependencies) 将入口配置的 `external`、`noExternal` 迁移到 `deps.neverBundle`、`deps.alwaysBundle`，保留原依赖策略，消除这两个弃用警告。

验证结果：

- `pnpm exec tsc -p tsconfig.json --noEmit` 通过；直接导入配置并验证依赖策略通过，未调用构建 API。
- 未重新构建、启动或重启 Stage0，未操作 Desktop/dsh-web。完整首次编译及实际页面加载仍需用户重新运行验证。

### 原生源码映射桥接与 Host 类型导入修复

用户再次运行 Stage0 后，同文件动态导入检查已通过，随后暴露 `BindingHookRenderChunkOutput.map` 类型错误；Host 同时报 `SpawnSyncReturns` 未定义。

- Client：`RolldownMagicString.generateMap()` 返回原生 `BindingSourceMap`，其 `x_google_ignoreList` 访问器返回 `null`，Rolldown 1.2.9 的 JS 桥接原样透传后被原生 `BindingJsonSourcemap` 拒绝。直接调用已安装版本的源码映射桥接与合并函数，复现了 `BindingSourcemap.inner` 类型错误；只去掉空 `ignoreList` 即可通过。
- 映射序列化：原生对象的字段位于原型访问器，直接 `JSON.stringify()` 得到 `{}`。转换返回值与入口映射拼接统一通过映射自带的 `toString()` 转成标准 JSON 对象；普通对象仍使用 JSON 序列化。这样既规范可选字段，也保留源码、映射和名称表。[原生映射接口说明](https://rolldown.rs/reference/Interface.RolldownMagicString)
- Host：二进制检测逻辑移出 `rpc-driver-utils.ts` 后，文件末尾仍公开 `SpawnSyncResult` 类型别名，因此保留 `node:child_process` 的 `SpawnSyncReturns` 类型导入；仅补齐类型依赖，不改变进程执行逻辑。

新增两项源码映射回归，修复前均失败，修复后通过；相关 7 个测试文件共 63 项全部通过。另以实际 Rolldown 原生映射桥接验证修复后的返回值，确认映射与原始源码内容完整保留，未调用打包 API。最终 `pnpm exec tsc -p tsconfig.json --noEmit` 和 `git diff --check` 通过。未构建或启停 Stage0，未操作 Desktop/dsh-web；完整首次编译仍需用户运行确认。
