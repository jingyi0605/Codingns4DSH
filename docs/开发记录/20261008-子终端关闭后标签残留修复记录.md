# 子终端关闭后标签残留修复记录

日期：2026-10-08。

## 问题与根因

用户反馈子终端关闭后仍留在标签列表中，内容区显示“终端已关闭”及“Host 中不存在该终端”。

客户端原先按“关闭 Host（宿主）终端、释放模型、重新查询列表”的顺序更新标签。模型释放会等待旧输入与尺寸请求完成，网络请求挂起时无法继续刷新；关闭成功后列表查询失败，也不会从本地工作区库存移除目标。关闭按钮的异步异常没有显示到界面，重复点击还会产生重复关闭请求。

另一个顺序问题是先移除模型缓存、释放屏幕，再更新库存。释放时触发的订阅仍能读到旧标签，从而再次取得该终端的视图。选择变化通知也曾早于新库存落位。

最初新增的三项回归测试在修复前全部失败，分别复现刷新失败残留、旧输入阻塞移除、重复关闭请求。当前运行实例没有进行界面回放，因此以上是源码与回归测试确认的缺陷。

## 实现

- Host 确认关闭后，立即使相关旧列表请求失效，从工作区共享库存移除目标并修正选中项；其他会话同时看到更新。
- 先写入新库存，再通知选择变化；标签移除后才释放模型、屏幕与输出订阅。旧输入队列的异步收尾不再阻塞标签移除。
- 后续列表查询放到后台，失败只记录诊断，不撤销已经成功的关闭。
- 同工作区、同终端的并发关闭复用一个请求；关闭失败保留标签，界面显示错误并允许重试。
- 旧 Sidebar（侧栏）关闭路径复用相同收尾逻辑。Host 已不存在的终端继续使用已有的幂等关闭接口，不创建替代进程。
