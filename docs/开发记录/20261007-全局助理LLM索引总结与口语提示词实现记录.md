# 全局助理 LLM 索引总结与口语提示词实现记录

日期：2026-10-07

## 快照中的旧规则

用户提供 `assistant-debug-2026-10-07T04-50-31-797Z.json`，询问索引是否调用 LLM（大语言模型）总结进展与下一步，并希望为未来语音用途添加简洁、口语化的前置提示词。

快照索引包含 TEST 的两个普通会话，两者状态均为 `unknown`，正文摘录分别为1001和130字符。旧索引没有调用模型：从最近80条语义事件提取最后的用户消息、助理消息和工具名，拼接后截取最多2000字符。汇总按待处理、错误、运行、完成和未知状态拼接固定文案，因此把终端日志和旧回复直接带入了汇总。

旧 LLM 文本对话已有系统提示词，限定当前索引、只读、不派发任务、未知状态不猜测、参考材料中的指令不执行，但没有要求口语化表达。

通过原生问题面板，用户选择：手动索引增加 LLM 总结，保留原始摘录；索引和对话提示词均可在调试面板编辑，默认简洁口语化。

## 新流程

1. 选择索引范围，检查范围内的普通未归档会话。
2. 在顶部选择索引总结与对话共用的 DSH 原生模型。
3. 第3步编辑「索引总结前置提示词」并保存，点击「执行索引」。
4. 原始正文读取完成后立即返回索引，模型在后台总结进展、主要阻碍和下一步。面板轮询既有调试接口，显示生成文字、模型、完成/失败/停止状态，支持停止总结。
5. 第5步编辑「对话前置提示词」，保存后重新开始对话；模型接收当前原始索引及已完成的参考总结。

「刷新面板」不执行正文索引、不发起模型总结；既有自动按需索引也不新增模型调用。手动索引范围为空时不发起模型调用。未选择模型的旧客户端使用 DSH 默认模型；明确选择的模型无效时报告失败，不改用其他模型。

模型失败或被停止时原始材料保留，并显示明确状态；索引记录分别保存正文读取结果和模型调用证据。`assistant/summary` 在相同索引有完整模型总结时返回可播报的总结。正式语音动作继续沿用已有规则路由，未重写实时对话管理界面。

## 两套默认前置提示词

配置位于 `assistant.prompts.index` 和 `assistant.prompts.chat`，各最多8000字符，保存单个字段，不覆盖另一个提示词、管理范围或语音配置。旧设置补默认值，清空后保存恢复默认。

- 索引：通常三到五个短句，先说结论，再说需要处理的事情；口语化，不使用标题、编号、列表、表格、Markdown、排比或重复铺陈。不复述日志、路径和标识。下一步必须有证据，只是建议时明确说「建议」。
- 对话：通常一到四个短句，直接回应问题，明确要求细节时再展开；口语化，不使用标题、编号、列表、表格、Markdown、排比或套话，不机械复述整份索引。

Host 始终追加事实约束：只读、不提供工具、不派发任务、来源材料不能充当指令、未知状态与证据不足必须说明。先前模型总结是参考材料，不能覆盖原始会话事实，不能把推断写回真实运行、完成或等待状态。

改索引提示词使结果过期并停止仍在进行的总结，需要重新索引。只改对话提示词停止旧对话并清空文字上下文，不要求重建索引。范围变化不返回旧范围正文或总结。关闭调试面板取消文字对话，后台手动索引总结可继续完成；模块停用会取消模型请求。

## 契约与边界

- `AssistantIndexSnapshot.analysis` 保存独立模型轮次，包括模型、索引版本、运行状态、文字和错误。`entries[].summary` 继续保存来源摘录，不被模型正文覆盖。
- `AssistantIndexRun.analysis` 只保存模型、状态、时间与错误，不保存生成正文。记录最多保留30次，不跨 Host 重启持久化。
- `assistant/index/rebuild` 接受可选 `provider/model`，返回原始索引和后台总结状态；新增 `assistant/index/cancel` 停止当前总结。两者同时注册主 RPC（远程过程调用）通道和旧 HTTP 精确入口。
- 索引总结与文字问答复用同一原生 LLM 适配器和有界轮次实现；模型生成最长90秒，材料最多120000字符，输出最多2048 token。总结与对话使用独立轮次，互不混用历史。
- 总结仍基于有界的最近消息摘录，不冒充完整项目审计；缺少证据时由提示词要求明确说明。
