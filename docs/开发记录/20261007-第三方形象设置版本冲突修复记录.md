# 第三方形象设置版本冲突修复记录

## 问题与原因

用户确认第三方形象协议后，启用失败并显示 `expected revision 48, now 50`。

DSH 的 revision（配置版本号）属于整个插件设置命名空间。形象管理器从 Client 快照读取版本号并替换 `assistant.appearance`，读取之后的后台会话索引或其他窗口设置写入都会推进同一版本号。原实现只串行化本管理器的写入，无法防止其他写入方造成版本冲突；远程设置普通 `load()` 又保留缓存，因此不能用它恢复权威快照。

另一个风险是原生 ConfigForm（配置表单）适配器总是使用不带版本的 Host 写入。单字段绝对值可以直接合并，但形象清单由旧快照计算，不能省略版本校验，否则可能覆盖其他窗口新增的形象、当前选择或尺寸。

## 修复

- `src/client/avatar/manager.ts`：同一串行队列中最多尝试三次；仅遇到设置版本冲突时调用 `reload()`，基于新配置重新计算、校验本次操作，保留其他写入方的更新。
- `src/client/settings-bridge.ts` 与 `src/host/rpc.ts`：RPC（远程过程调用）两端保留 `SETTINGS_CONFLICT` 稳定错误码；兼容旧 Host 的异常类名和仅有冲突正文的响应。
- `src/dsh-capabilities/client/config-forms-adapter.ts` 与 `src/client/index.ts`：原生设置路径支持带版本写入和权威快照重读；未指定版本的模块开关维持原来的单字段合并行为。
- `src/client/features/assistant-workbench.ts`：提示词保存是单字段绝对值，省略不必要的全命名空间版本校验，避免原生适配器恢复版本校验后引入后台索引冲突。
- 持续冲突达到上限时显示中文重试提示；普通拒绝、存储错误和重读失败直接报告，不自动重试。一次失败不会阻塞后续队列。
