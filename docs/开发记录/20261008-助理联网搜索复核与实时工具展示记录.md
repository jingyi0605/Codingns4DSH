## 实时工具展示

旧实现已采集工具调用并保存到通话详情，但工具事件只修改快照，没有立即通知订阅；文字消息不显示工具，流式消息要等正文出现才渲染。实时通话页面也没有展示当前工具记录。

本次调整：

- `AssistantTextChat` 在工具开始、完成和失败时立即发布累计快照。首次工具事件记录当时累计正文的 `textOffset`（UTF-16 字符位置），同一调用按 ID 更新且位置不变；并行调用保留开始顺序，不因完成先后重排。保留最多 24 条记录及原有取消边界，结束时同步校正正文开头空白被移除造成的位置偏移。
- 聊天、实时字幕和通话历史共用 `assistantMessageTimeline` 及 `AssistantMessageContentView`，按「调用前正文 → 工具 → 后续正文」穿插显示。工具卡片显示类别、真实名称、开始时间及进行中／已完成／失败／已取消状态。参数和结果默认折叠，通过 React 文本节点转义，沿用原有有界脱敏摘要。
- 没有正文但已有工具时也渲染当前助理消息；提交后只保留同一份记录。无工具的普通回答不增加工具区块。
- 实时通话展示本轮工具；回复完成后使用当前通话已归档消息中的记录。挂断详情直接在各轮助理消息内部展示对应工具，取消最底部的集中汇总，不跨轮挪动记录。
- 工作台沿用原有生命周期 RPC（远程过程调用）刷新：活跃问答及通话约每 600 毫秒更新。语音下行仍只传累计正文，工具明细从生命周期快照读取，不随每段文字增量重复传输。因此这里的实时展示指生成过程中刷新，短于一次刷新间隔的调用可能直接显示完成状态。

工具状态变化可触发跟随滚动，但同样内容的周期刷新不重复触发。流式消息与最终消息共用消息 ID，避免完成时重新创建工具详情节点。

工具位置随文字和通话记录一起持久保存。字段可选，不修改存储版本或主动迁移文件；恢复时拒绝负数、非整数等损坏位置。旧记录没有保存正文位置，工具放在所属助理回复之前，不从结束时间推测段内顺序。截断的残句将超出正文长度的位置限制在末尾，保留工具及原有打断状态。

## 只朗读 AI 正文

展示继续使用 `toolCalls`，模型正文继续使用 `text`，两者不合并。原生 Agent 的思考块和工具参数不进入正文；ClientSherpaVoiceAdapter（客户端语音适配器）的字幕和逐句 TTS（文字转语音）队列仍只消费 `run.text`。

因此工具名、状态、参数和原始结果只显示，不进入播报；同一正文的工具状态更新也不会重读。AI 在正文中根据搜索结果生成的最终回答仍正常朗读。
