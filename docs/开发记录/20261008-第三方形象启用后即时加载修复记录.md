# 第三方形象启用后即时加载修复记录

日期：2026-10-08

## 问题与原因

助理配置窗口点击「同意并启用」后，第三方形象目录仍为空，需要保存配置并重新打开窗口。原因是 `AssistantConfigurationSession`（助理配置会话）只更新内存草稿，却依据正式设置中的协议记录决定是否发送目录请求；首次同意时直接返回空列表。Host（服务端宿主）的目录、预览和安装接口同样只认可已保存协议。

## 实现

- 目录、临时预览、预览续期和素材采用请求携带当前配置草稿中的协议记录。现有组件监听协议变化，确认后立即加载列表，无须保存或重新打开窗口。
- Host 校验本次请求的协议版本和同意时间，不提前写入正式设置；没有携带协议的旧客户端继续使用已保存记录，显式无效记录不能回退。
- 请求内的同意仅授权对应临时预览租约，图片以及 Live2D 清单和依赖均可在保存前读取；释放或超时后授权失效。旧客户端的预览继续遵守正式协议撤销。
- 删除「需先保存才能加载」提示，保留加载状态、失败重试和真实空列表提示；关闭第三方开关立即隐藏目录选项。
- 整份配置仍统一保存，取消恢复原配置；只读限制、形象素材许可确认和现有引擎许可流程保持不变。

本记录更新 `docs/开发记录/20261007-助理配置统一草稿保存与模型路由修复记录.md` 中「首次同意后先保存才能浏览」的旧行为。
