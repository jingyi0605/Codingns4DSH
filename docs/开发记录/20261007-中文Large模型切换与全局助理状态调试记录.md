## 指定模型

`src/shared/voice-models.ts` 将 Large 放在推荐目录首位，保留旧 14M 和中英双语模型 ID。新配置默认推荐 Large，已有模型选择不自动迁移。模型源和文件名已核对[官方发布目录](https://huggingface.co/csukuangfj/sherpa-onnx-streaming-zipformer-zh-int8-2025-06-30/tree/main)。

| 设置项 | 发布文件 |
| --- | --- |
| ASR encoder（编码器） | `encoder.int8.onnx` |
| ASR decoder（解码器） | `decoder.onnx` |
| ASR joiner（连接器） | `joiner.int8.onnx` |
| ASR tokens（词元表） | `tokens.txt` |

Large 的 decoder 是浮点文件，不能套用旧模型的量化文件名。仍使用现有白名单下载、SHA-256（文件摘要）缓存校验和临时文件原子替换流程。

## 全局管理调试

入口：侧栏助理图标 → 助理窗口 → **全局项目状态调试**；设置页也提供同一按钮。未配置语音模型时仍可进入调试，不申请麦克风权限或语音租约；若正在实时对话，从该窗口进入调试时先停止采集。

调试窗口提供：

- 工作区范围勾选，合并 Host（宿主）、原生客户端与远端记录，并保留已选择但暂不可用的工作区。
- 强制刷新、索引代次、纳入/排除/正文读取失败计数、当前模型和更新时间。
- 全部受管会话的标题、工作区、Host/会话 ID、运行/完成/错误/未知/等待状态、等待审批或提问、正文摘要。
- 范围外和归档会话的元数据与排除原因。
- 工作区、会话、正文摘要、任务派发、远端 Gateway（网关）接口接入标记；远端读取失败和会话归属不明的诊断。
- 完整分组汇总、可展开的原始 JSON，以及快照下载。
- 文字指令输入、意图预览和执行，直接展示结构化结果，便于联调现有管理逻辑。

`assistant/debug` 强制读取当前状态；`assistant/preview` 复用规则意图解析但不派发；执行使用已有 `assistant/turn`，保留范围、归档、索引代次和请求去重检查。当前 Stage0 `managedWorkspaceIds` 为空，用户需要在调试窗口显式勾选项目，不自动纳入全部工作区。

数据源原来提前丢弃范围外/归档会话，导致界面无法解释排除原因。现在保留元数据，由索引构建器统一过滤，正文和额外标题读取仍限定在受管未归档会话。远端归档记录无需再生成重复占位；缺失归档记录的本地占位继续保留。强制刷新只清空缓存，索引代次持续递增。

快照仅包含助理事实，不返回整个设置文档、CLI 会话配置或凭据；诊断错误使用既有脱敏函数。服务标记表示接口接入，不能据此认定远端连接健康。未知状态在会话卡片与 JSON 中保持未知，既有汇总规则不凭空猜测完成。
