# 远程工作区归档会话即时投影修复记录

## 问题

远程工作区归档会话成功后，原生会话列表没有立即隐藏对应会话，需要等待下一次 PeerHost 聚合刷新。

## 根因

远程 Host 的 `workspace/archiveSession` 会返回完整的 `archivedSessionIds` 集合。PeerHost 原生响应 ID 改写只处理了 `sessionId`、`sessionIds` 等字段，没有处理 `archivedSessionIds`，DSH Workspace Store 无法把远程会话加入本地可见的归档集合。

## 修复

- 将 `archivedSessionIds` 纳入原生 Session ID 响应改写，转换为虚拟会话 ID。
- 继续使用 DSH Workspace Store 自带的归档响应回写和订阅通知，归档成功后由 Store 在微任务中就地更新列表。
- 不调用 `sessions.refresh()`，避免列表重新加载、闪烁或整页重绘。
- 后续 PeerHost 聚合刷新仍会校验并收敛完整状态。

## 验证

- `pnpm run typecheck`
- `node --test tests/peer-host-native-protocol.spec.ts tests/peer-host-native-store-projection.spec.ts tests/peer-host-native-connector.spec.ts`

回归测试覆盖了归档集合的虚拟 ID 改写和原生 Workspace Store 投影行为。
