# Magpie 会话配额归属修复记录

日期：2026-10-24

## 背景与结论

用户反馈：订阅入口的「上游配额」显示的余额与「最近路由」对不上。路由面板写的是
`glorinfo-api-platform/gpt-6.1-sol`，配额区却显示了 `grox-claude`（甚至不是 Codex 的
提供商），余额是 `$0.00 / 1 day 0%`。

这两个现象来自 Host 侧配额归属的同一组问题，与路由面板无关：路由面板直接读 Magpie 的
请求账本，因此始终正确；配额是 Host 在账本之上再做一次归属，归属规则出错就显示成别的账号。

用本机 Magpie 数据核对（`~/.config/magpie/routing/2026-10-23.jsonl`、`quotas.json`、
`providers.json`）：

1. `grox-claude`、`grox-codex`、`grox-ds` 这三个 provider 共用同一套 mcgrox 账号，账号名
   完全相同，`/api/usage/quotas` 里也都是 `$5.26 / 1 day` 的 USD 窗口。会话只要用过其中
   任何一个，`markSessionAccounts` 就会把另外两个用同名的配额行也标成 `active`。
   折叠态入口、额度环与组头摘要都优先取 `active` 账号，于是 grox-claude 的额度被当成了
   本会话余量。
2. `filterSessionQuotas` 在「有 `providerAccount` 但没有任何一行匹配」时返回空数组，而
   `quotaStatus` 仍为 `available`。Codex 这类量贩账号（`codex`、`glorinfo-api-platform`）
   在 `/api/usage/quotas` 里没有 `user` 字段，请求记录里的 `providerAccount` 永远匹配不上，
   于是路由明明已经识别出 `glorinfo-api-platform`，配额却整块消失，界面落到
   `usage.magpieQuotaNoWindows`（「上游没有报告配额窗口」）。

结论：活动账号必须按「厂商 + 账号名」判定；上游不提供账号名时，保留该厂商自己的配额，
不再把已识别厂商的额度整块丢弃。

## 决策

1. **活动账号键改为 `provider\u0000account`。** 请求历史与 route 的 `providerAccount` 都按
   该键比对；route 的厂商取自 `providerFromRoute`（与 `upstreamProviders` 的构建方式一致），
   因此比对口径只有一处。厂商无法解析时账号保持未标记，宁可显示「未知活动账号」。
2. **上游无账号名时保留候选，而不是清空。** 只有「存在命名行但一条都不匹配」才返回空，
   保持原有的严格性：不能把别的账号的额度说成本会话的。命名行能对上时仍只留命中的账号。
3. **不改动客户端分组。** `grox-claude` 与 `grox-codex` 在 Magpie 里本来就是同一账户的两条
   不同 provider 记录，按 `provider` 分组的现有行为是正确的，本次不动。

## 变更清单

| 文件 | 变更 |
| --- | --- |
| `src/host/cli-adapters/magpie-usage.ts` | `markSessionAccounts` 用「厂商 + 账号名」判定活动账号；`filterSessionQuotas` 在无命名行时保留该厂商候选，并补写判定顺序的注释；`quotaUsedPercent` 因相邻代码被顺带挪动，内容未变 |
| `tests/magpie-usage.spec.ts` | 新增两项：无账号名的 Codex 类 provider 保留自身配额且不被误标活动；不同厂商同名账号只有被路由的那个变为活动 |

## 需要特别注意的地方

- `markSessionAccounts` 现在依赖 `providerFromRoute(route)`：若后续 route 结构把厂商从模型名
  移到独立字段，需要同步更新该函数，否则活动账号会退化为「未标记」。
- `filterSessionQuotas` 的第一条分支 `accounts.size === 0` 仍然保留全部候选，这是历史行为；
  它现在与第三条「无命名行时保留」同时存在，改动时注意两者语义不同（前者是账本没有账号维度，
  后者是配额行没有账号名）。
