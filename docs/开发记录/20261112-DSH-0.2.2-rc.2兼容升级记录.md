# DSH 0.2.2-rc.2 兼容升级记录

## 目标

将本插件的已验证 DSH 版本从 `0.2.2-rc.1` 更新为 `0.2.2-rc.2`，保留 `>=0.2.1-alpha.2` 的兼容下界，并完成 Stage0 的隔离运行时切换。

## 已完成的修改

- 将 `package.json`、`pnpm-lock.yaml`、`version.json`、`profile/version.json`、`src/shared/contracts/version.ts` 和文档中的已验证版本同步到 `0.2.2-rc.2`。
- 将 Stage0 启动脚本切换到独立 rc.2 运行时路径，保留原有 Stage0 Home、profile 和端口。
- 适配 rc.2 的 Agent Team/SubAgent 接口，保留旧 TeamService 结构的兼容路径。
- 将 Team 任务更新继续按原生 `expectedRevision` 和 `taskAction` 转发，并把 rc.2 的任务所有者名称解析为 Session ID。
- 将 rc.2 的默认中断关闭状态反映到外部 MCP、Pi 和 Command Code 的 Team schema 与 guidance。
- 转发 Web Search/Fetch 的结构化错误代码。
- 发现 rc.2 侧栏 bundle 只是压缩了已有的 `SidebarSessionView` 回调，仍会把自身释放造成的 `ready` 拒绝记录为打开失败；扩展 Host 资源兼容路由，按 rc.2 的压缩格式加入 `disposed` 守卫。
- 增加真实 rc.2 TeamService 夹具和 rc.2 SubAgent 适配回归。

## 验证

已通过：

- `pnpm run version:check`
- `pnpm run capability:check`
- `pnpm run typecheck`
- 受影响的 Team、Proxy、Capability、Web Bridge 测试
- 侧栏资源兼容测试：直接执行 rc.2 原生 bundle，覆盖原始误报、释放幂等、真实失败、成功打开和注入链路
- 真实 `@deepseek-ai/dsh-agent-team@0.2.2-rc.2` 运行时夹具

完整构建在 rc.2 依赖安装后通过；构建输出中的动态导入提示属于既有 bundler 提示，不是本次兼容失败。

## 运行时边界

DSH `0.2.2-rc.2` 的默认 Team 中断 action 不进入外部协作工具 schema。底层 SubAgent 的可信中断入口仍在适配器边界保留，便于显式启用或原生运行时操作。Team 模式仍由 DSH 按会话选择，插件不会自动开启。

上下游 UI 菜单定位 API 的变化已完成类型和源码审查。插件的 Context Menu 贡献项继续使用 DSH 管理的目标捕获和定位；插件自有浮层仍使用现有组件和局部定位逻辑，后续可单独做视觉回归。

## 范围约束

本次只操作仓库、独立 Stage0 运行时和 Stage0 配置。没有修改 Desktop profile、Desktop 插件安装、Desktop 进程或 Desktop 会话数据。
