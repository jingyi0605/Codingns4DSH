# Codex 服务档位开关供应商切换后不显示修复记录

## 问题

Codex 适配器已登录官方订阅（ChatGPT 账号）时，模型选择弹层里仍不显示「服务档位」开关，
模型与思考等级正常，只有档位行缺席。用户报告的截图时间点是 22:31。

现象具有两个特征：

1. **重启 Host 或刷新页面后恢复正常**，说明不是判定逻辑或渲染逻辑写错。
2. 用 cc-switch 之类的工具切换过 Codex 供应商之后开始出现。

## 根因

`canSelectServiceTier` 要求「目录确认官方订阅 + 当前模型声明档位」同时成立。
本机 Codex 0.160.0 的 `model/list` 对 8/8 个模型都声明了 `serviceTiers`，
所以决定因素只剩 `officialSubscription`，而它来自 `account/read`：

| 配置 | `account.type` | `officialSubscription` |
| --- | --- | --- |
| 官方订阅（`auth_mode = chatgpt`） | `chatgpt` | `true` |
| 第三方中转（`model_provider` 指向中转） | `null` | `false` |
| 纯 API key | `apiKey` | `false` |

用户在 22:31:12 切到第三方、22:31:30 切回官方（cc-switch 日志），中间 18 秒窗口内
`account/read` 返回 `null`，判定为 `false`。问题在于**这个 `false` 之后再也没有被重新计算**：

- **Host 层**：目录缓存 TTL 为 10 分钟（`DEFAULT_MODEL_CACHE_TTL_MS`），且
  `models()` 是 stale-while-revalidate——过期后第一次读取仍然先返回旧值。
- **唯一的失效入口**是安装探测指纹 `detectionFingerprint`，它只包含
  `installed / command / version / diagnostic`，与 `config.toml`、`auth.json` 无关。
  切换供应商只改写这两个文件，CLI 可执行文件没有任何变化，指纹因此不变。
- **Client 层**：`loadModelCatalog` 命中缓存即 `Promise.resolve(cached)`，
  只有 `fallback === true` 才会删除缓存。页面不刷新就永远拿不到新目录。

两层叠加的结果：只要用户在第三方配置下打开过一次 Codex 会话，之后即使切回官方订阅，
档位开关也会一直不出现，直到重启 Host 或刷新页面。

## 修复

### Host：Provider 配置指纹驱动的即时失效

- `CodingNsCliDriver` 新增可选方法 `catalogFingerprint()`（`driver.ts`）：
  同步、廉价地返回**影响目录语义**的 Provider 配置指纹。
- `CodexAppServerDriver.catalogFingerprint()` 对两个文件做摘要后哈希：
  - `config.toml`：只取顶层 `model_provider / model / service_tier / openai_base_url / profile`，
    以及 `[model_providers.*]` 段内的 `base_url`；
  - `auth.json`：只取 `auth_mode`、`OPENAI_API_KEY` 是否非空、是否有 `refresh_token`、
    `account_id`。
- 两个文件都读不到时返回 `undefined`，表示「无法判断」——Registry 不会据此失效缓存，
  避免非标准部署下目录退化成每次都重新探测。
- `Registry.models()` 在返回任何缓存值（**包括 stale 值**）之前比对指纹；
  变化时调用 `invalidateModelCache` 并等待一次全新探测。
  这一点是必须的：账号判定从「第三方」变成「官方订阅」时继续先回旧值，
  本次渲染就仍然缺少控件。
- 指纹在 `listModels()` **调用之前**捕获，与目录一起落库。若在探测返回后再读，
  探测期间发生的第二次切换会被记成「已应用」，而目录其实来自切换前的配置，
  之后比对一直命中，旧判定又被锁进缓存。

### Client：缓存 TTL、显式失效与静默自愈

- `model-catalog-cache.ts`
  - 缓存条目附带写入时间，`MODEL_CATALOG_CACHE_TTL_MS = 60_000` 后重新请求；
    命中时直接返回，不阻塞渲染。
  - 新增 `invalidateModelCatalogCache(rpc, adapterId?)` 显式失效入口。
  - 新增 `shouldRevalidateModelCatalog(rpc, adapterId, needs)`：按适配器节流
    （`MODEL_CATALOG_REVALIDATE_INTERVAL_MS = 60_000`），
    保证真实第三方接入不会在每次挂载时反复探测。
- `service-tier.ts` 新增纯函数 `needsServiceTierRevalidation(catalog)`：
  判断「目录声明了档位、却未确认官方订阅」。该状态有两种来源且界面上无法区分——
  真实第三方（应当持续不展示）与判定过期（应当重新探测）——因此它只用于决定
  「值得再探测一次」，不参与「是否展示开关」。
- `cli-slots.ts`
  - 目录处于该状态时，先作废 Client 缓存，让本次请求真正走到 Host 的指纹比对。
  - 新增轮询 effect：仍处于该状态时每 65 秒触发一次目录重读。探测很廉价——
    Host 比对指纹后配置没变就直接返回缓存，不会重启 CLI。

#### 轮询与节流的时序（实现过程中修正的缺陷）

初版把「触发重读」和「消耗节流窗口」写在了同一个轮询回调里，结果轮询先消耗掉窗口，
紧接着主 effect 的 `shouldRevalidateModelCatalog` 判定被挡下，反而不会真正作废缓存
——轮询空转，用户切回官方订阅后开关依旧不出现。

修正为职责分离：

- 轮询 effect 只负责到点 `setCatalogRetry` 触发重跑；
- 是否真正作废缓存统一由主 effect 的节流判定决定。

同时把轮询间隔设为 `MODEL_CATALOG_REVALIDATE_INTERVAL_MS + 5_000`：`setInterval`
的实际触发可能略早于标称间隔，若两者相等，到点时节流窗口可能还差几毫秒没到期，
这一轮同样会白跑。

该缺陷已由 `tests/client-cli-sessions.spec.ts` 的
「复检节流不会吞掉主流程的失效判定」用例覆盖。

### 为什么不把 `officialSubscription` 单独缓存

曾考虑给账号查询单独设短 TTL。放弃的原因：`account/read` 只是判定来源之一，
真正的语义边界是「Provider 配置是否变化」。用配置指纹表达这个边界，
既覆盖供应商切换、登录方式变化，也自然覆盖 `service_tier` 默认档位变化，
不需要为每个字段单独维护缓存策略。

Client 自愈链路（不刷新页面）：

```

③ 缓存仍为旧值 = false | 允许复检 = true
④ 复检后：officialSubscription = true → 开关 = true
```

切换为 API key 后指纹变化。

## 后续：档位行与相邻菜单行的对齐缺陷

档位开关显示出来后，用户在移动端截图反馈「样式没有与模型选择工具对齐」。
复查截图为：档位行整体比相邻两行宽，开关被推到贴住弹层右缘，「标准」二字紧贴开关，
弹层底部还多出一条横向滚动条。

### 根因

`nativeMenuCellStyle` 用在 `<button>` 上，而 DSH 的全局样式给 button 设了
`box-sizing: border-box`；`serviceTierRowStyle` 用在 `<div>` 上，没有这层默认值。
`width: 100%` 配合 `padding: 0 10px`，在 content-box 下会把左右内边距**额外**加到
宽度上，于是档位行比相邻行整整多出 20px，撑破弹层并触发横向滚动条。

真实浏览器测量（Playwright + Chromium，取产物中的样式对象）：

| 项 | 修复前 | 修复后 |
| --- | --- | --- |
| 弹层 scrollWidth / clientWidth | 768 / 748（有横向滚动条） | 748 / 748 |
| 档位行宽度 | **760**（相邻行 740） | 740 |
| 开关右缘 vs 箭头右缘 | 754 vs 734（相差 20px） | **734 vs 734** |

### 修复

- `serviceTierRowStyle` 与 `nativeMenuCellStyle` 都显式声明 `boxSizing: 'border-box'`，
  不再依赖 button 的隐式默认值；两种元素的内边距都算进宽度。
- `nativeMenuStyle` 增加 `overflowX: 'hidden'`：横向滚动条只会来自子元素溢出，
  保留纵向 `auto` 的同时让这类溢出作为缺陷暴露，而不是被滚动条掩盖。

DSH 官方菜单（`Menu.module.css` 的 `.list` / `.item`）同样使用 `border-box`，
本次修复与该设计语言一致。

### 验证

- 新增 `tests/client-service-tier.spec.ts` 用例：断言两个样式都声明 `border-box`、
  最小高度与左右内边距一致，且弹层禁止横向滚动。已用「临时移除 border-box」
  确认该用例会失败，证明它确实能捕获此回归。
- 全量 `node --test tests/*.spec.ts`：1315 项全部通过。

## 已知边界

- 只处理 Client 已经加载过目录的场景。首次加载本来就会拿到最新判定，不受影响。
- 复检最坏延迟约 65 秒（轮询间隔）。用户在切换供应商后若想立刻看到开关，
  仍可刷新页面；但不再需要重启 Host。
- 指纹基于文件内容摘要，因此 `config.toml` 的任何相关字段改动（含格式化）
  都会触发一次目录重探。这是有意的保守取向：多探一次的代价远小于长期缺失控件。
- 其他适配器未声明 `catalogFingerprint`，行为完全不变。
