# PeerHost 远程工作区表格展示实现记录

日期：2026-10-06

## 实现内容

远程 HOST 工作区选择器现在按选中的 Host 分成两块：

- “已添加的远程工作区”使用表格展示；
- 尚未添加的候选工作区继续保留在下方，点击后写入可见工作区集合。

已添加表格包含四列：工作区名称、会话数、所属远程 HOST、路径。

## 数据来源

工作区名称、路径和会话数来自 `peerHost/aggregate` 返回的实际远端工作区摘要；所属 Host 名称来自本地 PeerHost 记录。`visibleWorkspaceIds` 只作为聚合暂时不可用时的旧数据回退，避免历史 ID 形态变化导致“左侧栏已有工作区、表格却为空”。添加成功后同步更新当前 Host 记录，使表格立即反映新的可见工作区，不需要关闭并重新打开对话框。

## 空表与新增不显示修复

- 表格容器设置 `flex: none`。它处于纵向 Flex 面板且带横向滚动，默认的 `flex-shrink: 1` 会让候选列表较长时表格高度被压到零，界面只剩标题与边线。整块面板负责纵向滚动，表格只负责横向滚动。
- 添加成功后立即把候选行写入表格状态，并保留聚合降级时已有的可见工作区；不再等待下一轮聚合刷新。
- 聚合没有返回目标 Host 或其摘要未就绪时，回退到可见 ID 与候选列表；不把暂时缺失的结果当成权威空列表。
- 候选列表为空时仍允许独立的已添加摘要渲染，避免两条读取链路互相遮挡。
- 2026-10-06 用户提供的 Elements 内容进一步证实：三条工作区已经进入 `<tbody>`，仍然只显示容器边线，问题位于 CSS 布局而非协议数据读取。此前的假 DOM 测试不计算尺寸，不能作为视觉通过证据。
- 样式安装时复用同名 `<style>` 并更新文本，修正遇到旧节点就直接返回的行为，防止页面重新挂载后继续使用压缩表格的旧 CSS。

此次表格显示与状态更新缺陷存在于本轮尚未提交的表格实现中，不能归因于已发布版本。历史提交 `2de4f47`（2026-09-30 16:24:38，最早包含于 `v0.2.0-beta.2`）引入显式添加入口，但没有已添加表格。
