# 20261007-Live2D预设加载优化记录

## 问题与结论

用户已能选中「大肥鱼 · Live2D 桌前」，但加载很慢。值得优化：首屏等待了没有消费的素材，还把多个阶段的外网延迟串在一起；问题主要发生在下载链路，不能只靠更换 loading 文案处理。

读取已安装 l2d@2.1.1 和固定版本模型清单，确认：

- [模型加载器](https://github.com/hacxy/l2d/blob/v2.1.1/src/model-loader.ts) 先获取模型 JSON 识别版本，Cubism 3 分支再获取一次清单。
- [Cubism 加载流程](https://github.com/hacxy/l2d/blob/v2.1.1/src/vendor/cubism6/Samples/TypeScript/Demo/src/lappmodel.ts) 按模型、表情、物理、动作和贴图阶段推进，首帧依赖前序阶段完成。
- [大肥鱼固定清单](https://raw.githubusercontent.com/A8Chann/dsh-pet-live2d/185c02bfbb3b886e1a236b5c2ec035cc085b9ca2/dsh-live2d-pet/pets/ds-whale-girl/c_0120.model3.json) 有 44 个表情和 8 个动作。当前助理不使用换装表情，统一状态映射只消费 Idle 与 SprayWater。

本机只读外网抽样中，清单约 0.52 秒、MOC 文件约 0.97 秒、主贴图约 0.80 秒、真实表情文件约 0.61 秒。以上为 curl 样本，不能当成用户页面耗时或浏览器首帧结果。

## 实现

共享资源包描述放在 `src/shared/assistant-avatar-resources.ts`：固定上游提交、同源版本路径、文件白名单、类型、体积上限和消费动作。预设和资源包共用动作映射，仍通过原统一管理器、适配器元数据和插槽展示。

`src/host/features/assistant-avatar-assets.ts` 只为源码登记的预设提供资源入口：

1. 首次请求模型清单时才下载原始 JSON，保留 MOC、贴图、物理、布局、参数分组等数据；表情为空，仅保留两个实际使用的动作。
2. 六个必要依赖并行预取，引擎后续按阶段请求时复用同一下载 Promise 或成功缓存。显示信息文件可读取，但不提前下载。
3. 成功素材在 Host 内存缓存，并返回 private/immutable HTTP 缓存头；失败移除对应缓存并返回不可缓存的 503，后续请求可重试。
4. 路径包含上游提交与精简策略版本。每个文件执行声明长度检查和流式实际体积限额；query 无法改变上游 URL，不提供任意代理或本地文件读取。

原形象运行时模块统一登记引擎和 8 个素材 GET 路由，使用原生 buffered 请求；停用、重复释放或登记失败时清理路由。缓存不落盘，不下载进 Desktop Profile，也不安装上游插件。

首屏模型依赖从 **56 个缩至 6 个**：省略 44 个表情和 6 个未使用动作。引擎仍按需加载，隐藏或切换展示容器时释放 WebGL 实例，再打开时复用资源数据。自定义与单独导入的完整模型保持原地址与内容；本轮只优化目录中的 Live2D 预设。

模型和贴图文件没有修改。精简清单的修改说明已加入界面许可摘要，原始清单、作者和 [CC BY-NC-SA 4.0 素材声明](https://github.com/A8Chann/dsh-pet-live2d/blob/185c02bfbb3b886e1a236b5c2ec035cc085b9ca2/NOTICE.md) 仍可查看。
