# 本地会话 Windows 文件链接修复

## 问题与根因

诊断报告实际存在于隔离工作树，但消息链接写为 `/D:/develop/Codingns4DSH-codex-native-computer-use/docs/diagnostics/computer-use-20261012/README.md`。Windows 将其解析成 `D:\D:\develop\…`，文件预览因此提示文件不存在。

已安装的 0.2.1-beta.8 包含此前的文件链接修复。遗漏在适用范围：普通 Markdown 正文转换只处理行号；资源入口的 Windows 前缀纠正依赖 PeerHost 模块，目录查询也只有远端会话。

## 改动

- 将文件资源入口包装从 PeerHost 模块移到通用 Client 装配，独立等待 `sidebarRight`、`sessions`、`workspaces` 服务就绪，不依赖 PeerHost 开关。
- 每次打开资源时按资源中的会话 ID 查询最新目录。远端工作区使用 `workspacePath` 的真实路径，避免空白会话的虚拟 cwd 影响平台判断。
- 复用已有 Windows 路径及行号规范，保留会话身份、导航参数、查询和片段。POSIX 与未知目录继续保持原样；卸载时还原包装。
- 不改写历史消息正文，重新点击旧消息即可经过通用入口。已经打开的本地坏地址标签需要关闭后重新点击。

## 验证

- 58 项源码回归通过：文件链接、PeerHost 文件转发及目录投影、Codex 流式引用。
- Windows 测试创建工作区外的真实报告，用原始 `/盘符` 资源地址验证实际 stat/read 成功，覆盖无 PeerHost、行号、查询片段、选项保留和卸载恢复。
- 插件 apply 测试覆盖原生服务延迟就绪及独立挂载；平台测试覆盖动态目录、远端空白会话、POSIX 和未知会话。
- TypeScript 编译及 Client、桌面助理、H5 打包通过；35 项构建入口及分块回归通过。
- 修改文件的国际化检查为 0 阻断。Windows 全量检查仍报告 1211 项阻断，包含未修改的词典文件；该检查使用反斜杠相对路径，无法匹配其正斜杠词典排除与 allowlist，未在本次文件链接修复中改动。

pnpm 的构建入口在本机自动触发依赖安装，因依赖构建脚本策略中止；撤回其锁文件和 workspace 配置改动后，直接调用已安装的 TypeScript 和 tsdown 完成编译及打包。
