最新有效日志为 `data/logs/voice-performance-2026-10-07T15-21-53-168Z-15071-0155ed4d.0.jsonl`，包含两次通话、六轮问答。性能日志仅保存标量指标；具体转写和回复从 Stage0 自有助理通话记录读取，没有读取 Desktop。

第一通话的 9583 个原采集帧合并为 2144 个传输帧，共 76664 毫秒；第二通话 2115 个原采集帧合并为 475 个传输帧，共 16920 毫秒。两次通话的上传序号分别为 1–9583、1–2115，没有缺口或重叠。Host 收到 792 个批次，诊断标识全部唯一，与客户端发起数一致。Host 识别指标中的帧数和音频时长与上述上传值完全相同，没有二次喂入的证据。

字幕和语音适配器都转发完整识别快照，界面使用替换赋值，不拼接识别增量。Host 首轮 ASR（语音转文字）最终输出已是 8 字，而通话记录中“测测测测试测试啊”也是 8 字；天气转写同样已保存为“帮我查一下济济南南的天气”。重复不是字幕显示阶段新增的。

当前 Stage0 选择的是 2023 年中英双语实时模型。使用本机 Tingting 合成四段 16 kHz 单声道 WAV（音频文件），在独立进程直接调用同一识别器；回放不经过网络、界面、LLM（大语言模型）或播放队列。报告保存在 `data/logs/voice-recognition-repeat-replay-20261007.json`。

当前双语模型在关闭热词和改用贪心解码后仍出现额外重复。中文 Large 的四段回放没有额外重复，并保留合法的“天天”“宝宝”“哈哈”和两次“测试”；在开启现有领域热词的模式下，第三句也识别为“会话”。这证明识别器可以在没有网络和文字拼接时独立产生重复，主要修复方向是识别模型质量，而非删除所有相邻重复字。机械文本去重会破坏合法叠词和用户确实重复的内容。

该回放采用合成录音，不是用户原录音；不能由此保证用户麦克风环境中的所有问题都消失。本次保留用户已保存的模型选择，没有自动更换识别模型、改写原始转写或增加句尾等待。

## 联网能力缺失的原因与修复

DSH 的 base 组合提供原生 WebRuntime（联网运行服务）及 DeepSeek 搜索提供商，但 Web 产品的组合明确把 Host 全局 `tool-web` 设为关闭，改由普通 Agent 的预设组装工具。独立助理根 Agent 没有普通编程预设；旧实现只查找全局 `web_search` 并继承，所以实际工具列表缺少搜索。天气轮次的工具调用数为零，没有尝试搜索，也不是一次搜索失败。此前的集成测试只覆盖已经全局注册搜索工具的场景，遗漏了实际的预设隔离配置。

新增 `assistant-web-search-adapter.ts`：全局搜索工具存在时继续继承；全局工具缺失而原生搜索服务存在时，仅在助理作用域注册 `web_search`。入口调用原生 `WebRuntime.search`，不自行读取凭据、替换端点、另建提供商或发起 HTTP 请求。参数限定一到四个公开查询，每个最多一千字符，重复查询合并；每个查询最多八个来源，调用带取消信号及六十秒预算。返回材料标记为外部参考信息，来源链接和日期保留。

局部搜索与管理、附件工具共用模型工具白名单和执行守卫；不开放网页抓取、项目文件、终端或子 Agent，不改变普通 Agent。原生服务缺失时如实标记不可用；提供商或凭据错误仍由原生工具执行流水线返回，工具已注册不能被当成联网已经成功。

诊断新增 `host.assistant.tools`，记录 `webSearchAvailable` 与 `searchRegistration`；`host.llm.tool` 增加工具名称，分析脚本分别显示搜索开放状态、发起数、完成数与失败数，不记录查询、提示词或凭据。
