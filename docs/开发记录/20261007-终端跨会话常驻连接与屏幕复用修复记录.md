# 终端跨会话常驻连接与屏幕复用修复记录

日期：2026-10-07。

## 检查结论

Host 已有持久终端记录和常驻连接，问题出在客户端生命周期。

| 状态 | 所属位置 | 恢复方式 |
| --- | --- | --- |
| Host、工作区、终端 ID、运行时键、Shell、标题、尺寸、运行状态 | DSH 设置文件旁的 `codingns4dsh/terminals.json` | JSON 原子写入；Host 初始化加载，恢复时检查真实运行时 |
| tmux Shell 进程、屏幕与历史 | tmux server | 切换浏览器卡片不会终止；运行时真正丢失才需显式重建 |
| backend attachment（后端连接）与有限输出缓存 | Host 内存 `residents` | 每个运行终端一条常驻连接；新浏览器 follow（输出订阅）复用连接并读取历史快照 |
| 卡片开关、子终端选择 | 浏览器工作区状态及 localStorage（本地存储） | 同工作区共享；这些 UI 状态目前不写入 Host 终端记录 |
| xterm 缓冲区、光标、备用屏幕与滚动位置 | 本轮新增的客户端常驻屏幕 | 同一页面内直接复用；页面刷新后首次订阅 Host 恢复历史 |

证据：`terminal-store.ts` 提供原子持久化；`terminal-service.ts` 的 `ensureResident` 复用常驻连接，`follow` 只登记订阅，取消订阅不释放 backend；`tmux-backend.ts` 的 resize 只调整窗口和 PTY 尺寸，不重新 attach。

## 根因

1. 聚合视图虽有保活标记，却使用会话级缓存键。同一工作区从另一会话打开会创建新模型、新 follow 和新 xterm，再捕获历史、清屏重放。
2. 新模型保活与 xterm DOM 生命周期分离，模型仅保存最近一帧，不能独立恢复已销毁的完整缓冲区。没有渲染者确认时，后续帧消费也会停住。
3. 隐藏视图仍按 Host 尺寸调整自己的 xterm，切回时再夺回尺寸，会导致不必要的尺寸往返和历史重绘。

新增浏览器订阅不等于重新连接 tmux。现有 Host 测试证明多订阅只有一条 backend attachment；用户可见的连接提示、历史清屏重绘来自客户端重新订阅与屏幕重建。未读取运行中 Profile 或日志，不能据此断言当前实例中的每次闪动都发生了真实 tmux attach。

## 实现

- 聚合模型按工作区作用域与 terminalId 复用。工作区解析前创建的模型解析后迁移，避免重复订阅；环境缺少工作区 ID 时继续保持会话隔离。
- `TerminalSurfaceCache` 将屏幕生命周期绑定到模型的 AbortSignal（取消信号），每个终端仅创建一个 xterm 和输出消费订阅。
- 会话卡片只借用屏幕显示位置，隐藏时移除 DOM 而不销毁屏幕。旧卡片清理必须检查当前所有者，防止拆走新卡片刚接管的屏幕。
- 输出在隐藏期间继续写入同一缓冲区并确认，切回不创建新连接、不清屏重放。
- 可见卡片更新会话调用上下文；隐藏卡片不修改共享屏幕尺寸和焦点。实际尺寸变化、真实断线、显式刷新及重建仍保持原有行为。
- 显式关闭子终端和服务 dispose（销毁）释放屏幕、输入事件、订阅、计时器与 follow；关闭终端卡片只隐藏。
