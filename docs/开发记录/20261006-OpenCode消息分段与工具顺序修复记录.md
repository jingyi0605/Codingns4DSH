# OpenCode 消息分段与工具顺序修复记录

## 问题现象

回放 `dsh-session-session-401b3697-118a-4fa8-8370-c2595e8073e9` 时，OpenCode 在同一轮先发送工具调用，再发送工具结果和后续 assistant 正文。DSH 界面出现两个问题：

- 工具前后的 assistant 正文被追加到同一个消息 block，后续输出看起来像堆叠在第一条 AI 回复中。
- `message.part.updated` 早于 `message.updated` 时，已暂存的正文可能被后到的工具事件越过，工具和正文顺序与 Provider 原始事件顺序不一致。

## 根因

`opencode-driver.ts` 已从 OpenCode part 中读取 `messageID`，但转换 `text-delta` 和 `reasoning-delta` 时没有把它带入公共事件。公共 `CodingNsAgentEventNormalizer` 无法识别 assistant item 切换，投影器自然会继续复用当前正文 block。

另外，角色确认延迟期间，正文先进入 `pendingMessageParts`，工具事件却直接实时投影；这会让工具跨过同一 assistant 消息中更早到达的正文。

## 修复内容

- OpenCode 正文和推理增量保留原始 `messageID`，让公共投影器在 assistant item 切换时封口旧 block 并创建新 block。
- 同一消息存在待确认 part 时，工具事件先进入同一有序队列，待 `message.updated` 确认 assistant 后按入站顺序冲刷；没有待确认正文时仍即时投影工具，保留实时性。
- 新增回放式测试，覆盖消息 ID 透传、工具前后正文分段，以及 `part.updated` 早于 `message.updated` 的顺序场景。

## 验证

- `pnpm exec tsc -p tsconfig.json --noEmit` 通过。
- 使用临时目录编译源码并回放 OpenCode SSE：输出顺序为 `text(工具前) → tool(completed) → text(工具后) → finish`，两个正文事件分别带有 `assistant-before` 和 `assistant-after`。
- 未构建仓库 `data/build/dist`，未启动 OpenCode server，也未触碰 Desktop 端。
