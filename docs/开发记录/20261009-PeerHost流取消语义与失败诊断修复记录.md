# PeerHost 流取消语义与失败诊断修复记录

## 问题与判断

`peerHost/nativeStreamNext` 曾把正常取消和真实连接故障统一显示为 `PEER_HOST_PROXY_UNREACHABLE`。内存回放确认：取消挂起读取后，底层取消异常会被 HTTP（超文本传输协议）代理包装成 502，最终由 RPC（远程过程调用）主处理器打印故障日志。因此，原日志本身不能证明发生了网络抖动或工作区绑定错误。

本次先修复错误语义并补充诊断。尚无真实现场的新失败记录，不能据此认定需要调整重连策略。

## 修改

- HTTP 代理逐请求透传取消信号，正常取消继续抛出 `AbortError`，不再包装为代理不可达。删除 Host 功能中重复创建代理的信号适配代码。
- 流关闭默认使用标准取消原因；取消挂起请求时保留原始 reason（原因），自定义取消原因向上传播时归一为 `AbortError`。`TimeoutError`（超时错误）仍作为真实失败处理。
- 流读取和重试等待均响应取消；取消不会继续访问目标。关闭远端句柄使用独立的 5 秒信号，不沿用已取消的订阅信号。
- RPC 主处理器对正常取消返回取消错误，不打印 warning/error（警告或故障日志）；开启普通调试追踪时仍可看到取消记录。
- 真实流失败携带 Host 内部诊断；完整底层异常只留在 Host 内存，日志使用错误名称、错误码、系统调用和有界 cause（异常原因）链。异常正文、完整地址、请求体及凭据不进入日志或客户端错误响应。
- 原有稳定业务错误码、认证恢复和客户端代理响应形状保持兼容。

## 诊断字段

| 字段 | 含义 |
| --- | --- |
| `endpoint` | 当前 Host 的 RPC 端点 |
| `targetHostId` | 实际访问的远端 Host 标识 |
| `method` | 原始订阅方法，例如 `session/follow`、`$events` |
| `phase` | `open`（打开流）或 `next`（读取帧） |
| `workspaceId` / `sessionId` | 本次订阅的资源作用域 |
| `elapsedMs` | 本次打开或读取操作的耗时，包含重试等待，不是整个会话时长 |
| `attempts` | 本次操作的实际尝试次数 |
| `status` | 最后一次取得的代理 HTTP 状态；未取得响应时为 `null` |
| `cause` | 脱敏后的底层原因，例如 `TypeError → ECONNREFUSED`、`TimeoutError` |

明确连接级 502 仍最多尝试 3 次，等待 400、800 毫秒。最终失败只由 RPC 边界打印一次诊断；正常取消不触发重试。未增加订阅重建或改变现有事件流重连策略。
