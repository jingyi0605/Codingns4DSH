# PeerHost 插件版本向下兼容实现记录

## 问题与规则

原握手直接比较插件版本字符串是否相等，客户端更新后会拒绝仍使用旧版插件的 PeerHost。现在允许客户端插件版本高于或等于 PeerHost 插件版本；客户端版本来自提供当前页面插件的本地 Host。

| 客户端插件 | PeerHost 插件 | 插件版本检查 |
| --- | --- | --- |
| `0.2.1-beta.5` | `0.2.1-beta.5` | 通过 |
| `0.2.1-beta.5` | `0.2.1-beta.4` | 通过 |
| `0.2.1-beta.5` | `0.2.1-beta.6` | 拒绝 |
| `0.2.1-beta.10` | `0.2.1-beta.9` | 通过 |
| `0.2.1` | `0.2.1-rc.1` | 通过 |

DSH 版本仍须落在插件支持范围内，API（应用程序接口）兼容标识仍须匹配；产品和插件身份、主机指纹、登录凭据的校验不变。连接放行不代表旧版 PeerHost 拥有新版新增的所有接口。

## 实现

- `src/shared/contracts/version.ts`：提取通用 `isVersionAtLeast`，保留原 `isDshVersionAtLeast` 入口；按语义版本处理预发布顺序与构建元数据，拒绝非法版本。
- `src/host/modules/peer-host/peer-host-handshake.ts`：用客户端版本不低于目标版本替换字符串相等条件，失败继续返回原有 `version_mismatch` 状态与错误码。
- `src/client/locales/peerHostWorkspace.ts`：同步中英文提示，避免继续错误地要求升级目标 Host。
- `tests/peer-host-handshake.spec.ts`、`tests/peer-host-edit-connect.spec.ts`：覆盖版本大小、预发布排序、非法版本、元数据、身份变化及跨版本握手登录；新版目标被拒绝时不发起登录、不保存凭据。
