# iPad 输入焦点与虚拟键盘修复记录

## 原因

原来的键盘限制和会话触摸交互共用 `1024px` 门槛。iPad 使用横屏桌面布局时没有启用限制；启用时也只保护 Composer（对话编辑框），且将编辑框周围的添加、模型、权限和发送按钮都当成输入授权。弹窗和搜索框的自动聚焦同样不受限制。

## 修改

- 新增 `src/client/touch-input-focus.ts`，将输入焦点保护从会话手势控制器中拆出。iPad 与带多点触摸的 Macintosh 浏览模式均启用保护，不受视口宽度限制；其他设备沿用窄屏触摸门槛。
- 捕获真实用户对文本输入框、搜索框、弹窗输入框和可编辑区域的直接点按，只给被点按的同一个组件授予 700ms 聚焦许可。脚本合成点击、外围按钮、滚动、拖动、取消、失焦及进入后台不能保留许可。
- 包装当前窗口的 `HTMLElement.prototype.focus`，在调用原生方法之前拦截无许可的输入聚焦；原生 `autofocus` 或缓存原生方法造成的聚焦由 `focusin` 同步失焦兜底。卸载时恢复原生方法并移除监听。
- 终端使用隐藏文本框接收输入，因此仅直接点按终端文字面板才授权该文本框。打开或恢复终端不能自动唤起键盘。
- 保留 Composer 工具按钮的原有点击链路；按钮不授予新的输入许可。会话行、侧栏与桌面布局沿用原有响应式规则。

## iPad 真机验收

1. 从主屏幕启动、切回前台、新建或切换会话、点击发送、打开设置及对话框时，键盘不得自行弹出。
2. 直接点按对话编辑框、搜索框、弹窗文本框或终端文字面板后，键盘应正常弹出并允许输入。
3. 关闭键盘、点击非输入区或切到后台后，程序恢复焦点不得重新唤起键盘。
4. 横屏、竖屏及桌面浏览模式分别检查；添加文件、模型和权限按钮应正常操作，普通桌面自动聚焦行为应保持可用。
