# 实时语音接入 LLM 多轮对话与简短回复记录

日期：2026-10-07

## 问题与结果

实时语音此前在最终识别后进入关键词意图与动作路由，没有调用文字调试已经实现的 LLM（大语言模型）、结构化索引或短回复提示词，窗口也只保存用户转写。

本次把最终话语接入同一生成引擎与系统提示词，使用成功结构化索引所选模型，支持连续追问。默认回复一到两个短句、100字以内，先回答重点，再说必要动作；用户要求细节时再展开。窗口区分用户与助理消息，逐步更新助理正文并显示思考、播报状态，生成完成后交给现有音色播放。长度由提示词约束，不在本地粗暴截断内容。

## 数据与生命周期

- `readChatContext` 共用文字／语音索引门禁：索引范围、代次和有效版本必须一致，逐会话结构化结果完整且成功。运行中、待更新、失败或过期索引均不放行问答，不由语音强制重建。
- `AssistantVoiceChat` 按唯一租约保存最多九对已完成问答，下一请求最多包含19条消息。失败、取消或失效结果不写历史；刚完成但尚未轮询的上一轮也可进入追问上下文。
- 模型、范围、索引版本或对话前置提示词变化重置上下文。停止、清空与租约丢失清除历史；打断只取消当前生成，保留完成历史。历史仅存在 Host 内存。
- 使用 owner、epoch、请求 ID 和递增话语顺序隔离请求；有界撤销标记处理取消早于启动到达。模型目录等待期间可撤销；取消和90秒生成超时立即结算等待者，忽略 Abort 的上游迟到结果不覆盖状态。
- Client 在250毫秒短轮询中获取累计正文，更新同一请求的助理消息。音频上传、识别事件与模型生成独立运行，生成／播报不阻塞下一句的实时文字。
- 新话语、打断、清空、关闭或停止同步取消模型请求与播放；相同 epoch 的旧结果也核对请求身份。清空期间的新话语等待 Host 清空完成；模型或索引错误明确显示并取消后台请求，不回退转写服务。

## 接口兼容与范围

新增 `assistant/voice/chat/start/read/cancel/clear`，所有入口校验当前租约，旧 HTTP 精确路由同样登记。旧 `assistant/voice/text` 继续返回可播报的 `speechText`，内部改为 LLM；显式文字派发接口及已注册动作继续保留。自然语音对话沿用文字调试的只读规则，不再按关键词自动执行项目任务。

修改保留工作区已有形象与 MOSS TTS（文字转语音）实现、当前音色和精细播报参数。仅补充消息角色和状态，不重设计助理窗口。

## 验证

使用 `node --import ./tests/register-source-loader.mjs --test --test-concurrency=4 --test-reporter=spec` 在内存加载源码，未构建。

语音对话、文字 LLM、调试、提示词、独立索引任务、自动增量、旧动作兼容、协调器、原生 HTTP 桥、语音流、上传、TTS 服务与播放器共15个文件97/97通过。测试覆盖三轮原生消息映射、结构化事实与短回复提示词、所选模型、不隐式派发、历史清空／有界、目录等待取消、超时、乱序、迟到结果、实时分段回显以及 TTS 参数兼容。最后新增客户端错误分支和取消清理后，客户端10/10复核通过，确认索引不可用时保留收音、显示具体错误、取消后台请求且不回退转写或关键词路径。

首轮客户端测试被另一并行工作新增夹具中的 TypeScript 参数属性阻断，已改成普通字段赋值，保持语速与音量测试含义不变。后续客户端9/9通过，完整回归97/97通过。类型检查 `pnpm exec tsc --noEmit` 和差异格式检查通过。
