# tmux 测试探测误杀终端服务器修复记录

## 问题与原因

用户在终端里运行测试时，测试输出中途出现 `[server exited]`，前端随后显示“终端运行时已丢失”。

`tests/tmux-backend.spec.ts` 的 `canUseTmux()` 原先直接执行不带 `-S` 的 `start-server` 和 `kill-server`。在 tmux 终端里运行测试时，子进程继承 `TMUX` 环境变量；不显式指定 socket（服务器通信端点）的 tmux 命令会连接当前终端服务器。可用性探测因此可能结束承载用户终端的服务器及其中所有 Shell。

这与普通命令返回错误码不同：退出的是服务器，Shell 包装器无法正常写下真实退出码，终端只能收敛为 `lost`。

本轮检查的 Stage0 持久化记录已有 58 条 `closed` 记录，未保留截图对应退出的直接记录；原因依据源码与独立临时服务器的真实复现确认，不据此声称已定位截图发生的精确时刻。

## 修改

- 可用性探测为每次调用创建独立临时目录，启动和清理均显式传入同一个 `-S <测试 socket>`。
- 探测使用 `-f /dev/null`，避免加载用户的 tmux 配置；创建一个 `/bin/sh` 测试会话，避免空服务器立即退出造成探测失真。
- 使用 `finally` 收尾，启动失败或超时时也尝试清理自己的服务器；命令设置 3 秒超时。
- 原有真实集成用例把服务器回收放进 `finally`，断言失败也不会遗留测试服务器。
- 新增成功、失败、超时结果的隔离收尾检查，以及继承 `TMUX` 时原会话与服务器身份保持不变的真实回归用例。

## 验证

- `node --test tests/tmux-backend.spec.ts`：17 个用例全部通过，无跳过。
- 整份测试在继承临时守护服务器 `TMUX` 的环境中执行：17 个用例全部通过，测试结束后守护服务器 PID 和会话 ID 保持不变。
- 检查 `tests/` 与 `scripts/`：tmux 的真实 `kill-server` 调用均显式指定测试 socket。

修复验证阶段仅修改仓库测试及开发记录，复用已有构建产物执行定向测试；没有构建、启动或重启 Stage0，没有操作 Desktop。随后按用户明确要求，将修复、回归测试和本记录分批提交；没有推送或发布。

## 生效范围

测试源码修复立即影响下一次测试执行，无需安装插件或重启服务。已经被结束的旧 Shell 无法通过此修复恢复；前端已有的重建终端入口可创建新会话。
