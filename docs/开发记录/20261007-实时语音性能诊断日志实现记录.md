## 保存位置与启用条件

专用 Stage0 通过现有启动器加载新版 Host 和 Client 后自动记录，不依赖控制台调试级别，也不用在浏览器打开额外开关。

本机目录：`/Users/jackson/Code/CodingNS/data/dsh-codingns/data/logs`。

文件名：`voice-performance-<UTC 时间>-<进程 ID>-<随机标识>.<轮转序号>.jsonl`。JSONL（每行一个 JSON 对象）同时包含 Host 与浏览器记录；`timestamp` 为事件时间，`receivedAt` 为 Host 落盘接收时间。不同设备时钟可能不同，耗时统一使用各自的单调时钟，不直接相减跨设备时间戳。

启用边界沿用 `isStage0Runtime()`：需同时具备 Stage0 Profile、仓库根目录和专用启动器标识。其他运行环境不安装写入器；设置 `CODINGNS4DSH_VOICE_DIAGNOSTICS=0` 可关闭后续启动的性能诊断。

## 记录范围

| 阶段 | 事件与关键指标 |
| --- | --- |
| 通话生命周期 | `client.call.*`、`host.call.*`：租约获取、启动和停止耗时 |
| 麦克风采集 | `client.capture.metrics`：帧数、音频时长、处理开销、最大回调间隔、静音状态 |
| PCM 上传 | `client.upload.start`、`client.upload.batch`、`client.upload.pressure`、`client.upload.error`、`host.upload.received`、`host.upload.batch`：批次 ID、序号、排队、往返、PCM 与首部字节、积压时长、在途等待、Host 收到／处理和旧代次丢弃 |
| ASR（语音识别） | `host.asr.*`：模型加载、同步解码总耗时与最长帧、partial／final 文本长度 |
| LLM（大语言模型） | `host.chat.*`、`host.llm.*`、`client.turn.*`：上下文准备、服务端／客户端首字、轮询、工具状态、取消、完成 |
| 短语队列 | `client.sentence.*`：待处理数量、文本长度和合成前等待 |
| MOSS 工作进程 | `host.moss.*`：冷启动、复用、忙状态、失败、Python CPU 和每张 ONNX 图的调用次数／累计耗时 |
| TTS（语音合成） | `host.tts.*`、`client.tts.*`：首块、分块间隔、PCM 解码、生成耗时、音频时长 |
| 播放 | `client.tts.playback_scheduled`：待播时长、断流间隙、音频节点数、上下文状态；首次播放指标指调度时间，不虚报硬件扬声器实际出声时间 |
| 运行负载 | `host.health`：Host CPU、内存、事件循环延迟；`client.health` 和 `client.longtask`：页面可见性、定时器延迟、支持该 API 的浏览器长任务 |

`callId` 关联整次通话，`requestId` 关联一轮模型回复，`diagnosticId` 关联一次上传或合成。常规帧的指标每两秒聚合一次，不逐麦克风采样输出。

## 写入开销与兼容性

- Host 每 500 ms 异步批量追加，单写任务保序；语音链路不等待磁盘。
- Host 待写缓冲最多约 1 MiB，浏览器最多 256 条待传记录；回传一次最多 64 条，只允许一个请求在途。超载记录丢弃数量，不无限堆积。
- 本轮 Host 最多循环五个约 20 MiB 的文件，只覆盖本轮唯一前缀文件，不清理目录里的旧运行日志。
- 写入失败只报告一次，并停止继续积压；诊断订阅者异常不能破坏通话。
- 字段采用标量白名单，不记录用户正文、模型正文、提示词、音频或认证信息。
- Python 仅在 Host 开启诊断时发送附加协议事件，按图聚合，不逐 token 写日志；诊断事件在 `done`／`error` 前发送。

## 使用与判断

在新版代码已加载的 Stage0 页面复现三到五轮实时语音，包含一次冷启动和连续追问。挂断后，执行：

```bash
node scripts/analyze-voice-diagnostics.mjs
```

默认分析最近写入真实指标的运行，跳过自检和只有启动标记的文件，并纳入该运行的全部轮转文件；也可传单个文件路径或日志目录。脚本输出首字、首音、上传、识别、事件循环和播放间隙的 P50／P95／最大值，以及各 ONNX 图的累计耗时。上传中断即使早于模型回复，仍会输出可用的启动和上传指标；新版记录包含中止原因码与未完成上传的批次 ID。

RTF（实时系数）为处理耗时除以音频时长；持续大于 1 表示处理速度赶不上实时音频。Host TTS 指标包含准备与冷启动，需结合图耗时判断；客户端合成指标还包含网络和主动预取等待。

播放间隙、合成 RTF、Host 阻塞是定位线索，不是单凭一个阈值就证明根因。后台页面降频、浏览器不支持长任务 API、设备时钟偏差和诊断丢弃都应结合记录判断。
