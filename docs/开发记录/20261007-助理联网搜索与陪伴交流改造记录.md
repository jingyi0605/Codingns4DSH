# 助理联网搜索与陪伴交流改造记录

## 目标与父仓库对照

用户要求助理保留管理能力，增加联网搜索；陪伴聊天自然回应，涉及工作区和会话时按事实进入工作状态。

参考父仓库 `apps/host/src/modules/workspace/affairs-lightweight-session-service.ts`：轻量会话只做问答、联网搜索和轻量分析，不开放本地文件或终端；需要最新信息先搜索。它的 OpenAI 请求只提供 `web_search`，Anthropic 请求只提供服务端搜索工具。本项目沿用工具边界，继续使用原生 DSH AgentLoop（代理执行循环），不另建上游模型调用或搜索凭据配置。

父仓库的标准 Markdown 要求没有移入语音助理；助理保留口语短答和现有分句播报。

## 工具与运行事实

- 四个范围内管理工具继续保留：工作区列表、会话列表、会话摘录和管理跟进；已收到的文本附件只能通过附件标识读取。
- 助理创建时只继承 Host 已注册的原生 `web_search`。原生工具执行、结果格式、来源、取消及提供商选择仍由 DSH 负责。
- 白名单同时作用于原生工具继承、模型工具声明和执行守卫。`web_fetch`、本地文件、终端、MCP、编程及子 Agent 工具均不开放；范围与思考设置只影响该助理根 Agent。
- Host 未注册搜索工具时，管理与日常问答仍可用，系统消息明确说明搜索工具缺失。已注册不等于提供商和凭据可用，实际错误进入原生工具结果，模型不能声称搜索成功。
- 在清除默认编程环境提示后补入可信运行事实：DSH 原生 AgentLoop、独立根 Agent、会话标识、独立工作目录、模型参数、本轮 UTC 时间和工具清单。用户问自身环境时可以据此回答，平时不主动报告内部路径与参数。

## 交流方式

场景交给模型结合本轮意图和连续历史判断，没有新增关键词匹配器或模式开关。

陪伴聊天先回应情绪和话题，不强行给结论、建议或任务清单；必要时只问一个自然的小问题。工作问题强调结论、事实和必要行动，只有用户明确要求跟进才向目标会话发送管理消息。亲切表达仍遵守真实身份，不能编造真人经历或当前所见。

常识和陪伴不强制联网；天气、新闻等实时公开问题先搜索。缺少地点先询问，不从工作区路径推测位置；搜索查询不发送私有会话正文、附件、主机路径或凭据。来源名称和必要日期可用简短口语说明，用户明确索要来源时才附真实链接。

默认一到两个短句、100 字以内，用户要细节再展开。旧的两版完整默认对话提示词读取时升级，真正的自定义提示词、性格背景和索引提示词保持原样。新规则在正式文字与语音共用提示词中生效；预览和索引总结保持无工具调用。

## 验证

本轮定向回归覆盖 10 个文件、84 项，全部通过且没有跳过。已安装 DSH 的原生 AgentLoop、ToolRuntime、WebRuntime 和 web_search 工具使用独立内存 Context（上下文）实际执行：搜索结果进入下一次模型请求，搜索失败保留错误，禁止工具无法执行，普通根 Agent 仍有原工具并保持 high 思考参数。搜索提供商和 LLM（大语言模型）在测试中使用内存替身，没有发送网络请求或读取用户凭据。

模型的真实陪伴语气与搜索上游可用性仍需实机联调；提示词检查不等于已经评测实际模型表现。现有共享历史、生命周期、管理工具、语音轮次和分句 TTS（文字转语音）回归通过。
