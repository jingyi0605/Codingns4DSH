后续需求说明：本文保留阶段 8 的实现与实测证据。缓存和耗时展示现已限定到专用 dsh-stage0，正式环境只保留加载动画与进度条；最新行为见[Stage0 诊断隔离与刷新持久化评估](20261007-形象Stage0诊断隔离与刷新持久化评估记录.md)。

## 问题与判断

用户反馈宠物载入时为空白，重复打开与首次等待相近，无法确认是否使用缓存。值得处理：素材下载、引擎准备与重新初始化混在同一个等待过程，原界面没有证据；原 Host 缓存还归属于 Handler（请求处理函数），重新登记路由会更换缓存。

这次让渲染器报告真实加载状态，插槽统一呈现等待和完成反馈；Host 提供实时缓存快照。不会通过虚假百分比、长时间保留隐藏 WebGL 实例或猜测浏览器缓存解决问题。

## 实现

- `AssistantAvatarRendererProps` 新增可选 `onLoadProgress`，公开 `AssistantAvatarLoadProgress`。注册项声明加载、初始阶段和缓存反馈能力，插槽按能力与数据展示；旧扩展不声明时维持原行为，不需要修改 ID 或两个展示容器。
- 图片、精灵图和 Live2D 共用呼吸光晕、轨道光点及细进度条。未知文件数量显示循环指示，已知文件数量按真实 `loaded/total` 展示；小尺寸使用紧凑文案，支持浅色、深色和减少动态效果。占位不接管拖动或点击。
- Live2D 监听真实 `loadstart/loadprogress/loaded` 事件。只有 `loaded` 确认才结束等待；上游静默返回按失败处理，连续 45 秒没有文件进度后清理并回退，持续加载的大模型不会因整体时间较长而误超时。隐藏或卸载立即取消等待，迟到进度不能写入旧插槽；热缓存图片在 effect 前完成也不会被重新遮住。
- 生产 Handler 复用模块级有界内存缓存，停用再登记资源入口不会丢失成功文件。素材返回 `X-CodingNS-Avatar-Cache: miss/hit/shared`，分别对应新下载、已完成缓存和共享正在下载的请求。
- 固定 `cache-status.json` 返回缓存代际 generation、首屏成功缓存、进行中、总数和累计下载次数，不触发下载，响应 `no-store`。Client 只诊断同源固定预设，加载前后取快照，诊断最多 250ms，失败显示未知；自定义外部模型不额外请求该入口。
- 完成后直接显示加载前缓存数量、新增下载数和耗时摘要，鼠标停留可见完整说明与资源就绪时间。只有前后快照属于同一缓存代际才计算新增次数，避免 Host 重建后计数相同被误判为下载 0 项。差值属于 Host 范围，多个 Client 同时加载时不能将其解释为单一 Client 的网络次数。

## 缓存证据复测

直接调用源码 Handler，真实下载固定上游素材；不启动 HTTP 服务。第二次使用重新创建的生产 Handler，验证缓存不依赖原 Handler 对象。

| 检查项 | 第一次 | 再次创建入口后 |
| --- | --- | --- |
| 加载前成功缓存 | 0/7 | 7/7 |
| 加载后成功缓存 | 7/7 | 7/7 |
| Host 累计外网下载次数 | 从 0 增至 7 | 仍为 7，新增 0 |
| 清单及依赖读取完成 | 1331ms | 4ms |
| 第二次各文件响应标记 | — | 7 个全部 hit |

这证明 Host 资源缓存命中，不代表用户界面会在 4ms 内显示，也不证明浏览器 HTTP 缓存状态。当前缓存仍为内存缓存，进程重启或模块热替换后可能重新获取素材。

## 独立浏览器验证

使用已安装 Microsoft Edge 的独立无头临时实例，未连接用户的运行界面，也未操作 DSH Desktop。浏览器请求通过测试专用路由直接调用源码 Handler，不启动开发或 HTTP 服务器，不产出 Client 构建文件。

1. 静态加载反馈检查 80px、144px、240px：发现 80px 文案挤压光点并溢出，修改为紧凑文案与固定光晕高度后全部无溢出。浅色和深色截图已人工查看；减少动态效果下四个轨道动画均为 none。
2. 加载真实大肥鱼模型：两次均有 loaded 确认、完整 7 项文件进度，截图确认模型可见，浏览器脚本错误为 0。第一次约 11.99 秒，销毁后第二次约 0.53 秒，两次完成后 Host 下载次数始终为 7。
3. 首次引擎中最后两张纹理的进度约在 11.93/11.95 秒出现；Node 资源层约 1.33 秒。该对照说明下载缓存和模型显示准备必须分开观察，不能只拿资源层毫秒值代表 WebGL 显示耗时。

无头浏览器的显卡、传输与用户环境不同，上述数值只是本次隔离样本。图片资源事件也包含解码与 GPU 上传；「资源就绪」是相对加载开始的时间点，不能相减后宣称获得了独立 GPU 基准。运行中的 Stage0、窗口切换、拖动和实际用户网络仍由 Spec014 的 4.2 验收。
