# 语音同音词理解与领域热词优化记录

日期：2026-10-07

## 问题与判断

Stage0 当前配置为 `sherpa-onnx-streaming-zh-en`，对应 2023-02-20 的中英双语 Zipformer。用户说“会话”时经常被转写为“绘画”，使工作区查询进入错误语境。两个词同音，优先补充上下文和领域热词，不进行模型微调。

## 语音理解

- `createAssistantVoiceSystem` 只用于语音轮次，说明输入来自 ASR（自动语音识别），可能存在同音词、近音词和名称偏差。
- 正式连续对话和不使用持久化存储的语音入口都接入同一规则；键盘输入、索引总结和预览不自动追加该规则。
- 结合本轮有效工作区／会话列表和历史指代理解查询；例如“查看 CodingNS 工作区有哪些绘画”可理解为会话查询。
- 保留原始转写及历史，不对所有“绘画”做字符串替换；实际绘画话题、含“绘画”的会话标题仍是合法内容。
- 缺少依据或匹配多个目标时澄清；理解纠错不新增跟进授权，发送消息仍受完整目标、版本和工具边界约束。

## 识别热词

- 改为 `modified_beam_search`（改进束搜索），束宽保持 4，沿用现有线程数与句尾设置。
- 每次新通话只读取元数据，不读取会话正文或等待 LLM（大语言模型）总结。受管工作区名称优先，其余预算按最近活动纳入未归档会话标题；每个短语最多 40 字符，最多 64 条，去重后使用。
- 名称读取最多等待 1.5 秒；异常或超时使用固定领域词，迟到的结果不能替换本轮词表。当前通话不热更新，下次通话重新取词。
- 单独“会话”采用低权重，完整业务短语采用较高权重；同时提供真实绘画语境，避免只有会话侧词表导致单边偏置。
- 初版单独提高“会话”的权重，在合成的绘画样本中出现误识别；提高全部业务短语权重或扩大束宽也没有消除误识别，因此保留较保守的参数。

## 中文与英文名称编码

Sherpa-ONNX 原生热词解析要求正确的建模单元，错误分词或 OOV（词表外词元）可能直接结束进程。

- 中文模型采用 `cjkchar`（中文字符）编码。
- 当前双语模型采用 `cjkchar+bpe`，随包携带模型官方公开的约 12 KB BPE（字节对编码）词表，不额外下载模型权重。
- 先验证名称可使用的字母词元与 `tokens.txt` 是否兼容。当前双语 `tokens.txt` 没有单独引号和连字符，而归一化名称也不包含这些字符，不能因此错误禁用整个英文词表。
- 不兼容的自定义模型仍可使用能编码的中文词；未知字符、过长标题、非法权重整条跳过，热词协议控制符不进入配置。
- 私有名称只写入权限 0600 的临时文件；原生构造器将词表读入内存后立即删除文件，加载失败也清理。诊断只记录数量或错误类型，不记录名称、转写或音频。

上游依据：[Sherpa-ONNX 热词说明](https://k2-fsa.github.io/sherpa/onnx/hotwords/index.html)、[固定 1.13.8 原生编码实现](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/sherpa-onnx/csrc/utils.cc)、[官方双语 BPE 词表](https://huggingface.co/csukuangfj/sherpa-onnx-streaming-zipformer-bilingual-zh-en-2023-02-20/blob/main/bpe.vocab)。

## 验证

1. 十个测试文件共 104 项通过：语音／文字来源隔离、共同历史和原文保留、真实 Host RPC 传词、管理范围变化、持续通话不重复刷新、归档及范围过滤、数量和长度上限、中文／英文兼容性、临时文件权限与清理、失败重试、元数据超时、多个候选澄清，以及既有句尾、模型验证、租约和管理工具边界。
2. 类型检查、脚本语法和本次涉及文件的差异检查通过。
3. 用户选择使用合成语音：使用本机已安装的 Tingting 和 Eddy 中文音色、180／225 两种语速生成 18 段 16 kHz 单声道 WAV，复用同一批文件对比原贪心解码、束搜索、束搜索加热词。每段文件的 SHA-256 摘要进入报告，以核对三组音频一致。
4. 当前固定参数下，12 段涉及会话的样本，“会话”词面命中从 0/12 升到 3/12；4 段纯绘画样本未被识别成“会话”。“全部指定术语均命中”的指标从 3/16 升到 5/16；两段歧义样本不参加该指标，不能将空预期条件计为成功。

最终独立原生回放的解码指标如下，热词组实际纳入 21 条词语，包括英文 CodingNS：

| 识别方式 | 会话词面命中 | 纯绘画误识别为会话 | RTF | 每帧最长解码耗时 |
| --- | --- | --- | --- | --- |
| 原贪心解码 | 0/12 | 0/4 | 0.053 | 40 ms |
| 束搜索 | 0/12 | 0/4 | 0.062 | 30 ms |
| 束搜索加热词 | 3/12 | 0/4 | 0.053 | 37 ms |

热词组平均每秒音频约需 53 ms 原生解码。在本批样本中没有出现平均解码性能恶化，单次测量不作为跨设备或端到端延迟保证。

词面改善有限，不能声称热词彻底解决了同音词问题。语义层负责结合上下文理解仍为“绘画”的项目查询。纯绘画样本数量也有限，0/4 不代表任意真实语音都不会误识别。

回放记录包含加载耗时、每帧最长解码耗时、RTF（实时因子，解码耗时／音频时长）和首次文字对应的音频位置。加速离线回放不包含网络、LLM、工具查询或播报延迟；加载时间受文件缓存及系统负载影响，不据此声称端到端响应变快。没有调用真实在线 LLM，因此不将 ASR 词面命中率当作语义理解或会话定位成功率。

## 复测入口

保留了通用回放脚本，不需要启动服务：

```bash
node --import ./tests/register-source-loader.mjs scripts/replay-voice-recognition.mjs tmp/voice-homophones/samples.json tmp/voice-homophones/report.json
```

清单格式：`paths` 提供四个绝对模型路径；`entries`、`managedWorkspaceIds`、`workspaces` 提供隔离的名称候选；`samples` 包含 `id`、`file`、`category`、`reference`、`expectedTerms`、`forbiddenTerms`。音频路径相对清单目录，音频要求 16 kHz 单声道 WAV。`category` 使用 `query`、`painting`、`mixed` 或 `ambiguous`；缺少预期词的歧义样本不计入术语命中分母。显式 `hotwords` 和 `maxActivePaths` 可用于独立参数对照。

本轮样本、清单、报告及日志位于被 Git 忽略的 `tmp/voice-homophones/`。脚本不读取默认 Profile，不占用通话租约；各解码模式运行于独立原生进程。真实用户录音及当前在线助理的会话定位效果继续由既有实际使用验收确认。

## 操作边界

只修改本仓库源码、测试、随包词表、打包文件列表、Spec 任务清单和记录；仅从明确归属的 Stage0 配置及识别模型读取当前模型。保留工作区原有改动，未修改模型选择或用户配置，未主动构建、启动或重启 Stage0，也未操作 Desktop。
