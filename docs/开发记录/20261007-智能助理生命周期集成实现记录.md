## 核心判断

值得做。现有项目索引、语音和形象能力已经具备，真正的问题是入口分散、文字与语音各持一份历史、索引变化与清空对话混在一起。把助理档案和连续对话交给 Host（宿主服务）持有，再统一 Client（前端）入口即可，不建立新的会话管理系统。

最关键的数据关系是一位助理对应一份连续对话，项目会话仅提供认知来源，语音租约仅拥有收音与当前语音轮次。最大的风险是迟到回复、初始化写入和索引结果在清理或重置后恢复旧状态，因此所有异步阶段都核对撤销信号或代次。

## 实际界面与使用方式

侧栏图标、悬浮形象、插件设置卡片打开同一工作台。首次进入四项配置与预览，主要字段只有名称、模型、性格背景、形象；窄屏双栏自动上下排列。创建成功进入单栏形象、连续消息和输入区，可随时切换配置。项目关联与声音选择放到创建后的折叠区域，没有助理会话列表、新对话或最近对话。

模型可以固定或跟随 DSH 默认。普通文字交流不依赖语音初始化；没有有效索引时仍可交流，但提示词禁止依据旧历史推断当前项目事实。所选项目自动增量索引，原有五步调试保留在更多设置中。

形象预览复用统一插槽，正式对话遵守形象显示开关。首次创建与试听使用浏览器 TTS，不要求安装 MOSS；创建后声音可选浏览器默认或已就绪的 MOSS 音色。试听不启动麦克风、不进入正式历史。创建后的更多设置复用音频设备、识别模型、音色参数及导入、形象包安装、提示词和索引诊断。资源管理沿用独立保存、立即生效的行为，界面有说明；主要字段统一点击保存。

文字和实时语音共用同一模型上下文与记录。停止语音、关闭工作台或自动更新索引不删除已完成消息。更换范围保留显示记录，清空摘要并划定新的上下文起点，避免旧项目内容进入新范围。

## Host 生命周期与持久化

新增可选档案和模型设置。只有显式 `assistant.profile.initialized=true` 表示已创建；档案缺省或明确未初始化时展示配置与预览，旧模型与形象预填，项目、语音模型和音色资料保留到创建后的能力配置，不清理历史。四项创建默认浏览器输出。Host 每次读取当前档案，不缓存启动时的推导状态；资源准备不提前放行正式文字或语音聊天。

`assistant/lifecycle/read、configure、reset` 负责读取、创建/配置和完整重置；`assistant/conversation/start、read、cancel、preview、clear、compress` 负责正式文字、预览与维护。端点已进入原生及旧 HTTP 白名单；名称、模型、工作区、资源 ID 和输出后端在写入前校验，只读设置拒绝创建与重置。

正式对话保存到当前 `DSH_HOME/codingns4dsh/assistant-conversation.json`，可由 `CODINGNS4DSH_STATE_DIR` 指定自有状态目录。文件以临时文件原子替换，权限为 0600。测试使用注入内存存储或独立临时目录，没有读写真实用户对话文件。

只有完整有效的问答写入记录。请求 ID 去重，最近九轮完整问答参与上下文，持久消息上限 200 条。压缩按完整问答分批整理旧消息，摘要不超过 4000 字符，保留最近三轮；全部批次成功、代次仍有效且保存成功后才替换。失败保留原数据，上游不响应撤销时也立即结算等待者。存储损坏不静默覆盖；完整重置可显式恢复为空记录。

项目选择兼容原生虚拟 ID 和 PeerHost 已显式加入的工作区。目录读取不触发远端登录或正文读取；索引和增量事件按所属 Host 匹配用户选择，远端读取时还原原生工作区 ID，不扩展既有可见范围。

## 维护动作

| 动作 | 实际效果 |
| --- | --- |
| 压缩对话 | 停止当前交流，模型总结旧消息，保留摘要与最近三轮；失败保留原记录 |
| 清理对话 | 停止生成与语音，删除助理消息和摘要，保留配置及项目索引 |
| 重置助理 | 撤销生成、索引、识别模型准备与 TTS（语音合成）操作，等待旧配置写入结算，恢复未创建状态，清空对话及派生缓存 |

清理与重置在界面中有就地二次确认。完整重置保留原始 DSH 项目会话、模型下载文件和形象素材。形象管理沿用已有设置 revision（版本号）与撤销检查；旧操作不能覆盖新的助理配置。模型和音色初始化的撤销信号在异步执行前捕获，保存前复核；完整重置等待旧写入完成后再保存默认配置。旧索引的晚到结果不能重新登记记录或材料。
