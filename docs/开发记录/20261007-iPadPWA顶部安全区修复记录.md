# iPad PWA 顶部安全区修复记录

## 问题

PWA（渐进式 Web 应用）启动页已开启 `viewport-fit=cover` 和透明状态栏，
但 DSH 应用根节点未预留顶部安全区，iPad 状态栏会覆盖主界面顶部按钮。

## 实现

- 在 `src/host/index-injection.ts` 的 PWA 启动页元数据中追加安全区样式，随 PWA 开关注入。
- 通过 `@media (display-mode: standalone)` 限定独立窗口，在 `#root` 上设置 `padding-top: env(safe-area-inset-top, 0px)`。
- 使用 `box-sizing: border-box` 将顶部留白计入根节点原有高度，避免底部内容被挤出视口。
- 不设置屏幕宽度门槛或固定设备高度，iPad 横屏、竖屏和分屏均按系统提供的安全区适配。
- 现有侧栏唤起按钮采用相对视口的固定定位，保留其原有安全区偏移。

- 在独立无头 Edge 浏览器中验证 6 种离线布局：iPad 竖屏、大屏横屏、分屏、手机 PWA、零安全区 PWA、普通浏览器。主界面与右栏顶部正确避让，底部未溢出，未新增页面滚动，悬浮按钮没有重复偏移。
- 无头浏览器不支持模拟独立窗口的显示模式；PWA 场景仅在测试页面中启用对应 CSS 媒体分支，安全区环境变量和布局几何由浏览器实际计算。这不等同于 iPad 真机验收。

## 2026-10-08 真机反馈后的补充修复

### 反馈与判断

用户确认从 iPad 主屏幕 PWA 图标启动，并提供截图：系统时间、网络和电量信息与主界面顶部处于同一区域，右上角按钮的点击区域被状态栏覆盖。

原有根节点安全区样式没有视口宽度限制，因此不能把这个问题归因于 iPad 使用桌面布局。截图只能确认避让效果不足，不能区分样式未注入、独立窗口媒体条件未匹配或安全区值为零。

### 修改

- 主页面与登录页的 `apple-mobile-web-app-status-bar-style` 统一由 `black-translucent` 改为 `default`，优先让 iOS/iPadOS 把页面放在系统状态栏下方。
- 保留原有 `viewport-fit=cover`、独立窗口根节点安全区样式，以及固定定位按钮的安全区偏移；不新增硬编码状态栏高度。
- 不调整移动端宽度门槛，iPad 继续按现有响应式布局显示。
- 同步 Spec 设计与任务说明；现有主页面注入测试和登录页响应测试增加状态栏模式断言。

状态栏行为依据 [Apple Safari HTML 参考文档](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariHTMLRef/Articles/MetaTags.html)：`default` 将内容放在状态栏下方，`black-translucent` 允许状态栏覆盖页面。
