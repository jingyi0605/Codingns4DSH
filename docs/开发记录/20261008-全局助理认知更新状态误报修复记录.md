# 全局助理认知更新状态误报修复记录

## 核心判断

值得修复。“认知更新”一直出现不能证明后台索引卡住。工作台原来把所有不为 `ready`（就绪）的索引状态映射成更新，包括未构建、过期、等待会话结束或未完成；这把结果是否齐全与任务是否正在执行混为一谈。

## 关键洞察

- 数据关系：工作台活动状态与索引就绪状态分别描述助理当前是否工作、索引结果是否可用。
- 复杂度：沿用后台已有的 `building`（构建中）证明，无须在前端重复推导逐会话任务状态。
- 风险：状态查询失败时保留旧 `building`，或查询一直不返回，会让标签永久停留在认知更新。清除前端过期证明不能取消真正运行中的后台索引。

## 实现

1. 只有关联项目且索引状态为构建中时显示认知更新；文字思考、语音活动和用户操作保持原来的优先级。
2. 尚未取得快照时保持未知的索引状态，不再用未构建充当查询结果。未构建、过期、未完成或已就绪均不冒充索引活动；具体索引进度仍在调试页独立显示。
3. 调试元数据查询采用独立十秒期限，同时保留组件生命周期取消信号。失败或超时后失效旧的状态证明，三秒后继续查询；查询不重建或取消后台索引。

- 组件回归验证：初次读取、真实构建、等待会话、查询失败、超时、超时后恢复轮询，以及再次构建；同时断言所有请求均为读取接口。

- 本次源码及测试差异的空白检查通过。
