# 全局助理会话状态与索引进度同步修复记录

## 核心判断

值得修复。原生列表的 `running=false` 和 Agent 的 `idle`（空闲）已经能证明当前轮次结束，但索引展示仅检查另一个 `completed` 布尔值，导致已确认空闲的会话仍显示未知。

## 关键洞察

- 数据关系：会话执行状态、材料版本、已索引版本和模型索引任务是四项不同事实。会话本轮完成不等于项目任务全部完成，也不等于索引完成。
- 复杂度：统一运行状态映射，构建索引和实时版本投影共用一份逻辑，不在界面根据互相矛盾的布尔值猜测。
- 风险：旧索引任务不能覆盖新轮次的进度；远端状态失去证明后，历史空闲不能继续冒充当前状态。

## 实现

1. 明确活动状态优先：本地实时 Agent 状态、远端明确活动状态优先于滞后的列表布尔值；`idle` 映射为本轮已完成，真正缺少状态证明时保留未知。
2. `turn/end`（轮次结束）直接写入空闲证明，不再依赖额外 Agent 通知。兼容明确的 `completed`（完成）等会话状态通知；状态名完整匹配，避免 `incomplete`（未完成）被识别为完成。
3. 审批、提问与错误状态变化纳入版本观察；即使没有等待解除事件，元数据轮询也能发现变化并安排更新。
4. 每个会话独立显示尚未索引、等待本轮完成、等待用户处理、等待状态同步、排队、索引中、索引已完成、待更新、失败或停止。只有当前版本成功提交索引结果才标记完成。
5. 范围会话、结果页原始条目和结构化结果共用最新执行状态。索引材料及证据保持原样，材料版本不会被实时版本替换。
6. 远端状态失去证明时，即使材料版本未变，整体索引也不显示就绪；原有索引问答门禁同步拒绝使用。

界面无需展开会话卡片即可查看执行状态与索引状态；范围列表显示当前版本，结果页明确标记索引材料版本。现有面板轮询和结束后五秒合并索引继续复用。
