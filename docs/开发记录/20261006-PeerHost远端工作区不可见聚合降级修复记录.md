# PeerHost 远端工作区不可见聚合降级修复记录

日期：2026-10-06

## 问题现象

PeerHost 管理窗口能够显示 Host 已连接，并显示已经添加的可见工作区数量，但左侧原生工作区列表没有对应的远端条目。

## 根因

远端工作区聚合读取分为三步：

1. 通过 DSH 原生 `workspace/follow` 首帧读取工作区基线；
2. 通过 `session/list` 补充会话元数据；
3. 通过 CodingNS 私有 `cli/session/adapter-map` 补充适配器标签。

原实现用 `Promise.all` 绑定前两步。目标 DSH 的 `session/list` 因协议、启动时序或会话状态暂时失败时，整个 source 都会 reject；聚合层随后把该 Host 降级成 `unreachable` 且返回空工作区。管理窗口里的 `visibleWorkspaceIds` 仍然是 2，因此出现“可见工作区数量正确、侧栏为空”的假象。

这不是外部 Agent 适配器协议的主故障。适配器映射已经是 best-effort，读取失败只丢失标签；工作区可见性只依赖 DSH 原生 `workspace/follow`。

## 修复

`session/list` 改为 best-effort：读取失败时使用空会话列表，继续投影 `workspace/follow` 返回的已显式添加工作区。这样会话详情暂时不可用时，工作区仍可见，后续聚合刷新可补齐会话。

新增回归用例覆盖 `session/list` 抛错但工作区仍应保留的场景。
