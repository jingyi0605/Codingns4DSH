# 助理配置统一草稿保存与模型路由修复记录

日期：2026-10-07

## 问题与改动

助理工作台原先只暂存身份与项目字段，形象、声音、设备和提示词分别写入正式设置。跨标签编辑会提前影响悬浮形象和播报，后台设置刷新还会覆盖尚未保存的对话模型。页面底部的保存按钮因此不能代表整份配置。

新增 `AssistantConfigurationSession`（助理配置会话），为所有配置标签提供同一份内存设置存储、资源调用代理及独立头像服务。原编辑器的设置操作只改变草稿，正式消息、全局按钮、宠物与语音仍读取原服务。取消、返回对话或关闭窗口丢弃草稿；切换标签保留草稿。身份输入保留编辑中的空白，参数保留空值和待验证数值，不在状态刷新时偷偷恢复默认值。

底部「保存配置」读取最新草稿，显式提交所选模型或跟随默认的 `null`，并通过同一个 `assistant/lifecycle/configure` 请求提交形象、声音和提示词补丁。Host（服务端宿主）在写入前验证整份配置、模型目录、形象登记和声音可用性；验证失败不保存。父字段和子字段修改按真实编辑顺序重放，避免跨标签再次选择形象后被旧草稿覆盖。后台状态刷新保留已编辑字段，更新未编辑字段。

保存后的模型继续通过现有设置读取进入原生助理 Agent（智能代理）的创建参数及每步模型请求。模型变化重建该助理实例，共享连续历史保留；其他 Agent 的模型及思考参数不变。

## 页面行为

- 「显示悬浮宠物」紧邻「悬浮宠物大小」上方。
- 「对话中显示角色」紧邻「对话角色大小」上方。
- 删除用户指定的独立保存及立即生效说明；普通配置底部只保留取消和统一保存。
- 名称在左、44×44 头像与微调入口在右。裁剪弹窗的「确认裁剪」只更新配置页预览，底部保存后才写入浏览器并同步正式消息与按钮。
- 音色选择、播报参数、后端、设备和提示词都随统一保存生效，配置页不再提供重复的应用音色或参数保存按钮。
- 第三方协议在统一保存后持久生效；首次同意尚未保存时不请求 Host 目录，页面提示先保存。许可确认和资源下载仍保留。

## 资源准备与兼容

用户主动点击下载、导入或准备资源时仍会下载和验证文件，并显示原进度；下载不是启用配置。新增 `prepareOnly`（仅准备资源）模式：识别模型返回待保存的路径，MOSS（本地语音合成）准备及声音导入返回待保存的声音记录，不改当前识别环境或输出后端。声音向导保留已选模型，不用宿主旧模型覆盖待保存选择。形象删除和资源移除也延后到统一保存。

Client（浏览器客户端）先查询 `assistant/configuration/capabilities`；旧 Host 不支持时提前报错，不发送可能忽略 `prepareOnly` 而立即启用的旧操作。既有独立设置入口和原资源接口默认行为保持兼容。

Host 设置与浏览器本地头像、设备使用不同存储：先完成 Host 校验及保存，再提交本地裁剪、设备和延期清理。它们并非跨存储原子事务；本地步骤失败时保留配置页和草稿并显示错误，允许重试，不能宣称全部已经成功。取消前已主动下载的资源文件可继续作为缓存保留，正式启用配置不会提前改变。
