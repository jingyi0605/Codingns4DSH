## 实现

### 通话开始预热 MOSS

- Host 在有效语音租约建立后启动异步预热，Client 设备准备、收音和模型回复继续进行，不等待冷启动完成。
- `MossTtsWorker.prepare()` 只加载模型，不占用串行推理名额；预热与首句共用同一个启动异步任务（Promise）。
- `AssistantTtsService` 共享工作进程创建任务，避免异步定位脚本时预热和首句各创建一个 Worker（工作进程管理对象）。
- 通话结束、租约失效或助理重置撤销预热。模型已加载时沿用原有空闲释放机制；初始化和释放继续等待旧资源结算。
- 浏览器语音后端不启动 MOSS；预热失败保留诊断，实际合成仍返回真实错误，不阻塞麦克风启动。

### 模型文字复用事件连接推送

- `AssistantTextChat` 发布累计文字、完成、失败及取消快照；`AssistantVoiceChat` 按持有页面及请求所属代次筛选，已有 RPC 读取接口保留。
- 现有语音 GET（读取）事件连接增加 `chat` 消息，响应首部 `x-codingns-voice-chat-stream: 1` 声明支持推送。Host 再核对活动租约、页面和代次；连接取消释放全部订阅。
- Client 每轮只保留最新累计快照，处理推送早于启动响应的情况；旧请求和旧代次不得覆盖当前字幕或播放。
- 支持推送时立即消费更新；700 ms 没有更新才降级读取 RPC。旧 Host 未声明推送能力时，继续使用原来的 250 ms 轮询。
- 慢连接发生背压时，Host 只保留最新完整累计文字；前文与终态仍在快照内，不无限积压增量。工具明细在持久记录中保留，不随每次文字增量重复传输。
- 文字消费与串行 TTS（语音合成）生成并行，慢播报不阻塞字幕更新；失败不能伪装成完整成功回复。

### 一次通话内复用安装验证

Host 按租约持有页面缓存安装验证异步任务，预热和后续各句共用。Client 实际播报请求传入 `ownerId`，只有同一有效租约可以复用；独立试听、其他页面和下一次通话重新检查。推理失败使缓存失效，初始化、取消及释放清除会话缓存，不能把缓存扩成永久就绪标记。

### 缩短有语音句尾的静音等待

识别端点的 `rule2MinTrailingSilence` 默认从 1.2 秒改为 0.8 秒；没有语音的规则仍为 2.4 秒，最长话语规则仍为 20 秒。通过 `CODINGNS4DSH_VOICE_ENDPOINT_SILENCE_SECONDS` 可恢复 1.2 秒，允许范围为 0.6～2.4 秒，无效值回退 0.8 秒。默认值理论上减少 0.4 秒句尾等待，不等于已经实测减少全部链路延迟。

### 完整字幕与回看

当前轮次的用户输入和助理回复不再分别裁成一到两行，合并到可滚动的字幕区域，最大高度为 `min(280px, 35dvh)`。段落保留完整累计正文，换行可见；滚动条和键盘焦点保留。默认跟随追加文字，用户向上回看时停止强制滚到底部，回到末尾后恢复跟随；新轮次清空字幕时恢复跟随。通话记录仍沿用原有持久历史。

## 验证

16 个相关测试文件共 120 项通过，类型、版本同步、能力退休、脚本语法及本轮定向差异检查通过。覆盖范围包括：

- 实际 Host 事件响应的累计文字、完成状态、页面隔离、订阅释放与慢下行快照合并。
- Client 推送早于启动响应、慢播放期间完整字幕更新、旧轮次过滤、无推送降级及失败取消。
- 模拟识别端点中 650 ms 短暂停顿不结算、0.8 秒有声句尾结算、1.2 秒恢复及无效设置回退；这些测试不能代表真实模型的停顿准确率。
