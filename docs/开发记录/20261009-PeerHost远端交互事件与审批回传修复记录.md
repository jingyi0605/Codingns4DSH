# PeerHost 远端交互事件与审批回传修复记录

## 问题与原因

经 PeerHost 打开远端会话时，普通消息和工具调用记录可以显示，但问题组件、权限审批及计划确认缺少完整交互链路。

- `session/follow` 只负责会话流；原生问题与审批还依赖 `$events` 事件流及 `$events/result` 结果入口。
- 客户端原先只订阅本机事件，结果提交也落到本机。
- 原生 Remote（远程调用）白名单遗漏 `userQuestions/answer`、`userQuestions/attachWait`，问题答案和等待状态无法送达目标 Host。
- `$events` 属于 Gateway（网关）自有协议，不能直接拆成普通的命名空间和方法调用；单纯补白名单不足以修复。

## 实现

1. 保留本机事件流的 `ready`（就绪）帧和本机事件，额外合并各就绪 PeerHost 的会话交互事件。目标端通过 Gateway 的公开 `wireStream.open` 打开原生事件流；结果通过 Connection（连接服务）的公开共享请求入口提交。
2. 每个远端交互登记所属 Host、远端客户端 ID、原始事件 ID、本机客户端 ID 及连接生命周期。交给原生组件前生成独立事件 ID，回答按登记表恢复身份并回传，不跟随当前页面选择。两台 Host 的同名事件不会碰撞。
3. 问题与计划确认使用原生问题组件，审批使用原生审批组件；没有新增弹窗或自动批准逻辑。问题回答仅根据正式 `agentId` 选 Host，答案中的任意字符串不参与路由；失效的远端会话不会回落本机接口。
4. 目标端过滤账号、设置和插件等全局通知。客户端仅接入聚合可见会话的提问、审批事件，其他交互交回目标原生处理链。
5. 单个 Host 断线时撤销其待答事件并独立退避重连；重新连接后的事件取得新身份。取消、移除 Host、模块释放和迟到回答均有清理与校验。
6. 流句柄持有独立取消信号，关闭前先取消挂起读取。读取和关闭均校验完整作用域，禁止其他 Host 关闭句柄。请求完成后解除取消监听，避免 HTTP 响应结束误杀后续轮询；健康长轮询不会因用户长时间未回答而过期。
7. 客户端启停插件时更新事件连接代次，使启动较早的原生事件订阅使用新入口。原生连接形态继续复用本机 mux（流复用通道），不替换本机传输和 UI 组件。

## 验证

使用 `tests/register-source-loader.mjs` 在内存加载 TypeScript 源码，没有执行构建。

- 定向回归 112 项通过，包含原生协议、客户端路由、两端 Host 交互回放、连接兼容、多 Host 隔离和隐私检查。
- 两端回放实际装配 Host Feature、RPC 分发表及流注册表，只替换 HTTP、WebSocket 和监听入口；两台远端使用相同事件 ID，分别验证审批、提问、计划确认、问题答案、等待流和会话 ID 还原。
- 生命周期测试覆盖取消、旧连接迟到回答、单 Host 断线重连、其他 Host 与本机持续可用、作用域不匹配、长期等待及句柄回收。
- `pnpm run typecheck`（不输出构建产物）和 `git diff --check` 通过。

## 生效边界

本次完成源码与模拟协议验证。聚合端及目标 Host 均需加载包含本修复的插件代码，完整事件闭环才能生效；旧版目标不支持事件协议时，只影响该目标的交互流。

后续日志核查发现，`nativeStreamNext` 报“未知 DSH 原生 Remote 方法: $events”时，实际是首次拉取触发目标 Host 的 `nativeStreamOpen`，目标白名单拒绝后由聚合端重新抛出。当前仓库源码与构建目录已登记 `$events`；目标运行实例是否使用旧插件、尚未加载更新或指向其他实例，仍需在对应环境核对。

当前客户端仍将明确不支持协议的错误按断线处理并持续退避重试，因此可能重复产生上述日志。永久不支持错误的停止重试和能力提示尚未实现，现有 112 项回归未覆盖这一降级行为。
