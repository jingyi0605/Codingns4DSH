# 功能模块注册表与设置页驱动记录

日期：2026-09-22

## 这次改了什么

改造前，插件虽然有两个功能模块（局域网访问、中转访问服务），但它们是硬编码的：

- `src/client/index.ts` 里有一份模块清单 `CODINGNS_MODULES`，渲染时靠 `module.id === 'reverseProxy' && ...` 决定画哪个表单。
- 模块开关 `reverseProxyEnabled` 只做两件事：写设置、把表单灰显；它不驱动任何启停。
- `FeatureRegistry` 写得很完整，但只有测试在用它，Host 与 Client 入口都没接。
- Host RPC 是一个 `switch (endpoint)`，所有端点共享同一份闭包状态。

现在改成"模块自己描述界面、自己提供服务，注册表统一管状态"：

- Host 与 Client 入口都创建 `FeatureRegistry`，模块清单集中在 `HOST_FEATURES` 和 `CLIENT_FEATURES`。
- `FeatureDescriptor` 增加 `ui` 字段：标题、说明、排序、是否可关闭、是否默认展开。
- 设置页只做一件事——遍历注册表渲染卡片；卡片内容由模块自己的 `settingsPanel` 提供。
- 设置里的模块开关从扁平布尔字段改成 `modules` 字典，新增模块不再需要改设置 schema。
- 设置变化通过 Host 侧 `SettingsScope.watch` 和 Client 侧 `subscribe` 驱动 `FeatureRegistry.reconcile`。
- Host RPC 改成 `CodingNsRpcTable` 按 `namespace/action` 前缀分发一次；认证动作下沉到 `auth` 模块，模块自己在 `start` 里登记命名空间。
- Client 侧模块通过 `context.services` 拿到设置句柄和 RPC 调用器，不再各自 import 全局单例。

外部 Agent 也采用同样的登记方式：`cliAdapters` Host 模块把不同协议收敛到统一驱动接口。当前内置驱动包括 Command Code、Claude Code、Kimi、Gemini、Pi、Codex、OpenCode 和 Grok；流式 JSON、JSON-RPC/ACP、HTTP/SSE 的私有消息只在 Host 驱动内部转换，Client 只读取标准目录、能力和会话选择。

## 加一个新模块要做什么

Host 侧模块（后台能力，比如终端、文件）：

1. 新建 `src/host/features/<模块名>.ts`，返回 `FeatureModule<CodingNsHostServices>`。
2. `descriptor` 里写 `name`、`version`、`enabledByDefault`、`dependencies`、`runtime: 'host'`。
3. 需要 RPC 时在 `start` 里 `context.services.rpc.register('<命名空间>', handler)` 并登记注销函数。
4. 在 `src/host/features/index.ts` 的 `HOST_FEATURES` 里加一行。

Client 侧模块（浏览器界面，比如局域网访问和中转访问服务）：

1. 新建 `src/client/features/<模块名>.ts`，实现 `CodingNsClientFeatureModule`。
2. `descriptor.ui` 提供 `label`、`description`、`order`；不可关闭的模块声明 `alwaysEnabled`。
3. 需要配置表单时提供 `settingsPanel`。
4. 在 `src/client/features/index.ts` 的 `CLIENT_FEATURES` 里加一行。

两种情况都不需要修改设置页、入口或中心 RPC 分发代码。

## 关键约定

- 模块名同时是依赖引用名和设置里的启用键，一旦发布不要再改名。
- 常驻模块声明 `ui.alwaysEnabled: true`：设置页不提供关闭入口，`reconcile` 也不会停用它。
- 模块不直接操作 DSH 服务，只通过 `context.services` 取用宿主注入的能力。
- 模块创建的资源必须登记到 `context.resources`，不要把清理时序留给自己。
- 用户没有表达过意图时，启用状态回落到模块自己的 `enabledByDefault`（见 `isFeatureEnabled`）。

## 遗留问题

- `specs/spec001-.../tasks.md` 第 92 行引用 `design.md` §3.2.1「CodingNsDshConfig」，但 `design.md` 没有该章节，`CodingNsDshConfig` 也已从代码中移除。这是改造前就存在的失效引用，需要后续单独整理 Spec。
- 中转访问服务模块的 `start` 会建立 DSH H5 Bootstrap；连接失败会在模块资源作用域内退避重试，停用时取消重试并释放 WebRTC、Session 和 Transport。真实四端联调仍未完成。
- 局域网访问DSH卡片负责单一 DSH Web 监听；Host 侧由独立的 `lanAccessDsh` 模块登记监听器和 RPC，不与中转访问服务共享监听器或配置。
- DSH 的 Host 与 Client 共用同一个 cordis `Context` 类型，Host 侧声明会把 `connection` 收窄成 Host 句柄，Client 入口用一次显式收窄（`as unknown as ConnectionHandle`）处理。DSH 若在后续版本补上浏览器侧声明，这段收窄可以删掉。
