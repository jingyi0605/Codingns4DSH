# 前端文案国际化规范

适用范围：`src/client/**`（浏览器可见文案）与 Host 侧向浏览器输出的 HTML / 通知资产。
守卫脚本：`node scripts/check-client-i18n.mjs`（`pnpm run i18n:check`）。

## 一、词典结构

| 位置 | 内容 |
| --- | --- |
| `src/client/locale.ts` | 命名空间声明、`CORE_EN` / `CORE_ZH` 核心词典、注册与取词 API |
| `src/client/locales/<域>.ts` | 各域的 en/zh 片段，只放该域新增键 |

新增域片段时必须同时：

1. 新建 `src/client/locales/<域>.ts`，导出 `en` 与 `zh` 两个 `Record<string, string>`；
2. 在 `src/client/locale.ts` 的 import 与 `en`/`zh` 合并处各加一行。

键名格式：`<域>.<语义>`，例如 `git.commitChanges`。域前缀必须与片段文件对应，避免跨域抢键。
**同一个键不得在两个片段里重复定义**（守卫会把重复键判为错误）。

## 二、取词方式

### React 组件

```ts
const t = useCodingNsTranslator(services.locale)
createElement('button', { 'aria-label': t('git.refresh') }, t('git.refresh'))
```

### 命令式模块（DOM 注入、通知、confirm 等）

```ts
import { resolveCodingNsTranslator, type CodingNsTranslator } from '../locale.js'

export function startXxx(options: { readonly t?: CodingNsTranslator }): XxxController {
  const t = resolveCodingNsTranslator(options.locale)
  ...
}
```

功能模块负责注入 locale：

```ts
startXxx({ ..., locale: context.services.locale })
```

`resolveCodingNsTranslator(undefined)` 会退回内置中文词典，仅用于单测/非 Cordis 宿主；
生产路径必须传 `services.locale`。

### 插值

```ts
t('debug.portListening', { port })   // 词条：'端口 {port} 正在监听' / 'Port {port} is listening'
```

- 参数名只能是 `[A-Za-z0-9_]`（DSH 用 `/\{(\w+)\}/` 替换）。
- 数量、单位、日期等必须整体进词条，不要在代码里拼中文片段。
- 多条并列文案（顿号、分号）要么进词条，要么用已有的分隔符词条。

## 三、禁止事项

以下都会被 `scripts/check-client-i18n.mjs` 阻断：

1. UI 位置出现没有走 `t()` 的中文字面量（含模板字符串）。
2. 把中文当成词典键，例如 `t(ui.label)` 而 `ui.label === '工作区调试'`。
3. `t('xxx')` 使用的键在 en 或 zh 词典中缺失。
4. 词典片段之间出现重复键。
5. 片段内 en/zh 键集合不一致。
6. feature descriptor 的 `ui` 缺少 `labelKey` / `descriptionKey`。

### 只有警告、暂不阻断的情形

- `console.*` / `debug*` 等日志里的中文。
- `new XxxError('中文')` / `throw` 构造的异常文案。它们会在设置页通过
  `error.message` 冒泡成 toast，属于下一轮需要按错误码本地化的对象；
  可用 `pnpm run i18n:check --strict-internal` 升级为阻断。

### allowlist

`scripts/client-i18n-allowlist.json` 只收纳「中文不是插件文案」的正当例外，
每条必须写 `reason`：

```json
[{ "file": "src/client/remote-web-context.ts", "kind": "template-literal", "reason": "注入脚本内的 DSH 原生弹窗选择器与注释" }]
```

支持 `text`（精确或包含匹配）与 `kind: "template-literal"`（整个模板字面量）。
守卫会报告失效条目，避免 allowlist 长期膨胀。

### 逻辑不要依赖中文

禁止用中文正则判断状态（例如 `/失败|错误/u` 判色调、`/已注册/u` 判错误类型）。
先定义稳定的枚举或错误码，再按码取词。

## 四、命令式模块里的浏览器原生对话框

`confirm` / `prompt` / `alert` 文案同样必须取词：

```ts
if (dom.defaultView?.confirm(t('fileMenu.confirmDelete', { name })) !== true) return
```

## 五、feature descriptor

```ts
ui: {
  label: 'Git 仓库管理',              // 仅作词典缺失时的兜底，不再直接渲染
  labelKey: 'feature.gitManagement.label',
  description: '查看改动并管理提交',
  descriptionKey: 'feature.gitManagement.description',
}
```

设置页用 `t(ui.labelKey ?? ui.label)` 渲染，缺 `labelKey` 会静默显示中文，因此守卫强制要求两者。

## 六、Host 侧浏览器资产

Host 没有 DSH Client 的 locale 运行时。约定：

- 由浏览器请求触发的页面（如局域网登录页、manifest）按 `Accept-Language` 选择 zh/en；
- 由 Host 主动推送的内容（如 PWA 会话通知）读取 DSH `locale` 设置命名空间里的
  `preference`，缺失时按 `zh` 兜底；
- 任何新增的 Host 侧可见文案都要在同一个语言选择函数里登记双语词条。

## 七、验证

```bash
node scripts/check-client-i18n.mjs          # 阻断式检查
pnpm run i18n:report                        # 只报告不阻断
pnpm run typecheck && pnpm test
```

守卫同时运行在 `tests/client-i18n.spec.ts` 中，`pnpm test` 会直接失败。
