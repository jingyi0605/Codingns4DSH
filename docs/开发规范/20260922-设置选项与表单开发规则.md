# 设置选项与表单开发规则

## 目的

这份规则约束 DSH 设置页中 CodingNS 功能模块的布局、启停方式和表单交互。新功能应先遵守这里的页面结构，再补充自己的业务字段，避免不同模块各自采用一套布局。

## 页面结构

### 1. 功能模块纵向排列

- 每个功能模块使用一个独立的上下折叠块。
- 模块块在内容区域中纵向排列，不使用左侧模块列表加右侧表单的双栏布局。
- 模块宽度跟随内容区域，表单字段不得因为并排布局被压缩。
- 模块之间保留稳定的垂直间距，模块内部也按垂直方向排列字段。
- 一个模块块可以使用原生 `details` 和 `summary` 表达折叠状态；不要额外维护一套与浏览器折叠状态重复的选中模块状态。

### 2. 标题栏

- 标题栏左侧显示功能模块名称。
- 启用开关放在标题栏最右侧，使用 Switch 表达启用或停用状态。
- Switch 必须使用真实的 checkbox 语义，并通过 `role="switch"`、可读的 `aria-label` 或等效方式让辅助技术识别。
- 点击 Switch 只改变模块启用状态，不应意外触发模块折叠或展开。
- Switch 的可用状态必须跟随设置作用域的可写状态；设置加载中或不可写时，Switch 也要禁用。
- 不使用“打开子菜单”这类额外按钮。模块配置直接位于对应的折叠块中。

## 启用与停用

### 已启用

- 配置表单正常显示并允许编辑。
- 登录、保存、刷新、绑定、解绑等操作按钮按业务状态决定是否可用。
- 网络请求和状态提示只属于当前模块，不得回写其他模块的设置状态。

### 未启用

- 配置结构仍然显示，便于用户了解该模块提供哪些选项。
- 配置区域整体灰显，降低透明度或使用等效的禁用视觉。
- 所有配置输入框、选择控件和业务按钮必须设置 `disabled` 或等效不可操作状态。
- 配置区域应设置 `aria-disabled="true"`，并阻止鼠标事件，避免仅靠视觉灰显却仍能操作。
- 标题栏 Switch 仍然可用，因为用户必须通过它重新启用模块。
- 未启用状态下不得因为隐藏表单而丢失已保存配置；重新启用后应继续使用设置作用域中的值。

## 表单编写规则

- 表单字段使用单列垂直布局，标签、输入框、帮助文字按从上到下的顺序排列。
- 输入框和按钮使用稳定的宽度、内边距和边框，避免内容变化导致页面跳动。
- 异步操作期间，相关输入框和按钮必须禁用，并提供明确的进行中状态。
- 密码输入完成后应清空本地密码状态，不在普通前端状态、日志或快照中保留 refresh token。
- 成功和失败提示放在当前模块内部，不使用全局提示遮挡其他设置。
- 模块停用只改变模块配置状态，不应自动删除登录信息、设备信息或 Host 绑定信息，除非业务需求明确要求。
- 服务地址有多个可选值时使用原生下拉框；新增地址要经过 HTTP(S) 校验并写入设置列表，不能把地址拼进密码或其他敏感字段。
- 地址新增入口与下拉框保持同一行并靠右对齐；新增流程使用模态框，取消模态框不得修改当前已选地址。

## 实现检查清单

提交设置页改动前，至少检查以下内容：

- [ ] 模块是否全部纵向排列，没有左右双栏挤压。
- [ ] Switch 是否位于标题栏右侧，并且有可访问名称。
- [ ] 点击 Switch 是否不会误触发折叠。
- [ ] 未启用时配置是否仍可见、灰显且完全不可操作。
- [ ] 未启用时标题栏 Switch 是否仍可操作。
- [ ] 表单是否在窄窗口下保持单列并且文字不溢出。
- [ ] 是否补充了构建产物或组件行为测试。
- [ ] 是否执行 `pnpm exec tsc --noEmit` 和相关定向测试。
