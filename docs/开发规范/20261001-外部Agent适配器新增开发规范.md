# 外部 Agent 适配器新增开发规范

本文约束后续新增或移植外部 Agent 适配器的实现边界。适配器是 Host 对外部进程的隔离层，不能把外部协议、凭据或版本判断泄漏到 Client 和 DSH 业务模块。

## 目录与注册

- 驱动、协议解析、模型目录和订阅读取器放在 `src/host/cli-adapters/`。
- 在 `feature.ts` 注册驱动，在 `model-catalog.ts` 登记静态回退目录，在 `provider-icons.ts` 和资源目录登记图标。
- 需要 DSH Provider 路由时，只通过 `dsh-virtual-providers.ts` 注册；不得在业务模块直接调用 DSH 版本专属对象。
- 新适配器必须有独立的启用、停用、未安装和释放路径。单个适配器失败不能让 `cli` RPC、设置页或其他适配器消失。

## 驱动契约

驱动必须实现 `detect`、`listModels` 和 `executeTurn`，并按能力实现 `probeSession`、`interrupt`、`dispose`、权限应答和问题应答。统一事件只能从 Host 向上层输出：会话绑定、正文增量、思维增量、工具生命周期、用量和唯一终态。外部协议错误要转换为稳定错误码和可读信息，不能把令牌、完整请求头或原始凭据写入日志。

模型目录必须返回稳定的 `providerId/modelId`，并明确每个模型支持的思维强度。切换模型前校验模型和思维强度属于当前目录；目录加载失败时可以返回静态回退项，但不得伪造动态模型可用。

## ZCode 与账号型 Provider

账号型 Provider 的同步快照必须遵守 app-server 的 `provider/updateAccountConfig` 契约，只发送允许的 `access.type` 与 `access.entitled` 字段；`accountType`、`mode` 等内置身份由 ZCode 的 built-in 配置维护，不能擅自塞进同步快照，否则请求会被 Zod 拒绝。

ZCode app-server 的客户端反向请求必须在首个请求前注册处理器。`session/requestRuntimePreferences` 使用固定默认偏好；`interaction/requestProviderRuntimeHeaders` 必须在 Host 内读取对应账号凭据并返回 `headersApplied/requestAuth`，凭据只能通过本地进程管道传给 app-server，不能进入 Client、事件流或错误文本。

## DSH 虚拟 Provider

DSH 0.2 注册虚拟 Provider 时必须实现 `providerInfo`、`providerRetryPolicy`、`imageRequestPricing`、`listModels`、`resolveModel`、`prepareCall` 和 `stream`。其中 `stream` 在 Feature 已接管时应明确抛出未拦截错误，禁止静默返回空流。fake Context 测试必须调用真实 DSH 注册路径会读取的方法，不能只覆盖当前实现恰好调用的方法。

## 会话、并发与资源

- 进程级 RPC 必须区分请求响应、服务端反向请求和通知；响应返回后仍需保留会话级终态监听。
- 会话绑定必须持久化原始 Provider 会话标识；工作目录变化、进程退出或 Provider 会话缺失时重建并清理旧句柄。
- 取消、打断、释放必须幂等，所有定时器、监听器、pending 请求和子进程都要回收。
- 附件路径、权限状态和工作区路径只传递给外部进程需要的最小字段。

## 用量与订阅

用量读取器必须只返回脱敏摘要，账期余额、剩余额度和 API 用量保持独立字段。Host 保存原始凭据和上游响应，Client 只显示摘要。Token 数量统一使用 `K/M/B` 紧凑格式；时间由浏览器使用 `toLocaleString()` 按本地时区显示。

## 测试与门禁

新增适配器至少覆盖：发现、未安装、模型目录、思维强度切换、首轮创建、连续回合、Provider 会话恢复、反向请求、失败终态、取消、进程退出、用量和凭据缺失。fake 协议夹具必须保持真实消息形状。

完成后运行：

```bash
pnpm run typecheck
pnpm run version:check
pnpm run capability:check
pnpm test
```
