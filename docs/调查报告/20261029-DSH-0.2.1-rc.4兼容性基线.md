# DSH 0.2.1-rc.4 Compatibility Baseline

Date: 2026-10-29

## Scope

Move the repository's DSH verification baseline to `0.2.1-rc.4` while preserving the existing minimum compatibility floor. This is a compatibility update, not a plugin release or a Desktop operation.

## Repository evidence

- The plugin already declares a minimum DSH version of `>=0.2.0-rc.2`.
- Capability routes introduced in the `0.2.1-alpha.3` series use structural probes and semantic version ordering; `0.2.1-rc.4` is expected to use those later routes.
- Existing route tests cover some `0.2.1-rc.4` cases, but the main alpha.3 compatibility and Agent Team fixtures omit it.
- The direct `0.2.1-rc.4` GitHub release page has no release notes. The target is therefore verified through the published package metadata and repository API fixtures, not inferred from a release changelog.

## Compatibility decision

- Keep `>=0.2.0-rc.2` as the supported minimum; do not drop existing supported DSH versions.
- Pin the tested DSH package set and metadata to `0.2.1-rc.4` using the repository version-sync script.
- Add `0.2.1-rc.4` to compatibility fixtures for the post-alpha.3 routes and native plugin manifest checks.
- Validate package synchronization, types, and focused tests. Do not run DSH servers or operate the Desktop profile.
