# DSH 0.2.3-alpha.1 接口差异

对照 npm 中 DSH `0.2.2-rc.5` 与 `0.2.3-alpha.1` 的类型声明、官方实现和插件的 TypeScript 引用。`0.2.2` 未发布正式包，最早可安装的是 `0.2.2-alpha.2`。

| 变化 | 0.2.2 | 0.2.3-alpha.1 | 插件如何处理 |
| --- | --- | --- | --- |
| Web 认证入口 | `connection.authenticatedUrl(baseUrl)` | Token 插件通过有 WebServer 实例作用域的 `webserver/entry-url` 事件贡献入口 | 保留旧方法，新版本请求官方事件。不自行签发凭据 |
| 请求身份 | 调用 `connection.admit()` 只需注入 `connection` | 原生方法还要从调用上下文取 `connection.authentication` | 在适配边界为新宿主增加该依赖；两代都继续使用原生身份判断 |
| 会话实时状态 | `dsh-client-ui-session` 声明 `useSessionStatus` | 类型移到 `dsh-client-ui-session-status`，运行时仍通过同名 Slot 属性注入 | 声明所消费的最小 Hook 类型，不增加旧宿主的必需注入 |
| 模型名称搜索 | Primitives 导出 `rankByName` | 移除该导出，官方模型选择器使用 `dsh-util-text-search` | 保留旧导出探测，缺失时沿用插件已有的名称匹配和排序 |
| Typert 终端服务 | 已发布 Cordis 使用字符串属性 `root` | 新 Typert 基类用 `Context.root` 符号，并新增 `dsh-error` 对等依赖 | 用两代 Gateway 都公开读取的 `typertRemote` 服务绑定，补齐运行依赖，终端 RPC 保持原名 |

官方 npm CLI 在加载插件前导入 `dsh-app-boot` 时失败：发布的 `@deepseek-ai/cordis-plugin-loader@1.1.0` 没有导出 `EntryValidationError`。同版本 [官方源码 tag](https://github.com/deepseek-ai/deepseek-harness/tree/dsh-v0.2.3-alpha.1) 的 `vendor/loader` 有该实现。
