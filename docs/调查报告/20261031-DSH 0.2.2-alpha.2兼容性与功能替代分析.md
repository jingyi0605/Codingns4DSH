# DSH 0.2.2-alpha.2 Compatibility and Feature Replacement Analysis

This report records the compatibility decision for `@jingyi0605/codingns4dsh` after reviewing DSH `0.2.2-alpha.2` against the repository's previously tested DSH `0.2.1-rc.5`.

Sources:

- [DSH v0.2.2-alpha.2 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-alpha.2)
- [DSH v0.2.1-rc.5 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.5)
- [DSH package comparison API](https://api.github.com/repos/deepseek-ai/deepseek-harness/compare/dsh-v0.2.1-rc.5...dsh-v0.2.2-alpha.2)

## Compatibility decision

- Tested DSH: `0.2.2-alpha.2`.
- Minimum DSH: `>=0.2.1-alpha.2`.
- Retired interface generation: DSH `0.2.0-*`.
- Node.js minimum: `24.9.0`, matching the new DSH runtime requirement.
- The plugin continues to allow newer DSH versions with an unverified-version warning.

The old `0.2.0` generation is removed from the install and activation range. Capability routes that were still structurally useful at `0.2.1-alpha.2` retain their adapters, but their lower bounds now begin at `0.2.1-alpha.2`. The pre-alpha.2 continuable-subagent route was removed because its upper bound is below the new compatibility floor.

## Functional changes

DSH `0.2.2-alpha.2` adds several host-owned functions that overlap existing CodingNS features:

| DSH functionality | Plugin overlap | Decision |
| --- | --- | --- |
| Third-party plugin detail pages, updates, and rollback after failed hot update | Host and Client `pluginUpdate` | Mark as full native replacement. |
| Native session-title bundle | Host `sessionTitleOptimization` | Mark as full native replacement. |
| Native terminal bundle | Client `terminalEnhancement` | Mark as full native replacement. |
| Native COT translation bundle | Host and Client `sessionTranslation` | Mark as partial; external Agent translation remains plugin-owned. |
| Worktrees and change requests | Host and Client `gitManagement` | Mark as partial; Git status, history, commit, and push remain plugin-owned. |
| Native session-list search, plugin icons, working-directory presentation, and transcript behavior | Client `workspaceSessionEnhancement` | Mark as partial; plugin-specific workspace and archive presentation remains. |
| File delivery, image upload, image drag, and original-file transfer | Host and Client `fileManagement` | Mark as partial; the plugin editor and workspace file operations remain. |

The markers are stored on `FeatureDescriptor.nativeReplacement` with the DSH feature name, the release where the overlap starts, a `full` or `partial` coverage value, and a bounded note. Partial replacements do not disable the plugin feature.

Other release additions do not replace a CodingNS feature:

- `subagent_oar`, personalized recommendations, and developer statistics are new DSH capabilities rather than replacements for the plugin's external Agent, Magpie, or workspace-debug modules.
- Native SDK file delivery, questions, scheduling, skills, context, and approvals do not replace the plugin's workspace MCP transport contract.
- DSH's native session search and fork semantics improve native sessions but do not replace external Agent session lineage storage.
- Image and Markdown improvements are host rendering behavior and require no plugin feature retirement.

## Interface changes

The package declarations and runtime release notes show these plugin-facing changes between `0.2.1-rc.5` and `0.2.2-alpha.2`:

1. **Session API expansion.** The Session controller adds independent event, projection, and state observation methods, event-page reads, and `wait`; `session/page` now returns an event page shape. The plugin's adapters use capability probes and do not assume the new methods, so the existing consumers remain compatible.
2. **Session lifecycle and projection ownership.** Creation announcements, append timing, cleanup, and asynchronous retained projection handles have stricter lifecycle rules. CodingNS keeps DSH session ownership in the capability boundary and does not introduce a competing session journal.
3. **Agent model selection.** DSH fixes the step model before prompt assembly and retries. Plugin integrations must use `agent.model`; they must not reroute through `agent/request`. Existing CodingNS adapters do not use the removed selection controller methods.
4. **Conditional tools.** Tool availability is now resolved per step through `tools.resolve` and `tools.executable`, with prompt assembly and execution admission using the same decision. Existing external Agent tools remain behind CodingNS's own adapter and capability boundaries.
5. **Typert resource extraction.** Resource declarations may provide a resolver over validated wire arguments instead of only a fixed field. The plugin's remote protocol does not register custom resource declarations, so no source change is required.
6. **PTC execution.** Node PTC gains VM Script mode, the control channel moves to `birpc`, and caller-cancelled `run_code` returns `ABORTED`. CodingNS does not own the PTC runtime and therefore does not translate that result.
7. **Client contracts.** The native composer gains quote insertion and compact previews; session APIs gain richer projection/event streams; UI packages add detail documents, new locales, drag helpers, and raw trajectory JSON. The pinned package update type-checks against these declarations without source import changes.
8. **Runtime requirement.** DSH raises its minimum Node.js version to `24.9.0`; the plugin manifest and profile now declare the same runtime floor.

## Verification scope

- The DSH dependency pins were updated to `0.2.2-alpha.2`.
- `pnpm run typecheck` passes against the alpha.2 package declarations.
- The capability retirement check passes with the new `>=0.2.1-alpha.2` floor.
- Focused compatibility, manifest, capability, and feature-wiring tests cover the retired 0.2.0 boundary and native replacement markers.
- No DSH server, Stage0 process, or Desktop profile was started or modified.
