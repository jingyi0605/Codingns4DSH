# OpenCode V2 协议变化调查

调查日期：2026-10-08。核对版本：OpenCode / `@opencode/client` **2.0.24**。

## 核心判断

模型列表无法加载是实际的协议不兼容。V2 更换了服务探测、认证、目录响应、会话输入和事件结构，仅增加一个模型接口地址不能修复完整对话。

本机原安装为 npm 全局包 `opencode-ai@1.18.34`。调查时该包的 `latest` 仍为 V1，而 V2 的安装包为 `@opencode/cli@2.0.24`，同时提供 `opencode`、`opencode2` 命令。已更换为该 V2 包，命令实际返回 `opencode v2.0.24`。

## 协议对照

| 能力 | 原适配器使用的 V1 协议 | V2 2.0.24 协议 |
| --- | --- | --- |
| 服务探测 | `/global/health`、`/health` | `/api/info`，包含 version、pid |
| 认证 | 原驱动未传认证头 | HTTP Basic（基本认证）；用户名 opencode，serve 默认生成密码 |
| 后台服务发现 | 默认端口 4096 | CLI 的 state/opencode/service.json 登记 URL、PID 和密码 |
| 模型目录 | `/config/providers` 的嵌套 providers/models | `/api/model` 的 `{ location, data: Model.Info[] }` |
| 提供商与默认模型 | 从旧配置推断 | `/api/provider`、`/api/model/default` |
| 模型标识 | providerID/modelID | Model.Ref 使用 `{ providerID, id, variant? }`；Model.Info.modelID 是上游名称，不能替代目录别名 id |
| 思考档位 | variants 对象 | variants 数组，保留每个条目的原生 id |
| 目录作用域 | `?directory=...` | `?location[directory]=...`；创建会话使用 `location.directory` |
| 创建和读取会话 | `/session`、`/session/:id` | `/api/session`、`/api/session/:id`，返回 data 信封 |
| 输入 | `/session/:id/message`，parts/model/variant | `/api/session/:id/prompt`，text/files/skills；模型改由会话创建或 `/model` 选择 |
| 事件订阅 | `/event`，properties/info/part | `/api/event`，事件内容在 data 中，以 sessionID 隔离 |
| 文本与推理 | message.part.updated/delta | session.text/reasoning.delta 与 ended；ended 是完整文本，不能重复输出 |
| 工具 | part.state | session.tool.input/called/progress/success/failed；参数、名称和结果跨事件关联 |
| 完成状态 | session.status idle 等 | session.execution.succeeded/failed/interrupted；step.ended 仅代表一个模型步骤 |
| 权限 | `/permission/:id/reply`，reply | `/api/session/:sessionID/permission/:requestID/reply`，decision |
| 提问 | question.asked 与 answers 二维数组 | form.created，`/api/session/:sessionID/form/:formID/reply`，answer 按字段 key 编码 |
| Skill（技能） | `/skill`，借 command API 调用 | `/api/skill`，prompt.skills 使用 Skill.id |
| 附件 | file part 的 url/mime/filename | files 的 uri/name；可以传内联 data URL |
| 中断 | `/session/:id/abort` | `/api/session/:id/interrupt` |

## 启动快照与现有配置

V2 官方模型接口返回当前快照，不等待插件初始化结束。真实 CLI 验证中观察到两种瞬态：空目录，以及只包含内置模型的非空目录。适配器需要短暂重读确认目录稳定；未收敛的目录不能进入长缓存。

现有 `~/.config/opencode/opencode.json` 仍使用 V1 配置形状。V2 能规范化其中的 provider/options 和默认模型。隔离临时数据库、仅复用该配置读取模型目录后，确认 OpenAI、DeepSeek 及默认模型 `openai/gpt-5.6` 可见。

V2 官方明确把 V1 `whitelist`、`blacklist` 列为不再生效的字段。因此本机这份旧配置在 V2 下会展示更多原生可用模型。该行为来自上游，不通过插件伪造目录，也未擅自改写用户配置。未进行真实付费模型调用，账号计费和远端模型可用性不在这次目录验证范围内。
