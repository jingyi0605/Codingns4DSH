# DSH 0.2.1-rc.3 内容更新与插件兼容性调查

日期：2026-10-24
范围：对比 DSH `0.2.1-rc.2` 与 `0.2.1-rc.3` 的 npm 发布树，说明 rc.3 的实际变更，并逐项评估对 Codingns4DSH 插件的影响。本次只做调查，**未修改任何源码、版本清单或配置**。

对比对象与证据来源：

- Release：https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.3
- npm 元包：`npm pack @deepseek-ai/dsh@0.2.1-rc.2` / `@0.2.1-rc.3`，见 `/tmp/dshrc2`、`/tmp/dshrc3`
- 子包逐字节对比：`app-boot`、`session`、`settings`、`host-webserver`、`client-ui-cordis`、`experimental-agent-team`、`plugin-manager`、`experimental-plugin-market-bundle`、`llm-deepseek-api-key`、`client-ui-conversation`、`client-ui-sidebar`、`client-ui-sidebar-right`、`client-ui-primitives`、`client-ui-plugin-manager`、`client-ui-workspace`、`client-ui-layout`、`client-ui-slots`、`host-plugin-inventory`、`host-frontend-static`
- 新包：`@deepseek-ai/dsh-client-ui-entry-customization@0.2.1-rc.3`
- Web 前端产物：`@deepseek-ai/dsh-web-frontend` 的 `dist/assets/index-*.js|css`
- 发布时间：rc.2 `2026-10-17T08:36:31Z`，rc.3 `2026-10-23T07:54:30Z`；dist-tag `latest` 仍为 `0.2.1-rc.2`，`next` 指向 `0.2.1-rc.3`

## 一句话结论

**rc.3 是纯功能增量的补丁级预发布：本次比对的所有宿主运行时包（server、app-boot、session、settings、agent-team、plugin-manager、connection 侧的 host-webserver 等）与 rc.2 编译字节完全一致，未删除、未改名、未改签名任何已探测的能力结构；唯一的功能新增大头是一个新的浏览器端包 `@deepseek-ai/dsh-client-ui-entry-customization`（左右侧栏与会话视图的三处「更多」菜单），它新增三个 root 级 list 槽位而不改动任何既有槽位语义。因此插件在 rc.3 上的唯一阻断点是插件自身的版本门禁：`DSH_COMPATIBILITY` 上界仍是 `<=0.2.1-rc.2`，`isDshVersionCompatible('0.2.1-rc.3')` 返回 false，Host 与 Client 会整体拒绝启用（而不是降级）。**

## 1. rc.3 官方发布说明与实际内容

Release 正文只有三条（源文与本次核对结果一致）：

| 官方条目 | 实际实现位置 | 是否影响插件接口 |
| --- | --- | --- |
| 新增左侧栏、会话视图、右侧栏的「更多」菜单，便于浏览和创建插件 | 新包 `dsh-client-ui-entry-customization`，由 `dsh-web-app` 的 `cordis.patch.yml` 在 `ui-agent-preset` 之后新增 `entry-customization` 行；`client-ui-sidebar` / `client-ui-conversation` / `client-ui-sidebar-right` 各加一个「更多」按钮与对应 root 级 list 槽位 | 只**新增**槽位，不改变既有槽位 |
| 修复切换会话后点击「新会话」找不回未发送草稿 | `client-ui-workspace` 的 `startSession()` 改为打开 `connectWorkspace()` 解析出的空白会话；`DraftInitializationOptions` 新增 `whenDraftExists: 'replace' \| 'append' \| 'keep'`；`connectWorkspace` 在请求了 preset 时跳过声明其它 preset 的空白会话 | 方法签名未变，只新增可选字段 |
| DeepSeek API Key 适配器的模型列表更新方式与账号登录模式保持一致 | `dsh-llm-deepseek-api-key`：当 `models` 等于内置目录且 Messages origin 为官方 `https://api.deepseek.com` 时，改为 GET 官方 `/models` 列表，新增 `modelsTimeoutMs`（默认 5000）与 `modelsMaxAgeMs`（默认 600000） | 模型 id 粒度，插件不依赖具体 id |

此外本次逐包对比还发现 Release 正文未提及的两处公开面变化（均为**新增**）：

- `client-ui-plugin-manager` 新增 `pluginNavigation.openList()`，供其它 Client 插件在详情页打开插件主列表。
- `client-ui-primitives`：`MenuItemButton` 新增可选 `current`；`Menu` 新增 `minWidthFromAnchor`；`Tooltip` 增加四向翻转与视口兜底（`TooltipSide` 仍为 `right|bottom|top`）；新增图标 `IconAppsAddOutlineRegular/Medium`。**无删除**。

## 2. 对插件的接口影响逐项评估

### 2.1 新增的三个 root 级 list 槽位

| 槽位 | 宿主 | 插件现状 | 结论 |
| --- | --- | --- | --- |
| `sidebar.panellist.actions` | `SidebarRootComponentProps` 增加该 render share；`SidebarRootInjected` 增加 `setPinned`、`trackEntryClick`，`hooks` 增加 `entryPins`、`entryActions` | 插件只注册 `sidebar.panellist`（入口图标）与 `main`（面板页），见 `src/dsh-capabilities/client/global-panel-adapter.ts`；不注册新槽位 | 无影响。注册的 Magpie 等面板会自动出现在「更多」菜单的列表项里（`panels.filter(id !== 'plugins')`，`label` 由 `resolveSlotLabel` 解析，插件的 `label: () => string` 已在上游被解析，rc.3 未改动这段解析） |
| `conversation.session.header.views.actions` | `ConversationSessionHeaderInjected` 增加 `hooks.entryPins`、`hooks.entryActions`、`setPinned` | 插件注入 `conversation.session.header.actions`（会话改动文件计数、子代理折叠谱系），不注册新槽位 | 无影响。Tab 行尾部多一个细的省略号按钮；`conversation.session.header.actions` 是 row 内独立 flex 子项，不受影响 |
| `sidebar.right.tab.guide.actions` | `GuideBodyProps` 增加该 render share；guide 卡新增「解绑」状态，`files` kind 固定显示 | 插件通过 `sidebarRightTabs.register()` 声明终端 guide entry，并注入 `sidebar.right.tab.guide.entry` | 无功能失效：guide 改按 `visibleEntries` 渲染，默认全部 `pinned`；仅在用户主动解绑终端卡后卡片隐藏（意图行为）。卡片下方多一个「更多工具」卡 |

要点：新增槽位都声明为 `kind: 'list'`、`scope: 'root'`，与插件已注册的 list 槽位并列而不是替换；三个宿主组件在无注册时不渲染任何「更多」按钮的点击面（`hasEntryActions` 门控）。插件不注册这些槽位，也不需要注册。

### 2.2 新包的「创建插件」草稿流程

`entry-customization` 的「创建你的插件」会调用：

```ts
uiWorkspace.startSession(undefined, { agentPreset: 'cordis', prompt, whenDraftExists: 'append' })
```

它不清空草稿、不发送消息。本次核对插件侧：插件不调用 `startSession`/`connectWorkspace`/`connectBlank`（`src/` 内命中的 `startSession` 全部是外部 CLI 适配器自己的方法名），也不读取 `DraftInitializationOptions`。因此 rc.3 对空白会话复用与草稿合并语义的调整**不会改变插件行为**。

### 2.3 草稿与输入契约的扩展

- `DraftInitializationOptions` 新增 `whenDraftExists`；`clearPreviousDraft` 保留并等价于 `replace`。
- `composer-submission` 的提交状态新增只读字段 `newSession`、`agentPreset?`。
- 插件只在 `src/client/quick-phrase-slot.ts:62` 读取输入快照的 `draft` 字段（只读用于显隐），未读写上述两个新增字段，也未自行合成输入事件。

结论：无影响。顺带确认 rc.3 中 `conversation.input.left/right`、`conversation.composer.dock`、`conversation.input.dock` 的声明与渲染门控（`sessionId === undefined ? null : …`、`variant === 'composer' && input !== undefined && sessionId !== undefined`）与 rc.2 相同，插件的订阅槽、快捷短语、终端分享入口在空白会话上的可见性保持不变。

### 2.4 右侧栏「更多工具」与会话视图「更多」对用户可见布局的取舍

- 右侧栏 guide 每张卡新增一个「解绑」动作；解绑状态只存内存，插件重载即恢复。插件的终端卡在 guide 中保持原位置（`order: 20`），「更多工具」卡排在最后。
- 会话视图 Tab 行尾部新增省略号按钮，**不改变 View 的折叠/选中逻辑**（`moreTabs` 仅是超出宽度的 View 加未固定的 View）。

结论：属于宿主原生新增控件，插件既有的 `data-conversation-tabs`、`data-sidebar-right-guide-entry`、`data-composer-dock`、`data-shell-overlay` 等 DOM 锚点在 rc.3 Web 前端产物中全部保留（本次对 `dsh-web-frontend` 的 `dist/assets/index-*.js` 做了 `data-*` 属性名集合对比，新旧完全一致）。

### 2.5 模型目录改为官方 `/models` 列举

- 账号路由在 rc.2 就已按 `GET /models` 列表提供模型，rc.3 让 **API Key 路由**行为一致，并新增 `modelsTimeoutMs`/`modelsMaxAgeMs`。
- 已被列表命名的模型受 `client_requirements["deepseek-harness"].min_version` 约束：版本不足时在发起网络前以 `CLIENT_UPGRADE_REQUIRED` 拒绝，未在列表中的内置 id 继续放行。列表没有列出的模型，服务端不存在就会 404。
- 插件对模型的依赖只存在于转译/助手场景：`llm.text` 能力取宿主目录（`src/dsh-capabilities/host/assistant-llm-adapter.ts:15`），会话标题、Git 提交信息、智能助理都按目录选择模型，不硬编码 DSH 内置模型 id。

结论：不构成兼容性问题。可观察变化仅是「DeepSeek 官方 provider 的模型列表由服务端下发」，插件 UI 会跟随展示；若账号侧列表前置要求更高的 harness 版本，新版模型在旧版本上会被拒绝，与插件无关。

### 2.6 逐字节等同确认

以下包 rc.2 与 rc.3 的 `package/` 内容除 `version` 与其依赖的版本号外逐字节一致（`diff -r` 无其它差异）：`dsh-app-boot`、`dsh-session`、`dsh-settings`、`dsh-host-webserver`、`dsh-client-ui-cordis`、`dsh-experimental-agent-team`、`dsh-plugin-manager`、`dsh-experimental-plugin-market-bundle`、`dsh-client-ui-layout`、`dsh-client-ui-slots`、`dsh-host-plugin-inventory`、`dsh-host-frontend-static`。

这意味着插件能力矩阵里依赖 Team 服务、Session Controller 结构、Gateway/Connection、Remote/Typert、槽位注册表等探测点的路由，在 rc.3 上的**结构结果**与 rc.2 完全相同。

## 3. 真正的阻断点：插件版本门禁

| 位置 | 现状 | rc.3 上的结果 |
| --- | --- | --- |
| `version.json` / `profile/version.json` | `dshCompatibility: ">=0.2.0-rc.2 <=0.2.1-rc.2"`，`dshTestedVersion: "0.2.1-rc.2"` | 安装期 `check-dsh-install.mjs` 拒绝 |
| `package.json` | `engines.dsh` 与 `peerDependencies['@deepseek-ai/dsh']` 同上 | DSH `evaluatePluginCompatibility()` 记录不满足 `requirements` |
| `src/shared/contracts/version.ts:13` | `DSH_COMPATIBILITY` 同上 | `isDshVersionCompatible('0.2.1-rc.3') === false` |
| Host 入口 `src/host/dsh-runtime-version.ts:41` | `assertSupportedDshVersion()` | 抛 `DSH_VERSION_UNSUPPORTED`，**Host 不启动** |
| Client 入口 `src/client/dsh-runtime-version.ts` | `assertInjectedDshVersion()` | 抛错，**Client 不启用** |
| 启动页 shim `src/bootstrap/dsh-peer-host-preboot-shim.ts:264` | 生成期烘焙 `supported` 常量 | rc.3 生成空操作脚本 |

实测（只读调用已构建产物）：

```text
isDshVersionCompatible('0.2.1-rc.1') = true
isDshVersionCompatible('0.2.1-rc.2') = true
isDshVersionCompatible('0.2.1-rc.3') = false
```

比较器是严格 semver：预发布段 `['rc','3']` 与 `['rc','2']` 均按数字比较，`rc.3 > rc.2`，因此上界 `<=0.2.1-rc.2` 不成立。**结论：rc.3 上插件整体不可用，这是唯一阻断，且是版本声明问题，不是接口问题。**

## 4. 如果要声明 rc.3 兼容，需要同步修改的位置

> 本节是后续适配的清单，本次调查**未执行任何修改**。

1. `src/shared/contracts/version.ts`：`DSH_VERSION` → `0.2.1-rc.3`，`DSH_COMPATIBILITY` 上界 → `<=0.2.1-rc.3`。
2. `version.json`、`profile/version.json`、`package.json`（`engines.dsh`、peer、各 `@deepseek-ai/dsh-*` 精确 pin）、`profile/package.json`；建议用 `pnpm run version:set-dsh 0.2.1-rc.3 ">=0.2.0-rc.2 <=0.2.1-rc.3"`。
3. `src/dsh-capabilities/matrix.ts` 中上界写死为 `<=0.2.1-rc.2` 的 11 条路由（`session-performance-*-021`、`session-prompt-assembly-021`、`session-external-model-selection-021`、`session-activation-021`、`message-presentation-021`、`connection.peer-021`、`connection.uplink-021`、`agent-team-external-{member,lead}-021`、`conversation-draft-share-021`）以及 `src/dsh-capabilities/routes.ts` 中对应的同一批范围。
   **注意**：`scripts/set-dsh-version.mjs` 用 `replaceAll(previousCompatibility, nextCompatibility)` 做整串替换，`>=0.2.1-alpha.3 <=0.2.1-rc.2` 这类起点不同的串**不会被脚本命中**，必须单独补齐；且本仓库 AGENTS.md 要求「旧、新、当前三个版本都要有 fake Context 测试」，因此建议按「新增 `-022` 路由」而不是直接改旧路由的写法处理，避免破坏历史版本的 fixture。
4. 依赖 rc.2 上界的测试：`tests/dsh-rc2-compatibility.spec.ts`（第 11 行的边界数组与第 18 行「rc.3 必须被拒」的反向断言）、`tests/contracts.spec.ts:214`，以及 `agent-team-bridge`、`terminal-sharing`、`session-performance`、`session-prompt-translation`、`session-model-selection`、`dsh-alpha3-compatibility` 各测试的版本数组。
5. 运行时与脚本：`scripts/run-dsh-stage0.sh`（启动器路径写死 `.../deepseek-harness/0.2.1-rc.2/...`）、`scripts/verify-agent-team-runtime.mjs` 的版本白名单。
6. 校验与报告：`pnpm install --lockfile-only`、`pnpm run version:check`、`pnpm run capability:check`、`pnpm run capability:report`、`pnpm run typecheck`、`pnpm test`。

若**只**放开 `DSH_COMPATIBILITY` 而不动矩阵上界，会出现静默降级（Team 协作被标记为「版本不支持」、消息译文气泡不渲染、终端分享入口消失、外部 Agent 模型选择失效等），因此第 1、3 步必须同时进行。

## 5. 可选的后续增强（非兼容性必需）

- rc.3 让插件面板可以出现在左侧栏「更多」菜单里被固定/解绑。若希望屏蔽或定制这一入口（例如给 Magpie 面板加固定默认值），需要注册 `sidebar.panellist.actions` 或读取 `uiLayout` 的 pin 快照；当前 `global-panel-adapter.ts` 未做任何处理，默认行为已足够。
- 右侧栏 terminal guide 卡支持用户解绑后隐藏，插件的终端恢复逻辑依赖 `sidebarRightTabs` 服务而不是 Dom 可见性，解绑不会导致终端实例丢失；如需在解绑后给出提示，可后续评估。
- `conversation.draft-share` 路由的探测目前不校验 `input.actions.captureInsertion`/`persistDraft`，缺失时会在 `insert()` 内部抛错而不是探测失败；这是 rc.2 就存在的小隐患，建议在新的 rc.3 路由里补齐这两个探测点。
