# macOS 27 本地网络隐私与 tmux 终端联网

## 现象

macOS 升级到 27 后，DSH 终端里的第三方程序（node、bun、Homebrew 工具）连局域网失败，
`EHOSTUNREACH` 或 `ECONNREFUSED`，耗时只有几毫秒。Apple 自带的 `nc`、`ssh`、`ping` 正常。
在 Terminal.app 里运行同样的命令正常。

## 结论

问题出在 macOS 的“本地网络隐私”按**责任进程**判定，不在网络或数据库。

- 苹果自带的二进制豁免；第三方二进制需要授权。
- 责任进程在进程创建时固定，之后不会改变。
- launchd 用户 LaunchAgent 以自己为责任进程。没有应用标识的第三方二进制（ad-hoc 签名的 tmux、
  node 等）会被静默拒绝，也不会弹授权框。

## 实测（macOS 27.2，临时 socket，同一目标 `10.255.0.1:443`）

| tmux 服务由谁拉起 | node | bun | nc |
|---|---|---|---|
| 我的 shell 直接拉起 | OK | OK | OK |
| launchd 直接跑 `tmux start-server` | EHOSTUNREACH | ECONNREFUSED | OK |
| launchd → `/usr/bin/osascript` → `tmux -D` | OK | OK | — |

## 三种启动方式的问题

1. **Desktop 直接拉起**：责任进程是 Desktop 当次的进程。Desktop 彻底退出后，仍存活的服务和其中的
   Shell 失去归属，第三方程序再连局域网会被拒绝。（这条推断与 Orca #29476 的描述一致，但
   没有在本机用“重启 DSH”单独证实。）
2. **launchd 直接拉起 tmux**（提交 `8735fe90` 的做法）：tmux 是没有应用标识的第三方进程，从一开始
   就被拒。这是此前“修复”无效甚至更糟的原因。
3. **launchd 经 osascript 拉起 `tmux -D`**（当前做法）：责任进程是苹果自带的 osascript，被豁免，
   且不依赖 DSH 进程。`-D` 让 tmux 留在前台，osascript 才会一直存活。

## 另一个缺陷：服务器就绪状态被永久缓存

`ensureServer()` 成功一次后缓存 `serverReady`，之后不再检查服务是否还活着。服务在 Host 存活期间
退出（例如手动 `kill-server`）后，下一次 `new-session` 会由 Host 直接把服务拉起来，绕开 launchd。
现已改为缓存命中时也探测服务是否存活。

## 排查方法

服务启动记录写在 `/tmp/codingns4dsh-501/launch.log`，每行一条 JSON，不依赖调试开关：

- `launcher`：`launchd`、`host-direct` 或 `unknown`
- `parentCommand`：经 osascript 拉起时应为 `/usr/bin/osascript ...`
- `outcome`：launchd 各步骤的结局，失败时带 `status` 和 `stderr`

手动确认当前服务是谁拉起的：

```bash
ps -E -p "$(tmux -S /tmp/codingns4dsh-501/codingns4dsh.sock display-message -p '#{pid}')" -o command= | tr ' ' '\n' | grep -E '^(XPC|__CF)'
```

`XPC_SERVICE_NAME` 等于 launchd 标签表示由 launchd 拉起；为 `0` 表示由 Desktop 直接拉起。

## 已知限制

- osascript 作为责任进程依赖未公开的系统行为（Hermes 在 26.3 上验证过，本次在 27.2 上验证），
  苹果以后可能改变。
- macOS 27 具体改了什么没有官方发布说明。论坛上有报告称 26/27 起子进程不再继承本地网络权限
  （反馈编号 FB24035385），苹果 DTS 也提到 27.0.1 与 27.2 之间行为有明显差异。这是间接证据。
- 升级后已经存在的旧服务（直接拉起或 launchd 直接拉起）不会被替换，需要手动
  `tmux -S /tmp/codingns4dsh-501/codingns4dsh.sock kill-server` 一次，再新开终端。
- 其他可选方案：带稳定签名身份的 `.app` 宿主配合 `AssociatedBundleIdentifiers`；
  `defaults write com.apple.network.local-network Allowed…LocalNetworkAddresses`（需要 sudo 并重启，格式未验证）。
