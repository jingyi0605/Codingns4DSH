# DSH 0.2.2-rc.2 兼容性调查

## 结论

DSH `0.2.2-rc.2` 可以作为 Codingns4DSH `0.2.2-rc.2` 的已验证运行时。插件的最低兼容版本继续保持 `>=0.2.1-alpha.2`。本次升级的实质性破坏性变化集中在 Agent Team；Web、Session 和 UI 接口以增量扩展为主。侧栏会话资源仍保留一个会话关闭后的 rejected `ready` 日志误报，需要继续沿用已有的 Host 资源兼容路由。

## 上游变更

上游发布说明列出以下与本插件直接相关的变化：

- SubAgent 支持具名子代理和多层协作。
- AgentTeam 改为按会话启用，并使用共享成员与任务面板。
- AgentTeam 统一使用具名 SubAgent；中断工具默认关闭。
- Session 支持批量追加事件。
- Web Search 增加查询和来源上限控制，并切换到新的默认搜索提供方。
- 工具失败提供结构化错误类型和错误代码。
- 菜单定位改为支持缩放、平移和长列表场景；自定义浮层需要使用新的定位参数。
- 侧栏会话 bundle 的 `SidebarSessionView` 仍在视图被 `dispose()` 后记录 `ready` 拒绝；rc.2 改为压缩单行 bundle，逻辑仍缺少 `disposed` 守卫。

依据：DSH `v0.2.2-rc.2` GitHub Release 页面。

## 实际接口差异

### Agent Team 与 SubAgent

rc.1 时代的 `ctx.agentTeams` 同时承担成员身份、成员列表、消息、创建队友、中断、任务和等待。rc.2 将职责拆分：

| 业务能力 | rc.1 入口 | rc.2 入口 |
| --- | --- | --- |
| Team 开关 | 隐含在 Team 服务可用性 | `agentTeams.isEnabled(agent)` |
| 任务面板 | `agentTeams.listTasks/getTask/createTask/updateTask` | 保持在 `agentTeams`，任务更新继续使用 `expectedRevision` 和 `action` |
| 成员身份 | `agentTeams.membership(agent)` | `subagents.namesOf(agent)`、`subagents.rootOf(agent)` |
| 成员发现 | `agentTeams.listMembers(agent)` | `subagents.listDescendants(rootSessionId)` |
| 消息 | `agentTeams.sendMessage(agent, request)` | `subagents.resolveName(...)` 后调用 `subagents.sendMessage(sender, targetId, content, { signal })` |
| 创建队友 | `agentTeams.spawnTeammate(agent, request)` | `subagents.startActivation({ provider, parent, label, name, prompt, delivery, signal, ... })` |
| 中断 | `agentTeams.interrupt(agent, targetName)` | `subagents.interrupt(targetSessionId, { kind: 'ancestor', agent })`；公共 Team 中断能力单独判断 |
| 等待 | `agentTeams.waitForChange(...)` | rc.2 没有同名 Team 等待方法；适配器组合成员/任务快照，并使用有界轮询或 SubAgent 活动等待 |

rc.2 的 Team 任务面板还要求通过 `sessions.flush()` 确认持久化；未确认时返回 `TEAM_TASK_PERSISTENCE_UNCONFIRMED`。插件保留这个错误，不把它改写成成功。

### Web Search / Fetch

`ctx.web.search(request, signal?)` 和 `ctx.web.fetch(request, signal?)` 的方法名保持不变。Search 请求新增可选 `maxResults`，结果来源可带 `summary`，并可能标记 `truncated`。插件原有桥接可以继续工作；本次增加了对错误 `code`、`errorCode` 和 `error_code` 的转发，避免丢失 rc.2 的结构化诊断。

### Session

rc.2 的 Session 支持一次追加多个事件，日志格式不变。插件的会话写入边界仍按单事件调用，未自行包装或重写原生 `append`，因此没有发现签名冲突。后续如果出现批量写入拦截器，应同时接受单事件和事件数组。

### Context Menu 与浮层

rc.2 的 context-menu 客户端服务仍保留 `register()`、`notify()` 和贡献项的 `target/order/resolve` 结构，但目标对象现在以 `{ kind, value }` 形式捕获，菜单打开位置使用 `{ x, y }` 坐标；`Menu` 原语增加了 `contextual`、`anchorPoint` 等定位参数。插件当前的 Context Menu 适配器只负责注册文件操作贡献项，由 DSH 负责目标捕获和菜单定位，因此不需要改变业务贡献项。

插件自有的树状目录、翻译详情、终端选区和账户菜单包含手工浮层定位代码。这些属于后续 UI 行为回归重点；rc.2 类型检查已通过，当前升级没有把它们错误地伪装成新的原生 context-menu 贡献项。

## 本插件需要修改的接口

本次实际修改了以下兼容边界：

1. `src/dsh-capabilities/host/agent-team-adapter.ts`：加入 rc.2 Team/SubAgent 双接口适配、会话 Team 开关、具名成员解析、任务所有者 Session ID 转换、有界等待和独立中断能力。
2. `src/host/cli-adapters/native-team-proxy.ts`、`src/host/index.ts`：原生 Team Proxy 接入 `ctx.subagents`，并保留旧 TeamService 的 `this` 绑定和转发路径。
3. `src/host/cli-bridge/team-dispatch.ts`：等待操作接收异步成员快照，并向 rc.2 `startActivation` 传递原生模型和推理强度。
4. `src/shared/contracts/agent-team.ts` 及各外部传输注入：Team schema 和 guidance 可以按 `CODINGNS_TEAM_INTERRUPT` 单独暴露中断 action；rc.2 默认隐藏该 action。
5. `src/dsh-capabilities/routes.ts`：原生 Team capability probe 同时识别旧版 TeamService 和 rc.2 的 Team/SubAgent 结构。
6. `src/host/cli-bridge/search-dispatch.ts`、`fetch-dispatch.ts`、`mcp-stdio-entry.ts`：保留 WebError 的机器可读错误代码。
7. `src/dsh-capabilities/host/sidebar-session-compat.ts`、`src/host/index.ts`：把 rc.2 的压缩侧栏 bundle 纳入已核对版本，并在资源响应层加入 `disposed` 守卫；保留旧版格式匹配和 immutable 缓存隔离。

无需修改的边界包括 Web 方法名、Session 日志格式、Context Menu 注册业务数据结构，以及插件的最低 DSH 兼容范围。Web Search 的默认提供方迁移属于 DSH 配置和账号选择，插件只透传原生 Web 服务，不自行替换提供方。
