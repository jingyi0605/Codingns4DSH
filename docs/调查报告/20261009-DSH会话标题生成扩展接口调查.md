# DSH 会话标题生成扩展接口调查

## 问题与证据

归档列表直接显示会话的标题投影。截图中末尾停在“会”“记”“当”的标题，符合标题内容已被字节上限裁短的表现；仅凭截图不能确定每条会话的模型请求为何失败。

本轮核对 DSH 0.2.1-alpha.1 同版标题包的默认策略：

| 环节 | 默认策略 | 影响 |
| --- | --- | --- |
| 确定性兜底 | 最多 5 词、40 UTF-8 字节 | 连续中文通常只能留下约 13 字，不保证句意完整 |
| 模型提示词 | 中文约 10 字、其他语言约 5 词 | 偏向很短的标题 |
| 模型请求 | 输出上限 64 token（模型文本单位），60 秒超时 | 不保证所选提供方能够执行辅助标题请求 |
| 接纳标题 | 最多 80 UTF-8 字节 | 模型结果太长时也会被宿主裁短 |

接口结构还与仓库现有上游源码归档交叉核对：`data/deepseek-harness-4878cdabd87d4041bdaff61d04c966883b9fd07a.zip`，其中标题包版本为 `0.2.0-rc.1`。重点检查路径为 `packages/session/session-title/src/index.ts`、`packages/session/session-title/src/normalize.ts`、`packages/session/session-title-llm/src/index.ts`。

## 标题所有权与路由

- DSH 的 `sessionTitle` 服务管理侧栏和归档列表标题，维护兜底、提供方生成、人工命名三种来源。
- 原生 `rename()` 会取消旧生成并固定人工标题；生成结果是否仍有权接纳，由原生修订状态和取消信号决定。
- `session/title` 是持久日志事件，客户端标题投影读取它，不进入主对话模型历史。
- 原生模型标题请求带有 `purpose: 'session-title'`、会话 ID、冻结的消息和取消信号，经 `llm/stream` 中间件链派发。
- 输入帧为 `Generate the session title from this JSON array of human messages:` 加换行与 `{ seq, text }` 数组。首条消息与全部消息标题提供方共用这个协议。
- 标题模型可单独指定提供方和模型；没有覆盖配置时，使用已记录的主请求路由。

CodingNS 的 CLI 中间件对 `session-title` 放行。外部 Agent 的虚拟提供方不能据此自动获得原生辅助模型调用能力，因此路由到虚拟提供方存在失败路径；本轮没有读取截图会话的实际请求日志，不能把该路径当作所有截图标题的已证实原因。

## 可扩展边界

原生标题服务只允许一个标题提供方注册。插件不应强行替换已经注册的提供方，也不应修改宿主私有字段。

可在 `llm/stream` 边界识别已核对的原生标题帧，改善提示词和输出校验，再交回原生生成器接纳。这样保留原生路由、生成时机、输入选择、持久化和人工命名保护。

能力边界新增 `session.title`，结构检查 `sessionTitle.get()`、`sessions.get()` 和事件注册接口；与已有 `llm.text` 共同使用。路由范围沿用插件支持的 `>=0.2.0-rc.2 <=0.2.1-alpha.1`。不支持的旧版本与缺失服务只停用标题优化，并给出能力诊断。

兼容性测试包括 `0.1.5-rc.3`、`0.1.6-alpha.2`、`0.1.7-rc.2`、`0.2.0-rc.2` 和 `0.2.1-alpha.1` 的模拟 Context（宿主上下文），另使用真实 Cordis（插件框架）验证服务读取和中间件链。本轮未启动宿主或调用线上模型。

实现及验证见 `docs/开发记录/20261009-DSH会话标题优化设置与生成逻辑实现记录.md`。
