# 外部会话持久化与 DSH 原生侧栏集成

## 结论

外部 Agent 的会话分成两部分保存：DSH 原生 Session 保存消息时间线，CodingNS Host 的 `CodingNsCliSessionStore` 保存适配器恢复所需的摘要。两者使用同一个 `dshSessionId` 关联，但不把 Provider 的会话编号当成 DSH 会话编号。

外部 Agent 的正文、推理、用量和终态仍然经过 Host 的 `llm/stream` waterfall 返回给 DSH Agent Loop。Agent Loop 负责追加 `turn/start`、`user/message`、`assistant/message` 和 `turn/end` 等原生事件，DSH 原生消息页面和侧栏读取这些事件。外部 CLI 已经执行完成的工具不能转换成模型流中的 `tool-call`，否则 Agent Loop 会再次执行；公共投影层改为直接追加成对的 DSH `tool/call` 与 `tool/result` 历史事件，只负责持久化和展示。各 CLI 驱动不依赖 DSH 消息协议，插件也没有复制消息列表。

## DSH 原生 API 边界

DSH `0.1.6-alpha.2` 提供的 `ctx.sessions` 是内存 `SessionStore`，包含 `get`、`list`、`create`、`flush` 等能力。它本身不负责磁盘持久化，持久化由宿主监听 `session/event` 和 `session/flush` 完成。完整 Host 还提供 `ctx.sessionController` 和 `ctx.workspaceController`：前者负责原生会话的创建和读取，后者的 `archiveSession`/`unarchiveSession` 负责改变原生侧栏可见性。

插件通过 `native-session-bridge.ts` 采用运行时探测，不把这些可选服务写进强制注入依赖。这样精简 Host 没有完整会话服务时仍能启动；完整 DSH 则复用已经存在的原生会话，必要时调用原生 Controller 创建指定 `dshSessionId`。插件不会用裸 `SessionStore.create` 伪造一个绑定插件 Fiber 生命周期的短命会话。

## Host 会话索引

`CodingNsCliSessionStore` 保存以下字段：适配器、模型、思考等级、Provider 会话编号、工作目录、标题、运行状态、Provider 存在状态和时间戳。运行状态仍是 `active/idle/error/archived`；Provider 存在状态独立为 `unchecked/available/missing/corrupt/unreachable/unknown/ephemeral`，不会再把“执行失败”和“原始会话已删除”混成一种状态。它使用设置 Scope 作为默认持久化后端，也允许注入独立后端；写入按队列串行化，Host 停止功能模块时先等待 `flush()`。冷启动会把崩溃前遗留的 `active` 归一为 `idle`，运行期设置回写则保留真实活动状态。

`providerSessionId` 是恢复 Provider 会话所需的 opaque 标识，`rawStoreRef` 可能是 Host 本地路径或其他内部引用。后者永远不会通过 `settings/get` 或 `cli/session/list` 暴露给浏览器；浏览器侧还会再次脱敏。凭据、原始 Provider 消息和进程句柄不进入索引。

Host 提供以下 RPC：

- `cli/session/get`、`cli/session/set`：读取或设置当前 DSH 会话的适配器绑定。
- `cli/session/list`：读取外部会话摘要，并在缓存过期后只读检查 Provider 原始会话。
- `cli/session/archive`：先调用 DSH 原生归档，再保留 CodingNS 绑定墓碑，便于从归档区恢复后继续识别适配器类型和 Provider 状态。
- `cli/session/steer`、`cli/session/follow-up`、`cli/session/interrupt`：调用适配器的运行中控制能力。

Client 设置页显示外部会话摘要和 Provider 状态。原始会话确认删除后显示“原始会话已删除”：用户仍可打开 DSH 历史，但恢复执行会被 Host 拒绝；点击“移除”会调用 DSH 原生归档，从侧栏隐藏记录，不删除 DSH 消息。原生归档不可用时不会先删插件索引；执行和归档按会话互斥，归档 tombstone 也不会被迟到的完成事件改回 `idle`。

## 原始会话检查

只有权威的文件不存在、HTTP 404 或等价的 Provider `not found` 才会标记 `missing`，并且默认间隔两秒连续确认两次。CLI 未安装、服务离线、超时和权限不足分别保持 `unknown` 或 `unreachable`，不能误报为删除。会话列表使用 60 秒检查缓存、4 路并发和单次 10 秒超时，恢复外部会话前强制复查；运行中的会话不做后台检查。磁盘扫描和 OpenCode HTTP 请求都会响应超时的 `AbortSignal`。`rawStoreRef` 只作为提示，即使旧路径不存在、内容损坏或已被复用，也会继续扫描 Provider 权威目录。

- Claude Code：按会话编号定位项目目录下的 JSONL，并核对首条记录的 `sessionId`。
- Kimi：定位会话目录并验证 `context.jsonl`。
- Gemini：定位 chat JSONL，并核对完整 `sessionId`。
- Codex：检查 sessions/archived_sessions 中的 rollout JSONL，并核对 `session_meta`。
- Pi：检查 JSONL 首条 `type=session` 和会话编号。
- Grok：检查会话目录及其 `updates.jsonl`。
- OpenCode：调用已托管或已连接 server 的只读 `GET /session/{id}`；只有 404 是删除。
- Command Code：当前使用单轮临时 transcript，标记为 `ephemeral`，不存在可删除的 Provider 长期会话。

## 外部工具历史

适配器把工具生命周期转换成统一观察事件，包括工具名、调用编号、状态、参数、结果、错误、子 Agent 编号和详情。结果通过 `outputMode=delta|snapshot` 明确表达增量或累计快照，不再根据字符串前后缀猜测。`CodingNsDshToolHistoryProjector` 对所有外部 Agent 使用同一套聚合逻辑，直到本轮结束再提交最终结果，因此迟到的最终 snapshot 仍会进入同一个调用。

公共投影层统一处理工具别名和参数字段，例如 `shell_command` 映射为 `bash`、`edit_file` 映射为 `edit`。`edit` 和 `write` 会生成 DSH 文件工具使用的 diff 元数据，因此可复用原生编辑组件；Command Code、Claude Code 等驱动只产出统一事件，不分别对接 DSH。为避免异常 Provider 无限放大日志，每字段最多 64 KiB、每调用最多 192 KiB、每轮字段总量最多 768 KiB，并且每轮最多保存 256 个调用。

DSH `0.1.6-alpha.2` 的 `Session.append()` 可以直接保存 `tool/call` 和带 `surfaceOp: append`、`sourceEventSeqs` 的 `tool/result`。这条历史事件接口不会进入 Agent Loop 的工具调度器；真正会触发执行的是模型流中的 `tool-call` 内容块。桥接层从活动 `step/start` 读取 turn/step，保持调用和结果的来源关系。原生 Session 或活动 step 不可用时只跳过工具展示，不把内部调用编号和参数降级塞进 Assistant 正文。

同样，原生 Workspace 会话行没有 badge/trailing Slot。插件可在 CodingNS 的外部会话列表显示适配器和删除状态，也可通过原生 API 归档侧栏记录，但不能把徽标直接插入原生侧栏行；禁止使用 DOM 补丁、篡改标题或复制整个 WorkspaceBrowser。

## 各适配器的长期会话

- Command Code：每轮根据 DSH 历史生成 transcript，Provider 进程可退出，长期状态由 DSH 会话历史维持。
- Claude Code、Kimi、Gemini：每轮可以启动新进程，但持久化 Provider 会话编号并通过 `resume`、`--session` 或 ACP `session/load` 恢复。
- Pi：同一 DSH 会话跨轮复用 RPC 进程；Host 重启后首次执行使用持久化编号发送一次 `resume`。
- Codex：同一 DSH 会话复用 app-server thread；Host 重启后通过 `thread/resume` 恢复。
- Grok：同一 DSH 会话复用 ACP 进程；新进程优先 `session/load`，不支持时建立新 Provider 会话并更新绑定。
- OpenCode：使用本地 server 的持久化 session id；插件只托管自己启动的 server，外部 server 不会被停止。
