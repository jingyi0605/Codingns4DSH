# 外部会话持久化与 DSH 原生侧栏集成

## 结论

外部 Agent 的会话分成两部分保存：DSH 原生 Session 保存消息时间线，CodingNS Host 的 `CodingNsCliSessionStore` 保存适配器恢复所需的摘要。两者使用同一个 `dshSessionId` 关联，但不把 Provider 的会话编号当成 DSH 会话编号。

外部 Agent 的输出仍然经过 Host 的 `llm/stream` waterfall 返回给 DSH Agent Loop。Agent Loop 负责追加 `turn/start`、`user/message`、`assistant/message`、`tool/call`、`tool/result` 和 `turn/end` 等原生事件，DSH 原生消息页面和侧栏读取这些事件。插件没有注册不存在的 sidebar/message Slot，也没有复制一套消息组件。

## DSH 原生 API 边界

DSH `0.1.6-alpha.2` 提供的 `ctx.sessions` 是内存 `SessionStore`，包含 `get`、`list`、`create`、`flush` 等能力。它本身不负责磁盘持久化，持久化由宿主监听 `session/event` 和 `session/flush` 完成。完整 Host 还可能提供 `ctx.sessionController`，其 `create/list` 结果会进入 DSH 原生侧栏的会话投影。

插件通过 `native-session-bridge.ts` 采用运行时探测，不把 `sessions` 或 `sessionController` 写进强制注入依赖。这样精简 Host 没有会话服务时仍能启动；完整 DSH 则复用已经存在的原生会话，必要时调用原生 Controller 创建指定 `dshSessionId`。插件不会用裸 `SessionStore.create` 伪造一个绑定插件 Fiber 生命周期的短命会话。

## Host 会话索引

`CodingNsCliSessionStore` 保存以下字段：适配器、模型、思考等级、Provider 会话编号、工作目录、标题、状态和时间戳。它使用设置 Scope 作为默认持久化后端，也允许注入独立后端；写入按队列串行化，Host 停止功能模块时先等待 `flush()`。

`providerSessionId` 是恢复 Provider 会话所需的 opaque 标识，`rawStoreRef` 可能是 Host 本地路径或其他内部引用。后者永远不会通过 `settings/get` 或 `cli/session/list` 暴露给浏览器；浏览器侧还会再次脱敏。凭据、原始 Provider 消息和进程句柄不进入索引。

Host 提供以下 RPC：

- `cli/session/get`、`cli/session/set`：读取或设置当前 DSH 会话的适配器绑定。
- `cli/session/list`、`cli/session/archive`：读取外部会话摘要和归档记录。
- `cli/session/steer`、`cli/session/follow-up`、`cli/session/interrupt`：调用适配器的运行中控制能力。

Client 设置页只显示外部会话摘要。点击“打开”时保存适配器绑定，然后切换到 DSH 原生会话路由；消息由 DSH 原生会话页面渲染。

## 各适配器的长期会话

- Command Code：每轮根据 DSH 历史生成 transcript，Provider 进程可退出，长期状态由 DSH 会话历史维持。
- Claude Code、Kimi、Gemini：每轮可以启动新进程，但持久化 Provider 会话编号并通过 `resume`、`--session` 或 ACP `session/load` 恢复。
- Pi：同一 DSH 会话跨轮复用 RPC 进程；Host 重启后首次执行使用持久化编号发送一次 `resume`。
- Codex：同一 DSH 会话复用 app-server thread；Host 重启后通过 `thread/resume` 恢复。
- Grok：同一 DSH 会话复用 ACP 进程；新进程优先 `session/load`，不支持时建立新 Provider 会话并更新绑定。
- OpenCode：使用本地 server 的持久化 session id；插件只托管自己启动的 server，外部 server 不会被停止。

## 验证范围

本轮已通过 `pnpm exec tsc --noEmit`、`pnpm build`、`node --test tests/*.spec.ts`（120/120）和 `git diff --check`。测试覆盖 Host 索引串行写入、Host-only 字段脱敏、原生会话桥接、Client 恢复入口、fake RPC/SSE/stream 驱动及取消清理。

真实 CLI 的具体版本差异、真实 DSH 宿主的磁盘 Session persistence 插件和远程 Host/Client 联调仍需在目标运行环境人工验收。
