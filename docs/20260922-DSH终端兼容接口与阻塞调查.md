# DSH 终端兼容接口与阻塞调查

## 调查范围

本记录针对 DSH `0.1.6-alpha.2`，核对官方 terminal controller、浏览器
`webTerminals` 服务、侧栏终端 UI 和 Bundle patch 行为。调查只读取本机已安装
的 DSH 包，没有调用 CodingNS 父仓库或 `apps/host/src` 私有实现。

## Host Remote 契约

官方 Host 服务名是 `terminalController`，wire namespace 是 `terminal`。兼容
controller 必须提供以下十个方法：

| 方法 | 用途 |
| --- | --- |
| `environment` | 返回 cwd、输入与尺寸上限、scrollback |
| `shells` | 返回 Host 验证过的 shell 列表 |
| `list` | 按 DSH session 列出可恢复终端，不激活 Agent |
| `create` | 按调用方生成的 terminal id 幂等创建 |
| `retain` | 保持窗口引用，不取得输入控制权 |
| `follow` | 首帧发送完整 snapshot，随后发送 output/state |
| `write` | 仅当前 controller attachment 可写 |
| `resize` | 仅当前 controller attachment 可调整尺寸 |
| `rename` | 更新显示标题 |
| `close` | 幂等地显式终止终端运行时 |

公开错误包括 `terminal/unavailable`、`terminal/control-unavailable` 和
`terminal/limit-reached`。官方终端是 `SessionId -> WebTerminalId` 作用域，不是
全局终端，也不是工作区单例。插件持久表在此基础上增加 `hostId + workspaceId`，
避免跨 Host 使用裸 ID。

## 已实现部分

- `CodingNsTerminalController` 已按上述十个方法登记 Typert Remote 元数据。
- 持久记录与 generation 级 attach 已分表；持久文件不包含 Socket、回调、订阅或
  Host token。
- POSIX backend 使用 tmux 持有 shell；卸载插件只结束 tmux client。
- Windows backend 使用 detached broker 持有 `@lydell/node-pty`/ConPTY，并通过
  Named Pipe 提供受控协议。
- controller 工厂始终实例化插件兼容 controller，并在进程启动时二选一：禁用强化时
  使用自有 Local PTY 与内存映射，启用时使用 tmux/ConPTY 与 JSON 持久映射；不支持
  运行中热切。
- Host 的 `terminal/status` RPC 现在报告实际 controller 模式、Host 平台和已安装
  shell；设置页不再用浏览器平台或刚保存的目标值冒充当前生效状态。
- shell 自然退出会先发送 `exited` 终态再结束 follow 流；终端重命名不再污染
  持久 shell 元数据。
- ConPTY broker 的新 attach 会接管输入，旧 attach 保持只读输出；控制请求有超时，
  显式终止等待真实退出确认，broker 退出时主动关闭 attach socket。
- 插件已经提供属于自身包身份的严格 Typert Host manifest、浏览器 `webTerminals`、
  DSH Sidebar tab 和 Shadow DOM xterm。浏览器卸载或 tab 隐藏只 detach，只有 Sidebar
  显式关闭才调用 Host `close`。

## Bundle 替换结论

官方 Bundle 的 Host 行是 `terminal-controller ->
@deepseek-ai/dsh-api-terminal-controller`，原生 UI 行是 `ui-sidebar-terminal`。DSH
patch 不支持 delete，也不能改已有行的 `name`；只能把官方行写成
`disabled: true`，然后插入新行。

官方 Host 行同时是 client-modules 扫描官方 API 浏览器模块的来源。禁用它会让官方
`ClientTerminals` 一并离开启动图；官方 terminal UI 又硬依赖官方包身份，因此只替换
Host controller 必然出现 `pending (waiting for service: webTerminals)`。

最终做法是替换完整终端栈，而不是伪装官方 package identity：Bundle 成对禁用官方
`terminal-controller` 和 `ui-sidebar-terminal`，再由 `dsh-codingns` 同一个插件行提供
`./typert`、Host controller、浏览器 `webTerminals` 与 Sidebar UI。这样启动图里只有
一个 `terminal` namespace，浏览器服务也有明确所有者。

`dsh --profile stage0 --dump-config` 已确认官方两行禁用且插件行 active。该结果只证明
静态 Bundle 合成正确；由于本轮按项目规则没有启动 DSH，真实冷启动是否还会出现
`waiting for service: webTerminals` 仍需 Web UI 回放验证。

## 外观实现

插件自有 xterm 直接使用公开 options 支持背景、前景、光标、字体、字号、行高、光标
形状、闪烁与 scrollback。xterm CSS 被构建为字符串并注入每个终端的 Shadow DOM，
不会修改全局 `body`，也不依赖官方 terminal UI 的私有 DOM。主题继承读取插件终端
容器上的 DSH 设计令牌，自定义值仍受设置 schema 的格式和范围校验。
